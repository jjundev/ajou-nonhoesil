## HWP 처리

외부 업로드 변환(allinpdf, `scripts/convert_hwp_to_pdf.py`, hwp-to-pdf 스킬)은 쓰지 않았다. 작업 폴더에 복사한 사본(해시가 원본과 같음)을 이 PC의 한컴오피스 2020 COM(`HWPFrame.HwpObject`)으로 열었다. `SaveAs PDF`는 COM 서버 예외로 실패했다. 대신 `CreatePageImage`로 3쪽을 150dpi로 렌더하고 `GetTextFile`로 본문 텍스트를 뽑아 대조했다. 그래서 HWP source는 held가 아닌 complete다. 위치는 렌더 페이지 번호로 기록했다(format=other, pdf_page=null).

## 검증 방법과 한계

1. inventory 출력 9개 path를 파일시스템 전체 목록과 대조했다. source id와 sha256은 inventory 출력을 그대로 썼다. 추출 뒤 원문 9개 SHA256을 다시 계산했고 변경이 없었다.
2. PDF는 PyMuPDF로 120dpi 렌더해 15쪽을 모두 봤다. 식(1)·회로·표는 300~400dpi로 확대해 프라임과 분기점, 게이트 모양을 확인했다.
3. DOCX는 설치된 Word를 읽기 전용·매크로 비활성으로 열어 작업 폴더에만 PDF로 내보냈다. 그 렌더를 보고 OOXML 문단 위치(P6, P8~P9, P13, P16~P17)를 대조했다.
4. 채점본 이미지는 원본과 2~6배 확대본으로 판독했다. 개인 식별 헤더는 전사하지 않았다.
5. 구조·참조·파일 해시 검사 CLI가 pass했다. 기계 검사와 이 판독은 정답이 옳다는 것을 보증하지 않는다. 다른 판독자의 독립 검토는 없다.

```powershell
python -m scripts.lab.review_pack.question_bank_cli check --root . --bank 문제은행/실험03/question-bank.json
```
