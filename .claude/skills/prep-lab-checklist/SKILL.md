# prep-lab-checklist

`<실험NN>/체크리스트/명세.md` 하나에서 실험실용 산출물 전부를 파생한다.

**PDF 와 md 를 항상 쌍으로 만든다.** 태블릿에 PDF 를 띄워 펜으로 채우고,
끝나면 `기록.md` 로 전사한다(④가 vision 으로 돕는다).

## 실행 절차

0. **실험 번호를 폴더 이름으로 옮긴다.** 사용자는 "실험1 …" 또는 "다음 실험 …"
   으로 부르고, 아래 절차의 경로는 `<실험NN>/` 이다. 손으로 `실험1` 이라고
   적지 않는다 — 0 을 안 채우면 `실험10` 이 `실험2` 앞에 정렬된다.

   ```bash
   python3 -c "
   from scripts.lab import config
   print(config.experiment_dir(<실험번호>))
   "
   ```

   **"다음 실험" 처럼 날짜로 물었으면** 아래로 찾는다. 한 날에 실험이 둘일 수
   있어 리스트가 온다(9/18 은 실험2·3 이다).

   ```bash
   python3 -c "
   from scripts.lab import config
   print(config.next_experiments())
   "
   ```

   `None` 이면 학기가 끝난 것이다. FPGA 프로젝트(11/27~12/11)는 실험 번호가
   없어 `config.PROJECT_DIR` 로 간다.

   **주차로 불렸으면**("2주차 체크리스트" 처럼) 아래로 옮긴다. 한 날에
   실험이 둘일 수 있어 리스트가 온다.

   ```bash
   python3 -c "
   from scripts.lab import config
   print(config.experiments_in_week(<N>))
   "
   ```

   - 빈 리스트인데 `config.is_project_week(<N>)` 가 참이면 FPGA 프로젝트
     주차(13~15주차)다. 실험 번호가 없어 `config.PROJECT_DIR` 로 간다.
   - 빈 리스트이고 거짓이면 그 주엔 실험이 없다(1주차 오리엔테이션·4주차
     추석·8주차 중간고사). 그대로 알리고 중단한다.
   - 둘 이상이면 **어느 쪽인지 되묻고 중단한다.** 한 날에 실험이 둘인
     주차가 있고, 그날 안에 둘 다 마쳐야 하므로 두 벌이 다 필요할 수도
     있다.
   - 하나면 그 번호로 위 `config.experiment_dir()` 을 부른다.

1. **실험 폴더·명세 확인.** `<실험NN>/체크리스트/명세.md` 가 없으면 **거절한다.**
   폴더가 없으면 `init-lab-experiment` 를, 명세가 없으면 `draft-lab-spec` 을
   안내한다. **명세를 지어내지 않는다.**

2. **먼저 검증한다.** 틀린 진리표를 인쇄해서 실험실에 들고 가는 것이 최악이다.

   ```bash
   python3 -c "
   from scripts.lab.spec_parser import parse_spec
   from scripts.lab.netlist_parser import parse_netlist
   from scripts.lab import validate
   spec = parse_spec('<실험NN>/체크리스트/명세.md')
   netlist = parse_netlist('<실험NN>/결선도/netlist.md')
   findings = (validate.validate_spec(spec)
               + validate.check_netlist('<실험NN>/결선도/netlist.md', spec)
               + validate.check_netlist_circuits(netlist, spec))
   print('\n'.join(str(f) for f in findings) or '문제 없음')
   "
   ```

   **error 가 하나라도 있으면 인쇄하지 말고 보고한다.** warn 은 알리고 진행한다.

   `parse_netlist` 가 `NetlistError` 를 던지면 그 결선도에 회로 메타가 없는
   것이다. **예외 메시지를 그대로 사용자에게 전하고 멈춘다** — 옛 방식으로
   대충 렌더하지 않는다. 백필 방법은 메시지가 담고 있고 계약은
   `docs/schema/lab-netlist-v2.md` 다.

3. **기록 템플릿 파생 — 이미 채워진 기록은 덮지 않는다.**

   ```bash
   python3 -c "
   from scripts.lab.record import derive_record, write_record
   from scripts.lab.spec_parser import parse_spec
   spec = parse_spec('<실험NN>/체크리스트/명세.md')
   print(write_record('<실험NN>/체크리스트/기록.md', derive_record(spec)))
   "
   ```

   **`write_record` 로 쓴다. `Path(...).write_text(...)` 로 쓰지 않는다** —
   파생은 언제나 **빈** 템플릿이라, 손으로 쓰면 체크리스트를 다시 뽑는 것만으로
   실험 기록을 지우는 명령이 된다. 2026-09-20 실험03 재생성이 실제로
   `filled_by: vision`·확인 칸 16개·종료 메모 4문항을 말없이 날렸다(작업자가
   알아채고 `git checkout` 으로 되돌렸다).

   - `created`·`regenerated` 면 그대로 4단계로 간다. 파일이 없거나 손대지 않은
     템플릿이면 지금까지와 똑같이 동작한다.
   - **`RecordExistsError` 가 나면 멈춘다.** 예외 메시지의 근거 목록(확인 칸
     N개 · 종료 메모 N문항 …)을 **그대로 사용자에게 전하고** 판단을 받는다.
     기록을 그대로 둔 채 4단계로 가면 인쇄본(html·pdf)만 다시 나오는데, 대개
     이쪽이 사용자가 원하던 것이다.
   - 사용자가 "빈 템플릿으로 되돌려 달라"고 **명시적으로** 답했을 때만
     `force=True` 로 다시 부른다(`기록.md.bak-<시각>` 백업이 먼저 남는다).
     **스스로 켜지 않는다** — 켜는 순간 이 가드는 없는 것과 같다.

4. **인쇄본 렌더 + PDF.**

   ```bash
   python3 -c "
   from pathlib import Path
   from scripts.lab import config
   from scripts.lab.render import render_checklist
   from scripts.lab.spec_parser import parse_spec
   from scripts.lab.netlist_parser import parse_netlist
   from scripts.lab.html2pdf import DEFAULT_CHROME, html_to_pdf
   root = config.find_project_root(Path('.'))
   info = config.load_course_info(root)
   spec = parse_spec('<실험NN>/체크리스트/명세.md')
   netlist = parse_netlist('<실험NN>/결선도/netlist.md')
   tmpl = Path('.claude/skills/prep-lab-checklist/template.html').read_text(encoding='utf-8')
   out = Path('<실험NN>/체크리스트/체크리스트.html')
   out.write_text(render_checklist(spec, netlist, tmpl), encoding='utf-8')
   from scripts.lab.fit_pages import fit_pages
   fit_pages(out, chrome=info.get('chrome') or DEFAULT_CHROME)
   html_to_pdf(out, out.with_suffix('.pdf'),
               chrome=info.get('chrome') or DEFAULT_CHROME)
   "
   ```

   **`fit_pages` 를 빠뜨리지 않는다** — 단계 블록마다 높이를 실측해 블록 하나를 제 높이의
   쪽 하나로 만든다(쪽 길이 wrap_content, 2026-09-28 사용자). 빠뜨리면 단계가 기본 쪽에서
   흘러 그림과 확인 줄·단계 진리표가 쪽 경계에서 갈린다. HTML 을 덮어쓰므로 렌더 직후에
   부른다 — 여러 번 불러도 결과는 같다.

   **`chrome=` 를 반드시 넘긴다** — 안 넘기면 `과목정보.md` 의 `chrome` 필드가
   선언만 되고 아무 효과가 없다 (⑥ 표지 스킬과 같은 규칙이다).

5. **인쇄본 자체 검사.** 마크다운 표기가 벗겨지지 않고 남는 경우가 있다 —
   실험02 인쇄본이 `**` 10개를 담은 채 커밋된 적이 있다. 이 절차가
   `check_rendered_html` 을 안 돌려서 아무도 못 봤다.

   ```bash
   python3 -c "
   from pathlib import Path
   from scripts.lab import validate
   html = Path('<실험NN>/체크리스트/체크리스트.html')
   for f in validate.check_rendered_html(html) + validate.check_embedded_images(html):
       print(f)
   "
   ```

   **error 가 0 이 아니면 인쇄하지 않는다** — 마크다운을 HTML 로 옮길 때 표
   셀을 빠뜨리면 인쇄본에 그대로 찍힌다.
   `check_embedded_images` 는 경로가 안 풀려 깨진 결선도 그림을 잡는다 —
   2026-09-14 점검 전까지 이 단계는 마크다운 표기만 보고 그림은 안 봤다.

6. **쪽 크기 실측.** 아래를 돌려 쪽 크기를 본다.

   **폭은 전부 `209.9`, 높이는 두 가지다.** 이 PDF 는 인쇄하지 않고 태블릿으로 본다(2026-09-28
   사용자) — 쪽 수는 신경 쓰지 않는다.
   - 공통면·배선 상자·기록표 쪽은 기본 쪽 `420.2` 다. 완성본 결선도(세로/가로 최대 1.9)가
     폭 100% 로 캡션과 한 쪽에 들어가야 해서 A4 297mm 에서 늘렸다.
   - 단계 쪽은 블록마다 다르다(실험04 실측 323~451). **단계 수만큼 420 이 아닌 쪽이 있어야
     한다** — 단계 쪽이 전부 420 이면 4단계의 `fit_pages` 가 빠진 것이다.

   Chrome 헤드리스의 폭은 이름값 210mm 보다 0.11mm 좁은 `209.889mm` 로 고정이다 —
   **결함이 아니다.** 폭이 눈에 띄게 벗어날 때만(예: Letter 로 나와 215.9)
   `template.html` 의 `@page { size: 210mm 420mm }` 를 확인하고 다시 낸다. 새 주차 완성본
   결선도가 더 길면 `test_가장_긴_결선도도_한_쪽에_폭_그대로_들어간다` 가 먼저 알린다.

   ```bash
   python3 -c "
   from pypdf import PdfReader
   for p in PdfReader('<실험NN>/체크리스트/체크리스트.pdf').pages:
       print(round(float(p.mediabox.width)/72*25.4,1),
             round(float(p.mediabox.height)/72*25.4,1))
   "
   ```

7. **AI 활용 로그.** `과목정보.md` 의 `ai_usage_log` 가 `~` 가 아니면 그 경로에
   한 줄 추가한다(⑥·③·④ 와 같은 규칙). `~` 면 아무것도 하지 않는다. 이 스킬도
   저장소 안에 PDF 를 만드므로 빠뜨리면 그 값이 채워지는 순간 로그가 조용히
   불완전해진다.

8. **결과 안내.** `기록.md` · `체크리스트.pdf` 링크와 표 개수·행 수를 한 줄로.

## 인쇄물 구성 (이 순서를 지킨다)

**1. 공통면 (1쪽)** — 한 번만 보면 되는 것
- 전원 박스 (사용 게이트 입력 플로팅 금지 · 미사용 핀은 회로마다 핀 점검 상자)
- 꼭 읽을 것 (`kind: must-read`, 불릿 ≤5 + 표) — 전원 박스 바로 아래 빨간 테두리
- 물리 주의 상자 3줄 — 선은 클립 깊이까지만 꽂는다(실험03 GND 접촉 불량) · 칩을 꽂고
  뽑을 때 전원을 끈다 · 회로를 바꿀 때 걷을 선부터 뽑는다. 셋째 줄은
  어느 회로의 `## 단계` 표에 걷기 행(`<k>걷기`)이 하나라도 있으면 "걷기 그림(빨간
  점선)의 선부터" 로 바뀐다
- 선 색 범례 한 줄 + `kind` 별 기록 범례 3줄 (진리표 · 스텝표 · 파형)
- 오늘의 흐름 표 (회로 순서 · 이름 · 쓰는 IC · 기록할 표)
- 참조 핀아웃 표 (`kind: lookup`)
- 칩 자리표 (`kind: layout`)
- **`common`·`open-issues`·`sources` 는 인쇄하지 않는다**(2026-09-28) — 공통 규칙과
  미확정 표는 실험04 공통면 420mm 4쪽을 차지했는데 실험실에서 읽히지 않았다. netlist 에
  저작·검토용으로 남는다. `sources` 는 ③ 의 참고문헌 재료다

**2. 회로 페이지** — `kind: circuit` 마다 하나. 강제 개쪽
- 머리글 `회로 3/5 · 이름 · 기록: T3`
- 칩 교체 배너 (앞 회로와 IC 를 비교해 뺄 칩·꽂을 칩). 회로에 `continues` 가
  있으면 "앞 회로(제목)를 그대로 두고 이어 붙여요. 점퍼선은 뽑지 않아요"
  문구로 바뀐다 — `continues` 는 **바로 앞** 회로만 가리킬 수 있다. 이 회로에
  `## 단계` 표가 있으면 기본 문구("점퍼선을 모두 뽑아요") 대신 "앞 회로
  배선은 그대로 둬요. …" 로 바뀐다 — 슬롯 고정·기준선 비교로 그리는 회로는 실제로 앞
  회로를 뜯지 않는다. 뒷말은 단계 표의 **첫 행**이 걷기냐로 갈린다(회로 경계 판정이다):
  걷기면 "걷을 선은 걷기 그림(빨간 점선), 새 선은 단계 그림(회색·번호)을 따라가요",
  아니면 "걷을 선·새 선은 단계 그림(회색·번호·'걷는다' 표)을 따라가요" 다 — 걷기 보드가
  없는 주차(실험01)에서 없는 그림을 가리키지 않기 위해서다
- 강의노트 회로도 — 명세 항목의 `schematic` 이 가리키는 PNG(폭 80%·최대 70mm, 캡션
  `강의노트 p5 · 회로 구성` — 쪽은 `pages` 의 첫 쪽만). 한 항목을 가리키는 회로가 여럿이면
  **첫 회로에만** 싣는다. 필드가 없으면(실험01·02) 아무것도 내지 않고, 파일이 없으면 그림도
  캡션도 없이 안내 한 줄(`회로도가 아직 없어요: …`)만 낸다
  (2단계 검증이 `check_schematics` warn 으로 먼저 알린다)
- 완성본 결선도 (없으면 빈 브레드보드 크롭). 단계가 있으면 "완성본 — 손그림 원도" 캡션
  + 그 아래 사이드카의 결선 순서 목록(`ol.steps`, 손그림 따라 그리기 순서). 결선도 PNG 에는
  보드만 있고 글자는 옆 `.json`(`breadboard-sidecar/v1`)에 있다 — **JSON 이 없으면 렌더가
  멈춘다.** 결선도를 `render_breadboard.py --experiment <N>` 로 다시 뽑는다
- 칩별 배선 상자 — 두 형식이 있다. 불릿형(`- U<n> = <칩>` 아래 들여쓴
  `- ` 배선)은 번호 목록 + 체크박스, 헤딩형(`## U<n> = <칩>` 아래 마크다운
  표)은 표 + 선행 체크박스 열. **상자 안은 원문 순서다** — 표와 산문이
  섞여 있으면 쓰인 순서 그대로 찍힌다
- 핀 점검 상자 (칩마다 따로) — 사용 핀은 다 물렸는가, 미사용 핀은 지시대로인가. 상자째 한
  쪽에 든다(`break-inside: avoid`) — 제목만 쪽 끝에 남던 것을 막았다(2026-09-28)
- 이 회로의 유의사항 산문
- 단계 블록 (`## 단계` 표의 행마다) — 절차 그림(회색 = 앞 단계에서 그대로) + 이 단계에서
  + 사이드카 목록(먼저 뽑아요 · 결선 순서 · 계측 · 회색 N개)
  + `확인 노드: <이름> (<핀>)` + ☐ 확인 + **단계 진리표**. 칩이 둘 이상인 회로와 앞 회로가
  있는 회로에 있다. 완성본·배선·핀 점검 **뒤**다 — 전체 모습을 먼저 보고 단계를 밟는다(2026-09-28).
  `확인 노드` 는 그 행의 `확인` 칸이 가리키는 노드 이름과 그 핀인데, **핀은 회로의
  `## 노드` 표에서 조회한다** — 저작자가 단계 표에 적지 않는다(적으면 두 자리가 표류한다).
  `확인` 이 노드를 안 가리키는 행, 즉 **걷기 행(`<k>걷기`)에는 이 줄이 없다.** 걷기
  블록의 제목은 `2단계 전 · 걷기` 다. **블록 하나가 PDF 한 쪽이고 쪽 높이는 블록만큼이다**
  (4단계의 `fit_pages`) — 그림과 확인 줄·단계 진리표가 쪽 경계에서 갈리지 않는다
- 단계 진리표 — 그 단계 노드의 기대값을 단계 블록 안에 싣는다. 입력 열은 **그 노드 식에
  나오는 입력만**(기록표 헤더 순서)이고, 행은 기록표 행을 그 입력으로 줄여 겹치는 것을
  합친 것이다 — 2^k 전개가 아니다(실험04 MUX 는 입력이 7개다). 줄인 입력에 X 가 남아도
  노드 값이 정해지면 X 째 싣고, 안 정해지면 그 행을 뺀다. 입력 열 위에는 `입력 — 점퍼
  1=+5V · 0=GND` 묶음 머리가 붙고(입력을 LED 로 읽지 않게), 노드 열 머리는 그 단계
  `이 단계에서` 칸의 `→LED<n> 급전` 표기가 **정확히 하나**면 `LED4 = E'` 처럼 볼 LED 를
  먼저 쓴다(없거나 둘 이상이면 노드 이름만). 행마다 ☐ 는 `td.box` 이고
  `.check` 가 아니다. **마지막 관측 단계에는 없다** — 바로 뒤에 기록표가 오고 그것이 그
  단계의 표다. 단 그 노드가 기록표 **출력 열**일 때만이고, 중간 노드면 마지막 단계에도 싣는다.
  걷기 행·노드를 안 가리키는 옛 단계 표에도 없다. 계산은 `nodes.stage_table`
- 단계에서 안 본 노드 표 (`## 노드` 중 어느 단계도 가리키지 않는 노드가 있을 때만) — 기록표
  뒤에, 기록표 전 행 × 그 노드들 열, 열 머리에 프로브 핀. 한 단계 안에서 함께 세운 노드
  (실험04 C2 `S0'`·`S1'`)와 단계 없는 회로의 노드가 여기 남는다. 단계 진리표와 겹치는 열은
  찍지 않는다 — 옛 "중간 노드 기대값" 표(전 노드)는 2026-09-28 에 이것으로 줄였다
- 측정표 + 사진 지시 + 미니표 (`kind` 마다 다르다 — 아래 표 참고). 단계가 있는 회로에서는
  마지막 단계 바로 뒤다
- `refs` 로 가리킨 참조표(role: reference) — 회로 페이지에 읽기 전용으로
  실리고 기록 칸·미니표를 받지 않는다

**3. 종료면 (1쪽)** — 실험실을 나오기 전 확인 목록(확인 칸·사진·사진 파일명·실험실 확인·
조교 질문·종료 메모 거리·부품 반납). 종료 메모 4문항 필기란은 두지 않는다 — 메모는
`기록.md` 나 자유 메모 파일로 적고 `write-result-report` 가 받는다

**결선도를 그리지 않는다.** `diagram:` 이 가리키는 완성본 PNG 와 `## 단계`
표의 절차 PNG 를 싣기만 한다. 그림이 필요하면 `breadboard-diagram` 을
**먼저 따로** 돌린다. 인쇄가 렌더러에 묶이면 회로 ID 가 없는 주차에서
조용히 실패한다.

진리표 행 사진은 `<항목> <입력비트>.jpg`(예 `1-2 000.jpg`)이고 인쇄본의 `사진 파일명` 열에
행마다 찍혀 있다. 항목 토큰은 항목 제목의 `실험 N)` 번호다 — 없으면 열을 내지 않는다.
스텝표·파형 사진은 `<항목> <표ID> <설명>.jpg`(예 `1-1 T1 xy.jpg`)다. 어느 쪽이든 앞에
`실험03 ` 같은 접두어를 붙이지 않는다 — 실험02 사진이 그래서 시트 규칙 밖이 됐다.

## 인쇄본 문구

인쇄본은 실험실에서 태블릿을 한 손에 들고 읽는다. 문구는 토스식 사용자 말투로 쓴다 —
학생이 다음에 할 행동이 한 번에 읽혀야 한다. **이 절은 인쇄본(html·pdf)에 찍히는 고정
문구에만 적용한다.** 이 문서의 본문과 `기록.md` 는 저장소 문체(`~다`)를 그대로 쓴다.

**적용 대상** — 문구를 새로 쓰거나 고칠 때 이 절을 따른다.
- `scripts/lab/render.py` 의 `LEGEND` · `_CAUTION` · `_CAUTION_SWAP` · `WIRE_LEGEND` ·
  `_INSTRUMENT` · `CLOSING`, 칩 교체 배너 문구, 머리글(`실험실을 나오기 전에` 등)
- `template.html` 의 CSS `content` 문자열(`그다음 꽂는다` 등)

**규칙**
1. 해요체로 쓴다. 지시도 설명도 `~해요` 로 끝내고(`전원부터 꺼요`), 점검 목록은 `~했나요?` 다.
   `~하세요` 는 쓰지 않는다 — 명령조로 읽혀 다른 줄과 말투가 갈린다(2026-09-28 사용자).
   과한 존대(`~하실게요`, `~되시겠습니다`)도 쓰지 않는다.
2. 한 문장에 행동 하나만 담는다. 행동이 둘이면 두 줄로 나누거나 순서를 `먼저 … 그다음 …` 으로 적는다.
3. 행동을 앞에 두고 이유는 뒤에 짧게 붙인다 — `전원부터 꺼요. 켜 둔 채 꽂으면 칩이 상해요.`
4. 부정문보다 해야 할 일을 쓴다. 금지가 꼭 필요하면(플로팅 입력 같은 것) 그대로 금지로 쓴다.
5. 명사형·한자어 뭉치를 풀어 쓴다 — `재배선한다` → `선을 다시 꽂아요`.
6. 한 개념에는 한 단어만 쓴다. 이미 인쇄본에 있는 용어(`걷기 그림` · `단계 그림`)는 그대로 둔다.

**바꾸지 않는 토큰** — 말투와 상관없이 원문 그대로 둔다.
- 신호·핀·IC·노드 이름(`B`·`Bo`·`74LS86`·`S0'`) — 강의노트 표기가 모호해도 그대로 쓴다
- 사진 파일명과 그 규칙(`<항목> <입력비트>.jpg`)
- `진행하지 않았음` — `기록.md` 의 마커(`record.py` `NOT_RUN`)와 맞아야 한다
- 선 색 이름과 그 뜻(`빨간 점선 = 뽑는다`) — 결선도 렌더러와 짝이다

**예시** (2026-09-28 이 규칙으로 고친 문구 — 옛 문구 → 지금)

| 옛 문구 | 지금 |
|---|---|
| 칩을 꽂고 뽑을 때는 전원을 끈다 | 칩을 꽂거나 뺄 때는 전원부터 꺼요 |
| 앞 회로의 점퍼선을 모두 걷는다 | 앞 회로의 점퍼선을 모두 뽑아요 |
| 새로 꽂는 것은 없다 — 뽑기만 한다 | 이번엔 뽑기만 해요 — 새로 꽂는 선은 없어요 |
| 부품을 반납했는가 | 부품을 반납했나요? |

**문구를 고치면 테스트도 같이 고친다.** `tests/test_lab_render.py` 가 문구 조각을
`assertIn` 으로 잡는다(`전원부터 꺼요` · `걷을 선부터 먼저 뽑고` · `점퍼선을 모두 뽑아요` ·
`그대로 둬요` · `뺄 칩:` · `꽂을 칩:`). 조각을 새 문구에 맞추고, 배너 갈래를 가르는 `assertNotIn` 이 여전히 한쪽만
잡는지 확인한다.

## 비-목표

- 명세를 만들지 않는다. 없으면 `draft-lab-spec` 이 교안에서 저작한다.
- 결선도를 그리지 않는다. `netlist` 의 `diagram:` 이 가리키는 PNG 와 `## 단계`
  표의 절차 PNG 를 있으면 그대로 삽입할 뿐이다. 없으면 `diagram:` 은 빈
  브레드보드로 대신하지만 단계 그림은 회색 기준선이 요점이라 격자로 대신하지
  않고 한 줄 `src` 안내만 낸다 — 어느 쪽도 검증이 warn 으로 알린다. 그림은
  `breadboard-diagram` 이 별도로 만든다.
- 강의노트 회로도를 크롭하지 않는다. `schematic` 이 가리키는 PNG 는 `draft-lab-spec` 이
  `scripts/lab/schematic.py` 로 만든다 — 없으면 인쇄는 되지만 그 자리에 안내 한 줄만 남는다.
- 캐시 신선도 로직(mtime 비교·SOURCES 블록)을 만들지 않는다.
  소스가 고정이므로 그냥 다시 만드는 게 싸고 안전하다.
