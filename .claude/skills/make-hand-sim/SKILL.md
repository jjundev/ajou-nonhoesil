# make-hand-sim

완성본 결선도(`배치.py` 의 `FINALS`)로 팀원 전달용 PDF 두 개를 `<실험NN>/결선도/팀원전달용/` 에 낸다.
완성본 하나가 각 PDF 의 한 쪽이다. 손그림모사 쪽은 빈 판형 PDF(v2 `.claude/assets/breadboard_v2/Breadboard_v2.pdf`,
A4)와 크기·그림 자리가 같고, 부품그리기 쪽은 210×420mm 태블릿 판이다.

| 파일 | 쪽마다 | 팀원이 하는 일 |
|---|---|---|
| `실험NN_손그림모사.pdf` | 흔들린 배선 그림만 — 제목·실험 이름도 없다(작성자가 손으로 적는다). 칩·LED·저항·입력 이름 배지·번호 원·보드 밖 꼬리표는 **비어 있다** | 이 위에 부품을 그려 넣는다 |
| `실험NN_부품그리기.pdf` | 제목 + 범례 + 안내판(같은 흔들림의 선은 전부 회색, 그릴 부품만 제 색) + 부품표(칩 pin 1 행, LED·저항 홀, 입력 이름 자리) | 어디에 무엇을 그릴지 본다 |

그림·표·쪽 검사는 전부 코드(`scripts/lab/hand_sim.py`, 엔진 `hand=`·`hand_guide=`)가 한다. 이
스킬이 하는 일은 빌더에 인자를 달고, 뽑고, 눈으로 보는 것이다.

## 인자 — 실험 하나로 정한다

`<실험번호|N주차> [회로 이름]`. 번호 토큰이 없으면 한 줄로 되묻고 멈춘다.
- "실험N"·"N" → 실험 N.
- "N주차" → `.venv/bin/python -c "from scripts.lab import config; print(config.experiments_in_week(N))"`.
  결과가 **정확히 하나**일 때만 진행한다. 비었거나 둘 이상이면 후보를 들어 한 줄로 되묻고
  멈춘다 — 같은 번호의 실험 폴더(`실험0N`)가 있으면 첫 후보로 든다.
- 회로 이름을 말하면 그 완성본 PNG 이름을 `--final` 로 넘겨 그것만 뽑는다. 이름이 `FINALS` 에
  없으면 생성기가 `FINALS 에 없는 완성본: … — 가능한 이름: …` 으로 멈춘다 — 그 후보를 들어 되묻는다.
- 회로 이름을 말하지 않았으면 그 실험 `FINALS` 전부를 싣는다.

## 고치는 파일 — 이 둘뿐이다

1. 그 주차 `보고서/실험NN/결선도/배치.py` — `FINALS` 빌더의 `hand`·`hand_guide` 인자
2. 그 주차 `결선도/팀원전달용/` 의 두 PDF

엔진·`hand_sim.py`·공용 시험이 실패하면 고치지 않는다. 실패한 명령과 출력 끝부분을 보고에 싣고
멈춘다 — 도구 결함은 도구 커밋으로 따로 고친다.

## 절차

1. **빌더.** `FINALS` 빌더마다 시그니처 끝에 `hand=None, hand_guide=False` 가 있고
   `BreadboardRenderer(..., hand=hand, hand_guide=hand_guide)` 로 넘기는지 본다. 없으면
   `보고서/실험05/결선도/배치.py` 의 `build_e5_bcd` 처럼 더한다 — `stage` 와 함께 주면 거절하는 두 줄
   (`if hand is not None and stage is not None: raise ValueError('hand 는 완성본(stage=None)에만 준다')`)
   포함. 단계 그림에는 임시 급전선이 있어 팀원이 그릴 그림이 아니다. 빌더가 인자를 안 받으면
   `hand_sim` 이 아무것도 그리기 전에 그 빌더 이름을 모두 대고 멈춘다.
2. **픽셀 불변.** 빌더를 고쳤으면 `render_breadboard.build_all(load_board(N), <tmp>)` 로 뽑은 전 장의
   `Image.tobytes()` sha256 을 고치기 전·후로 대조한다 — 한 장도 달라지면 안 된다(인자 통과뿐이다).
   그다음 `.venv/bin/python -m pytest tests/test_breadboard_hand.py -q`.
3. **뽑기.** 기존 PDF 가 있으면 먼저 스크래치 폴더에 복사해 둔다. 그다음
   `.venv/bin/python -m scripts.lab.hand_sim --experiment N`. 생성기가 임시 폴더에서 만들고 쪽 검사
   (완성본 n 장 → 쪽별 그림 `[1]*n`)를 통과한 뒤에만 옮긴다. `… 가 3쪽(쪽별 그림 [1, 0, 1])이다` 가
   나오면 부품표가 넘친 것이다 — 도구 결함으로 보고하고 멈춘다(`hand_sim.CSS` 의 `img.guide` 높이를
   줄이는 도구 커밋이 필요하다. 실험05 BCD 25행이 230mm 에 맞춘 근거다).
4. **보기.** `pymupdf` 로 두 PDF 의 모든 쪽을 60dpi PNG 로 스크래치 폴더에 뽑아 Read 로 본다.
   - 손그림모사: 글자(제목)가 **없고**, 칩·LED·저항 몸통과 입력 이름 배지·번호 원이 **없고**, 보라 입력
     점퍼선은 **있다**. 쪽을 빈 판형 PDF 와 겹치면 홀이 맞는다.
   - 부품그리기: 색 배선이 **하나도 없고**(전부 회색), 칩·LED·저항·입력 이름 배지가 **색**이고,
     부품표가 그 쪽 안에서 끝난다.
   - 두 그림의 회색·색 선 모양이 같다(같은 시드).
5. **다시 뽑은 경우.** 3 의 사본과 새 PDF 를 쪽별로 잰다(쪽 텍스트 + 그림 md5):
   ```python
   import pymupdf, hashlib
   def sig(f):
       d = pymupdf.open(f)
       return [(p.get_text(), [hashlib.md5(d.extract_image(x[0])['image']).hexdigest()
                               for x in p.get_images()]) for p in d]
   ```
   같으면 사본을 제자리로 복사해(`cp <사본> <PDF>`) 그대로 두고 "바뀐 것 없음" 으로 보고한다 —
   타임스탬프만 다른 재생성은 커밋하지 않는다. `git checkout` 은 쓰지 않는다 — 커밋 안 된 최신본
   대신 옛 커밋본이 돌아온다.
6. **커밋.** 바뀐 `배치.py` 와 두 PDF 를 커밋한다. `결선도/` 에 새 PNG·JSON 이 생겼으면 결함이다 —
   커밋하지 말고 보고한다.

## 정한 규칙과 근거 (2026-10-12 세션)

- **선만 코드가 긋는다.** 칩·LED·저항·글자는 사람이 그린다. 코드로 부품 윤곽을 흔들고 손글씨
  글꼴(Bradley Hand)을 쓴 2단계는 사용자가 결과를 보고 거절했다(521a17a 로 되돌림) — 다시
  제안하지 않는다.
- **입력은 점퍼선만 남기고 이름 배지를 비운다**(5187ba6). 사용자가 "입력 점퍼선은 그대로, 라벨만"
  이라고 정했다. 이름 자리는 0/1 을 바꿀 때 옮겨 꽂는 **레일 쪽 끝** 옆이고 부품표가 그 홀을 적는다.
- **비우기는 `_blank_parts` + `_NullDraw`**(엔진 `base.py`) — 그리기 호출만 버리고 `textbbox` 는 진짜
  붓에 물어 기록·배치가 평소와 같다. 그래서 `verify()`·점유표가 바뀌지 않는다.
- **안내판(`hand_guide=True`)은 같은 시드의 흔들림을 `KEEP` 회색으로** 긋고, `_blank_parts` 안
  (`_in_parts`)의 부품·배지만 제 색으로 그린다(cbca160). 팀원이 두 쪽을 겹쳐 봐도 선이 같은 자리다.
- **범례에 "칩 핀·LED·저항의 회색 다리도 부품과 함께 그려요"** — 다리가 회색이라 "회색은 이미
  그려져 있다" 만 읽으면 팀원이 다리를 빠뜨린다. 최종 리뷰에서 Important 로 올려 고쳤다(cfe7219).
- **시드 = 손그림모사 PNG 이름의 sha256 앞 8바이트** — 다시 뽑아도 같은 그림이다.
- **흔들림은 `step_wire` 만** — ±2px, 굵기 ×0.7~1.3. 번호 원·보드 밖 꼬리표·사이드카·도장은 없다.
- **PNG 는 `결선도/` 에 두지 않는다** — 도장·사이드카 없는 PNG 를 검사 도구가 정본으로 읽는다.
- **판형.** 실험05~ 는 v2(`config.BOARD_V2_FROM`)가 기준이다. 실험04 MUX(v1)는 시험판으로 처음
  만든 곳이라 시험 고정용으로 남는다. 실험04 DMUX 는 아직 `hand` 를 안 받는다.
- **손그림모사 쪽 = 빈 판형 PDF 쪽**(`hand_sim.board_page`) — 판형 그림 자리에 위쪽·너비를 맞춰 놓는다.
  손그림모사 PNG 는 판 아래를 잘라 내므로 높이만 짧다. 제목·실험 이름은 싣지 않는다 — 작성자가 손으로
  적는다(사용자 결정). 판형 PDF 가 없는 v1 은 A4 너비에 그림을 꽉 채운다.
- **안내판 쪽 210×420mm**, 안내판 그림 최대 230mm.

## 넓힐 때 손볼 곳 (지금 주차엔 영향 없음)

- `connect_unused_inputs` 의 미사용 입력 선은 `draw.line` 곧은 선이다 — 흔들리지 않는다.
- `instrument()` 프로브 리드·원·번호는 안내판에서도 제 색으로 남는다(`signal_tag` 배지만 회색).
- `_in_parts` 는 중첩 호출에 안전하지 않다 — 부품 그리기 안에서 또 부품을 그리면 표시를 일찍 끈다.

이 셋 중 하나를 쓰는 주차가 오면 엔진 결함으로 보고하고 멈춘다.

## 보고

1. PDF 두 개의 경로·쪽 수 (또는 "바뀐 것 없음")
2. 완성본마다 부품표 행 수(칩·LED·저항·입력)
3. 고친 것 — `배치.py` 의 빌더 이름, 픽셀 불변 결과
4. 본 쪽 — 쪽 번호와 확인한 것
5. 걸린 것 — 멈춘 명령과 출력 끝

팀원이 그려 오면 `export-hand-diagram` 으로 PNG 를 뽑고 `review-hand-diagram` 으로 검토한다고 한 줄 붙인다.

## 흔한 실수

| 실수 | 대신 |
|---|---|
| 부품을 코드로 흉내 내 "더 손그림답게" 한다 | 하지 않는다 — 521a17a 로 거절된 방향이다 |
| 입력 점퍼선까지 비운다 | 선은 남기고 이름 배지만 비운다 |
| 안내판 쪽이 넘쳐 `hand_sim.py` CSS 를 이 스킬에서 고친다 | 보고하고 멈춘다 — 도구 커밋으로 따로 고친다 |
| 단계 빌더에도 `hand` 를 단다 | `FINALS` 완성본만. `stage` 와 함께면 거절 |
| 시험에서 `--out-dir` 없이 `main` 을 부른다 | 커밋된 PDF 를 덮는다 — 늘 임시 폴더를 준다 |
