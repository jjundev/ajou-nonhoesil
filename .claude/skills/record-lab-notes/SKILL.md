# record-lab-notes

실험실에서 막 돌아왔을 때 쓰는 스킬이다. 사용자는 "2-1 하다가 CC 뜨고 0.03V,
선 두 개 닿아 있었음" 처럼 짧게 말하고, 이 스킬은 그 말을 결선과 맞춰 본 뒤
`기록.md` 에 옮긴다. 결과보고서는 며칠 뒤 ④ `write-result-report` 가 이
`기록.md` 에서 쓴다 — 원인 검토를 그날로 미루면 기억이 흐려진 뒤에 따지게 된다
(실험01 메모의 "11 을 안 넣어서" 는 결보를 쓰다가야 결선표와 어긋난다는 것이
드러나 고쳐졌다).

기준 사례는 실험04 2-1 이다(커밋 `2aa1604`): "CC 0.03V, 선 두 개 닿음" →
결선도 데이터로 두 선을 추정 → "S0·S1 을 반대로 읽음" → "전부 예상대로" 네
입력이 항목 메모·하위 항목 두 줄·4문항·확인 칸 14개가 됐다.

## 절대 규칙

1. **`기록.md` 와 자유 메모 파일에만 쓴다.** 보고서 md·명세·`netlist.md`·결선도
   JSON 은 고치지 않는다. 보고서는 쓰지 않는다 — ④ `write-result-report` 의 일이다.
2. **보고서에 들어갈 내용은 반드시 종료 메모 4문항에도 넣는다.** 항목 메모에 적은
   사건·원인·해결·교훈은 4문항 중 맞는 문항에도 실험 항목 번호 태그(`(2-1)`)를 붙여
   같이 적는다 — 항목 메모에만 두면 고찰의 재료(④ §절대 규칙 4)에서 빠진다.
   사용자가 요청한 추정(예: "몇 번째 선인지 추론해줘")은 쓰기 계획 승인을 받아들임으로
   보고, 그 사건이 놓인 문항에 **한 구절만** 추정 표시를 달아 넣는다 — 근거 전문은
   항목 메모의 추정 하위 항목에만 둔다. 예외는 확인 칸을
   읽는 법만 말하는 메모(시험 범위 "조교 지시로 4행만 시험"·"확인 칸은 칩 교체 후
   결과")다. 이것은 고찰이 아니라 결과 표의 해석이라 항목 메모에만 둔다.
3. **4문항의 재료는 사용자의 말이다.** Claude 가 덧붙인 설명(예: 전원공급기
   CC/CV 원리)은 대화로 제안만 하고, 사용자가 받아들인 것만 넣는다. 사용자가
   요청한 추정은 §절대 규칙 2 대로 한 구절만 들어간다. 고찰은 본인
   경험이어야 한다(④ §절대 규칙 4) — 이 스킬이 거기에 남의 문장을 심으면 결보가
   그대로 옮긴다.
4. **추론은 끝까지 추정으로 둔다.** 사용자가 기억하지 못한 것을 결선으로 좁혔으면
   `(추정 — 근거…; 미확인: …)` 으로 적고, 미확인 조건이 사용자 확인으로 풀리기
   전까지 표시를 떼지 않는다. ④ 는 메모를 사실로 옮기므로 표시가 빠지면 추정이
   보고서에서 사실이 된다.
5. **`✓` 는 사용자가 "예상대로였다" 고 말한 표의 행에만 친다.** 사진을 보고
   추론해 채우지 않는다 — 사진 전사는 ④ 의 경로다(`.claude/skills/write-result-report/필기전사.md`); 이름 없는 사진은 `label-lab-photos`).
   다르게 나온 행은 사용자가 말한 실제 관찰값을 그 칸에 적는다.
6. **채워진 칸을 덮어쓰지 않는다.** 항목 메모에는 사건 하나를 줄 하나로 적는다 —
   첫 사건은 `- 메모:` 줄에, 다음 사건부터는 그 아래 들여쓴 하위 항목 `  - ` 로
   새 줄을 연다. 같은 줄에 이어 붙이지 않고, 자기 항목 메모 안이라 태그도 붙이지
   않는다. 사건의 추정은 그 사건 줄 바로 아래 4칸 들여쓴 `    - (추정 — …)` 이다 —
   첫 사건(`- 메모:` 줄)의 추정도 4칸이다(2칸은 다음 사건 자리다). 4문항에는 첫
   항목부터 실험 항목 번호 태그(`(2-1)`)를 붙이고, 이미 값이 있으면 `; (2-1) …` 로
   같은 줄 뒤에 이어 쓴다. 체크리스트 재생성이 채운 기록을 덮어 사라진 일이 있었다
   (`scripts/lab/record.py` 의 "채워진 기록 보호" 주석).
7. **쓰기 전에 계획을 보여 주고 승인받는다.** 어느 줄에 무엇을 쓰는지 보여 준
   뒤에만 고친다. 커밋은 하지 않는다.

## 실행 절차

0. **실험 폴더를 찾는다.** 사용자가 실험 번호로 말하면 폴더 이름으로 옮긴다.

   ```bash
   python3 -c "
   from scripts.lab import config
   print(config.experiment_dir(<실험번호>))
   "
   ```

   번호 없이 "오늘 실험" 처럼 말하면 ② `prep-lab-checklist` 의 날짜 조회를 그대로
   쓴다. 둘 이상이면 되묻는다.

1. **`기록.md` 가 있는지 본다.** `<실험NN>/체크리스트/기록.md` 가 없으면 거절하고
   ② `prep-lab-checklist` 를 안내한다. 이 스킬이 대신 만들지 않는다.

2. **원문을 보존한다.** 사용자가 이번에 한 말을 요약하지 않고 그대로
   `<실험NN>/실험중있었던일.md` 끝에 덧붙인다(없으면 만든다). 형식은 메시지마다
   `## YYYY-MM-DD` 헤딩 한 줄과 그 아래 원문뿐이다 — 같은 날 두 번째부터는 헤딩 없이
   빈 줄 하나를 두고 잇는다. 파일 머리말·번호·설명을 덧붙이지 않는다. 실험01~03 이 쓴
   파일이다. `기록.md` 는 정리본이고 이 파일은 원문이다 — 정리가 틀렸을 때 되돌아갈
   자리다. 이 덧붙이기는 승인 없이 한다(원문 그대로라 판단이 들어가지 않는다).

3. **메모를 항목에 붙인다.** 명세(`체크리스트/명세.md`)의 항목 ID·표 ID 와
   `결선도/netlist.md` 의 해당 회로 절을 찾는다. 어느 항목 얘기인지 말에서 안
   나오면 묻는다.

4. **원인 주장을 결선과 맞춘다.** 사용자의 말에 "~때문에"·"~가 닿아서" 같은 원인
   주장이 있거나, 사용자가 "몇 번째 선인지 추론해줘" 처럼 빈자리를 채워 달라고
   하면 한다. 없으면 건너뛴다. **사용자가 묻지 않은 빈자리는 추정하지 않는다** —
   "어느 행이 이상해 보였나" 처럼 원인 검토에 필요 없는 세부를 지어 기록에 넣지
   않는다. 판정에서 떨어진 대체 후보(예: "D=1 이었다면 다른 두 선")는 대화로만
   알리고 기록에는 적지 않는다.

   - 재료는 `netlist.md` 의 칩별 핀 목록과 결선도 JSON
     (`결선도/실험NN_<항목>_결선도_*.json` 의 `steps`: 선 번호 `n`·`from`·`to`
     구멍 좌표·`desc`)이다. ④ §실행 절차 7 의 대조 규칙처럼 **게이트·핀·구멍
     단위까지** 내려간다.
   - 말에 나온 위치(예: "맨 왼쪽 위 칩 오른쪽 열")에 해당하는 선을 표로 늘어놓는다:
     `| 핀 | 행 | 선 | 신호 |`.
   - 증상에서 전기적 조건을 끌어내 거른다. 예: 전원공급기가 CC 로 넘어가며 전압이
     0 에 가까우면 VCC–GND 직결 수준이다 — 그 열의 VCC 선과, 그 순간 GND 와 같은
     노드였던 선(입력 점퍼가 GND 레일에 꽂힌 입력 넷 등)만 남는다. 출력끼리·출력과
     전원의 충돌은 출력단 저항 때문에 전압이 그만큼 떨어지지 않는다.
   - 시점도 근거다. "마지막에" 났다면 마지막 결선 단계(`netlist.md` 의 단계 표)에서
     새로 꽂은 선을 먼저 본다.
   - 판정을 셋 중 하나로 낸다: **맞다**(근거 표) / **어긋난다**(어긋나는 결선 사실)
     / **좁혔다**(후보와, 사용자가 확인하면 확정되는 조건 — 예: "당시 D=0 이었나").

5. **쓰기 계획을 보여 준다.** 다음 셋을 한 번에 보여 주고 승인받는다
   (§절대 규칙 7).

   - 항목 메모에 쓸 줄. 사건마다 줄 하나, 추정은 그 사건 줄 아래 한 단 더
     들여쓴 `(추정 — …)` 줄로 가른다(§절대 규칙 6).
   - 종료 메모 4문항에 넣을 문장과 문항 배정(§절대 규칙 2). Claude 가 제안하는
     "새로 안 것" 문장은 따로 표시해 받을지 묻는다(§절대 규칙 3).
   - `✓` 를 칠 표와 행(§절대 규칙 5).

6. **승인되면 `기록.md` 를 고친다.** Edit 로 해당 줄만 바꾼다. 결과가 확인됐으면
   프론트매터 `filled_by` 를 `hand` 로 둔다(이미 `vision` 이면 그대로). 고친 뒤
   체크리스트 재생성이 이 파일을 덮지 않는지 확인한다.

   ```bash
   python3 -c "
   from scripts.lab import record
   print(record.record_marks(open('<실험NN>/체크리스트/기록.md', encoding='utf-8').read()))
   "
   ```

   빈 리스트가 나오면 보호가 걸리지 않은 것이다 — 보고하고 멈춘다. 들여쓴 추정
   하위 항목은 여기서 "덧쓴 산문" 으로 잡힌다(정상이다 — 보호 쪽으로 센다).

7. **다음 단계를 안내한다.** 무엇을 어디에 적었는지와 남은 미확인 조건을 알리고,
   결과보고서는 ④ `write-result-report` 로 쓴다고 안내한다. 실험사진이 빠진 항목이
   있으면 그것도 알린다. 커밋하지 않는다.

## 비-목표

- 결과보고서·고찰 문장을 쓰지 않는다.
- 필기 PDF·사진을 vision 으로 전사하지 않는다(④ 의 `필기전사.md`).
- 결선도·netlist 를 고치지 않는다 — 결선 계획이 틀렸다고 보이면 알리기만 한다.
