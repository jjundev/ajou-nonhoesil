# 검증과 정직한 완료 보고

1. 원문 확인: 회로도·오버바·엣지·enable·초기 조건·단위·페이지를 직접 대조한다.
2. 독립 계산: 조합회로는 작은 입력 전수검사. boolean_equivalent는 명시적 ·,+,⊕,후위 prime, 입력 8개 이하만 지원한다. 다른 표기는 명시적으로 변환하거나 별도 검산한다.
3. 순서회로는 초기 상태와 각 엣지 전후를 표로 추적한다. 초기값이 없는 Q를 0으로 가정하지 않는다. 비동기 제어가 있으면 먼저 적용한다.
4. 계산 문제는 단위·차원·경계값을 확인한다. 정답지와 다르면 양쪽을 재검토하고 불명확하면 disputed/unresolved를 유지한다.
5. 설명 충분성: 노트와 원문 문제만으로 풀이에 필요한 조건·개념을 찾을 수 있어야 한다. 별도 승인된 리뷰어가 있으면 정답을 뺀 사본과 노트로 검토한다. 없으면 self_review이며 independent=pass를 쓰지 않는다.
   - 첫 토픽에서 해결할 문제 → 회로가 필요한 이유 → 작은 입력·출력 예 → 이번 실험과 연결을 찾을 수 있어야 한다. 입력·출력 예는 직접 검산하고 조건·극성·one-hot·수행 제외 항목을 확인한다. 정의만 쓰거나 시험 출제를 이유로 대체한 설명은 충분하지 않다.
   - 새 팩·전체 갱신의 개념 토픽마다 「한눈에 보기」 규칙표가 formal보다 앞에 있어야 한다. 규칙표에 쓰인 핀·용어는 그보다 앞에서 소개돼야 한다. 앞 회로의 변형이면 차이 한 줄이 있어야 하고, 요약은 규칙으로 시작해야 한다([authoring.md](authoring.md#개념-토픽-안의-순서-규칙-먼저)). 수동 감사이며 검사 코드는 없다.
   - ‘이해를 위한 예시’와 ‘보충’이 실제 교안 수행 조건·측정값과 구분되는지 확인한다. 첫 토픽 제목·요약과 HTML/MD 내용이 일치해야 한다. 기존 팩을 갱신할 때 비도입 본문·IDs·읽음 저장 키·기출 자료·원문 증거를 비교하고 변경 후 검토 상태를 새로 기록한다.
6. check_pack로 ID/링크/그림/수식/MD 보존을 검사한다. 이 통과는 내용 정확성의 증명이 아니다.
7. 브라우저에서 375px/1280px, 다크모드, 이전/다음, 목차, 우측 요약·힌트·풀이, 읽음·푼문제 상태, 위젯, 인쇄를 확인한다. 외부 요청 없이 폰트·KaTeX가 동작해야 한다.
   - `자료 이동` 영역이나 pack-nav가 없어야 한다. `이 페이지 목차` nav에는 해당 문서의 토픽/문항 hash 링크만 있어야 하며, 현재 토픽 강조와 읽음/풂 체크는 별개다.
   - `이 페이지 목차` 소제목과 진행 숫자/막대가 없어야 한다. 토픽 목록의 들여쓰기 0와 긴 제목·체크·키보드 포커스를 밝은/어두운 테마에서 확인한다.
   - 모바일에서는 목차 링크 선택 후 drawer가 닫혀야 한다. hash 직접 열기·뒤로가기·읽음 상태 복구를 확인한다.
   - JS 비활성에서도 전체 토픽 링크가 남아야 하며, 잘못된 토픽 링크·hash로 화면 초기화가 멈추지 않는다. 섹션 링크나 toc-group이 없는 평평한 목록이어야 한다. 인쇄에서는 탐색 패널을 숨긴다.
   - 기존 팩 갱신은 전체 사전 검사/백업, 본문·IDs·payload 보존, 두 번째 실행의 변경 0을 확인한다. standalone의 상대경로 참조는 leftovers 검사에서 0이어야 한다.
8. 수정은 최대 두 회. 남은 보류·불확실성을 검증결과.md에 남긴다. 구조 실패나 확인하지 못한 브라우저 상태를 pass로 표시하지 않는다.

판독하지 않은 페이지·검토하지 않은 문항을 검증 완료에 포함하지 않는다.
publish는 원문 해시를 다시 확인한다. 변경된 자료가 있으면 관련 설명·문항을 재검토한 뒤 해시를 갱신한다.
산출물 개수는 이해도 점수가 아니다. 최종 보고에는 사용자가 읽을 네 파일과 제한사항을 준다.

## 은행 수입 검증

import는 독립 풀이를 수행하지 않으며 checks 전부 not_run으로 시작한다.
로컬 check는 snapshot의 바이트 hash·은행 id/version/experiment·선언 자산·인덱스 고정 정보·모든 문항과 원문 위치를 대조한다.
build/publish는 원래 은행 JSON·원자료·원래 자산의 현재 해시도 확인한다. 입력 변경 시 새 import와 관련 저작 재검토가 필요하다.
원문 partial/unreadable 문제를 included로 올리지 않는다. 제공 답안 confirmed/candidate는 정답 확인을 대신하지 않는다.
답 노출 present/unknown 원문은 문제 영역·힌트·바로 보이는 카드 영역에서 금지한다. 허용되는 원문/풀이 details에서만 사용한다.
파일명 변경·복사로 노출 상태가 바뀌지 않는다. 새 교육용 그림의 의미상 답 노출은 별도 내용 검토로 확인한다.
srcset 후보와 스타일의 로컬 이미지 URL도 검사한다. summary는 항상 보이므로 답 노출 증거를 넣지 않으며, 증거 details의 초기 open 상태도 허용하지 않는다.
은행 카드의 CSS @import/image-set은 지원하지 않는다. 원문 그림은 직접 로컬 URL을 사용하는 img로 배치한다.
snapshot·인덱스·안내를 최종 팩과 함께 보존하며 독립 검토·실제 브라우저 확인 전 완료 상태를 표시하지 않는다.

## 본문–요약 감사와 패널 검증

모든 학습 토픽을 읽고 `자료·토픽`을 키로 본문 주장·대응 요약 문장·판정/생략 이유를 감사표에 기록한다. 일반·강조·주의·보충의 서로 다른 핵심은 별도 행에 둔다. 이미 충분한 요약은 수정 없이 반영으로 기록한다. 원리·조건·구분이 빠진 행은 보완 전 unresolved로 두고, 보완 후 실제 요약을 다시 읽어 pass 또는 unresolved로 판정한다. 항목 수에 고정 상한을 두지 않고 본문에 없는 사실을 추가하지 않는다. 기존 동반 MD 및 실제 생성 원고를 대조하고, 동반 MD가 없으면 새 형식을 만들지 않는다.

검증 JSON에는 `{schema_version:1, html, html_sha256, audit_path, audit_sha256, semantic_status, browser_status, evidence, unresolved}`를 기록한다. semantic_status와 browser_status는 실제 검사를 수행한 뒤에만 갱신한다. 산출물 또는 감사표 해시가 바뀌면 기존 기록은 갱신 전까지 오래된 근거다. UI 구조 검사 성공을 의미 검토 pass로 대신하지 않는다.

HTTP 임시 stage에서 1280×900과 375×812 각각 light/dark로 우측 패널을 실제로 연다. 중앙 h3와 고정 패널 제목이 보이고 우측 중복 토픽·문항 제목은 없어야 한다. 현재 요약 하나와 예상 전문을 대조하며, 토픽 이동 뒤 이전 요약 숨김·요약 없는 표지 안내·유일한 `.sums#sum-for`·읽음 저장 키 유지를 확인한다. legacy 문제 카드는 힌트·풀이·푼 문제 토글과 저장 키를 확인한다. 문제설명은 문제와 원문으로 가는 기존 탭/링크·이전/다음·수식 오류 0을 확인하고, 원래 없는 탭을 새로 만들지 않는다. pageerror는 0이며 missing-sum 검사가 계속 누락을 잡아야 한다. 문제·보기·정답·해설 본문·원문·앵커·저장 키와 워크북 payload는 전후 비교한다.

칩 빌더는 `복습노트/칩 정리/.pack/build.py`의 OUT·PACK을 별도 임시 stage로 지정하고 읽기용 mcq.json·mcq.css·mcq.js를 복사한 뒤 실행한다. 세 HTML의 패널과 문제 payload를 비교한다. 원본 폴더에서 build()를 실행해 questions.json·sources.json을 덮어쓰지 않는다. 실제 `.pack/assets` 소비 경로를 확인해 동봉 템플릿만 맞추며 과거 export·source·영상 사본은 바꾸지 않는다. provenance.sha256의 원래 upstream 값을 보존하고 local_adjustments에 실제 최종 템플릿 해시와 이유를 기록한다.
