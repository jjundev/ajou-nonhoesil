# export-hand-diagram

손그림 PDF를 `보고서/실험NN/결선도/손그림/`에 PNG로 저장한다. 기본은 **전체 페이지**이며 사용자 크롭 요청 또는 `--crop`이 있을 때만 아래 크롭 절차를 사용한다.

## 입력과 정본

`<실험번호|주차> [PDF 경로] [--out DIR] [--dpi DPI] [--crop]`

- 번호가 없으면 한 줄로 묻는다. 주차는 `scripts.lab.config.experiments_in_week`로 확인한다.
- PDF를 지정하면 그 파일을 사용한다. 없으면 `scripts.lab.export_hand_diagrams.find_default_pdf`가 최신 `output/손그림검토/round*/hand.pdf`, 다음으로 최종통합본을 찾는다.
- 기본 DPI는 300이다. 파일명은 netlist 및 PDF/검토 전사로 결정되는 `실험NN_{소단원}_손그림_{회로명}.png`다. 실험별 이름을 코드에 하드코딩하지 않는다.
- 검증/시안은 별도 `--out`에 저장한다. 원본 PDF를 수정하지 않는다. 기존 정본 교체 요청이 없으면 새 출력 폴더를 사용한다.

## 크롭하지 않는 기본 실행

```bash
python3 -m scripts.lab.export_hand_diagrams <실험번호> [PDF경로] [--out DIR]
```

`--no-crop`과 기존 `--full-page`는 `--crop`보다 우선한다.

## 크롭 규칙

1. 전원 단자 **3개**, 극성 표시와 연결선, **보드 전체 외곽과 모든 홀**, 양쪽 행 번호·화살표를 보존한다. 사용하지 않은 보드 하단도 포함한다.
2. 외부 **신호 이름·핀 번호·연결 화살표**까지 보존한다. 페이지마다 경계를 조절한다.
3. 제목·설명 메모 때문에 경계를 넓히지 않는다. 포함 영역 안에 걸친 제목 조각은 허용하며 지우거나 덧칠하지 않는다.
4. 판형 위아래 구분선·하단 캡션·주변 큰 여백은 제외한다.
5. 보존 요소를 감싸는 사각형에 **상하좌우 각각 보드 본체 너비의 2%** 여백을 붙인다. 페이지 끝이면 여백만 제한하고 그 사실을 보고한다.
6. 외부 필기가 직접 결선 표기인지 애매하면 **추측해 포함/제외하지 않는다**. 아래 pending 절차로 후보를 보여주고 사용자 응답을 기다린다. 명확한 다른 페이지는 계속 처리한다.

## 크롭 실행 절차

### 1. 전체 페이지를 보고 영역을 판단한다

PDF 모든 대상 페이지를 먼저 전체 렌더하여 이미지 도구로 직접 열어본다. 텍스트 추출만으로 판단하지 않는다. 필요한 경계와 작은 표기는 확대해서 확인한다.

```python
import fitz
from pathlib import Path
with fitz.open(pdf_path) as doc:
    for i, page in enumerate(doc):
        page.get_pixmap(matrix=fitz.Matrix(1.5, 1.5)).save(str(Path(out_dir)/f'full-p{i+1:03d}.png'))
        print(i+1, tuple(page.rect))
```

- `board_box`: 전원 단자/행 번호를 제외한 보드 본체 **외곽 테두리**. 내부 홀의 끝과 혼동하지 않는다.
- `keep`: 보드 밖에 있는 단자·극성·전선, 행 번호, 직접 결선 표기의 경계. 내부 배선은 board_box에 이미 포함되므로 개별 기록 불필요.
- `excluded`: 제목·설명·판형 캡션 등의 제외 이유.
- `ambiguous`: 결선 표기인지 결정할 수 없는 필기의 경계와 이유.
- 좌표는 **해당 페이지의 회전 적용된 PDF pt 좌표계**다. 픽셀을 pt로 변환하는 공식과 스키마는 [crop-plan.md](references/crop-plan.md)를 읽는다.
- 원본 이미지 배치 정보나 자동 선 검출은 좌표 측정 보조 수단이다. **고정 템플릿 좌표/특정 색상만으로 의미 판독을 대체하지 않는다.**

### 페이지별 외부 필기 누락 확인

각 페이지마다 **보드 위·아래·왼쪽·오른쪽을 각각 확대해 확인하고**, 보이는 외부 필기를 실행 기록의 표에 빠짐없이 나열한다(`페이지 / 위치 / 필기 / keep·excluded·ambiguous / 이유`). 전 페이지에서 본 필기를 다음 페이지의 판독 결과로 대신하지 않는다. 같은 기호가 여러 페이지에 있으면 각 페이지에 각각 기록한다. 필기가 없는 영역도 `없음`으로 명시한다.

전체 렌더를 다시 보며 표에 없는 외부 필기가 남았는지 확인한 뒤 JSON을 확정한다. 작은 고립 기호도 의미가 불분명하면 ambiguous다. 보드와 연결되지 않았다는 사실만으로 설명 메모라고 제외하지 않는다. 명확히 읽히는 제목·캡션은 묶어 기록할 수 있다. 이 확인을 마치지 않은 페이지는 saved로 진행하지 않는다.

### 2. 에이전트가 crop-plan.json을 작성하고 실행한다

사용자에게 좌표/JSON 작성을 떠넘기지 않는다. 판독한 경계를 [JSON 계약](references/crop-plan.md)으로 기록하고 실행한다.

```bash
python3 -m scripts.lab.export_hand_diagrams <실험번호> <PDF경로> --crop --crop-plan <계획JSON> --out <출력폴더>
```

직접 CLI 호출도 `--crop-plan`이 필요하다. 예전 고정 좌표로 fallback하지 않는다. 코드가 SHA-256/페이지 크기/범위를 검증하고 여백을 붙인다. **plan의 box에 2% 여백을 미리 넣지 않는다.**

### 3. pending이면 후보를 제시하고 질문한다

종료 코드 **2**와 `crop-report.json`의 pending은 실패한 추출이 아니라 사용자 판단 대기다. `candidates/`의 include/exclude 이미지 및 boundaries 미리보기를 열고, 어떤 필기를 포함할지 한국어로 구체적으로 질문한다. 주황 경계는 제외, 파랑은 포함 후보다. 여러 필기는 항목별로 확인한다. 후보를 정본으로 사용하지 않는다.

사용자 응답 후 포함 항목은 keep, 제외 항목은 excluded로 옮기고 ambiguous에서 제거한다. 해당 페이지만 `--pages 2`처럼 재실행한다. 이미 출력한 다른 페이지를 대기 상태로 만들지 않는다. 보고서는 **이번 선택 페이지 실행**에 대한 기록이며 과거 상태 전체를 합친 기록이 아니다.

### 4. PNG를 직접 열고 확인한다

파일 존재/세로 비율만으로 성공 판정하지 않는다. 최종 PNG뿐 아니라 전체 원본 위에 보고서의 crop box 경계를 겹친 미리보기도 생성해 직접 열어본다. 잘라낸 바깥에 누락된 필기가 없는지 확인한다. 원본과 대조해 단자·극성·외부 신호 표기·행 번호·마지막 홀·**하단 외곽선**을 확인한다. 잘렸으면 원본을 다시 읽어 plan을 수정하고 재추출한다. 미리보기에서 생긴 불확실성도 pending으로 처리한다.

파일명·크기·용량, crop 여부, pending 페이지, 제한된 여백을 보고한다. 보고서 삽입용 상대 경로도 안내한다. 일반 종료 코드: 0=모두 저장, 1=잘못된 입력/오류, 2=사용자 확인 대기.
