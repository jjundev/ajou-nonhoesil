# 새 결선도의 기본: LED 숫자 순서 고정 탐색

## 순서와 좌표를 먼저 확정한다

새 v2 결선도는 LED 숫자 순서가 최우선이다. `BIT1→BIT6`, `Y0→Y9`처럼 **숫자 값으로 위→아래** 정렬한다.
문자열 정렬로 Y10을 Y2보다 앞에 놓지 않는다. active-low LED도 같은 순서다. 여러 신호 묶음은 명세의
묶음 순서를 유지하고 각 묶음 안에서 숫자로 정렬한다. 숫자가 없는 태그는 명세의 출력 순서를 따른다.
명세에 순서가 없으면 순서를 명시해 확정하고 탐색 입력에 기록한다. 기존 승인본에는 소급하지 않는다.

1. 교안·명세의 신호와 LED 극성을 대조해 `PLACE`의 `leds`를 위→아래 순서로 선언한다.
2. 보드 geometry와 엔진의 `LED_SPAN`·행 범위를 읽어 위에서 아래로 사슬을 놓는다. 저항·LED 다리와
   배지가 겹치지 않고 GND/VCC 착지가 가능하도록 초기 좌표를 정한다. 칩 출력 핀 행에서 순서를 유도하지 않는다.
   작성자가 태그의 숫자순을 명세와 직접 대조한다. 엔진은 숫자를 자동 정렬하지 않고 `PLACE.leds`의 선언 순서를
   검사하므로, Y1,Y10,Y2처럼 잘못 선언해도 숫자순 오류는 잡지 못한다. `fixed_search.validate_anchors`로
   태그·행 범위·최소 간격·레일 홀 조건을 확인하고 실제 고정물도 검증한다.
3. 좌표를 `LAYOUT['leds']`에 저장하고 netlist `kind: layout` 표에 기록한다. 이것이 이번 탐색의 고정 입력이다.
   이후 칩 위치·허용된 등가 할당·배선 순서·λ만 바꾼다. LED 좌표와 순서는 탐색 변수가 아니다.

LED 없는 회로는 고정 LED 탐색 적용 대상이 아니다. 해당 회로의 기존 배치 절차를 따른다.

## 새 실험용 어댑터를 준비한다

현재 실행 가능한 본보기는 `보고서/실험07/결선도/배치.py`의 `search_*` 함수다. 실험07의 핀·단계 수를
복사하지 말고 해당 회로의 netlist와 빌더에 맞춘다. `scripts/lab/fixed_search.py`가 요구하는 계약:

- `PLACE`·`SLOTS`·`LAYOUT`, `BOARDS`·`FINALS`, 필요한 `ASSEMBLY_BOARDS`를 선언한다.
- `search_variants()`·`search_circuit(variant)`: 논리적으로 등가인 할당만 열거한다. 데이터·제어·출력 단자를
  함께 매핑하고 전원 핀은 데이터시트대로 유지한다. 등가 할당이 없으면 원래 할당 하나만 쓴다.
- `search_fixed(bb, layout, variant)`·`search_temporaries(variant)`: 고정물과 임시 입력 급전선을 제공한다.
- `search_context(...)`: 후보 경로·임시선·할당을 실제 빌더에 적용하고 예외가 나도 원상 복구한다.
- `search_baseline()`: 같은 고정 LED 좌표를 가진 검증 가능한 기준 배치·영구 경로·임시 경로를 제공한다.
  새 실험은 교안·명세와 맞춘 기준 결선을 먼저 만들고 검증한다. 과거 승인본이 없다는 이유로 넷 검사를 생략하지 않는다.
- `search_assert_drivers(bb, stage)`·`search_assert_equivalent(bb, name)`: 전원이 켜진 단계의 사용 입력 구동과
  각 보드의 논리 연결을 기준 명세와 대조한다. 비교 기준 자체도 netlist로 검증한다.

현재 `run()`은 **어댑터당 회로 하나**만 받는다. 여러 회로가 있는 실험은 회로별 어댑터 파일을 마련해
각각 실행하고 해당 회로의 준비·걷기·단계·완성본을 검증한다. 공유 슬롯은 같은 좌표를 유지해야 하며,
독립 후보가 충돌하면 그대로 합치지 않는다. 공유 제약을 지원하도록 어댑터/탐색을 확장하고 회로 전환 걷기까지
검증한 뒤 채택한다. 이 제약을 지원하지 못하면 미완료로 보고한다. 여러 회로가 든 `PLACE`를 그대로 넘기지 않는다.
어댑터 미지원 시 먼저 구현·검증하며, 숫자 LED를 legacy 탐색으로 자동 전환하지 않는다.

## 기본 실행과 선택

```bash
python -m scripts.lab.place_search <배치.py> --mode fixed --budget 256 --length-slack 1.10 --out <별도폴더>
```

프로젝트 가상환경의 Python을 사용한다. `--out`은 승인 결선도 폴더와 다른 곳으로 지정한다.
CLI 자체 기본값은 호환성을 위해 `legacy`이므로 **`--mode fixed`를 반드시 명시한다**.
탐색 예산은 회로별 경로 계산 256회다. 별도 검증하는 기준 배치는 이 횟수에 포함하지 않는다.

검증된 최단 신호선 길이의 110% 안에서 **밀도 → 실제 교차 → 단계 최대 밀도 → 꺾임 → 길이** 순으로 고른다.
λ는 후보 생성 설정이며 최종 평가 기준이 아니다. 칩 순열·행·등가 할당과 여러 배선 우선순위·λ를 탐색한다.
실제 준비/걷기/결선/완성본을 같은 후보 경로와 임시선으로 검증한 후보만 비교하며, `--jobs`가 달라도 답은 같다.

새 빌더는 `led_order_policy='fixed'`를 명시한다. R10의 칩→LED 연결 규칙은 유지하고 출력 핀 순서 역전 검사만
제외한다. LED 숫자 순서·좌표는 선언과 고정 anchor 검증으로 확인한다. 홀·넷·전원·겹침·가독성 검사는 완화하지 않는다.
기존 승인 주차의 `pin` 정책과 legacy 지문·도장은 보존한다.

## 결과 채택과 실패 처리

`result.json`·`report.md`·`selected/`를 확인하고 기준 대비 길이·밀도·실제 교차·꺾임·전체 배선 길이,
탐색 예산·유효 후보 수·실패 원인·고정 LED 좌표를 기록한다. 결과는 예산 안에서 찾은 최선이며 전역 최적해라고 부르지 않는다.
새 후보가 모두 실패해도 기준 결선이 유효하면 기준을 유지한다. 기존 승인본은 fallback으로 보존한다.
현재 자동 보고서의 “기존 승인본” 표기는 새 실험에서는 검증된 초기 기준 결선을 뜻한다.

후보를 채택하면 배치·등가 할당·영구/임시 경로를 빌더에 반영하고 netlist 표·신호 연결을 맞춘다.
준비·걷기·단계·완성본 PNG/JSON을 다시 생성하고 체크리스트·따라그리기·손그림모사 등 기존 파생 자료도 함께 갱신한다.

기준을 포함한 유효 후보가 없거나 기준 결선 자체가 검증되지 않으면 실패 원인과 미완료 상태를 보고한다. LED 순서를 핀 순서로
바꾸거나 검사를 완화해 통과시키지 않는다. 고정 좌표를 바꿔야 한다면 변경 이유·새 좌표를 명시한 별도 탐색으로
다시 실행하고 비교 기록을 남긴다. 이미 사용자가 좌표를 지정했다면 그 제약의 변경은 사용자에게 확인한다.
