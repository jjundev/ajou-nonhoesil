# Breadboard Diagram Skill (`breadboard-diagram`)

아주대학교 논리회로실험 표준 브레드보드 템플릿(`Breadboard.jpg`)을 기반으로, 회로 소자(IC), 점퍼선, 저항, LED를 물리적 홀 격자 규격에 맞춰 정밀하게 렌더링하는 스킬입니다.

## 1. 개요 및 목적
- **목적**: 학부 논리회로실험 운영계획서 규정(손스케치 첨부 필수, 미사용 핀 처리 규정, 보호 저항 필수)을 100% 충족하면서, 학생이 태블릿(GoodNotes 등)이나 종이에 따라 그릴 수 있는 오차 없는 정답 결선도 이미지를 제공합니다.
- **주요 기능**:
  1. 표준 브레드보드 템플릿 행/열 좌표 기반 정밀 안착.
  2. 칩별 정확한 DIP-14 핀아웃 매핑 (74HC00, 74HC02, 74HC04, 74HC08, 74HC32 등).
  3. **전기적/안전 규칙 강제**:
     - VCC(14번) -> +5V 적색 레일, GND(7번) -> 0V 청색 레일.
     - **미사용 입력 핀**: 접지하지 않는다 — 2026-09-11 실험01 실측에서 결과에 영향이 없었고 접지선이 순서표의 절반이었다. `mark_unused_inputs()` 로 개방 등록만 한다. 교안이 미사용 핀 처리를 명시한 주차(실험02 p9)만 `connect_unused_inputs()` 로 그린다. **사용하는 게이트의 입력은 반드시 물린다.**
     - **미사용 출력 핀**: 내부 소손(Burn-out) 방지를 위해 **절대 접지 금지, 완전 개방(NC)** 처리.
     - **LED 및 330Ω 보호저항**: 단순 텍스트가 아닌 실제 다리 위치와 저항 색띠(주-주-갈-금)를 갖춘 실물 그래픽 배치.
  4. 브레드보드 물리 규칙 준수 (단자대 세로 절연, 동일 행 5홀 도통).
  5. 활성 행 영역(Active Rows) 자동 줌인 크롭 및 고대비 타이포그래피.

## 2. 브레드보드 물리 좌표계 — v1 (`Breadboard.jpg`, 실험01~04 전용)

(998x1345)에 맞춰 떠 놓은 것이라, "같은 브레드보드 그림"이면 아무거나 써도
되는 게 아니다. 렌더러는 저장소 루트 기준으로 이 파일을 먼저 찾고, 크기가
998x1345 가 아니면 그리기 전에 멈춘다.

> **2026-2 배포본으로 갈아끼우지 마라.** `강의노트/공지사항/Breadboard.pdf`
> 는 같은 도면이고 세로 좌표까지 일치하지만(보드 상하단 y=242·1317)
> **가로가 중앙 기준 약 5% 넓다.** 중앙 레일은 0~2px 차이인데 좌우 끝 레일이

> 옆 홀에 그려지는데, 그림 자체는 멀쩡해 보여서 눈으로는 안 잡힌다. 배포본을
> 쓰려면 아래 좌표를 전부 다시 떠야 한다.
>
> `from_the_past/정리/강의노트/Breadboard.jpg` 는 정본과 바이트가 같은 과거
> 학기 사본이다. 최후 대체물로만 남아 있고, 본문·보고서에서는 인용하지 않는다.

**아래 값은 템플릿을 직접 측정한 것이다 (2026-09-07).** 그 전에는 눈대중
값(`r_y = 243 + (r-1)*17.15`, 좌측 GND 레일 x=163)을 썼는데, 그림은 그럴듯한데
**배선 끝점이 홀 안에 들어가지 않았다** — 1행이 29px, 우측 f~j 열이 한 칸
(16.5px) 통째로 어긋나 있었다. 홀을 세어가며 손으로 따라 그리라고 만든
그림에서 이건 치명적이다. 크기 검사(`TEMPLATE_SIZE`)는 판본 교체만 잡지
좌표 자체의 회귀는 못 잡으므로, `BreadboardRenderer.verify()` 가 내보내기
직전에 **그림대로 꽂을 수 있는지**를 좌표로 확인한다 (§5).

- 캔버스 원본 크기: 998 x 1345 px. **아래 좌표는 전부 이 논리 좌표다.** 출력 PNG 는

  NEAREST 로 늘리고 선·글자는 2배로 새로 그린다(2026-09-28, 태블릿에서 글자가 작았다).
  PNG 픽셀을 읽는 테스트는 논리 좌표에 `SCALE` 을 곱해 읽는다.
- **행**: 63행. `y = 272.0 + (r-1) * 16.345` (1행 y=272, 63행 y=1285)
- **열**:
  - 좌측 블록: GND 레일 174 · VCC 레일 190 · a~e `[239, 256, 272, 288, 305]`
    · 중앙 홈 305~354 (IC 안착) · f~j `[354, 370, 386, 403, 419]`
  - 좌측 중앙 레일: GND 468 · VCC 484
  - 우측 중앙 레일: GND 542 · VCC 558
  - 우측 블록: a~e `[607, 623, 640, 656, 672]` · 중앙 홈 672~721
    · f~j `[721, 738, 754, 770, 786]` · GND 레일 836 · VCC 레일 852

> **레일에는 홀이 없는 행이 있다.** 5홀씩 묶여 있어서 1·2·63행과 6행 주기의
> 빈 행(8·14·20·26·32…)에는 꽂을 데가 없다. 단자대(a~j)는 63행 전부 홀이
> 있다. `free_rail_row()` 가 레일 착지 행을 가까운 **빈** 실제 홀로 옮긴다.

> **좌우 블록은 전원 레일이 뒤집혀 있다.** 좌측 보드는 pin 1~7 쪽(a~e)이 바깥
> 왼쪽 레일에, pin 8~14 쪽(f~j)이 중앙 레일에 붙는다. 우측 보드는 반대다.
> `connect_power()` 와 `nearest_gnd_rail()` 이 블록별로 갈라 준다.

## 2b. v2 판형 (`breadboard_v2/`, 실험05~)

실험실 실물 보드는 **가운데 전원 레일이 2열(GND·VCC 한 쌍)** 이다. 실험05 부터 이 판형을 쓴다.
v1(§2)은 실험01~04 전용으로 남는다 — 승인·손그림 검토·도장이 끝난 그림이라 옮기지 않는다.

- **고르기.** 주차 `배치.py` 에 `BOARD = 'v2'` 를 두고, 빌더마다
  `BreadboardRenderer(template_path, baseline=baseline, layer=layer, board=BOARD)` 로 넘긴다.
  렌더러 기본값(`DEFAULT_BOARD`)은 **v2** 라 `board` 를 안 넘기면 v2 로 그린다. 그래서 v1 주차
  (실험01~04)는 `배치.py` 에 `BOARD = 'v1'` 을 적어 두었고, 어느 실험이든 `BOARD` 가 없으면 불러올 때
  `require_board()` 가 멈춘다(판형이 갈리는 실험은 `config.BOARD_V2_FROM` = 5). 빌더가 `board=BOARD` 를 빠뜨리면 `build_all` 과 손그림 참조가
  `check_board()` 로, 체크리스트가 사이드카 `board` 대조로 멈춘다 — 주차 판형과 다른 그림이
  조용히 나가지 않는다. 체크리스트 빈 판형은 `배치.py` 가 아직 없어도 실험 번호로 v2 를 깐다.
- **좌표는 `.claude/assets/breadboard_v2/geometry.json` 에서만 읽는다.** 숫자를 문서·코드에
  베껴 적지 않는다. 양식 PNG(1200×1600)는 **1배 고정**이다 — 2배로 뽑으면 레일 극성선이 4px 가
  되어 손그림 검토가 레일 열을 6.5px 밀어 잡는다. 렌더러가 PNG 해시를 `png_sha256` 과 맞대므로,
  판형을 다시 뽑으면 그 값도 고치고 `hand_grid.detect_grid` 가 0px 로 맞는지 다시 본다.
- **26열**: `좌 GND·VCC | 좌 a~e (골) f~j | 가운데 GND·VCC | 우 a~e (골) f~j | 우 GND·VCC`.
  63행, 레일 빈 행은 v1 과 같다. 모든 레일은 왼쪽이 GND, 오른쪽이 VCC 다.
- **가운데 레일은 한 넷이다.** `cols['left']['mid_gnd']` 와 `cols['right']['mid_gnd']` 가 같은
  x 라 좌 칩 pin 14(가운데 VCC)와 우 LED 사슬 GND(가운데 GND)가 브리지 없이 한 레일이다. 주소는
  접두어 없이 `중앙GND레일9행` 이다. 가운데끼리 `bridge_rails` 를 부르면 오류다 — v1 의
  `좌 중앙 ↔ 우 중앙` 브리지 습관을 옮기지 않는다.
- **전원 표준**: `connect_jacks()` 로 잭 → **좌 바깥 레일**, 거기서 `bridge_rails(L['gnd'],
  L['mid_gnd'], …)`·`bridge_rails(L['vcc'], L['mid_vcc'], …)` 두 가닥으로 가운데 레일에 넘긴다.
  **우 바깥 레일은 기본 배선에서 쓰지 않는다**(그림에는 있다).
- 사이드카 JSON 에는 `"board": "v2"` 가 든다(v1 은 키가 없다 — 없으면 v1).
- 본보기: `tests/fixtures/board_v2/배치.py` — 칩 둘·LED 둘·브리지 둘의 18단계 보드. **판형·전원·입력
  본보기**다 — 급전선 둘을 손좌표로 찍은 2026-10-03 연기 시험이라, 신호선은 따르지 않는다. v2 신호선은
  `route_plan` 으로만 고른다(§4, 본보기 `tests/fixtures/board_v2_e4/배치.py`) — 배치(`PLACE`·`LAYOUT`·
  `배치탐색.md`) 본보기도 같다.

## 3. CLI 사용법
```bash
python3 .claude/skills/breadboard-diagram/scripts/render_breadboard.py \
    --experiment <N> \
    [--output <출력 폴더>] \
    [--template <template_path>]
```

`보고서/실험NN/결선도/배치.py` 의 `BOARDS`(절차 사슬)와 `FINALS`(완성본)를 **전부** 뽑는다.
출력 폴더 기본값은 그 `배치.py` 가 있는 결선도 폴더다. 회로 하나만 뽑는 옵션은 없다 — 절차
그림은 앞 보드를 기준선으로 쓰므로 사슬째 뽑아야 맞는다.

**엔진과 주차 결선은 따로 산다** (2026-09-15, `docs/plans/2026-09-15-결선도-엔진-주차분리-설계.md`).
스킬 폴더의 `render_breadboard.py` 는 엔진(보드·배선 도구·`verify()`)만 갖고 주차 이름을 모른다.
주차마다 결선은 그 실험 폴더의 `결선도/배치.py` 에 쓴다(§4a 「주차 빌더를 쓸 때」). 새 주차
때문에 스킬 폴더의 **코드**(엔진 `render_breadboard.py`)를 고치게 되면 그것은 도구 변경이다 —
따로 커밋한다.

**보드만 PNG, 글자는 사이드카 (2026-09-28).** 뽑은 PNG 에는 **보드만** 있다 — 제목·주석·
범례·결선 순서·계측표·걷기 목록은 PNG 옆 같은 이름의 `.json`(`breadboard-sidecar/v1`:
`title`·`subtitle`·`kept`·`steps`·`removals`·`probes`)으로 나가고 체크리스트가 목록으로 싣는다
(`scripts/lab/render.py` 의 `_board_text_html`). 그림에 구운 글자는 태블릿에서 작고 체크할 수
없었다. PNG 와 JSON 은 늘 쌍이다 — 체크리스트는 JSON 이 없으면 멈춘다. `note()` 문구는 학생
면에 나가지 않는다(저작 흔적이다). 실험실에서 손으로 할 일이면 netlist 의 `must-read` 절에 쓴다.

**도장.** 뽑은 PNG 에는 그 그림이 싣는 내용(배선·부품·제목·주석·결선 순서·계측표·걷기 목록)의
해시가 텍스트 청크 `breadboard-stamp` 로 찍힌다. 접두어는 `v2:` 다(보드만 PNG) — `v1:` PNG 는
전부 stale 이다. 글꼴·줄바꿈은 해시에 들지 않는다 — 기계마다
시스템 글꼴이 달라 픽셀은 달라도 결선이 같으면 도장이 같다. `tests/test_breadboard_boards.py` 가
결선도 폴더의 PNG 목록이 `BOARDS`·`FINALS` 와 같은지, 도장이 지금 코드와 같은지 본다 —
`배치.py` 를 고치고 PNG 를 안 뽑으면 여기서 걸린다.

### 주차별 결선 (`보고서/실험NN/결선도/배치.py`)

아래 ID 는 빌더 이름 `build_<ID>` 의 `<ID>` 이고 손그림 검토(`hand_compare.CIRCUITS`)의 회로 ID 다.
이 목록은 그 주차 결선 커밋에서 함께 고친다 — 도구 변경이 아니다.
- **실험 1 (기본 게이트 및 조합논리)** — 슬롯 고정 배치 (S1 좌 7행 · S2 좌 18행 · S3 우 10행):
  - `e1_and`: 실험 1-1 3입력 AND (74HC08). 첫 보드 — 완성본 겸 절차 그림
  - `e1_or`: 실험 1-2 3입력 OR (74HC32) 완성본 · `e1_or_s1`: C1 에서 칩만 갈아끼우는 전환 그림
  - `e1_nand`: 실험 2-1 3입력 NAND 완성본 · `e1_nand_s1`(앞단 AND 검사) · `e1_nand_s2`(뒷단 NAND, 완성)
  - `e1_nor`: 실험 2-2 3입력 NOR 완성본 · `e1_nor_s1` · `e1_nor_s2`
  - `e1_comb`: 실험 3 복합 논리회로 완성본 · `e1_comb_s1`(인버터, Z = A') · `e1_comb_s2`(AND 추가) · `e1_comb_s3`(OR 추가, 완성)
  - `--experiment 1`: 절차 9장 + 완성본 4장 = 13장 일괄. 절차 그림은 앞 보드를 기준선으로 회색을 넣고, 완성본은 기준선 없이 전부 색이다

  **완성본과 단계 그림을 섞지 않는다.** 예비보고서·손그림 원도는 완성본(`FINALS`)이고, 체크리스트의 단계 블록은 절차 그림(`BOARDS`)이다. netlist 의 `diagram` 은 완성본을, `## 단계` 표는 절차 그림을 가리킨다.

  **따라 그리기 층.** 손그림을 팀원에게 맡길 때는 완성본을 층으로 나눈 PDF 를 준다 — `배치.py` 의 `LAYERS`(`{완성본 파일명: [(lo, hi, 이름), …]}`, 완성본 번호 1..N 을 빈틈없이)와 엔진 `BreadboardRenderer(layer=(lo, hi))`(앞 층 회색·번호 없음, 이번 층 색·완성본 번호, 뒤 층은 안 보이게 그리되 점유는 남긴다). `.venv/bin/python -m scripts.lab.trace_guide <실험번호>` 가 `결선도/팀원전달용/실험NN_따라그리기.pdf` 를 낸다. 절차 그림(`BOARDS`)은 임시 급전선이 있어 따라 그리기에 쓰지 않는다. 새 주차의 완성본 빌더는 처음부터 `layer=None` 을 받아 `BreadboardRenderer(..., layer=layer)` 로 넘긴다. 층을 정하고 PDF 를 뽑는 절차는 `make-trace-guide` 스킬이다. 실물: 실험04(2026-09-28).

**OR·NOR 은 2026-09-06 에 되살렸다.** 그 전에는 `e1_or`·`e1_nor` 가 각각
AND·NAND 빌더를 가리키는 별칭이라 **틀린 그림을 OR·NOR 이름으로 냈다.**
별칭을 지웠다가, `74HC32` 전용 빌더(`build_e1_or`)와 `74HC02` 빌더
(`build_e1_nor`, 출력이 1번 핀)를 실제로 작성해 복원했다. 두 회로가 한 빌더를

## 4. 그림을 두 층으로 나눈다

운영계획서 3.2 6) 은 **"직접 손으로 작성한 회로 결선도 첨부"** 를 요구한다.
그러니 이 PNG 는 제출물이 아니라 **따라 그릴 원도**다. 원도에 들어갈 것과
들어가면 안 될 것이 갈린다.

**보드 위 (손으로 옮겨 그릴 것)** — 배선, 칩과 핀 번호, LED·저항, 그리고
**신호 이름**. 입력 `A`·`B`·`C` 는 점퍼의 레일 쪽 끝 옆(보드 좌 테두리와 GND
레일 사이 여백)에, 출력 `L1`·`L2`·`X`·`Y`·`Z` 는 LED 옆에 `signal_tag()` 가
찍는다. 2026-09 실험01 예보가 "결선도에 입력 A·B·C 위치 표기가 없다" 로
감점됐다(-1) — 그때 입력 이름은 보드 밖 꼬리표(`입력 A → b7`)에만 있었고,
학생은 보드 판형 위만 따라 그려 그 글자가 옮겨지지 않았다. 신호 이름은 규칙
문구가 아니라 그림의 일부다. **입력 배지는 보라(`INPUT`) 바탕에 흰 화살촉과 흰 글자**
다(`signal_tag(arrow=...)`, 보드 밖 꼬리표도 같은 보라). 화살촉은 점퍼선이 뻗는 쪽 끝에서
그쪽을 가리킨다 — `D0▶`·`◀E`. 중앙 여백 배지는 이것으로 우 블록행(`S1▶`)과 좌
블록행(`◀D1`)이 갈린다(2026-09-29 사용자). 2026-09-29 실험04 MUX 에서 흰
바탕 검정 글자 입력 배지 여섯이 흰 번호 원 41 개 사이에 묻혔다. 화살촉은 글리프가 아니라
다각형이다 — 이모지·기호 글리프는 기계마다 □ 가 되고 손그림에 못 옮긴다. 화살촉 폭
`INPUT_TRI` 4.5 는 좌 바깥 여백(보드 테두리 149 ~ GND 레일 174, 25px)에 `D0` 배지가
들어가는 상한이라 더 키우지 않는다. 입력 점퍼도 LED 도 없는 주차(실험02 X-Y)는
**계측 지점**이 신호 이름을 갖는다 — `instrument(..., name='VIN')` 이 교안
회로도의 이름(`VIN`·`VOUT`·`CH1`·`CH2`)을 그 접점과 같은 스트립 끝 여백(칩 왼쪽
스트립이면 레일과 a 열 사이, 오른쪽이면 j 열 바깥)에 찍는다. 보드 밖 계측
꼬리표(`1. 함수발생기 + CH1 (가로축)`)만 두면 실험01 과 같은 이유로 빠진다.

**보드 밖 (옮겨 그릴 수 없는 것)** — 미사용 입력을 접지하지 않는 *이유*(실험01
실측), 미사용 출력을 개방하는 *이유*, 잭 색 주의 같은 규칙 문구. 전부
`note()` 로 넘겨 아래 범례에 모은다. 꽂을 자리 꼬리표(`입력 A → b7`)도 보드
밖에 남는다 — 이름이 아니라 홀 주소를 알려 주는 것이다.

> 이전 판은 이 둘을 섞어 보드 위에 라벨 박스를 30개 넘게 얹었다. 그중 절반은
> 손으로 옮겨 그릴 것이 하나도 없는 문구인데, 하필 **따라 그릴 홀을 덮었다.**
> 같은 내용이 예비보고서 본문 `공통 결선 규칙` 에 이미 문장으로 있다.

**배선 색은 넷뿐이다** — 빨강 +5V, 파랑 0V, 검정 신호, 초록 중간 노드. 입력 배지의
보라는 배선 색이 아니다 — 입력 점퍼선 자체는 검정 신호선 그대로다.

**모든 선은 홀에서 홀로 간다.** 입력 A·B·C 도 예외가 아니다 — 2026-09-07 까지는
보드 밖 x=95 허공에서 선을 끌어와 "보드밖(입력)" 이라 적었는데, 따라 그리는
사람은 그 왼쪽 끝을 어디에 꽂아야 하는지 알 수 없었다. 지금은 `_input_jumper()`
가 **좌 GND 레일 홀 → 같은 행 b열** 로 그린다(0 자리). 1 은 레일 쪽 끝만 빨간
레일로 옮겨 꽂는 것이고, 그 문장은 범례에 있다. 오른쪽 블록으로 가는 갈래는
허공 줄기에서 분기하지 않고 **같은 스트립의 다른 홀(a열)에 꽂는 두 번째 점퍼**
로 그린다 — 점퍼는 이어 붙일 수 없다. 꼬리표에는 꽂을 자리(`입력 A → b10`)를
그대로 적는다. 왼쪽 눈금이 10·20·30 뿐이라 이름만 있으면 홀을 세어야 한다.
같은 행에 입력이 둘이면(실험04 C2 의 `S1` a31·`D` j31) 꼬리표가 포개져 앞 것이 사라졌다 —
`_tag()` 가 앞 꼬리표와 겹치면 아래로 비키고 상자를 `margin_tag_boxes` 에 남긴다
(`test_보드_밖_입력_꼬리표끼리_겹치지_않는다`, 2026-09-28).
이전 판은 한 장에 16색을 썼는데 `(0,110,170)` 과 `(0,120,180)` 처럼 눈으로
구분되지 않는 쌍이 여럿이라 색이 정보를 나르지 않으면서 눈만 어지럽혔다.
따라 그리는 사람 손에 있는 펜도 네 자루다.

**결선 순서표.** `step_wire()` 로 그린 배선은 번호가 붙고 사이드카 `steps` 에
`⑦ 좌 b10 → 좌 GND레일10행 · pin 7 -> GND 레일` 로 쌓여 체크리스트의 `ol.steps` 체크박스 목록이 된다. 손으로 그리는
사람이 실제로 막히는 지점은 "이 선이 어느 홀에서 어느 홀로 가는지"와 "내가
몇 번째 선까지 그렸는지"다. 표를 위에서 아래로 지워가며 한 줄씩 그리면
30가닥을 동시에 볼 필요가 없다. 주소는 좌표에서 자동으로 뽑는다(`addr()`).

## 4a. 슬롯 · 기준선 · 단계

**슬롯.** 한 실험의 모든 회로가 칩 자리를 공유한다. 정본은 netlist 의 `kind: layout` 표이고
주차 `배치.py` 의 슬롯 상수(`E1_SLOTS`)는 사본이다 — `tests/test_breadboard_wiring.py` 가 맞댄다. 실험01 실험실
기록(2026-09-11): 1-1→1-2 는 칩만 갈아끼우면 되는데 그림이 회로마다 달라 전부 걷었다. v2 주차의 슬롯
**행**은 배치기(`place_search`)가 정하고 netlist 표가 그 값을 받아 적는다(§4) — `tests/test_breadboard_place.py` `PlaceLayoutTable` 이 맞댄다.

**기준선.** `BreadboardRenderer(baseline=앞_보드.snapshot())` 로 그리면 같은 (색, 끝점, 끝점)
의 배선과 같은 네 홀의 LED 사슬은 **회색**이고 번호를 받지 않는다. 기준선에 있었는데 이번에
없는 것은 사이드카 `removals`(체크리스트의 "먼저 뽑아요" 목록)에 주소로 나온다. 같은 자리에 다른 칩이면 순서표
첫 줄이 "뽑는다/꽂는다" 다. 기준선은 색과 번호만 바꾼다 — 배선 집합은 그대로라 `verify()` 도
그대로 돈다. **회색이 되려면 앞 보드와 같은 순서로 그려야 한다** — `free_rail_row()` 가 점유
순서로 레일 행을 고르므로, 공통 배선(`_e1_frame`·`_e1_front`)은 빌더마다 같은 헬퍼를 같은
순서로 부른다.

**rebuild 경계.** netlist 회로에 `rebuild: true` 가 있으면(앞 회로 신호선을 전부 뽑고 새로 짓는다) 걷기 보드를 만들지 않고, 그 회로 첫 보드를 `fresh_board(build_…)` 로 감싸 `BOARDS` 에 넣는다 — 기준선을 끊어 앞 회로 배선이 '걷는다' 로 잡히지 않게 한다. 실물: 실험04 C2(2026-09-27).

**걷기 보드.** **걷기 그림 정책의 정본은 이 절이다.** **선을 뽑는 자리마다**
사슬에 **걷기 전용 보드 한 장**을 끼운다 — 회로가
바뀌는 경계(전가산기 → 전감산기)도, 회로 **안**의 임시 프로브 급전선도 같다. 앞 상태가
전부 회색이고, 다음 보드에 없는 배선만 **빨간 점선 + 빨간 채움 원 번호**(걷기 ①②)다.
다음 보드에 없는 **LED 사슬**은 LED·저항을 빨갛게 칠하고 빨간 점선 상자로 두른다 — 번호는
그 사슬의 GND 선이 받고, 부품은 순서표에 번호 없는 줄로 나간다(2026-09-29 실험04 8걷기).
새 선도 순서표도 없다. `배치.py` 의 `BOARDS` 에
`removal_board((앞_빌더, stage), (다음_빌더, stage), 제목, 부제)` 로 넣는다 — 회로 안
걷기는 **같은 빌더의 인접 단계**를 물린다(`(build_e3_fa, 1), (build_e3_fa, 2)`). 엔진이
다음 보드를 임시 렌더해 `removals()` 로 뽑을 key 를 얻고, 앞 보드를 기준선 dict 의
`ghost` 키로 다시 그린다. 유령선은 점유표·구간에 없고(`verify()` 가 안 본다) 템플릿과
overlay 사이 층이라 회색 선이 덮는다. 걷기 보드의 `snapshot()` 이 다음 보드의 기준선이라
다음 보드에는 "걷는다" 표가 없다 — 그래서 **단계 보드는 아무것도 걷지 않는다**
(`tests/test_breadboard_boards.py::StageBudget` 이 실험01·02 를 뺀 모든 주차에
단언한다). netlist 단계
표의 `<k>걷기` 행이 그 번호를 인용한다(`**걷기 ①·② 를 뽑는다**`). 주차 파일에 `build_`
래퍼를 두지 않는다 — `tests/_boards.py` 가 잡아 `steps > 0` 검사에 걸린다. 걷을 배선이
없는 전환에는 끼우지 않는다 — `removal_board` 가 스스로 `ValueError` 로 거절한다
(실험03 C2 2→3).
걷기 보드는 **앞 회로(또는 앞 단계)를 그대로 다시 그려** 만들므로, 주차 파일이 단계
노트를 그냥 두면 걷기 종이에 **앞 단계의 노트**("5단계: … 74HC32 를 꽂아 완성한다")가
찍혀 같은 종이의 "새로 꽂는 것은 없다" 와 부딪힌다 — 그래서 주차 파일은
`bb.ghost is not None` 이면 단계 노트를 건다(실물: `보고서/실험03/결선도/배치.py` 의
`note = None if bb.ghost is not None else _E3_STAGE_NOTE.get(...)`). 걷기 보드가
학생에게 **무엇을 뽑으라고 말하는 자리**는 `removal_board(...)` 의 제목·부제다.

**게이트 좌우 배정.** DIP-14 쿼드 게이트는 게이트 1·2 가 핀 1~6(a~e 쪽), 3·4 가 핀 8~13(f~j
쪽)이고 hex 인버터는 1·2·3 이 a쪽, 4·5·6 이 f쪽이다. 배정 순서는 셋이다.
① **R7 에 걸리는 칩만 나눈다.** 한쪽 리드가 8 이하면 게이트 1·2 로 둔다 — 승인본 실험03 의
74HC08(왼쪽 7리드)·74HC04(왼쪽 5리드)가 그렇다. 게이트 1·2 만 써서 걸린 것은 74HC86(좌 11, 입력 셋과 갈래
셋이 한쪽에)뿐이었다. ② **게이트 자리는 신호가 오는 쪽이다.** 같은 블록 위/아래 칩에서 오면
그 출력 핀과 같은 쪽, 다른 블록에서 오면 그 블록을 향한 쪽(우 블록은 a쪽, 좌 블록은 f쪽), 레일
입력은 바깥 레일 쪽. 그래서 나눌 때는 게이트 4(핀 12,13→11 — 행 +1~+3 로 게이트 1 의 거울)나
hex 6(13→12)이 짝이 된다. ③ **나눈 칩 안의 사슬만** 칩 위/아래 행(pin1_row−1 또는 +7)으로
건넌다 — 칩 몸통 위는 지나지 않고(핀 번호를 가린다), **두 칩 사이에서는 건너지 않는다.**
2026-09-20 격리 시험에서 무조건 1·4 로 나눈 판은 `좌 a9 → 좌 h19`(A⊕B → NOT2) 같은 X자를 만들었다
— 승인본 실험01~03 완성본에는 0건이다(시험 전용 실험02 t_pd 보드의 같은 칩 두 패키지 사슬 한
가닥만 예외). f~j 쪽 게이트의 입력은 `_input_jumper(..., side='f')` 로 그쪽
GND 레일(좌 블록 중앙 468 / 우 블록 바깥 836)에서 i 열로 넣는다. 결과는 `verify()` 가 잰다 —
R7(칩 한쪽 리드 ≤ `SIDE_LEAD_MAX` 8)과 R8(같은 블록 두 칩 사이 배선은 쪽을 안 바꾼다).
netlist 를 저작할 때 게이트 번호를 이렇게 적는 것이 먼저다(`draft-lab-spec` SKILL 의 「결선도 절에 회로 메타를 단다」 절).

**주차 빌더를 쓸 때:** 파일은 `보고서/실험NN/결선도/배치.py` 하나다. 머리에서

시그니처는 `build_eN_x(output_path, template_path=None, stage=None, baseline=None)` 이고 끝에
`return bb` 를 둔다. 보드 사슬은 `BOARDS = [(파일명, 빌더, stage), …]`, 완성본은
`FINALS = [(파일명, 빌더), …]` 다 — 일괄 렌더 함수는 쓰지 않는다(엔진 `build_all` 이 한다).

`stage is not None` 인 보드만 골라 검사한다.

JSON 에 저장되므로 한 번 쓴 이름은 바꾸지 않는다.

**v2 배치 규약 (R9·R10).** 칩은 **좌 블록에만**, 우 블록에는 **LED 사슬(LED + 330Ω)만** 둔다 —
칩 사이 연결이 가운데를 좌우로 왕복하면 선이 꼬인다. 칩끼리는 좌 블록 안에서 세로로 잇는다.
LED 를 구동하는 게이트는 **f~j 쪽(pin 8~14)** 에 배정해 건너는 선이 칩 몸통 위를 지나지 않게
하고, 사슬은 **우 a 열**에서 받아 GND 를 가운데 레일로 내린다(우 f~j 에 두면 GND 가 쓰지 않는
우 바깥 레일로 가서 레일 연결성 검사에 걸린다). 건너는 선의 위아래 순서는 LED 순서와 같게 둔다.
좌 블록에 칩이 다 안 들어가는 주차가 생기면 규약에 예외를 두지 않고 면제 열쇠 방식
(`docs/plans/2026-09-21-면제열쇠-설계.md`)으로 연다.

**v2 에서 R8 과 함께 가기 — MUX·디코더 류.** 칩이 전부 좌 블록이면, 인버터가 x 와 x' 를 같은
쪽에서 내는데 앞단 게이트 한 칩이 x 와 x' 를 서로 다른 쪽에서 받는 회로(MUX 의 74HC20 둘)는 칩
사이 선만으로는 R8 을 못 지킨다. R8 을 면제하지 않고 이렇게 푼다(2026-10-03 실험04 시험판 —
`docs/plans/2026-10-03-실험04-v2-시험판-결과.md`, 본보기 `tests/fixtures/board_v2_e4/배치.py`).

- 칩 **사이** 선은 같은 쪽끼리만 잇고, 쪽 바꾸기는 목적지(또는 출발) 칩 **안에서** 이어 간다 —
  R8 은 같은 칩 안의 a↔f 선을 보지 않는다.
- 그래도 남는 신호는 **n.c. 핀**(74HC20 pin 3·11)이나 **미사용 게이트 입력**을 디딤돌로 쓴다
  (그 게이트 출력은 개방). 빈 행을 거쳐 쪽을 바꾸는 우회는 쓰지 않는다 — R8 의 구멍일 뿐이다.
- 대가: 교안 핀 번호가 바뀌고(바뀐 것은 netlist 미확정 표에 적는다), 칩 한쪽 리드가 8 에 붙고,
  단계당 새 신호선이 7 까지 는다(예산 결정은 결과 문서 제안 1).

번호 원이 끝점 홀을 덮은 곳 MUX 22·DMUX 15, 검정 선이 검정 홀 열 위를 지나 꽂힌 것인지 지나가는
것인지 안 보이는 곳 9가닥 — 사용자). v2 빌더는 그래서 이렇게 그린다.

- 신호선의 가로 구간은 **반 행**(두 행 사이, `r_y(row) ± row_pitch/2`)으로, 세로 구간은 **홀 열
  사이**(열 x ± 12)나 여백 차선으로 낸다. 끝점에는 반 행에서 반 칸 꺾어 들어간다 — 그러면 선이
  닿은 홀은 전부 꽂는 홀이다(R12). LED 로 건너는 선도 가운데 레일 홀 위를 같은 행으로 지나지
  않는다 — GND 레일에 꽂은 것으로 읽힌다.
- 번호 원은 `marker_at` 을 안 주면 엔진이 가리는 것 없는 자리(가로 구간 먼저, 긴 구간 가운데부터)를
  찾는다(`_auto_marker`). 이 자리는 **그려졌든 안 그려졌든** 앞 번호들의 자리(`_marker_slots`)를
  피하므로, 선 순서가 같으면 완성본·따라 그리기 층·단계 그림에서 같은 자리다 — 그려진 원만 피하면
  층 그림에서 자리가 달라져 완성본은 통과하는데 층이 R11 로 멈췄다(2026-10-04 검토). 자리를 못 찾으면
  `[WARN] 번호 원 자동 자리 없음` 을 내고 옛 자리에 찍는다 — 그때는 `marker_at` 을 직접 준다.
  직접 줄 때는 꽂힌 홀·다른 번호 원·칩 몸통·남의 배선을 피한다(R11).
  뒤에 그리는 선이 앞 선의 번호 원 아래로 지나가도 R11 이다 — 경로를 고를 때 이미 찍힌 원을 피한다.
  엔진 고정 부품(LED 사슬·전원선·입력 점퍼)은 `marker_near` 로 기본 자리를 주고, 그 자리가 R11 에 걸릴
  때만 가까운 빈 자리로 비킨다(`_settle_marker`) — 빌더가 준 `marker_at` 은 그대로 찍는다. `route_plan`
  은 원을 선을 깔 때 고르니 뒤 선의 끝점을 모른다 — 다 깐 superset 판에서 R11 에 걸리는 경로 원만 다시
  고른다(`_resettle_markers`). 걷기 번호 원도 v2 는 꽂힌 홀을 피한다(2026-10-05 배치 탐색에서 손 배치보다
  짧은 후보가 전부 이 셋으로 떨어졌다).
- 양 끝이 칩의 같은 쪽인 선은 칩 몸통을 건너지 않는다(R13). 몸통을 건너는 것은 칩 안 a↔f 이어
  가기와 a쪽 출력 → LED 뿐이다.
- 그렇게 건너는 선도 **칩 이름 글자 위**는 지나지 않는다(R14). 이름은 몸통 가운데(pin 4 행 둘레)에
  세로로 적히므로, 건너는 반 행은 pin 1~3 사이나 pin 5~7 사이(칩 하나에 넷)와 칩 위아래 바깥이다.
  한 칩 안 이어 가기가 셋이면 이 넷을 나눠 써야 해서, 싼 자리부터 고르는 배선기는 막힐 수 있다 —
  엔진 `route_plan` 은 막히면 직전 몇 가닥 중 한 가닥만 다음 후보로 바꿔 다시 깐다.
- **v2 주차의 신호선(`sig`·`mid`)은 손좌표로 찍지 않는다 — 반드시 엔진 `route_plan(build_fixed, chips,
  wires, board=BOARD)` 에 배선표만 주고 `draw_routed` 로 그린다**(2026-10-04 사용자 결정, 본보기
  `tests/fixtures/board_v2_e4/배치.py`). 선이 한 가닥뿐이어도 같다. 입력 점퍼(`_input_jumper`)·전원·레일
  브리지·LED 사슬은 지금처럼 고정 빌더가 그린다. `route_plan` 이 다루지 못하는 끝점(16핀 이상 칩 —
  `_dip_pin_row` 가 14핀만 안다 —, 7-segment 등)이 나오면 그 선만 손으로 찍어 우회하지 말고 `route_plan`
  을 먼저 넓힌다. 비용은 `길이 + 40·꺾임 +
  400·몸통횡단 + λ·밀도` 이고 λ 는 엔진 `DENSITY_WEIGHT`(2026-10-04 스윕으로 0.5 —
  `docs/plans/2026-10-04-v2-배선기-밀도-설계.md`, 다시 재려면 `python -m scripts.lab.route_sweep`)다.
  밀도는 1칸보다 가깝게 나란한 두 신호선의 겹친 길이 × (1 − 간격/칸)이다 — 버림 조건이 아니라 비용이라
  `verify()` 는 안 본다. 지표는 `wire_metrics(bb)`. 홀 통과(R12)는 배선기 자체 계산이고, 몸통 횡단(R13)은
  버리지 않고 비용 벌점으로만 피한다. 꺾임점이 남의 선에 닿는 경로도 버린다 — 끝과 끝이 맞닿은 두 선은
  한 가닥으로 읽히는데 R4 는 2px 이하 겹침을 봐준다. 최종 판정은 늘 엔진 `verify()` 다.
- **v2 주차의 칩 행·LED 윗행·브리지 행도 손으로 정하지 않는다 — 배치기가 고른다**(2026-10-05 사용자
  결정, 설계 `docs/plans/2026-10-05-v2-배치기-설계.md`). 주차 `배치.py` 는 `PLACE`(`PlaceCircuit` 목록 —
  칩→슬롯·모델·LED 태그 위→아래·배선표(LED 끝은 태그 `('LED', 'L1')`)·`fixed(bb, stage, superset,
  layout)`·입력 핀)·`SLOTS`·`LAYOUT` 을 두고, 빌더는 행 상수 대신 `LAYOUT` 을 읽는다(경로는
  `place_paths(circuit, LAYOUT)`, 고정물을 그리기 전에 `bb.marker_hints = place_marker_hints(circuit,
  LAYOUT)` — 고정 부품 번호 원이 단계 그림·완성본 어디서나 같은 자리다). 배선표를 쓰거나 바꾸면 `python -m scripts.lab.place_search <배치.py>`
  를 돌려 같은 폴더 `배치탐색.md` 를 만들고, 고른 layout 을 `LAYOUT` 과 netlist `kind: layout` 표에
  옮겨 적는다. 테스트 `PlaceEnforced` 가 지문·layout 을, `PlaceLayoutTable` 이 netlist 표 행과 `LAYOUT` 을 맞댄다.
  - 후보: 칩 사이 빈 행 3~6(`PLACE_GMIN`), 슬롯 순서는 탐색, LED 는 태그 순서 고정. 칩 행 k·k+6,
    LED 윗행+3, 입력 핀 행은 레일 빈 행(LED 윗행+3 은 가운데 레일 사용 행도)을 피한다 — 전원선·GND·입력
    점퍼가 곧다.
  - 순위: 근사 비용 앞 8개씩 3라운드 실측(superset 신호선 총길이·밀도). 기준(탐색 시점 `LAYOUT`)보다
    짧고 밀도가 기준 이하인 것을 전부 단계 사슬 `verify()` 로 그려 보고, 통과한 것 중 최단 길이의
    ×`PLACE_LENGTH_SLACK`(1.02) 안에서 밀도가 가장 낮은 것을 고른다(동률은 꺾임·길이). 통과가 없으면
    다음 라운드, 끝까지 없으면 기준. ε 를 바꾸면 지문이 바뀌어 모든 v2 주차가 다시 돌린다.
  - 실측·verify 는 프로세스 `--jobs` 개(기본 min(8, 코어 수))로 나눠 돈다 — 시험판 3라운드가 약 3분.
    `--jobs 1` 이면 차례대로 돌고 답은 같다.
  - 14핀 칩만(`DIP14`) — 16핀·7-segment 는 배선기부터 넓힌다.

## 5. 물리 실현성 규칙 — verify() 가 집행한다

렌더러는 홀 점유표(`_leads`)와 배선 구간(`_segments`)을 기록하고, `export()`
직전에 `verify()` 가 아래를 본다. 위반이면 파일을 쓰지 않고 `AssertionError`
로 **어느 홀·어느 배선**인지 그대로 낸다.

| | 규칙 | 잡는 결함 |
|---|---|---|
| R1 | 모든 배선 끝점은 실제 홀이다. 전원잭(`_jack_at` — v1 y<240, v2 y<보드 위 테두리)만 예외 | 허공(x=95)에서 출발한 입력선, 레일 빈 행(8·14·20…)에 꽂은 끝점 |
| R2 | 한 홀에는 리드 하나 — 점퍼 끝·LED 다리·저항 다리·칩 핀 전부 | 7행·8행 입력이 같은 레일 홀로 스냅, 브리지 사슬의 가운데 홀, LED 애노드와 배선 끝이 한 홀 |
| R3 | 배선 끝점·부품 다리 위를 다른 배선이 지나가지 않는다 — **같은 넷이라도** | 복합 회로 a7·a19 갈래 밑동(굵은 입력선 아래 깔림), Z 선의 a19 관통, AND·OR 의 c12 T 접속, 중앙 GND 레일 홀에 착지한 접지선 위를 지나는 pin 14 전원선 |

| R5 | 넷이 말이 된다 — ⓐ 같은 스트립 안에서 끝나는 점퍼가 없고 ⓑ +5V 와 GND 가 한 넷이 아니며 ⓒ 아무 데도 안 물린 칩 핀이 없다 (미사용 출력·개방 등록한 미사용 입력·계측 접점·`partial` 은 ⓒ 면제) | 복합 회로 `우 a10 → 우 b10`(같은 스트립이라 무의미, 74HC32 pin 1 이 뜸), 실험02 Rn 의 1kΩ 아랫다리가 pin 5 행에 앉아 +5V 를 GND 로 직결 |

| R7 | 칩 한쪽(핀 행 7 × 그쪽 자유 열 4 = a~d 또는 g~j)에 꽂힌 리드가 `SIDE_LEAD_MAX`(8) 이하다 — 끝점만 세고 칩 핀·지나가는 선은 뺀다. `density_policy = 'legacy'` 는 실험01~03 승인본만 | 실험03 전감산기 74HC86 왼쪽 11리드(게이트 1·2 만 써서 입력·갈래·사슬·LED 급전·GND 가 전부 a~d 열에) |
| R8 | 같은 블록의 서로 다른 두 칩 핀 스트립을 잇는 배선은 양 끝 쪽(a~d / g~j)이 같다. 같은 칩 안·다른 블록 사이·칩 행 밖(LED 사슬·레일·잭) 끝점은 안 본다 — 칩 행 안 a~d/g~j 에 앉은 LED 다리는 그 핀 스트립이라 본다. `density_policy = 'legacy'` 가 함께 끈다 | 2026-09-20 격리 시험판 `좌 a9 → 좌 h19`(74HC86 a쪽 → 74HC04 f쪽), `우 g13 → 우 b21`(74HC08 f쪽 → 74HC32 a쪽) — 게이트를 무조건 1·4 로 나눠 생긴 X자 |
| R9 | 칩은 판형이 허용한 블록에만 둔다(`spec.chip_blocks`) — v2 는 좌 블록만. v1 은 두 블록 다 허용 | v2 에서 칩을 우 블록에 놓은 빌더 |
| R10 | LED 전용 블록(`spec.led_only_blocks`, v2 는 우)으로 건너는 선은 **칩 핀 스트립 → LED 사슬 신호 스트립**뿐이고, 건너는 선끼리 위아래 순서가 LED 순서와 같다. 레일↔레일 전원 브리지는 가운데 레일이 어느 블록도 아니라 안 본다. 핀 방향표가 없어 '출력' 인지는 안 본다 — LED 에 무엇이 물렸는지는 R5·netlist 대조가 본다. v1 은 안 돈다 | 칩 사이 중계를 우 블록으로 돌린 선, 건너는 선끼리 X자 |
| R11 | 번호 원이 꽂힌 홀(끝점·부품 다리)·다른 번호 원·칩 몸통을 가리지 않고, 원 아래를 지나는 배선이 **많아야 하나**다(원은 제 선 위에 앉는다 — 누구 선인지는 안 가린다. 손으로 준 `marker_at` 이 남의 선 한 가닥 위에 앉으면 못 잡는다). `spec.readability`(v2)만 돈다 | 2026-10-03 실험04 v2 시험판 — 엔진 기본 자리(첫 구간 가운데)가 반 행 토막 위라 원이 끝점 홀을 덮었다(MUX 22·DMUX 15곳), 칩 몸통 위 원이 핀 번호를 가렸다 |
| R12 | 신호선(`sig`·`mid`)은 끝점 말고 홀 위를 지나지 않는다 — 단자대 홀도 레일 홀도. 전원·GND·브리지·잭 선과 입력 점퍼는 안 본다. `spec.readability`(v2)만 | 같은 시험판 — 검정 선이 검정 홀 열 위를 지나 꽂힌 것인지 지나가는 것인지 안 보였다(9가닥), LED 로 곧게 건너는 선이 가운데 GND 레일 홀 위를 지났다(v2 본보기 `board_v2`) |
| R13 | 양 끝이 칩 기둥의 같은 쪽인 신호선은 그 칩 몸통 상자에 들어가지 않는다(가로로 건너기도, e·f 사이 골을 세로로 타기도). 칩 안 a↔f 이어 가기·a쪽 출력 → LED 는 한 번 건너야 하므로 안 본다. `spec.readability`(v2)만 | 같은 시험판 — f쪽끼리 잇는 E' 선이 차선이 차서 칩 둘을 가로질러 돌아갔다. 2026-10-04 검토 — 골을 세로로 타는 선은 옛 판정(가로 건너기만)과 R12(골에 홀이 없다)를 다 빠져나갔다 |
| R14 | 어떤 배선도(전원선 포함) 칩 이름 글자 상자(`chip_label_boxes` — 세로로 돌린 이름 글자 + 여백 2px. 글꼴 픽셀이라 도장에 드는 `chips` 와 따로 둔다)를 지나지 않는다. R13 이 허용한 칩 안 a↔f 이어 가기·a쪽 출력 → LED 도 이름 위아래 반 행으로 건넌다. `spec.readability`(v2)만 | 2026-10-04 실험04 v2 시험판 검토 — R1~R13 을 다 통과한 MUX·DMUX 에서 칩 안 이어 가기 7가닥이 이름 한복판을 건너 `7⁴HC20`·`7⁴HC 1 1` 처럼 읽혔다 |

R11~R14 는 기하(R1~R4·R6~R10)·넷(R5)·레일 연결성 **뒤에** 보고 `따라 그릴 수 없다:` 로 멈춘다 —
꽂을 수 없거나 회로가 틀린 그림의 읽기는 따질 필요가 없다. v1 승인본(실험01~04)은 소급하지 않는다.

> 왜 이 검사가 없었나 (2026-09-07). `verify()` docstring 은 "끝점이 홀 위에
> 있는지 검사한다"고 했지만 구현은 주소 문자열에 `'레일'` 이 든 끝점의 빈
> 행만 봤다. `addr()` 이 x<149 에 `'보드밖(입력)'` 이라는 이름까지 붙여 줘서
> 순서표에 기능처럼 찍혔다. 규칙(이 문서)도 검사도 막지 않았고, 따라 그리던
> 사람이 잡았다. 그래서 규칙을 문서에 더 쓰는 대신 검사에 넣었다 —
> 문서를 읽어선 안 나온다.

**넷은 홀이 아니라 스트립이다.** R1~R4 는 전부 기하다 — 홀 점유표(`_leads`)만
보면 같은 스트립의 다른 홀에 꽂은 두 점퍼가 남남으로 보인다. `nets()` 가
단자대 한 행의 `a~e`·`f~j` 와 레일 열 하나를 각각 한 스트립으로 묶고 배선으로
union 한다. 입력 점퍼의 레일 쪽 끝만 **가상 입력 노드**로 바꿔 센다 — 지금
GND 에 꽂혀 있어도 1 을 줄 때 옮길 자리라, 레일로 세면 입력 A·B·C 가 GND 와
한 넷이 되어 "pin 1 이 A 에 물렸는가" 를 물을 수 없다.

**덜 그린 그림은 `bb.partial = True`.** 누적 단계 그림(복합 1·2단계)은 뜬 핀이
정상이다. 이 플래그는 R5ⓒ 만 끈다 — 같은 스트립 점퍼도 전원 단락도 덜
그렸다고 봐줄 것이 아니다.

> 왜 R5 가 없었나 (2026-09-09). 2026-09-08 에 R3 를 통과시키려고 복합 회로의
> A 갈래를 여백으로 옮겼는데, 그 재배치가 `우 a10` 으로 오던 공급을 끊었다.
> 검사는 오히려 **통과**로 바뀌었다. 기하 검사를 조일수록 배선을 옮길 일이
> 늘고, 옮길 때마다 넷이 끊길 수 있다 — 기하만으로는 그물이 되지 않는다.

> 왜 R6 가 없었나 (2026-09-10). 같은 일이 형태를 바꿔 반복됐다. AND·OR 의
> 중간단 갈래는 2026-09-07 에 "점퍼에서 갈라져 나오는 것을 보이려고" `c12`
> 에서 출발했다. 다음 날 R2 가 그 홀 충돌을 잡자 시작 홀을 `d12` 로 옮겼고
> — **이때 `c12` 에서 출발할 이유는 사라졌지만 경로 모양은 남았다** — R3 가
> 그 가로 구간을 잡자 다시 `c12` 로 맞바꿨다. 두 번 다 원인은 가로 구간
> 자체였는데 두 번 다 시작 홀만 한 칸씩 옮겼다. **검사를 통과시키려는 최소
> 패치는 증상을 건드리고 원인을 남긴다.** 홀을 옮기기 전에 그 구간이 필요한
> 것인지부터 묻는다. 그리고 남은 주석은 제약("왜 `c` 이고 `d` 가 아닌가")만
> 적고 목적("왜 가로 구간이 있나")을 안 적어, 다음 사람이 잔재를 기능으로
> 읽게 만들었다 — **빌더 주석에는 제약이 아니라 목적을 적는다.**

> 왜 R7 이 없었나 (2026-09-18). R1~R6 은 전부 "이 그림대로 꽂을 수 **있는가**" 였다.
> 실험03 그림은 꽂을 수 있었고 검사도 통과했다 — 그런데 실험실에서 74HC86 왼쪽
> 7행 × 4열 안에 11가닥을 꽂자 손가락이 안 들어가고 어느 홀에 꽂혔는지 눈으로 못
> 셌다. 꽂을 수 있음과 꽂기 쉬움은 다르고, 뒤의 것은 홀 하나가 아니라 **한 구역의
> 리드 수**로만 잡힌다. 네 칩 모두 게이트 1·2 만 쓴 것이 원인이라 게이트 배정(§4a)이
> 해법이고 R7 은 그 배정이 지켜졌는지를 재는 자다.

> 왜 R8 이 없었나 (2026-09-20). R7 을 넣고 실험03 을 게이트 1·4 로 다시 짠 격리 시험판은
> R1~R7 을 전부 통과했다 — 그런데 위 칩 a쪽에서 아래 칩 f쪽으로 대각선처럼 건너는 배선이
> 셋 생겼다. 같은 열에 앉은 두 칩이면 같은 쪽 게이트를 고르면 그만인데, "쿼드 둘 = 1·4"
> 라는 규칙이 방향을 안 보고 나누라고만 했다. R7 은 한쪽 리드 **수**만 세니 이것을 못 본다.
> 규칙을 "필요한 칩만, 신호가 오는 쪽으로" 로 고치고, 결과는 R8 이 잰다.

**빈 홀 고르기.** 레일 끝점은 `snap_rail_row()` 가 아니라 `free_rail_row(row,
*xs)` 로 고른다 — 홀이 있고 **비어 있는** 가장 가까운 행이다. 헬퍼 전부
(`connect_power`, `connect_unused_inputs`, `bridge_rails`, `led_chain`,
`connect_jacks`, `_input_jumper`)가 이것을 쓰므로 **레일 끝점**의 충돌은
저절로 피한다. 먼저 그린 배선이 **지나간** 레일 홀(`_passed`)도 찬 것으로
보므로, pin 14 전원선이 지나는 중앙 GND 홀에 접지선이 착지하지 않는다. 단자대(a~j) 충돌은 `verify()` 가 잡아 주되 피하는 것은 빌더
몫이다 — 같은 스트립의 옆 홀로 옮긴다.

**LED 사슬은 세 열.** `led_chain(x, top_row)` 의 `x` 는 신호가 **도착하는**
열이다. LED 는 옆 열, 저항은 그 다음 열 (오른쪽에 두 열이 없으면 왼쪽으로).
저항 아래 GND 점퍼는 저항 행에서 레일에 가장 가까운 빈 홀에서 나간다 — 다른
다리 위를 넘지 않는 자리다. 같은 행 a~e 는 한 노드라 어느 홀이든 이어지지만
한 홀에 다리 하나다. 전원선도 칩 핀 홀(e·f)이 아니라 옆 홀(d·g)에서 출발한다.

**경고 모드.** `bb.overlap_policy = 'warn'` 은 R4 만 경고로 낮춘다. 지금은
아무 빌더도 안 쓴다 — 복합 회로(`build_e1_comb*`)가 포개짐 2건 때문에 유일하게
썼는데 2026-09-08 에 초록 Z 선을 11행으로 옮겨 0 이 됐다. 새 빌더는 엄격
모드로 시작하고, 경고 모드가 필요하면 그 이유를 빌더 주석에 적는다.
`tests/test_breadboard_physical.py` 가 모든 빌더가 엄격 모드인지 본다.

**밑동 허용은 면허가 아니다.** R4 가 같은 색 30px 이하를 봐주는 것은 같은
스트립 옆 홀에 꽂은 두 번째 점퍼가 첫 점퍼 위를 되짚어 나가는 밑동을 잡지
않으려는 것이다. 그런데 그 밑동은 굵은 입력선 아래 깔려 **얇은 선이 굵은 선
중간(홀 아닌 여백)에서 솟는 그림**이 된다 — 2026-09-08 복합 회로 a7·a19 지적.
갈래는 옆 홀에서 **세로로** 뺀다 — 입력 점퍼가 b열에 끝나면(실험01 netlist 자리표가 `b7`·`b19`
로 고정한다) c열처럼 위가 빈 옆 홀에서 올린다. 실험01 복합회로의 A 갈래 `c7→a13` 이 실물이다.
`_input_jumper(..., col='a')` 로 a열에서 멈추고 b열에서 갈래를 올리는 방식은 netlist 가 입력
홀을 고정하지 않은 주차에만 쓸 수 있다.

**안 보는 것.** 대각선 구간의 포개짐은 안 본다 — `_overlaps()` 는 축
방향(가로·세로) 구간만 비교한다. R3 는 대각선도 본다.

> R3 는 2026-09-08 까지 "같은 넷의 T 접속과 구분이 안 되니 넷 추적 뒤에" 로
> 미뤄져 있었다. 그날 지적된 a7·a19 밑동은 **같은 넷**이었고 그래서 더
> 헷갈렸다 — 점퍼는 이어 붙일 수 없으니 T 접속은 애초에 없다. 넷 무관으로
> 넣었다.

## 6. 새 회로 빌더를 쓸 때 (다음 주차용)

주차마다 `보고서/실험NN/결선도/배치.py` 에 `build_eN_*` 를 손으로 쓰고(§4a 「주차 빌더를
쓸 때」), `render_breadboard.py --experiment N` 으로 뽑는다. 스킬 폴더의 엔진은 고치지 않는다 —
고쳐야 한다면 도구 변경이라 따로 커밋하고, 지난 주차 PNG 가 코드와 같은지(도장 테스트)를 본다.
도장은 그리는 방식(색·범례·배치)을 담지 않는다 — 엔진의 그리는 방식만 바꿨다면 도장은
그대로이니 전 주차를 `--experiment N` 으로 다시 뽑는다.
**옛 함수(`draw_wire`, `draw_badge`)가 그대로 살아 있고 더 짧기 때문에, 아무 생각 없이 쓰면
옛 방식으로 돌아간다.** 그래서 아래를 `tests/test_breadboard_readability.py` 가 센다 — 엔진과
주차 `배치.py` 를 전부 읽는다.

새 주차 결선을 쓸 때 손댈 곳 — ① `보고서/실험NN/결선도/배치.py` ②
`render_breadboard.py --experiment N` 으로 뽑기 ③ `scripts/lab/hand_compare.py` 의
`CIRCUITS` 에 회로 ID 추가 ④ `tests/test_breadboard_nets.py` 의 빌더 수 단언(`len(builders)`)
⑤ §3 「주차별 결선」 목록.

새 빌더에 `bb.density_policy = 'legacy'` 를 쓰지 않는다 — `tests/test_breadboard_physical.py` 가
실험 4 이상은 strict 인지 본다. R7 에 걸리면 게이트를 나눈다(§4a), 정책을 끄지 않는다.

| 하고 싶은 것 | 쓸 함수 | 쓰면 안 되는 것 |
|---|---|---|
| 배선 한 가닥 | `step_wire()` | `draw_wire()` — 번호도 순서표도 안 남고, R1·R2·R3·R4·R5 검사도 통째로 빠진다(`_leads`·`_segments` 를 채우지 않는다) |
| 배선 여러 가닥을 표에 한 줄로 | `step_note(marker_at=...)` | — |
| 보드 위 신호 이름(입력·출력) | `bb.signal_tag()` — `_input_jumper()`·`draw_led()` 가 이미 부른다 | `draw_badge()` 직접 호출 |
| f~j 쪽(핀 8~13) 게이트의 입력 | `_input_jumper(bb, c, row, name, target, side='f')` — 그쪽 GND 레일 → i 열 | 좌 바깥 레일에서 끌어와 칩 위를 넘기는 것 — 가닥이 길고 R3·R4 에 걸린다 |
| 보드 밖 꽂을 자리 꼬리표 | `_tag()` | `draw_badge()` 직접 호출 |
| 규칙·주의·이유 | `note()` (보드 밖 범례) | 보드 위 라벨 박스 |
| LED + 330Ω + GND 한 벌 | `led_chain()` | — |
| 프로브·함수발생기·DMM | `instrument()` / `instrument_note()`. 교안 회로도가 그 접점에 이름(`VIN`·`CH1`)을 붙였으면 `name=` 으로 넘겨 보드 안 배지를 찍는다 | `step_wire()` — 배선이 아니다 |
| 미사용 입력 접지·풀업 | `connect_unused_inputs(rail=...)` | — |
| 미사용 입력 개방(기본) | `mark_unused_inputs()` | `connect_unused_inputs()` — 교안이 지시한 주차만 |
| 전원 | `connect_jacks()` + `bridge_rails()` + `connect_power()` | — |

빌더 첫 줄에 **`bb.enable_steps()`** 를 부른다. 안 부르면 번호도 순서표도 안 나온다.

**레일 브리지를 빼먹지 않는다.** 레일쌍 넷(좌 174/190, 중앙좌 468/484,
중앙우 542/558, 우 836/852)은 서로 **별개 스트립**이다. +5V 를 한 레일에 넣고
칩 14번 핀을 다른 레일에 물리면 **그림은 완벽해 보이는데 전원이 안 간다.**
실제로 실험01 그림 다섯 장이 이 상태로 나갔다 — `verify()` 의 연결성 검사를
넣고서야 잡혔다. 눈으로는 절대 안 잡힌다.
v2 는 좌 바깥 레일과 가운데 레일 두 쌍만 쓴다 — 브리지도 그 사이 두 가닥이다(§2b).

**브리지는 끝점이 있는 레일만 잇는다.** 아무것도 꽂히지 않는 레일 구간을 잇는 브리지는
실험01 교훈 1(필요없는 선)의 브리지판이다 — 손으로 따라 그릴 가닥만 늘린다. 2026-09-12 격리
재생성이 잰 것: 승인본 실험01 은 좌 GND↔중앙GND(29행)·우 중앙GND↔우GND(33행) 브리지에
끝점이 하나도 없고, 이 문서만 읽은 재생성은 쓰는 레일만 이어 같은 넷을 냈다. `verify()` 는
여분 브리지를 안 잡는다(R1~R6 위반이 아니다) — 빌더에서 그 레일에 끝점이 있는지 먼저 본다.

## 7. 손스케치 활용 가이드 (학생용)
1. 생성된 고해상도 PNG를 필기 앱(GoodNotes, Notability, Samsung Notes 등)에 삽입합니다.
2. 이미지 불투명도를 40~50%로 설정한 후 상단 레이어에서 펜으로 점퍼선과 칩을 트레이싱합니다.
3. 보드 위 **신호 이름 배지**(`A`·`B`·`C`, `L1`·`L2`, 계측 지점의 `VIN`·`VOUT`·`CH1`·`CH2` 등)도 같은 자리에 옮겨 적습니다. 보라 화살촉 배지가 입력입니다 — `A▶`·`◀E` 처럼 화살촉 방향까지 옮겨 적으면 입력과 그 선이 뻗는 쪽이 한눈에 보입니다. 조교가 이 표기가 없다고 감점한 적이 있습니다(2026-09 실험01).
4. 체크리스트 완성본 아래 **결선 순서 목록**을 한 줄씩 따라가며 ☐ 를 채웁니다.
5. 우측 상단/하단 여백에 `작성일자 / 학번 / 성명`을 자필로 기재합니다.
