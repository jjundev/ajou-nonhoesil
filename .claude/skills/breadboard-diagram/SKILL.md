# Breadboard Diagram Skill (`breadboard-diagram`)

아주대학교 논리회로실험 표준 브레드보드 템플릿(`Breadboard.jpg`)을 기반으로, 회로 소자(IC), 점퍼선, 저항, LED를 물리적 홀 격자 규격에 맞춰 정밀하게 렌더링하는 스킬입니다.

## 1. 개요 및 목적
- **목적**: 학부 논리회로실험 운영계획서 규정(손스케치 첨부 필수, 미사용 핀 처리 규정, 보호 저항 필수)을 100% 충족하면서, 학생이 태블릿(GoodNotes 등)이나 종이에 따라 그릴 수 있는 오차 없는 정답 결선도 이미지를 제공합니다.
- **주요 기능**:
  1. 표준 브레드보드 템플릿 행/열 좌표 기반 정밀 안착.
  2. 칩별 정확한 DIP-14 핀아웃 매핑 (74HC00, 74HC02, 74HC04, 74HC08, 74HC32 등).
  3. **전기적/안전 규칙 강제**:
     - VCC(14번) -> +5V 적색 레일, GND(7번) -> 0V 청색 레일.
     - **미사용 입력 핀**: 접지하지 않는다 — 2026-09-11 실험01 실측에서 결과에 영향이 없었고 접지선이 순서표의 절반이었다. `mark_unused_inputs()` 로 개방 등록만 한다. 교안이 미사용 핀 처리를 명시한 주차(실험02 p8)만 `connect_unused_inputs()` 로 그린다. **사용하는 게이트의 입력은 반드시 물린다.**
     - **미사용 출력 핀**: 내부 소손(Burn-out) 방지를 위해 **절대 접지 금지, 완전 개방(NC)** 처리.
     - **LED 및 330Ω 보호저항**: 단순 텍스트가 아닌 실제 다리 위치와 저항 색띠(주-주-갈-금)를 갖춘 실물 그래픽 배치.
  4. 브레드보드 물리 규칙 준수 (단자대 세로 절연, 동일 행 5홀 도통).
  5. 활성 행 영역(Active Rows) 자동 줌인 크롭 및 고대비 타이포그래피.

## 2. 브레드보드 물리 좌표계 (`Breadboard.jpg`)

**정본은 `.claude/assets/Breadboard.jpg` 한 장이다.** 아래 좌표는 전부 이 판본
(998x1345)에 맞춰 떠 놓은 것이라, "같은 브레드보드 그림"이면 아무거나 써도
되는 게 아니다. 렌더러는 저장소 루트 기준으로 이 파일을 먼저 찾고, 크기가
998x1345 가 아니면 그리기 전에 멈춘다.

> **2026-2 배포본으로 갈아끼우지 마라.** `강의노트/공지사항/Breadboard.pdf`
> 는 같은 도면이고 세로 좌표까지 일치하지만(보드 상하단 y=242·1317)
> **가로가 중앙 기준 약 5% 넓다.** 중앙 레일은 0~2px 차이인데 좌우 끝 레일이
> 최대 19px 밀린다 — 홀 간격이 17px 이니 한 열을 넘는다. 갈아끼우면 결선이
> 옆 홀에 그려지는데, 그림 자체는 멀쩡해 보여서 눈으로는 안 잡힌다. 배포본을
> 쓰려면 아래 좌표를 전부 다시 떠야 한다.
>
> `from_the_past/정리/강의노트/Breadboard.jpg` 는 정본과 바이트가 같은 과거
> 학기 사본이다. 최후 대체물로만 남아 있고, 본문·보고서에서는 인용하지 않는다.

**아래 값은 템플릿을 직접 측정한 것이다 (2026-09-07).** 그 전에는 눈대중
값(`r_y = 243 + (r-1)*17.15`, 좌측 GND 레일 x=163)을 썼는데, 그림은 그럴듯한데
**배선 끝점이 홀 안에 들어가지 않았다** — 1행이 29px, 우측 f~j 열이 한 칸
(16.5px) 통째로 어긋나 있었다. 홀을 세어가며 손으로 따라 그리라고 만든
그림에서 이건 치명적이다. 크기 검사(`TEMPLATE_SIZE`)는 판본 교체만 잡지
좌표 자체의 회귀는 못 잡으므로, `BreadboardRenderer.verify()` 가 내보내기
직전에 **그림대로 꽂을 수 있는지**를 좌표로 확인한다 (§5).

- 캔버스 원본 크기: 998 x 1345 px
- **행**: 63행. `y = 272.0 + (r-1) * 16.345` (1행 y=272, 63행 y=1285)
- **열**:
  - 좌측 블록: GND 레일 174 · VCC 레일 190 · a~e `[239, 256, 272, 288, 305]`
    · 중앙 홈 305~354 (IC 안착) · f~j `[354, 370, 386, 403, 419]`
  - 좌측 중앙 레일: GND 468 · VCC 484
  - 우측 중앙 레일: GND 542 · VCC 558
  - 우측 블록: a~e `[607, 623, 640, 656, 672]` · 중앙 홈 672~721
    · f~j `[721, 738, 754, 770, 786]` · GND 레일 836 · VCC 레일 852
- **전원 잭**: 빨강 x=439 · 노랑 603 · 회색 766, 원 아래끝 y≈160

> **레일에는 홀이 없는 행이 있다.** 5홀씩 묶여 있어서 1·2·63행과 6행 주기의

> 있다. `free_rail_row()` 가 레일 착지 행을 가까운 **빈** 실제 홀로 옮긴다.

> **좌우 블록은 전원 레일이 뒤집혀 있다.** 좌측 보드는 pin 1~7 쪽(a~e)이 바깥
> 왼쪽 레일에, pin 8~14 쪽(f~j)이 중앙 레일에 붙는다. 우측 보드는 반대다.
> `connect_power()` 와 `nearest_gnd_rail()` 이 블록별로 갈라 준다.

## 3. CLI 사용법
```bash
python3 .claude/skills/breadboard-diagram/scripts/render_breadboard.py \
    --circuit <circuit_id> \
    --output <output_path> \
    [--template <template_path>]
```

### 지원 회로 ID (`--circuit`):
- **실험 1 (기본 게이트 및 조합논리)** — 슬롯 고정 배치 (S1 좌 7행 · S2 좌 18행 · S3 우 10행):
  - `e1_and`: 실험 1-1 3입력 AND (74HC08). 첫 보드 — 완성본 겸 절차 그림
  - `e1_or`: 실험 1-2 3입력 OR (74HC32) 완성본 · `e1_or_s1`: C1 에서 칩만 갈아끼우는 전환 그림
  - `e1_nand`: 실험 2-1 3입력 NAND 완성본 · `e1_nand_s1`(앞단 AND 검사) · `e1_nand_s2`(뒷단 NAND, 완성)
  - `e1_nor`: 실험 2-2 3입력 NOR 완성본 · `e1_nor_s1` · `e1_nor_s2`
  - `e1_comb`: 실험 3 복합 논리회로 완성본 · `e1_comb_s1`(인버터, Z = A') · `e1_comb_s2`(AND 추가) · `e1_comb_s3`(OR 추가, 완성)
  - `e1_all`: 절차 9장 + 완성본 4장 = 13장 일괄. 절차 그림은 앞 보드를 기준선으로 회색을 넣고, 완성본은 기준선 없이 전부 색이다

  **완성본과 단계 그림을 섞지 않는다.** 예비보고서·손그림 원도는 완성본(`E1_FINALS`)이고, 체크리스트의 단계 블록은 절차 그림(`E1_BOARDS`)이다. netlist 의 `diagram` 은 완성본을, `## 단계` 표는 절차 그림을 가리킨다.

**OR·NOR 은 2026-09-06 에 되살렸다.** 그 전에는 `e1_or`·`e1_nor` 가 각각
AND·NAND 빌더를 가리키는 별칭이라 **틀린 그림을 OR·NOR 이름으로 냈다.**
별칭을 지웠다가, `74HC32` 전용 빌더(`build_e1_or`)와 `74HC02` 빌더
(`build_e1_nor`, 출력이 1번 핀)를 실제로 작성해 복원했다. 두 회로가 한 빌더를
공유하지 않는지는 `tests/test_breadboard_diagram_cli.py` 가 검사한다.
- **실험 2 (CMOS 회로의 전기적 특성)** — 2026-09-13 에 2026-2 배포본(12쪽) 기준으로
  슬롯·기준선·단계 규약에 맞춰 다시 썼다. 슬롯은 S1 좌 7행 · S2 좌 18행 (`E2_SLOTS`,
  netlist `kind: layout` 과 테스트가 맞댄다). 옛 판의 Rn·Rp(DC 특성) 회로는 배포본
  교안에 없어 지웠다:
  - `e2_inv`: 실험 1-1 Inverter 입출력 특성 (74HC04 게이트 1, X-Y 모드). 첫 보드 — 완성본 겸 절차 그림
  - `e2_schmitt`: 실험 1-2 Schmitt-trigger 입출력 특성 (74HC14) 완성본 · `e2_schmitt_s1`: C1 에서 칩만 갈아끼우는 전환 그림
  - `e2_tpd`: 실험 2 CMOS AC 특성 t_pd (74HC04 두 패키지, U1 6단 체인 + U2 부하) 완성본 · `e2_tpd_s1`(U1 체인만, C2 의 pull 선을 걷는다) · `e2_tpd_s2`(U2 부하 추가, 완성)
  - `e2_all`: 절차 4장 + 완성본 2장 = 6장 일괄 (`E2_BOARDS` · `E2_FINALS`)

  미사용 입력은 이 주차만 `connect_unused_inputs()` 로 그린다 — 교안 p9 가 명시하고
  그림이 pin 3·5 → GND, pin 9·11·13 → VCC 다. GND 브리지는 그리지 않는다 — 접지
  끝점이 전부 좌 바깥 레일 하나에 앉아 끝점 없는 레일을 이을 이유가 없다.
- **실험 3 (가산기 & 감산기)** — 2026-09-14 에 2026-2 배포본(9쪽) 기준으로 저작. 슬롯은
  S1 좌 7행 74HC86 · S2 좌 18행 74HC04 · S3 우 10행 74HC08 · S4 우 21행 74HC32 (`E3_SLOTS`,
  netlist `kind: layout` 과 테스트가 맞댄다). 칩 종류는 회로가 바뀌어도 자리에서 바뀌지 않고
  **급전선만** 옮긴다 — LED 가 두 개뿐이라(교안 p8) LED1(S·D) 은 좌 a25, LED2(C·Co·B·Bo) 는
  우 c29 사슬에 고정이다. AND 를 우측에 둔 이유는 좌우를 건너는 선이 입력 갈래와 인버터
  출력 둘뿐이 되기 때문이다(netlist M4):
  - `e3_ha`: 실험 1-1 반가산기 완성본 · `e3_ha_s1`(XOR + LED1, S = A⊕B) · `e3_ha_s2`(AND 추가, 완성)
  - `e3_fa`: 실험 1-2 전가산기 완성본 · `e3_fa_s1`(Ci·XOR2, LED1 을 pin 6 으로) · `e3_fa_s2`(74HC32 + AND2, 완성)
  - `e3_hs`: 실험 2-1 반감산기 완성본 · `e3_hs_s1`(전가산기 확장 여덟 가닥을 걷고 XOR 로 되돌림 — 74HC32 는 전원만 둔 채 쉰다) · `e3_hs_s2`(74HC04 추가, 완성)
  - `e3_fs`: 실험 2-2 전감산기 완성본 · `e3_fs_s1`(Bi·XOR2) · `e3_fs_s2`(NOT2 + AND2 + OR, 완성). 새로 꽂는 칩이 없다
  - `e3_all`: 절차 8장 + 완성본 4장 = 12장 일괄 (`E3_BOARDS` · `E3_FINALS`)

  전감산기 1단계는 반감산기 완성 상태를 **뜯지 않는다** — 처음 저작에서 `_e3_draw` 의 인버터
  블록이 `done` 에만 걸려 74HC04·74HC32 가 "뽑는다" 로 나왔다. `tests/test_breadboard_wiring.py`
  의 `WiringE3` 가 그 회귀를 잡는다.

## 4. 그림을 두 층으로 나눈다

운영계획서 3.2 6) 은 **"직접 손으로 작성한 회로 결선도 첨부"** 를 요구한다.
그러니 이 PNG 는 제출물이 아니라 **따라 그릴 원도**다. 원도에 들어갈 것과
들어가면 안 될 것이 갈린다.

**보드 위 (손으로 옮겨 그릴 것)** — 배선, 칩과 핀 번호, LED·저항, 그리고
**신호 이름**. 입력 `A`·`B`·`C` 는 점퍼의 레일 쪽 끝 옆(보드 좌 테두리와 GND
레일 사이 여백)에, 출력 `L1`·`L2`·`X`·`Y`·`Z` 는 LED 옆에 `signal_tag()` 가
찍는다. 2026-09 실험01 예보가 "결선도에 입력 A·B·C 위치 표기가 없다" 로
감점됐다(-1) — 그때 입력 이름은 보드 밖 꼬리표(`입력 A → b7`)에만 있었고,
학생은 보드 판형 위만 따라 그려 그 글자가 옮겨지지 않았다. 신호 이름은 규칙
문구가 아니라 그림의 일부다. 입력 점퍼도 LED 도 없는 주차(실험02 X-Y·t_pd)는
**계측 지점**이 신호 이름을 갖는다 — `instrument(..., name='VIN')` 이 교안
회로도의 이름(`VIN`·`VOUT`·`CH1`·`CH2`)을 그 접점과 같은 스트립 끝 여백(칩 왼쪽
스트립이면 레일과 a 열 사이, 오른쪽이면 j 열 바깥)에 찍는다. 보드 밖 계측
꼬리표(`1. 함수발생기 + CH1 (가로축)`)만 두면 실험01 과 같은 이유로 빠진다.

**보드 밖 (옮겨 그릴 수 없는 것)** — 미사용 입력을 접지하지 않는 *이유*(실험01
실측), 미사용 출력을 개방하는 *이유*, 잭 색 주의 같은 규칙 문구. 전부
`note()` 로 넘겨 아래 범례에 모은다. 꽂을 자리 꼬리표(`입력 A → b7`)도 보드
밖에 남는다 — 이름이 아니라 홀 주소를 알려 주는 것이다.

> 이전 판은 이 둘을 섞어 보드 위에 라벨 박스를 30개 넘게 얹었다. 그중 절반은
> 손으로 옮겨 그릴 것이 하나도 없는 문구인데, 하필 **따라 그릴 홀을 덮었다.**
> 같은 내용이 예비보고서 본문 `공통 결선 규칙` 에 이미 문장으로 있다.

**배선 색은 넷뿐이다** — 빨강 +5V, 파랑 0V, 검정 신호, 초록 중간 노드.

**모든 선은 홀에서 홀로 간다.** 입력 A·B·C 도 예외가 아니다 — 2026-09-07 까지는
보드 밖 x=95 허공에서 선을 끌어와 "보드밖(입력)" 이라 적었는데, 따라 그리는
사람은 그 왼쪽 끝을 어디에 꽂아야 하는지 알 수 없었다. 지금은 `_input_jumper()`
가 **좌 GND 레일 홀 → 같은 행 b열** 로 그린다(0 자리). 1 은 레일 쪽 끝만 빨간
레일로 옮겨 꽂는 것이고, 그 문장은 범례에 있다. 오른쪽 블록으로 가는 갈래는
허공 줄기에서 분기하지 않고 **같은 스트립의 다른 홀(a열)에 꽂는 두 번째 점퍼**
로 그린다 — 점퍼는 이어 붙일 수 없다. 꼬리표에는 꽂을 자리(`입력 A → b10`)를
그대로 적는다. 왼쪽 눈금이 10·20·30 뿐이라 이름만 있으면 홀을 세어야 한다.
이전 판은 한 장에 16색을 썼는데 `(0,110,170)` 과 `(0,120,180)` 처럼 눈으로
구분되지 않는 쌍이 여럿이라 색이 정보를 나르지 않으면서 눈만 어지럽혔다.
따라 그리는 사람 손에 있는 펜도 네 자루다.

**결선 순서표.** `step_wire()` 로 그린 배선은 번호가 붙고 그림 아래 표에
`☐ ⑦ 좌 b10 → 좌 GND레일10행 · pin 7 -> GND 레일` 로 쌓인다. 손으로 그리는
사람이 실제로 막히는 지점은 "이 선이 어느 홀에서 어느 홀로 가는지"와 "내가
몇 번째 선까지 그렸는지"다. 표를 위에서 아래로 지워가며 한 줄씩 그리면
30가닥을 동시에 볼 필요가 없다. 주소는 좌표에서 자동으로 뽑는다(`addr()`).

## 4a. 슬롯 · 기준선 · 단계

**슬롯.** 한 실험의 모든 회로가 칩 자리를 공유한다. 정본은 netlist 의 `kind: layout` 표이고
빌더 상수(`E1_SLOTS`)는 사본이다 — `tests/test_breadboard_wiring.py` 가 맞댄다. 실험01 실험실
기록(2026-09-11): 1-1→1-2 는 칩만 갈아끼우면 되는데 그림이 회로마다 달라 전부 걷었다.

**기준선.** `BreadboardRenderer(baseline=앞_보드.snapshot())` 로 그리면 같은 (색, 끝점, 끝점)
의 배선과 같은 네 홀의 LED 사슬은 **회색**이고 번호를 받지 않는다. 기준선에 있었는데 이번에
없는 것은 footer 의 "앞 단계에서 걷는다" 표에 주소로 나온다. 같은 자리에 다른 칩이면 순서표
첫 줄이 "뽑는다/꽂는다" 다. 기준선은 색과 번호만 바꾼다 — 배선 집합은 그대로라 `verify()` 도
그대로 돈다. **회색이 되려면 앞 보드와 같은 순서로 그려야 한다** — `free_rail_row()` 가 점유
순서로 레일 행을 고르므로, 공통 배선(`_e1_frame`·`_e1_front`)은 빌더마다 같은 헬퍼를 같은
순서로 부른다.

**단계.** 칩이 둘 이상인 회로는 **칩 하나를 더할 때마다 단계 하나**다. 단계 끝은 반드시 그
회로의 LED 로 관측된다. 상류가 아직 없으면 임시 점퍼로 대체하고(복합회로 1단계의
`c7→c9` — 입력 홀에서 다음 칩 핀으로 가는 `step_wire()` 다. 레일에서 오는 `_input_jumper()` 가
아니다), 다음 단계 첫 줄에서 걷는다. 여분 LED 를 더하지 않는다 — 교안 부품 수와 손그림
제출본을 지킨다. 전원·브리지는 그 회로가 쓰는 슬롯 전부를 1단계에 미리 꽂는다 — 회로가
바뀌어도 그대로인 선이다. 마지막 단계 전까지는 `bb.partial = True` 다 — 2단계 회로는 1단계만,
3단계 회로는 1·2단계. 마지막 단계는 완성 상태라 뜬 핀이 없어야 한다.

**주차 빌더를 쓸 때:** 빌더 시그니처는 `build_eN_x(output_path, template_path=None,
stage=None, baseline=None)`, 보드 사슬은 `EN_BOARDS = [(파일명, 빌더, stage), …]`,
완성본은 `EN_FINALS`, CLI 래퍼 `build_eN_x_sK` 는 `_eN_board(index, …)` 로 앞 보드를 임시
렌더해 기준선을 만든다. 실험01 의 `_e1_*` 가 실물이다.

**파일명 규칙.** `실험NN_<소단원>_결선도_<회로명>.png` 이 완성본,
`실험NN_<소단원>_결선도_<회로명>_<k>단계_<이름>.png` 이 절차 그림이다.
`<소단원>` 은 명세 항목 ID 의 `P` 뒤 토큰이다 (`E1.P1-1` → `1-1`, `E1.P3` → `3`).
`export-hand-diagram` 의 손그림 이름 `실험NN_<소단원>_손그림_<회로명>.png` 과 같은 틀이라,
폴더 밖(노션·예비보고서 참조)에서도 파일명만으로 주차와 소단원이 읽히고 폴더 안에서는
소단원 순으로 정렬된다. `실험NN` 을 빼지 않는다 — 소단원 번호는 주차마다 1부터 다시
시작해 한 학기 안에서 유일하지 않다. 실물: `실험01_1-2_결선도_3입력_OR_1단계_칩교체.png`,
`실험01_3_결선도_복합논리회로.png`.

## 5. 물리 실현성 규칙 — verify() 가 집행한다

렌더러는 홀 점유표(`_leads`)와 배선 구간(`_segments`)을 기록하고, `export()`
직전에 `verify()` 가 아래를 본다. 위반이면 파일을 쓰지 않고 `AssertionError`
로 **어느 홀·어느 배선**인지 그대로 낸다.

| | 규칙 | 잡는 결함 |
|---|---|---|
| R1 | 모든 배선 끝점은 실제 홀이다. 전원잭(y<240)만 예외 | 허공(x=95)에서 출발한 입력선, 레일 빈 행(8·14·20…)에 꽂은 끝점 |
| R2 | 한 홀에는 리드 하나 — 점퍼 끝·LED 다리·저항 다리·칩 핀 전부 | 7행·8행 입력이 같은 레일 홀로 스냅, 브리지 사슬의 가운데 홀, LED 애노드와 배선 끝이 한 홀 |
| R3 | 배선 끝점·부품 다리 위를 다른 배선이 지나가지 않는다 — **같은 넷이라도** | 복합 회로 a7·a19 갈래 밑동(굵은 입력선 아래 깔림), Z 선의 a19 관통, AND·OR 의 c12 T 접속, 중앙 GND 레일 홀에 착지한 접지선 위를 지나는 pin 14 전원선 |
| R4 | 서로 다른 배선이 같은 축 위에 포개지지 않는다 (다른 색 8px, 같은 색 30px 초과 — 같은 스트립에 꽂은 두 번째 점퍼의 밑동은 봐주지만 그 밑동의 끝점은 R3 가 잡는다) | 입력 C 세로 구간이 초록 중간단 선에 삼켜진 것 |
| R5 | 넷이 말이 된다 — ⓐ 같은 스트립 안에서 끝나는 점퍼가 없고 ⓑ +5V 와 GND 가 한 넷이 아니며 ⓒ 아무 데도 안 물린 칩 핀이 없다 (미사용 출력·개방 등록한 미사용 입력·계측 접점·`partial` 은 ⓒ 면제) | 복합 회로 `우 a10 → 우 b10`(같은 스트립이라 무의미, 74HC32 pin 1 이 뜸), 실험02 Rn 의 1kΩ 아랫다리가 pin 5 행에 앉아 +5V 를 GND 로 직결 |
| R6 | 배선이 **자기 스트립 안을 달리는 구간**이 없다 — 이웃한 꺾임점 둘이 같은 스트립이면 그 구간은 전기적으로 없는 것과 같다. 뒤쪽 홀에서 출발하면 그만이다 (양 끝이 다 실제 홀일 때만 본다 — 전원잭처럼 보드 밖에서 오는 구간은 뺀다) | AND·OR 중간단 갈래의 `좌 c12 → 좌 a12` 가로 구간 |

> 왜 이 검사가 없었나 (2026-09-07). `verify()` docstring 은 "끝점이 홀 위에
> 있는지 검사한다"고 했지만 구현은 주소 문자열에 `'레일'` 이 든 끝점의 빈
> 행만 봤다. `addr()` 이 x<149 에 `'보드밖(입력)'` 이라는 이름까지 붙여 줘서
> 순서표에 기능처럼 찍혔다. 규칙(이 문서)도 검사도 막지 않았고, 따라 그리던
> 사람이 잡았다. 그래서 규칙을 문서에 더 쓰는 대신 검사에 넣었다 —
> 문서를 읽어선 안 나온다.

**넷은 홀이 아니라 스트립이다.** R1~R4 는 전부 기하다 — 홀 점유표(`_leads`)만
보면 같은 스트립의 다른 홀에 꽂은 두 점퍼가 남남으로 보인다. `nets()` 가
단자대 한 행의 `a~e`·`f~j` 와 레일 열 하나를 각각 한 스트립으로 묶고 배선으로
union 한다. 입력 점퍼의 레일 쪽 끝만 **가상 입력 노드**로 바꿔 센다 — 지금
GND 에 꽂혀 있어도 1 을 줄 때 옮길 자리라, 레일로 세면 입력 A·B·C 가 GND 와
한 넷이 되어 "pin 1 이 A 에 물렸는가" 를 물을 수 없다.

**덜 그린 그림은 `bb.partial = True`.** 누적 단계 그림(복합 1·2단계)은 뜬 핀이
정상이다. 이 플래그는 R5ⓒ 만 끈다 — 같은 스트립 점퍼도 전원 단락도 덜
그렸다고 봐줄 것이 아니다.

> 왜 R5 가 없었나 (2026-09-09). 2026-09-08 에 R3 를 통과시키려고 복합 회로의
> A 갈래를 여백으로 옮겼는데, 그 재배치가 `우 a10` 으로 오던 공급을 끊었다.
> 검사는 오히려 **통과**로 바뀌었다. 기하 검사를 조일수록 배선을 옮길 일이
> 늘고, 옮길 때마다 넷이 끊길 수 있다 — 기하만으로는 그물이 되지 않는다.

> 왜 R6 가 없었나 (2026-09-10). 같은 일이 형태를 바꿔 반복됐다. AND·OR 의
> 중간단 갈래는 2026-09-07 에 "점퍼에서 갈라져 나오는 것을 보이려고" `c12`
> 에서 출발했다. 다음 날 R2 가 그 홀 충돌을 잡자 시작 홀을 `d12` 로 옮겼고
> — **이때 `c12` 에서 출발할 이유는 사라졌지만 경로 모양은 남았다** — R3 가
> 그 가로 구간을 잡자 다시 `c12` 로 맞바꿨다. 두 번 다 원인은 가로 구간
> 자체였는데 두 번 다 시작 홀만 한 칸씩 옮겼다. **검사를 통과시키려는 최소
> 패치는 증상을 건드리고 원인을 남긴다.** 홀을 옮기기 전에 그 구간이 필요한
> 것인지부터 묻는다. 그리고 남은 주석은 제약("왜 `c` 이고 `d` 가 아닌가")만
> 적고 목적("왜 가로 구간이 있나")을 안 적어, 다음 사람이 잔재를 기능으로
> 읽게 만들었다 — **빌더 주석에는 제약이 아니라 목적을 적는다.**

**빈 홀 고르기.** 레일 끝점은 `snap_rail_row()` 가 아니라 `free_rail_row(row,
*xs)` 로 고른다 — 홀이 있고 **비어 있는** 가장 가까운 행이다. 헬퍼 전부
(`connect_power`, `connect_unused_inputs`, `bridge_rails`, `led_chain`,
`connect_jacks`, `_input_jumper`)가 이것을 쓰므로 **레일 끝점**의 충돌은
저절로 피한다. 먼저 그린 배선이 **지나간** 레일 홀(`_passed`)도 찬 것으로
보므로, pin 14 전원선이 지나는 중앙 GND 홀에 접지선이 착지하지 않는다. 단자대(a~j) 충돌은 `verify()` 가 잡아 주되 피하는 것은 빌더
몫이다 — 같은 스트립의 옆 홀로 옮긴다.

**LED 사슬은 세 열.** `led_chain(x, top_row)` 의 `x` 는 신호가 **도착하는**
열이다. LED 는 옆 열, 저항은 그 다음 열 (오른쪽에 두 열이 없으면 왼쪽으로).
저항 아래 GND 점퍼는 저항 행에서 레일에 가장 가까운 빈 홀에서 나간다 — 다른
다리 위를 넘지 않는 자리다. 같은 행 a~e 는 한 노드라 어느 홀이든 이어지지만
한 홀에 다리 하나다. 전원선도 칩 핀 홀(e·f)이 아니라 옆 홀(d·g)에서 출발한다.

**경고 모드.** `bb.overlap_policy = 'warn'` 은 R4 만 경고로 낮춘다. 지금은
아무 빌더도 안 쓴다 — 복합 회로(`build_e1_comb*`)가 포개짐 2건 때문에 유일하게
썼는데 2026-09-08 에 초록 Z 선을 11행으로 옮겨 0 이 됐다. 새 빌더는 엄격
모드로 시작하고, 경고 모드가 필요하면 그 이유를 빌더 주석에 적는다.
`tests/test_breadboard_physical.py` 가 모든 빌더가 엄격 모드인지 본다.

**밑동 허용은 면허가 아니다.** R4 가 같은 색 30px 이하를 봐주는 것은 같은
스트립 옆 홀에 꽂은 두 번째 점퍼가 첫 점퍼 위를 되짚어 나가는 밑동을 잡지
않으려는 것이다. 그런데 그 밑동은 굵은 입력선 아래 깔려 **얇은 선이 굵은 선
중간(홀 아닌 여백)에서 솟는 그림**이 된다 — 2026-09-08 복합 회로 a7·a19 지적.
갈래는 옆 홀에서 **세로로** 뺀다 — 입력 점퍼가 b열에 끝나면(실험01 netlist 자리표가 `b7`·`b19`
로 고정한다) c열처럼 위가 빈 옆 홀에서 올린다. 실험01 복합회로의 A 갈래 `c7→a13` 이 실물이다.
`_input_jumper(..., col='a')` 로 a열에서 멈추고 b열에서 갈래를 올리는 방식은 netlist 가 입력
홀을 고정하지 않은 주차에만 쓸 수 있다.

**안 보는 것.** 대각선 구간의 포개짐은 안 본다 — `_overlaps()` 는 축
방향(가로·세로) 구간만 비교한다. R3 는 대각선도 본다.

> R3 는 2026-09-08 까지 "같은 넷의 T 접속과 구분이 안 되니 넷 추적 뒤에" 로
> 미뤄져 있었다. 그날 지적된 a7·a19 밑동은 **같은 넷**이었고 그래서 더
> 헷갈렸다 — 점퍼는 이어 붙일 수 없으니 T 접속은 애초에 없다. 넷 무관으로
> 넣었다.

## 6. 새 회로 빌더를 쓸 때 (다음 주차용)

주차마다 `build_eN_*` 를 손으로 쓴다. **옛 함수(`draw_wire`, `draw_badge`)가
그대로 살아 있고 더 짧기 때문에, 아무 생각 없이 쓰면 옛 방식으로 돌아간다.**
그래서 아래를 `tests/test_breadboard_readability.py` 가 센다.

| 하고 싶은 것 | 쓸 함수 | 쓰면 안 되는 것 |
|---|---|---|
| 배선 한 가닥 | `step_wire()` | `draw_wire()` — 번호도 순서표도 안 남고, R1·R2·R3·R4·R5 검사도 통째로 빠진다(`_leads`·`_segments` 를 채우지 않는다) |
| 배선 여러 가닥을 표에 한 줄로 | `step_note(marker_at=...)` | — |
| 보드 위 신호 이름(입력·출력) | `bb.signal_tag()` — `_input_jumper()`·`draw_led()` 가 이미 부른다 | `draw_badge()` 직접 호출 |
| 보드 밖 꽂을 자리 꼬리표 | `_tag()` | `draw_badge()` 직접 호출 |
| 규칙·주의·이유 | `note()` (보드 밖 범례) | 보드 위 라벨 박스 |
| LED + 330Ω + GND 한 벌 | `led_chain()` | — |
| 프로브·함수발생기·DMM | `instrument()` / `instrument_note()`. 교안 회로도가 그 접점에 이름(`VIN`·`CH1`)을 붙였으면 `name=` 으로 넘겨 보드 안 배지를 찍는다 | `step_wire()` — 배선이 아니다 |
| 미사용 입력 접지·풀업 | `connect_unused_inputs(rail=...)` | — |
| 미사용 입력 개방(기본) | `mark_unused_inputs()` | `connect_unused_inputs()` — 교안이 지시한 주차만 |
| 전원 | `connect_jacks()` + `bridge_rails()` + `connect_power()` | — |

빌더 첫 줄에 **`bb.enable_steps()`** 를 부른다. 안 부르면 번호도 순서표도 안 나온다.

**레일 브리지를 빼먹지 않는다.** 레일쌍 넷(좌 174/190, 중앙좌 468/484,
중앙우 542/558, 우 836/852)은 서로 **별개 스트립**이다. +5V 를 한 레일에 넣고
칩 14번 핀을 다른 레일에 물리면 **그림은 완벽해 보이는데 전원이 안 간다.**
실제로 실험01 그림 다섯 장이 이 상태로 나갔다 — `verify()` 의 연결성 검사를
넣고서야 잡혔다. 눈으로는 절대 안 잡힌다.

**브리지는 끝점이 있는 레일만 잇는다.** 아무것도 꽂히지 않는 레일 구간을 잇는 브리지는
실험01 교훈 1(필요없는 선)의 브리지판이다 — 손으로 따라 그릴 가닥만 늘린다. 2026-09-12 격리
재생성이 잰 것: 승인본 실험01 은 좌 GND↔중앙GND(29행)·우 중앙GND↔우GND(33행) 브리지에
끝점이 하나도 없고, 이 문서만 읽은 재생성은 쓰는 레일만 이어 같은 넷을 냈다. `verify()` 는
여분 브리지를 안 잡는다(R1~R6 위반이 아니다) — 빌더에서 그 레일에 끝점이 있는지 먼저 본다.

## 7. 손스케치 활용 가이드 (학생용)
1. 생성된 고해상도 PNG를 필기 앱(GoodNotes, Notability, Samsung Notes 등)에 삽입합니다.
2. 이미지 불투명도를 40~50%로 설정한 후 상단 레이어에서 펜으로 점퍼선과 칩을 트레이싱합니다.
3. 보드 위 **신호 이름 배지**(`A`·`B`·`C`, `L1`·`L2`, 계측 지점의 `VIN`·`VOUT`·`CH1`·`CH2` 등)도 같은 자리에 옮겨 적습니다. 조교가 이 표기가 없다고 감점한 적이 있습니다(2026-09 실험01).
4. 그림 아래 **결선 순서표**를 한 줄씩 따라가며 ☐ 를 채웁니다.
5. 우측 상단/하단 여백에 `작성일자 / 학번 / 성명`을 자필로 기재합니다.
