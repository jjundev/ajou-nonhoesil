# 논리회로실험 인터랙티브 자료

학생이 예측 하나를 세우고, 입력 하나를 바꿔 신호를 확인한 다음, 결과를 설명할 수 있는 짧은 실험을 만든다. 실험 하나에 여러 오프라인 HTML을 등록한다. 실험06에는 [74HC76 플립플롭](lessons/06.json)과 [D 래치](lessons/06/d-latch.json)가 있으며, 각각 해당 복습노트 토픽에서 연다.

## 화면 구성

[공통 화면](assets/lesson.html)과 [스타일](assets/lesson.css)은 전자회로2 `ec2-interactive` v2의 `lab-template.html`(전자회로2 리비전 `4dbc0991`)에서 가져왔다. 상단 바, 테마와 모바일 서랍, 조작·실험·설명의 3단 구성을 재사용한다. 빌드할 때 Pretendard와 회로 SVG를 HTML에 포함한다.

파형과 팝업은 `traces`의 전체 순서로 핀별 색을 배정한다. 선을 켜고 끄거나 단계를 이동해도 같은 핀의 색은 유지된다. 팝업의 왼쪽 테두리와 핀 값 제목은 파형 색을 공유한다. 파형 설명은 팝업 하나에 표시한다. 파형에 마우스를 올리면 설명을 미리 보여주고, 클릭·탭·Enter로 팝업을 고정한다. 고정한 팝업은 닫기 버튼이나 Escape로 닫는다. 오른쪽 패널에는 현재 핀 값과 진리표를 배치한다.

실험06 D 래치는 `prediction_sidebar: true`를 지정한다. 화면 폭이 1024px 이상이고 오른쪽 패널이 열려 있으면 예측 카드를 패널 맨 위에 둔다. 화면이 좁거나 오른쪽 패널을 닫으면 같은 카드를 회로 위로 옮긴다.

왼쪽에서 입력과 단계를 조작한다. 가운데 회로에서 값이 바뀐 입력 핀과 출력 핀을 눌러 파형 표시를 켜고 끈다. 고정 입력은 파형 위에 한 줄로 요약하고, 단계에 미리 지정된 비교용 선은 기본으로 표시한다. 선을 가리키면 해당 핀의 값과 이유를 미리 보여준다. 클릭하거나 탭하면 설명을 고정하고 회로의 핀·LED와 진리표도 같은 시점으로 옮긴다. 키보드에서는 좌우 화살표로 시점, 위아래 화살표로 핀을 고르고 Enter로 설명을 연다. 실험06의 [회로 SVG](assets/74hc76.svg)에는 노치가 보이는 DIP-16과 C3의 +5 V·GND·330 Ω·LED 결선을 넣었다.

[D 래치 회로 SVG](assets/d-latch.svg)는 핀·신호선·LED를 중심으로 구성한다. 74HC04 반전기와 74HC00 점퍼·되먹임의 별도 결선 요약 블록은 생략한다.

## 저작

파형 머리글은 제목·안내, 입력 조작 버튼, 조작 이력 사이에 여백을 두고 좁은 화면에서는 줄바꿈한다. 버튼은 최소 높이 44px를 유지한다. 파형 위 버튼에는 현재 단계에서 실행할 입력 조작만 표시한다. 마지막 조작이 끝나면 버튼이 사라지고 키보드 포커스는 파형으로 이동한다. 다른 단계는 조작 패널의 ‘단계별 살펴보기’에서 고른다.

자유 조작 중에도 파형 위에서 자주 쓰는 입력을 바꿀 수 있게 하려면 `free_toggle_pin`에 입력 핀 라벨을 지정한다. 실험06의 74HC76은 `CLK`를, D 래치는 `D`를 지정한다. 74HC76에서 왼쪽의 CLR을 직접 누르면 파형 위 버튼은 현재 CLK 값에 따라 `CLK 올리기 ↑` 또는 `CLK 내리기 ↓`를 표시한다. 이 버튼도 자유 조작 이력에 기록한다.

1. 발행 팩의 `.pack/manifest.json`에서 토픽 ID를 찾는다. 교안·명세·결선도에서 실제 핀 번호, 입력·출력, 활성 극성, 유효 엣지와 예외를 대조한다. 패키지나 교안의 범위를 명시하고 근거가 어긋나는 동작은 범위를 확정한 뒤 넣는다.
2. [D 래치 원고](lessons/06/d-latch.json)를 참고해 자료별로 `lessons/NN/<lesson_id>.json`을 작성한다. 파일 이름의 자료 ID에는 영문 소문자·숫자·하이픈을 쓰고 실험 안에서 고유하게 지정한다. `topic_id`는 노트 링크 위치, `model_id`는 사용하는 회로 모델과 SVG를 지정한다. 토픽과 모델은 여러 원고에서 공유할 수 있다. `pins`는 번호순, `traces`는 표시 순서다. `default_probes`와 단계별 `probes`에는 출력과 그 실험의 근거가 되는 입력을 넣는다. 비동기 리셋 단계에서는 클럭이 0에 머무는 것을 보여주기 위해 CLK를 비교용 선으로 표시한다. 학생이 핀에서 표시 여부를 선택할 수 있는 신호는 출력과 현재 이력에서 값이 바뀐 입력이다. 이력을 다시 갈라 입력이 고정값으로 돌아오면 해당 핀의 표시 선택도 초기화한다.
3. `presets`에는 시작 상태를, `tasks`에는 예측 보기·정답 인덱스·근거 피드백과 한 번에 핀 하나를 바꾸는 조작을 넣는다. `truth_table.rows`의 ID를 모델 규칙에 맞춘다. `truth_table.reference`의 표 번호와 각 행의 `label`을 넣으면 팝업에 짧은 근거가 표시된다. 교안 표에 없는 조작에는 모델의 동작 설명을 표시한다. 입력 팝업은 조작과 유지 상태를 설명하고 출력 팝업은 모델의 전이 근거를 표시한다.
4. 모델의 `transition(previous, action)`은 `{next, accepted, reason, rule}`을 반환한다. 새 모델은 `scripts/lab/interactive.py`의 모델 목록에 등록하고 같은 모델 ID의 SVG를 작성한다. SVG의 `data-dip`는 칩 다리 위치를, `data-net`과 `data-led`는 핀 라벨에 대응하는 선과 LED를 지정한다. 이상 모델의 파형은 조작 순서와 논리 상태를 표현한다. 실제 시간이나 실측값을 넣을 때는 근거를 제시한다.
5. 예측 공개 단계에는 `challenge: true`를 사용한다. 제출 전에는 초기 조건을 제외한 출력 파형과 함께 칩 출력·LED·현재 출력값·적용 진리표 행을 가린다. 가려진 출력 구간의 팝업과 접근성 안내에는 `예측 후 공개`를 표시한다. 기본 건너뛰기 동작은 해당 단계의 시작 조건에서 자유 조작을 여는 것이다.
6. 실험06 D 래치는 `guided_prediction: true`를 지정한다. 일반 단계에서 답을 고르면 카드에 파형 위의 다음 입력 조작을 안내하고, 건너뛰면 현재 조작 이력에서 이어간다. 예측 공개 단계에서는 ‘파형 펼쳐서 확인’과 ‘예측 없이 파형 보기’ 모두 준비된 전체 파형을 마지막 시점에서 공개한다. 답을 제출한 경우에는 채점 피드백도 표시한다.

## 빌드와 검증

저장소 루트에서 실행한다. `RUN`은 비어 있는 새 실행 폴더다.

```sh
python -m scripts.lab.interactive 6 --stage RUN/실험06
python -m pytest -q tests/test_logic_lab_interactive.py
```

교안의 표나 상태 전이로 독립 기대값을 적어 검증한다. 실험06은 처음 Q가 다른 두 상태, 상승·유지·하강, 비동기 PR/CLR과 동시 활성 조작 거부를 확인한다. 1440×900·375×812의 밝은·어두운 화면에서 고정 입력 핀은 선택이 제한되고, 값이 바뀐 입력 핀은 파형을 켜고 끌 수 있는지 확인한다. 호버 중 이력 커서 유지, 클릭·탭·키보드 선택과 핀·LED·진리표 연동을 확인한다. 이력 분기 뒤의 파형 목록, 예측 가림·공개와 건너뛰기, 모바일 서랍, 노트 복귀도 확인한다. HTML을 따로 복사해 외부 리소스 없이 열어 본다.

밝은·어두운 테마에서 파형 색을 구분할 수 있고 팝업의 핀 색이 해당 파형과 일치하는지 확인한다. 마우스 호버·클릭, 모바일 탭, 키보드 Enter에서 같은 팝업을 쓰고 파형 아래에 설명 카드가 추가되지 않는지 확인한다.

넓은 화면과 모바일에서 파형 머리글의 제목·버튼·이력이 겹치지 않는지 확인한다. 마지막 조작 직후 버튼이 사라지고, 조작 이력을 한 칸 되돌리면 해당 입력 조작 버튼이 다시 나타나는지 확인한다.

실험06은 왼쪽에서 CLR을 0으로 내린 뒤 파형 위 버튼으로 CLK를 올리고 내릴 수 있고, 그동안 Q=0과 T3의 CLR 행이 유지되는지 확인한다.

새 스테이지에는 그 실험에 등록한 모든 HTML이 생성된다. 실험06 D 래치는 E=1에서 D가 양방향으로 바뀔 때 Q도 따라가는지, E=0에서는 Q가 유지되는지, E를 다시 올릴 때 현재 D가 반영되는지 확인한다. 각각의 노트 링크로 HTML을 열고 HTML의 돌아가기 링크가 해당 토픽을 다시 여는지 확인한다.

D 래치의 1023px·1024px 경계와 넓은 화면의 오른쪽 패널 토글에서 카드 위치를 확인한다. 카드를 옮긴 뒤 선택한 답, 피드백과 파형이 유지되는지 확인한다. 데스크톱과 모바일에서 첫 두 단계의 카드 안내가 답 선택과 조작 이력에 맞춰 갱신되는지 확인한다. 세 번째 단계는 제출과 건너뛰기에서 조작 순서, 신호 파형, 마지막 커서, LED 값이 일치하는지 대조한다.

통과 후 자료별로 스테이지의 `.pack/자료_인터랙티브/<lesson_id>/verification.json`에서 `checks`를 제외한 내용을 `lessons/NN/<lesson_id>.verification.json`의 `basis`에 넣는다. `checks`는 바깥에 두고 실제로 수행한 논리·브라우저·화면 검사와 관측 결과를 기록한다. 해시가 달라진 원고를 스테이지에서 다시 생성하면 새 검증 근거만 출력된다. [D 래치 검증 기록](lessons/06/d-latch.verification.json)을 참고한다.

기존 단일 원고 `lessons/NN.json`도 함께 읽는다. 이 원고의 학생용 HTML 이름, `.pack/자료_인터랙티브/<model_id>/` 경로와 `lessons/NN.verification.json` 형식은 기존 발행 링크와 호환된다.

## 발행

```sh
python -m scripts.lab.interactive 6 --install
```

학습팩 잠금 아래에서 현재 팩을 기준으로 스테이지를 새로 만든다. 등록 원고마다 HTML·원고·외부 근거의 해시가 검증 기록과 맞으면 팩 전체를 발행한다. 새 HTML 이름은 `실험NN_인터랙티브_<lesson_id>.html`이다. 같은 토픽에 여러 자료가 있으면 자료 ID 순으로 링크를 붙인다. 원고를 옮기거나 삭제한 뒤 발행하면 해당 팩의 이전 생성물과 링크도 갱신된다. 학습팩을 다시 빌드할 때도 등록 원고 전체로 같은 링크와 HTML을 생성한다. 발행 후 자료별 양방향 링크를 확인하고 학생용 HTML, 노트 링크와 실제 검사 결과를 보고한다.
