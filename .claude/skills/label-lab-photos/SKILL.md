# label-lab-photos

## 산출물 이름 (실험07부터)

파일 경로는 `scripts.lab.config.artifact_path(실험폴더, 종류, 확장자)`로 정한다.
실험07 이상은 `실험NN_실험_제목_산출물종류.확장자`이고, 실험01~06은 기존 이름 그대로다.
실험 제목은 명세의 `title`에서 읽는다. 문서 안의 제목·내부 그림 이름은 바꾸지 않는다.
이 문서의 `기록.md`·`체크리스트.pdf` 같은 짧은 이름은 종류를 뜻하는 별칭이며,
실제 생성·존재 확인·전사·검증·결과 링크에는 반드시 공통 함수가 반환한 경로를 쓴다.
종류는 `체크리스트`, `기록`, `예비보고서`, `결과보고서`, `예비보고서표지`,
`결과보고서표지`, `손그림모사`, `부품그리기`, `따라그리기`, `예상결과`다.
저장 위치·예외·이력 보존 규칙은 `docs/schema/lab-artifact-naming.md`를 따른다.

사진 속 입력 스위치·점퍼는 얽혀 있어 읽지 않는다(`write-result-report/필기전사.md`).
그래서 입력은 **LED 켜짐 패턴을 진리표 출력과 맞대 거꾸로** 찾는다. 이 역산과 LED 순서·
극성 대응은 `scripts.lab.photo_label` 이 하고, Claude 는 사진에서 LED 만 읽는다.

결과물은 `<실험NN>/실험사진/<항목> <입력비트>.jpg` 사본과, `기록.md` 의 그 행 확인 칸·항목 메모다.

## 절대 규칙

1. **LED → 신호 대응과 라벨은 스크립트 출력만 옮긴다.** 손으로 "k번째 LED = Yk" 를 세지 않는다.
   다른 LED 순서였다면 어떤 라벨이 되는지도 `--order columns` 로 돌린 출력에서 옮긴다 —
   결선도가 출력 핀 행 순서로 LED 를 붙여(실험05 1-2: Y0~Y5, Y9, Y6, Y8, Y7) 손 계산이
   뒤바뀌기 쉽다.
2. **확정 전에는 아무 파일도 쓰지 않는다.** 판독·라벨 대조표를 보여 주고 AskUserQuestion 으로
   확정받은 뒤에만 `--apply` 와 `기록.md` 편집을 한다. 사용자가 답할 수 없는 상황(서브에이전트 등)
   이면 대조표와 질문을 내고 거기서 멈춘다.
3. **질문은 한 번에, AskUserQuestion 으로, 추천 답을 첫 옵션에 `(Recommended)` 로.** 묻는 것은
   아래 「언제 묻나」 표에 있는 것뿐이다.
4. **`기록.md` 는 빈 칸만 채운다.** 확인 칸에는 스크립트의 `확인 칸` 열 값을 그대로 쓴다.
   이미 값이 있는 칸이 사진과 다르면 두 값을 나란히 보여 주고 사용자가 정한다.
5. **커밋은 묻는다.** 기본은 하지 않는다.

## 언제 묻나

| 스크립트 출력 | 물을 것 | 추천 답 | 답을 받으면 |
|---|---|---|---|
| `ORDER-SENSITIVE` | 실물 LED 를 위에서부터 어떤 순서로 꽂았나 | 결선도 순서 | 열 순서면 `--order columns` 로 다시 돌린다 |
| 흐리거나 반사로 애매한 LED | 그 사진의 그 LED 가 켜졌나 | 판독한 값 | `--read` 를 고쳐 다시 돌린다 |
| `ambiguous` (출력이 같은 행이 여럿 — MUX 등) | 진리표 행 순서대로 찍었나 | 행 순서 | `--sequence` 로 다시 돌린다. 출력이 그 행과 다르면 확인 칸에 관찰값이 나온다 |
| `none` (어느 행과도 안 맞음) | 그 사진의 입력 조합 | 패턴과 가장 가까운 행 | `--assign '<경로>=<비트>'` — 확인 칸에 관찰값이 나온다 |
| `duplicate` | 같은 행으로 라벨이 난 두 장 중 무엇이 맞나 | 더 선명한 쪽 | 다른 쪽은 판독을 다시 본다 |

`ORDER-SENSITIVE` 가 없으면 LED 순서는 묻지 않는다(어느 순서로 읽어도 라벨이 같다).

## 실행 절차

1. **LED 읽는 순서를 받는다.**

   ```bash
   python3 -m scripts.lab.photo_label <실험번호> <항목>
   ```

   `<항목>` 은 명세 제목 `실험 N)` 의 번호다(`1-2` — `P1-2`·`E5.P1-2` 아님). "첫번째 실험" 처럼 말하면
   `기록.md` 의 항목 순서로 옮긴다.

   완료: `LED 읽는 순서(판 위 행 오름차순): …` 줄. 패턴 비트는 이 순서다(1 = 켜짐, 극성 무관).
   `오류:` 면 멈추고 그 문장을 보여 준다(사이드카·기록용 진리표가 없는 항목이다).

2. **사진을 전부 열어 LED 를 판독한다.** 판 위 행이 작은 LED 부터 큰 쪽으로 켜짐 비트를 적는다.
   사진이 기울었거나 회전돼 있어도 판의 행 번호 기준이다. 애매한 LED 는 따로 적어 둔다.

3. **역산한다.**

   ```bash
   python3 -m scripts.lab.photo_label <실험번호> <항목> --read '<경로>=<비트>' ...
   ```

   `ORDER-SENSITIVE` 가 나오면 같은 인자에 `--order columns` 를 붙여 한 번 더 돌려 두 라벨 열을
   얻는다 — 질문의 두 옵션 설명에 각각 옮긴다.

4. **대조표를 보이고 묻는다.** 스크립트 표(원본·패턴·출력값·상태·입력·파일명·확인 칸)를 그대로
   보여 주고, 「언제 묻나」 에 걸린 것만 AskUserQuestion 하나로 묻는다. 걸린 것이 없어도 이 표를
   보여 주고 "이대로 복사·기록" 을 확인받는다.

5. **복사한다.** 확정된 인자에 `--apply` 를 붙여 돌린다. 원본은 남고, 같은 이름이 이미 있으면
   아무것도 복사하지 않는다(exit 1 — 그 파일을 사용자에게 보여 주고 멈춘다).

6. **`기록.md` 를 채운다** (`config.artifact_path('<실험NN>', '기록', '.md')`).
   - 사진이 있는 행의 빈 확인 칸 ← 스크립트 `확인 칸` 값. 사진이 없는 행은 공란으로 둔다.
   - 프론트매터 `filled_by: vision`.
   - 그 항목의 `- 메모:` 줄(이미 차 있으면 그 아래 `  - ` 새 줄)에 이 형식으로 쓴다:

     ```
     사진 판독(`실험사진/<항목> *.jpg`, N장). 입력 라벨은 LED 패턴을 진리표 출력과 맞대 역산했다 — ✓ 는 패턴이 그 행과 일치한다는 뜻이고 입력을 따로 확인한 것은 아니다. LED 순서: <결선도 순서 | 사용자 확인 (YYYY-MM-DD)>.
     ```

     `--sequence`·`--assign` 으로 붙인 사진이 있으면 "입력 라벨은 사용자가 알려 준 촬영 순서/입력이다" 로
     바꿔 쓴다 — 그때는 ✓ 가 독립 확인이다.

7. **커밋 여부를 묻는다** (추천: 커밋만, push 안 함). 다음 단계는 `export-photo-sheet` 다.

## 흔한 실수

| 실수 | 바로잡기 |
|---|---|
| "실물 배치가 결선도와 다르다" 며 순서를 직접 추정 | 스크립트가 `ORDER-SENSITIVE` 를 낼 때만 묻는다. 추정 라벨은 만들지 않는다 |
| 대안 라벨을 머릿속으로 재배치 | `--order columns` 출력만 옮긴다 (규칙 1) |
| 사용자가 없다고 기록부터 채움 | 대조표·질문에서 멈춘다 (규칙 2) |
| 메모에 "전부 예상대로" 만 적음 | 역산이라 ✓ 가 자동 일치라는 점을 반드시 적는다 (6단계 형식) |
| 종료 메모 4문항까지 채움 | 사용자 경험이 재료라 `record-lab-notes` 의 일이다 |
