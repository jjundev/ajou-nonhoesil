# explain-lab-preview — 실험 전 맞춤형 프리뷰 설명

실험실에 들어가기 **전에**, 그 주차 실험이 "무엇을 왜 하는지"를 학생이 가장 잘 이해하는 방식으로 미리 풀어주는 **대화형** 스킬이다. 문서를 생성하는 스킬이 아니라 **대화 자체가 산출물**이다. 그 주차의 교안(강의노트)을 읽어 추상적 이론이 아닌 **그 주차의 실제 IC·진리표·핀아웃에 grounding** 한 설명을 한다. 예비보고서 등 과거 제출본은 grounding 소스로 쓰지 않는다 (§2).

이 스킬은 논회실 프로젝트(`.claude/` 를 가진 디렉토리) 안에서만 동작한다. cwd 가 다른 프로젝트로 바뀌면 자동 트리거되지 않는다.

이 스킬은 **read-only 교육 전용**이다. 명세·기록·netlist·보고서 파일을 수정하지 않고, 새 진리표·핀맵을 계산해 만들어내지 않으며, 기록 칸을 채우지 않는다. 기존 값은 **인용**할 뿐이다. (체크리스트·기록 파생은 ②, 보고서 작성은 ③·④, 표지 생성은 ⑥ 의 영역이다.)

## 0. 학생 학습 프로파일 (이 스킬의 교수법 근간)

이 학생(`.claude/과목정보.md` 참조)이 실험 전 설명을 잘 이해하는 방식이다. **잠정(provisional)** 프로파일이다 — 단일 세션 관찰에 기반하며, 매 주차 관찰로 갱신·반증한다 (§7 참조).

| # | 패턴 | 적용 |
|---|---|---|
| P1 | **비유 먼저, 수식 나중** | 추상 정의 전에 일상/물리 비유로 직관을 먼저 잡아준다. |
| P2 | **동기→한계→핵심통찰→예시** | 정의를 던지지 않고 "왜 필요한가"부터 빌드업한다. |
| P3 | **정밀 디테일 확인 욕구** | "정확히는 X가 아니라 Y" 식 경계 확인을 섹션마다 1개 이상 넣는다. |
| P4 | **구조를 스스로 일반화** | 조건 비교를 "통제 실험: 변수 하나만 바꿈" 프레임으로 제시한다. |
| P5 | **표 비교 선호** | 비교·매핑은 산문 대신 표로 보여준다. |
| P6 | **대화형 페이싱** | 한 번에 다 쏟지 않고 덩어리마다 "다음 뭐 볼까" 메뉴로 끊는다. |
| P7 | **점진적 난이도 하강** | 앞서가서 막히면 수식을 걷어내고 일상 비유 단독으로 리셋한다. |

## 1. 입력 해석

**주차로 불렸으면 폴더를 코드로 옮긴다.** 사용자는 "2주차 …" 처럼 주차로
부르는데 아래 절차의 경로는 `<실험NN>/` 이다. **매핑은 1:1 이 아니다** —
실험4는 7주차다. 손으로 옮기지 말고 아래를 돌린다.

```bash
python3 -c "
from scripts.lab import config
print(config.folder_for_week(<N>))
"
```

출력이 이후 모든 경로의 `<실험NN>` 이다. 사용자가 `실험N` 으로 불렀으면
`config.experiment_dir(<N>)` 을 대신 쓴다. `ValueError` 가 나면(중간고사·범위
밖) 그 메시지를 그대로 사용자에게 전하고 중단한다. 13~15주차는 `실험NN`
대신 `프로젝트` 를 돌려준다 — 그 뒤로는 모든 경로에서 `<실험NN>/` 자리에
`프로젝트/` 를 쓴다.

`ARGUMENTS` 토큰을 해석한다.

- `N주차` 토큰 → 프로젝트 루트(`.claude/` 를 가진 가장 가까운 상위 디렉토리, `scripts.lab.config.find_project_root` 와 동일한 규칙) 아래의 `<실험NN>/` 폴더를 그 주차 폴더로 쓴다. 폴더가 없으면 **거절**하고 `init-lab-experiment` 를 안내한다.
- 디렉토리 경로 → 그 디렉토리를 그 주차 폴더로 쓴다.
- `쉽게` 또는 `처음부터` 포함 → **난이도 하강 모드**로 시작 (비유 비중 ↑, 부울식 최소화; P7 을 사전 옵션으로 노출).
- `저장` 포함 → 대화 종료 시 프리뷰 요약을 `<실험NN>/output/<실험NN>_실험프리뷰.md` 로 옵션 저장 (§6).
- `pdf` 포함 → 프리뷰를 `<실험NN>/output/<실험NN>_실험프리뷰.html` + `.pdf` 한 쌍으로 산출 (§8). `저장`과 독립·조합 가능.
  - **세션 스냅샷**: 대화가 진행된 뒤 `pdf` 요청 → 그때까지 다룬 내용을 캡처.
  - **일괄 생성**: 대화 없이 `/explain-lab-preview 2주차 pdf` → 소스에서 [1]~[4] 전 섹션을 구성해 한 번에 산출.
- 주차 토큰이 없으면 한 줄 안내 후 종료:
  > 어느 주차 실험을 미리 볼까요? 예: `/explain-lab-preview 2주차` (쉽게 / 저장 / pdf 옵션 추가 가능)

## 2. 소스 디스커버리 (grounding 의무)

`<실험NN>/` 에서 다음을 순서대로 찾아 `SOURCES` 로 수집한다.

**과거 예비보고서는 grounding 소스로 쓰지 않는다.** 이 과목의 예비보고서는 자료 권위 5순위 코퍼스이고 알려진 오염이 있다 — 실험2 180928(Rn/Rp 누락), 실험4 200928·실험6 201012(측정 대신 PSpice), 실험10 201117_1("원인을 찾지 못하였다"), 실험3 200921·실험9 181123(결과 표 없음). 꼭 필요하면(예: 학생들이 그 개념을 실제로 어떻게 이해했는지 감을 잡을 때) **다수결로만, 연도를 명시하고** 인용한다. 단일 제출본을 근거로 삼지 않는다.

`<실험NN>/체크리스트/명세.md` 가 있으면 **최우선 grounding 소스**다 — 교안과 이미 대조·검증된 IC·진리표·핀아웃이다. 프론트매터의 `experiment` 필드는 §1에서 `config.folder_for_week`/`config.experiment_dir` 로 이미 구했어야 할 실험 번호를 다시 한번 확인해 줄 뿐이다 — 그 폴더를 애초에 찾으려면 §1을 먼저 거쳐야 한다(명세.md 자체가 그 폴더 안에 있으니, 순서를 건너뛸 방법이 없다).

| 우선순위 | 패턴 | 용도 |
|---|---|---|
| 1 | `docs/강의노트_이론_실험_매핑_정리.md` | 주차 ↔ 실험 ↔ 이론 챕터 매핑. 실험별 심화 이론·자주 나오는 함정을 domain 단위로 정리해 둔 문서다 |
| 2 | `<실험NN>/강의노트/실험N.pdf` 또는 `from_the_past/정리/강의노트/실험N.pdf` | **주 grounding.** 목적·IC·회로도·절차. 교안이 아직 배포되지 않아 후자가 현재 대부분 주차의 실제 위치다. **회로도·수식·타이밍 기호가 있는 쪽은 반드시 vision 으로 읽는다** (아래 경고) |
| 3 | `from_the_past/정리/논회 강의노트/Ch*.pdf` | 이론 배경 (게이트 이론·CMOS·조합/순서 논리 등) |
| 4 | `docs/study/*.md` | 이미 정리된 학습 모듈 (도메인별 묶음. 모듈당 실험 2~3개) |
| 5 | `<실험NN>/STT/` | 강의 녹취 (있으면) |

> **교안 PDF 를 텍스트 추출로만 읽지 마라.** `extract_text()` 는 오버바를 벡터
> 선이라 통째로 버리고, 라이징 엣지 기호를 지우고, 아래첨자를 날린다. 실험1
> p7~p9 의 드모르간 식은 추출하면 `A B A B A B C ⇒De Morgan의 법칙` 같은
> 뭉개진 문자열이 되고, 실험6 p9·p11 의 C 컬럼은 **리터럴 `1` 로 나온다**
> (엣지 기호가 살아 있는 텍스트 위에 덮인 불투명 이미지라서).
> 그대로 믿고 설명하면 학생에게 틀린 진리표를 가르치게 된다.
>
> **회로도·부울식·타이밍 기호가 있는 쪽은 `Read` 도구로 PDF 를 직접 열어
> 눈으로 확인한다.** 이 프로젝트는 이미 이 함정에 한 번 빠졌다.
>
> `<실험NN>/체크리스트/명세.md` 가 있으면 그것이 이미 vision 으로 검증된
> 결과이므로 우선 쓴다. 지금은 2·6·12주차에만 있고, 나머지 주차는 교안을
> 직접 읽어야 한다.

**주차 → 실험 회전 매핑 (1:1 아님).** **이 표로 번호를 옮기지 않는다** — §1 이 `config.folder_for_week` 로 이미 구했다. 아래는 학생에게 "이번 주가 왜 실험4냐"를 설명할 때 보여줄 자료다:

| 주 | 실험 | 주 | 실험 |
|---|---|---|---|
| 2 | 실험1 | 9 | 실험7 |
| 3 | 실험2 | 10 | 실험8 |
| 4 | 실험3 | 11 | 실험9 |
| **5** | **실험5** | 12 | 실험10 |
| **6** | **실험6** | 13~15 | FPGA |
| **7** | **실험4** | | |

5·6·7주차가 실험 5·6·4 로 어긋나는 것이 이 표의 요점이다. 8주차는 mid-term(실험 없음). 13~15주차는 FPGA — 회로도·진리표가 아니라 HDL·시뮬레이션이 산출물이라 이 스킬이 전제하는 grounding 대상(IC·진리표·핀아웃)이 적용되지 않는다. 그 구간을 다룰 땐 첫 줄에 그 점을 밝힌다.

**명시 제외:** `<실험NN>/output/*_review_round*.md` (review-lab-report 가 남기는 검토 라운드 문서). 이 스킬 자신의 QA 메모이지 교육 자료가 아니므로 grounding 소스로도, 학생에게 노출도 하지 않는다.

소스가 **하나도 없으면** 거절하지 말고 degrade: 개념 수준 프리뷰만 제공하되 첫 줄에 "이번 주차는 grounding 파일이 없어 일반 이론 위주입니다" 를 명시한다.

## 3. 설명 흐름 (페이싱 규칙)

**[1] 오프닝만 자동 출력한다.** [2]·[3]·[4]·[5]·[6] 은 **메뉴 선택으로만 진입**하며, 절대 자동으로 이어 쓰지 않는다. 각 덩어리 끝에서 멈추고 §5 메뉴를 제시한 뒤 학생의 선택을 기다린다 (P6). [5]·[6] 은 일괄 생성 모드(§1)에도 포함하지 않는다 — 특정 IC·타이밍도는 학생이 그 필요를 명시할 때만 의미가 있는 곁가지 심화이지, 매주 기본으로 주는 개요가 아니다.

### [1] 오프닝 — 큰 그림 + 비유 (항상 먼저, 약 1화면)

- 그 주차 실험을 **한 문장**으로 (예: "이번엔 3-input 게이트를 2-input IC 둘로 짜 맞추는 실험").
- **논리회로 비유 1개**로 직관 제공 (P1). 비유 시드:

  | 도메인 | 비유 |
  |---|---|
  | 논리 게이트 | 수문 — AND 는 직렬 수문 둘, OR 은 병렬 수문 둘 |
  | 드모르간 | "둘 다 열림의 반대 = 하나라도 닫힘" |
  | 진리표 | 가능한 모든 스위치 조합을 빠짐없이 적은 목록 |
  | 플립플롭 | 딸깍 스위치 — 손을 떼도 상태가 남는다 |
  | 래치 vs F/F | 문이 열려 있는 동안 통과 vs 종 칠 때만 통과 |
  | 디코더 | 우편번호 → 정확히 한 집의 초인종 |
  | 멀티플렉서 | 여러 수도관 중 하나만 고르는 밸브 |
  | 시프트 레지스터 | 컨베이어 벨트 — 클럭마다 한 칸씩 |
  | 카운터 | 주행거리계 자릿수 올림 |
  | DAC/ADC | 계단 vs 자 — 이산 단계를 연속량에 맞춘다 |
  | 플로팅 입력 | 아무 데도 안 연결된 스위치 — 값이 정해지지 않는다 |

  시드에 없으면 그 자리에서 적절한 비유를 생성한다. **그 주 개념과 가장 가까운 항목 1개**를 주 비유로 고른다.
- **비유 ↔ 회로 매핑 표** (P5).
- **한 문장 요약도 P3 정밀 검사를 통과해야 한다.** 오프닝 첫 문장은 학생이
  가장 먼저 믿는 문장이라 부정확하면 가장 오래 남는다. 특히 **IC 개수와 게이트
  개수를 혼동하지 마라** — 74HC08 은 2입력 AND 가 4개 든 패키지 하나이므로,
  3입력 AND 는 "IC 두 개" 가 아니라 **한 칩의 게이트 둘을 캐스케이드** 하는
  것이다. 그 주 `netlist.md` 의 물리 칩 배분을 확인하고 쓴다.
- **플로팅 입력 콜아웃 (항상, 예외 없음).** 위 표의 마지막 항목을 그 주의 주 비유로 쓰지 않더라도, 오프닝 말미에 한 줄은 반드시 짚는다 — 미사용 입력핀을 GND(또는 필요시 VCC)로 내리지 않으면 값이 안 정해지고 IC 가 오동작·발열한다는 것이 이 과목 배선 실수의 대표 원인이다. 그 주 `netlist.md` 에 "미사용 입력핀 → GND" 지시가 있으면 그 문구를 그대로 짚어 연결한다.

### [2] 핵심 개념 빌드업 (메뉴 진입)

그 주차의 가장 중요한 개념 1~2개를 **이 스킬 안에서 직접** 다음 5단계 흐름으로 설명한다 (외부 스킬 호출/위임이 아니라 **인라인 재현** — concept-explain 과 동일한 철학이되 자립적으로 수행).

1. **왜 이 개념이 필요한가** (동기·문제 상황)
2. **단순 해법은 왜 안 통하나** (해당 시)
3. **핵심 통찰** (한 문장 Aha)
4. **왜 작동하나** (부울식·회로 직관)
5. **구체적 예시** (그 주차 실제 IC·진리표 사용)

규칙:
- 정의를 맨 앞에 던지지 않는다 (P2).
- **정밀 디테일 1개 이상 의무** (P3): "정확히는 X가 아니라 Y" 형태의 경계 확인 (예: "OR 도 74HC08 을 재배선하는 게 아니라 별도 IC(74HC32)로 바꾸는 것").
- 비-elementary 용어는 그 자리에서 한 줄 정의.

### [3] 실험 구조 — "각 단계가 뭘 확인하나" (메뉴 진입)

명세.md 의 `items[]` 순서대로, 각 항목이 딸린 표(`tables`)의 **목적**(무엇을 검증하려는가)을 한 줄씩. 측정 절차 나열이 아니라 "왜 이 표를 만드나" 중심. 명세.md 가 없으면 강의노트의 실험 단계 순서를 대신 쓴다.

### [4] 조건/Part 비교 — 통제 실험 프레임 (해당 시, 메뉴 진입)

여러 Part·항목이 있으면 "변수 하나만 바꾸는 통제 실험" 으로 프레이밍 (P4) 하고 비교 표 (P5):

| 구분 | 고정 변수 | 독립 변수(바뀐 것) | 종속 변수(따라 바뀐 것) |
|---|---|---|---|

### [5] 특정 IC·핀 디테일 (메뉴 진입)

학생이 특정 IC 하나를 짚으면(예: "74HC02 자세히", "핀 배치 다시"), 그 칩에 한정해:

- 그 주 `netlist.md` 에서 그 IC 가 맡은 역할(입력·출력·핀 배정, 물리 칩을
  여러 항목이 재사용하는지)을 인용한다 — 지어내지 않는다.
- 핀아웃을 표로 제시하고 **출처를 반드시 밝힌다**(§2 grounding 의무와
  동일 — 데이터시트로 확인됐는지, 표준 배치를 가정한 것뿐인지 구분해서 말한다).
- 그 칩이 "같은 계열의 나머지와 다른 점"이 있으면(예: 74HC02 는 출력 핀이
  1·4·10·13 이라 나머지 74HC00/08/32 와 다르다) P3 정밀 디테일로 강조한다 —
  이런 예외가 실제 배선 실수의 원인이다.
- 데이터시트가 저장소에 없으면 §절대 규칙과 같은 태도를 쓴다: "표준 DIP-14
  배치로 가정했다, 실물 각인·데이터시트 대조를 권고한다"를 명시하고 확정된
  사실처럼 말하지 않는다.

### [6] 타이밍도 그리는 법 (메뉴 진입, **vision 판독 필수**)

**이 경로는 §2 의 vision 경고("교안 PDF 를 텍스트 추출로만 읽지 마라")가 가장
직접적으로 걸리는 영역이다** — `extract_text()` 는 라이징/폴링 엣지 기호를
지운다. 이 메뉴로 들어가기 전에, 그 주 회로의 클럭/트리거 파형이 있는 교안
쪽을 **`Read` 로 PDF 를 직접(vision) 확인**한 적이 없다면 먼저 확인부터
한다 — 이미 이번 세션에서 그 쪽을 vision 으로 읽었다면 그 결과를 재사용하면
된다. 확인 없이 타이밍도 설명을 시작하지 않는다.

흐름 (그리는 **법**을 가르친다 — 완성된 파형을 대신 그려주지 않는다):

1. 그 주 회로의 클럭/트리거 신호가 무엇인지 짚는다(예: 카운터의 클럭 pin,
   플립플롭의 트리거 엣지 — 그 주 실제 신호명으로).
2. 가로축(시간) 맨 위에 클럭 파형부터 그리는 관례를 설명한다.
3. 그 아래 각 신호선을, 클럭 엣지가 지날 때마다 진리표/상태표 값을 따라
   계단식(high/low 로만, 사선 없이)으로 내려 그리는 방법을 설명한다.
4. 그 주 실제 신호명으로 축의 뼈대만 제시한다 — 값을 전부 미리 계산해
   대신 채워 주지 않는다. 이 스킬은 "새 진리표·핀맵을 계산해 만들어내지
   않는다"(머리말 §read-only 원칙)와 같은 이유로, 완성된 타이밍도를 대신
   만들어 주지 않는다. 학생이 그 주 표를 보고 직접 그려보는 것이 훈련이다.

## 4. 톤·렌더링 (대화/터미널 출력)

- 한국어, 친근한 존댓말. **이모지 금지**.
- **부울식은 평문 표기** — 대화 출력은 GFM 터미널이라 오버바를 그릴 수 없다. 복소(complement)는 **`'`** 로 적는다: `A'`, `(A·B)'`. 스코프가 넓을 땐 괄호로 감싼다 — `(A'·B)'` 처럼. **PDF 산출(§8)도 저작은 똑같이 `'`** 이고, 거기서만 부울식을 오버바로 시각 승격한다(R5) — 대화·PDF 저작 표기는 통일돼 있고 승격 여부만 다르다. 두 경로를 혼동하지 말 것.
- 기호는 유니코드: `· + ⊕ Ω → ⇔ ≠`. AND 는 `·` 또는 이어쓰기, OR 는 `+`, XOR 는 `⊕`.
- **인코딩(`0/1` 또는 `H/L`)은 그 표에 적힌 그대로 쓴다. 임의로 바꿔 말하지 않는다** — 실험1 이론표는 `H`/`L`, 실험6 은 `0`/`1` 이다. 학생이 교안과 대조할 때 혼란을 막기 위함이다.
- 비교·매핑은 표. 단, **표 셀에는 짧은 표현만**(IC 번호·핀 번호·비트·단어) — 배선 절차나 여러 문장은 셀 밖 산문·목록으로.
- 짧은 문단, 섹션 헤더로 분리.
- 그 주차 실제 IC·진리표를 인용할 때는 출처(교안 쪽수 등)가 드러나게. 단, `*_review_round*.md` 같은 내부 QA 파일명은 노출하지 않는다.

## 8. PDF 산출 (`pdf` 인자일 때만)

프리뷰를 미니멀 모노크롬 A4 **HTML + PDF 한 쌍**으로 산출한다. 디자인 톤은 ⑥ 표지 · ② 체크리스트와 통일한다. **이 스킬은 read-only 교육 전용** 원칙을 유지한다 — PDF 는 `output/` 에 새로 추가되는 학습 아티팩트일 뿐, 명세·기록·보고서 등 기존 소스 파일은 절대 수정하지 않는다. 로컬 파일·시스템 폰트·Chrome 헤드리스만 쓰고 외부 CDN 의존이 없어 오프라인에서도 항상 렌더된다.

### 8.1 파이프라인

```
프리뷰 내용 → {{CONTENT}} HTML 본문 작성 → template.html 치환
  → Write 로 <실험NN>_실험프리뷰.html 저장 → scripts.lab.html2pdf.html_to_pdf 로 .pdf 변환
```

**MathJax 는 쓰지 않는다.** 이 과목의 수식은 부울식뿐이고, `.ov` CSS 오버바(체크리스트 템플릿과 동일 규칙)로 충분하다:

```css
.ov { border-top: 1px solid currentColor; }
```

### 8.2 템플릿 치환

`Read` 로 `.claude/skills/explain-lab-preview/template.html` 를 읽고 4개 placeholder 를 모두 교체:

| placeholder | 값 |
|---|---|
| `{{TITLE}}` | `config.document_title(experiment, title, '프리뷰')` 의 출력 (`실험1 Basic Gates 프리뷰`). **손으로 짓지 않고, 제목에 주차를 넣지 않는다** — 주차는 §1 에서 폴더를 찾을 때만 쓴다. `experiment` 는 §1 에서 구한 **0 을 뺀 정수**이고(§1 의 출력은 `실험01` 이라는 폴더 이름이다), `title` 은 명세.md 프론트매터의 `title`, 명세가 없으면 교안 제목이다. ②·③·④ 가 쓰는 것과 같은 함수다 |
| `{{COURSE}}` | `.claude/과목정보.md` 의 `course` — **헤더·푸터 2곳에 등장하므로 전부 치환한다** |
| `{{DATE}}` | 오늘 날짜, `과목정보.md` 의 `date_format` 으로 포맷 |
| `{{CONTENT}}` | 본문 HTML (아래 §8.3) |

치환 후 파일에 `{{` 가 남아 있지 않은지 확인한다 — 하나라도 남으면 PDF 에 그대로 찍힌다.

`COURSE`·`DATE`·PDF 변환용 `chrome` 은 한 번에 읽는다:

```bash
python3 -c "
from pathlib import Path
from datetime import datetime
from scripts.lab import config
root = config.find_project_root(Path('.'))
info = config.load_course_info(root)
print(info['course'])
print(datetime.now().strftime(info['date_format']))
print(info.get('chrome'))
"
```

본문에 부울식을 쓸 때는 §4 와 동일하게 `'` 로 저작하되, 오버바로 보이고 싶은 부울식(**진리표 헤더·신호명·셀 값은 제외** — 상태 토큰이지 부울식이 아니다)만 `<span class="ov">…</span>` 로 감싼다. 규칙은 `scripts/lab/notation.py` 의 `to_overbar_html`(R5)과 동일하다:

- `A'` → `<span class="ov">A</span>`
- `(A·B)'` → `<span class="ov">A·B</span>`
- `(A'·B)'` (2주차 T5 처럼 중첩된 경우) → `<span class="ov"><span class="ov">A</span>·B</span>` (바깥쪽 스팬이 식 전체 위, 안쪽 스팬이 `A` 위)

별도 markdown→HTML 라이브러리·콘텐츠 빌더는 쓰지 않는다 (본문은 직접 HTML 작성).

### 8.3 본문 구조 (스킬 흐름 미러링)

§3 흐름 순서로, **세션에서 실제 다룬 섹션만** `<h2>` 로 구성. 일괄 생성 모드면 [1]~[4] 전체.
`<h2>` 에는 번호가 자동으로 붙으므로 제목에 "1." 같은 번호를 직접 적지 않는다.

**템플릿이 제공하는 클래스만 쓴다 — 인라인 `style` 을 새로 붙이지 않는다.**
필요한 표현이 없으면 template.html 에 클래스를 추가하고 여기 표를 갱신한다.

| 요소 | 용도 |
|---|---|
| `<h2>` / `<h3>` / `<p>` / `<ul>` | 섹션·하위 제목·서술 |
| `<div class="callout"><span class="tag">비유</span>…</div>` | 비유·직관 (P1). 태그 라벨은 자유롭게 (`비유`, `직관`, `한 걸음 더`) |
| `<div class="callout note">` | P3 정밀 디테일. 태그는 `정확히는` 을 기본으로 |
| `<div class="callout warn">` | **배선 사고 경고 전용.** 오프닝의 플로팅 입력 콜아웃(§3 [1])은 반드시 이것으로. 문서에서 강조색을 쓰는 유일한 자리이므로 주차당 1~2개를 넘기지 않는다 |
| `<div class="summary">` | 한 문장 요약. 가장 무거운 상자이므로 섹션당 1개 |
| `<div class="tblock">` | **제목(`<p class="cap">`)·표·출처(`<p class="src">`) 를 한 덩어리로 묶는다** — 안 묶으면 쪽이 넘어갈 때 출처만 앞 쪽에 남아 어느 표의 근거인지 알 수 없게 된다 |
| `<table>` | 비교·매핑 표 (좌측 정렬) |
| `<table class="truth">` | 진리표·상태표. 가운데 정렬 + 고정폭 숫자로 열이 눈에 잡힌다. 신호명 등 문자열 셀만 `<td class="io">` 로 좌측 정렬 |
| `<span class="tok">` | 본문 속 IC·핀 번호처럼 교안과 대조하며 읽는 토큰 (`74HC08`, `pin 7`) |
| `<span class="ov">` | 부울식 오버바 (§8.2 의 R5 규칙) |
| `<p class="aside">` | 말미의 "이번 프리뷰에서 다루지 않은 항목: …" 한 줄 |
| `<div class="page-break">` | 강제 쪽 나눔 (거의 쓸 일 없다) |

- 옴(Ω) 등 기호는 HTML 엔티티(`&#937;`) 또는 유니코드로
- 다루지 않은 메뉴 섹션이 있으면 말미에 `<p class="aside">` 로 한 줄

### 8.4 변환·산출

1. §8.2 의 python 호출로 오늘 날짜·과목명·`chrome` 경로를 얻는다.
2. template 치환 → `Write` 로 `<실험NN>/output/<실험NN>_실험프리뷰.html` 저장.
3. PDF 변환:

   ```bash
   python3 -c "
   from pathlib import Path
   from scripts.lab import config
   from scripts.lab.html2pdf import DEFAULT_CHROME, html_to_pdf
   info = config.load_course_info(config.find_project_root(Path('.')))
   html_to_pdf('<실험NN>/output/<실험NN>_실험프리뷰.html',
               '<실험NN>/output/<실험NN>_실험프리뷰.pdf',
               chrome=info.get('chrome') or DEFAULT_CHROME)
   "
   ```

   **`chrome=` 를 반드시 넘긴다** — 안 넘기면 `과목정보.md` 의 `chrome` 필드가 선언만 되고 아무 효과가 없다 (⑥ 표지 · ② 체크리스트와 같은 규칙이다). 실패하면 에러를 그대로 보여주고 **HTML 은 남긴다.**
4. **덮어쓰기**: 기존 html/pdf 가 있어도 본인 산출물이므로 확인 없이 덮어쓴다 (② 체크리스트 관례).
5. **AI 활용 로그.** `과목정보.md` 의 `ai_usage_log` 가 `~` 가 아니면 그 경로에 한 줄 추가한다(⑥·③·④ 와 같은 규칙). `~` 면 아무것도 하지 않는다. 이 스킬도 저장소 안에 PDF 를 만드므로(§8) 빠뜨리면 그 값이 채워지는 순간 로그가 조용히 불완전해진다.
6. 생성된 html·pdf 의 markdown 링크를 한 줄로 출력.
