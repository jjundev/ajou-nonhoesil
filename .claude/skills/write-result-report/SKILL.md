# write-result-report

③ `write-pre-report` 의 사후(事後) 짝이다. ③이 "무엇을 예상하는가"를 쓴다면
이 스킬은 "실제로 무엇이 일어났는가"를 쓴다. 재료는 지어내는 것이 아니라
**`기록.md` 확인 칸 + 실험사진 + 종료 메모**에서 그대로 옮기는 것이다.

## 절대 규칙

서식 규칙 열 가지(7~9·11~16·18)는 번호와 굵은 첫 문장만 여기 있고 본문은
`.claude/보고서서식.md` 에 있다. §실행 절차 4 가 그 파일을 읽힌다.

1. **`기록.md` 의 확인 칸도 실험 사진(행 사진·스텝표·파형 사진)도 없으면 결과
   표를 만들지 않고 멈춘다.** 실험을 아직 하지 않았다는 신호이지, 예상값으로 대신 채울 자리가
   아니다. (§실행 절차 2가 이 판정을 가장 먼저 한다.) 단, 확인 칸이 비어도
   `<실험NN>/실험사진/` 에 행 사진(`<항목> <입력비트>.jpg`)이 있으면 멈추지 않고
   §실행 절차 3 의 사진 전사로 간다 — 확인 칸 대신 사진만 찍는 것도 정식 경로다.
   스텝표·파형 사진(`<항목> <표ID> <설명>.jpg`)만 있는 주차도 멈추지 않는다
   (§실행 절차 2).
2. **섹션 목록을 이 문서에 적지 않는다.** `.claude/보고서양식.md` 에서 읽는다.
   양식은 연도마다·학생마다 다르고 이번 학기 것이 미확정이다 (R1).
3. **불확실한 vision 전사를 자동 확정하지 않는다.** 목록으로 제시하고
   사용자가 정한다 — 체크 표시와 숫자는 판독기에서 혼동하기 쉽다.
4. **고찰을 지어내지 않는다.** `기록.md` 끝의 종료 메모 4문항이 재료다.
   비어 있으면 실험 폴더의 자유 메모 파일을 후보로 제시하고(§실행 절차 7),
   그것도 없으면 만들지 말고 사용자에게 묻는다.
5. **일치한 척하지 않는다.** `✓` 행은 예상값을 그대로 옮기고, 불일치 행은
   **실제 관찰값**으로 채운 뒤 본문에서 둘을 구분해 서술한다.
5b. **표 아래에 `> 출처:` 인용 블록을 줄줄이 달지 않는다.** 실제 결과보고서
    제출본(`160314`) 에도 표에 출처 각주를 단 것은 하나도 없다 — 이 장르에
    없는 장치다. 표마다 같은 자리에 같은 모양의 블록이 반복되면
    채점자가 글을 읽기도 전에 그 무늬를 먼저 본다. 근거가 필요하면 표 제목줄이나
    앞뒤 산문에 녹인다. 특히 **"직접 계산했다"·"직접 측정했다" 류의 서술을
    금지한다** — 자기가 한 일을 각주로 증명하는 학생은 없다. 그 문장은 베끼지
    않았음을 입증해야 하는 처지에서만 나오고, 그 처지를 드러내는 순간 의심을
    부른다 (§절대 규칙 8).
6. **없는 퀴즈 문제를 지어내지 않는다.** 양식이 요구할 때만 생성하고, 입력은
   그 주 실제 문제뿐이다. 없으면 요청하고 멈춘다.
7. **본문에서 그 주 실습 자료는 `강의노트`라 부른다.**
   본문은 `.claude/보고서서식.md` §강의노트 호칭.
8. **생성형 AI 를 써도 되지만 티가 나면 안 된다.**
   본문은 `.claude/보고서서식.md` §AI 티.

   이 보고서에서는: v3 는 칩 불량 경위를 결과 표 아래·결과 분석·고찰·추가 공부
   네 곳에 거의 같은 두 문장으로 적었다. 원인이면 결과 분석에 두고, 다른 절은
   "결과 분석에 적었다" 처럼 가리킨다. 고찰은 종료 메모 그대로가
   재료이지만(§절대 규칙 4) 다른 절과 겹치는 문장은 빼도 된다.
9. **강의노트 외의 다른 파일은 본문에서 언급하지 않는다.**
   본문은 `.claude/보고서서식.md` §다른 파일 언급.
10. **출처 및 참고문헌 = 기본 목록 + 추가 공부에서 실제로 연 문헌.** 교집합
    프리셋의 결과보고서는 맨 뒤에 `# 출처 및 참고문헌` 대절을 둔다(2026-09-12,
    실험01 결보 v2 되읽기에서 사용자가 추가 공부 절 안의 불릿을 빼서
    독립시켰다 — 예비보고서와 같은 자리·같은 이름이다). 다른 절 안에 참고문헌
    불릿을 두지 않는다. 목록은 두 층이다.

    - **기본 목록은 항상 싣는다** — 그 주 예비보고서의 참고문헌과 같다:
      `- 논리회로실험 강의노트` 한 줄, IC 특성 분석 가이드, 그리고 **명세
      `ics` 에 있는 IC 전부**의 제조사 데이터시트. 결과보고서는 예비보고서의
      결선·핀 배치·예상값 위에 쓰는 문서라 그 근거를 전부 물려받는다. ⑤
      `validate.check_report_references` 가 IC 마다 인용 줄을 요구하고 그
      규칙에 테스트가 붙어 있다 — 이 절이 그 검사와 다른 말을 하면 ④ 가
      만든 보고서는 ⑤ 에서 반드시 떨어진다(실험01 결보 v2 가 실제로 그랬다:
      추가 공부에서 연 74HC08 하나만 실어 error 5건).
    - **추가 공부에서 새로 찾은 외부 문헌은 실제로 연 것만 잇는다** — 이
      스킬이 도는 세션에서 내려받아 표를 읽은 것만 인용하고, 열지 못한 문헌은
      이름을 대지 않는다. 확인하지 못한 근거가 필요해지면 지어내거나 조용히
      단정하지 말고 "실물 IC 로 확인이 필요하다"고 밝힌다(없는 근거를 지어내지
      않는다는 원칙은 ③ §절대 규칙 5 와 같다).

    **형식은 ③ §절대 규칙 9 와 같다**: 데이터시트는 `.claude/데이터시트_출처.md`
    「인용 형식」 절에 적힌 대로 제조사·문서번호·개정·발행일·URL 을 갖추고, 2차 미러
    (alldatasheet·네이버·블로그)는 올리지 않는다.
11. **목차 블록을 문서 맨 앞에 넣는다.**
    본문은 `.claude/보고서서식.md` §목차 블록.

    이 보고서에서는: `table_of_contents`·`empty-block` 은 §실행 절차 5 의
    "원시 HTML 태그를 쓰지 않는다" 의 예외다.
12. **헤딩에서 번호를 빼고 한 단계 올린다.**
    본문은 `.claude/보고서서식.md` §헤딩.

    이 보고서에서는: `repeat: per-item` 프리셋에서 항목마다 반복되는 헤딩도
    마찬가지다 — §repeat 처리 절 참고.
13. **대절·소절 앞에 여백 블록을 둔다.**
    본문은 `.claude/보고서서식.md` §여백 블록.
14. **표에 캡션이 있으면 불릿 제목으로 바꾸고 표를 탭으로 들여쓴다.**
    본문은 `.claude/보고서서식.md` §표 캡션.

    이 보고서에서는: 공용 예시(`- **AND** (…)`)는 예비보고서 모양이다. 결과 표의
    불릿 제목은 아래처럼 표 이름으로 쓴다.

    ```
    - **3-input AND 진리표**
    	| A | B | C | L1 | L2 |
    	|---|---|---|---|---|
    	…
    ```
15. **표 뒤에 표가 이미 말하는 관찰 문장을 붙이지 않는다.**
    본문은 `.claude/보고서서식.md` §관찰 문장.

    이 보고서에서는: 표가 말하지 않는 새 정보의 서술 골격은 §실행 절차 6 이다.
16. **"~는 다음과 같다" 류로 표를 예고하지 않는다.**
    본문은 `.claude/보고서서식.md` §표 예고.
17. **준비물에는 있으나 그 주 회로에 쓰지 않는 소자를 본문에서 다루지
    않는다는 규칙(③ `write-pre-report` §절대 규칙 16)은 이 스킬에는 해당
    없다.**
    결과보고서 프리셋에는 실험 부품/준비물 섹션이 없고, `기록.md` 의 확인
    칸도 그 주 회로에 실제로 쓰인 항목에만 생기므로 애초에 다룰 자리가
    생기지 않는다. **수량도 같다** — 결과보고서 프리셋에 준비물 표가
    생기면, 강의노트 준비물이 회로가 실제 쓰는 것보다 많이 잡아 두었을 때
    **표의 수량은 강의노트대로 두고** 비고에 사실만 적는다. 예: 74HC04
    2개 — 인버터가 한 칩에 6개라 두 단 모두 한 칩으로 잡힌다.
18. **숫자·영문·기호 뒤 조사와 숫자 뒤 단위는 붙여 쓴다.**
    본문은 `.claude/보고서서식.md` §붙여쓰기.
19. **결과 표 머리와 산문 속 회로 신호 이름은 명세 열 이름 그대로 쓴다.** 명세
    기록표의 열 이름·열 수·열 순서를 옮기고(③ §절대 규칙 22 와 같다), 추가 공부처럼
    산문에서 회로 신호를 부를 때도 `L1`·`L2` 같은 명세 이름을 쓴다 — `Y`·`P` 처럼
    새 이름을 짓지 않는다. 2026-09 실험01 예보가 회로도 출력 `L1`·`L2` 를 `Y` 로
    바꿔 조교 감점(-1)을 받았고, 같은 실험 결보의 추가 공부는 3입력 AND 의 신호를
    `P`·`Y` 로 불렀다. 표 머리는 12단계의 `check_report_tables(…, cells=False)` 가
    잡고, 산문은 기계 검사가 없다.

## 실행 절차

0. **실험 번호를 폴더 이름으로 옮긴다.** 사용자는 "실험1 …" 또는 "다음 실험 …"
   으로 부르고, 아래 절차의 경로는 `<실험NN>/` 이다. 손으로 `실험1` 이라고
   적지 않는다 — 0 을 안 채우면 `실험10` 이 `실험2` 앞에 정렬된다.

   ```bash
   python3 -c "
   from scripts.lab import config
   print(config.experiment_dir(<실험번호>))
   "
   ```

   **"다음 실험" 처럼 날짜로 물었으면** 아래로 찾는다. 한 날에 실험이 둘일 수
   있어 리스트가 온다(9/18 은 실험2·3 이다).

   ```bash
   python3 -c "
   from scripts.lab import config
   print(config.next_experiments())
   "
   ```

   `None` 이면 학기가 끝난 것이다. FPGA 프로젝트(11/27~12/11)는 실험 번호가
   없어 `config.PROJECT_DIR` 로 간다.

   **주차로 불렸으면**("2주차 결과보고서" 처럼) 아래로 옮긴다. 한 날에
   실험이 둘일 수 있어 리스트가 온다.

   ```bash
   python3 -c "
   from scripts.lab import config
   print(config.experiments_in_week(<N>))
   "
   ```

   - 빈 리스트인데 `config.is_project_week(<N>)` 가 참이면 FPGA 프로젝트
     주차(13~15주차)다. 실험 번호가 없어 `config.PROJECT_DIR` 로 간다.
   - 빈 리스트이고 거짓이면 그 주엔 실험이 없다(1주차 오리엔테이션·4주차
     추석·8주차 중간고사). 그대로 알리고 중단한다.
   - 둘 이상이면 **어느 쪽인지 되묻고 중단한다.** 한 날에 실험이 둘인
     주차가 있고, 그날 안에 둘 다 마쳐야 하므로 두 벌이 다 필요할 수도
     있다.
   - 하나면 그 번호로 위 `config.experiment_dir()` 을 부른다.

1. **실험 폴더·명세·기록.md 확인.** `<실험NN>/체크리스트/기록.md` 가 없으면
   **거절**하고 ② `prep-lab-checklist` 를 안내한다(기록.md 는 명세에서
   기계적으로 파생되므로, 명세가 없으면 그보다 먼저 그것부터). **기록.md 를
   이 스킬이 대신 만들지 않는다.**

1b. **명세·결선도 검증 (②·③과 같은 게이트).** 결과보고서는 명세의 예상값을
    "예비 비교"·"결과 분석" 절의 기준선으로 그대로 쓴다 — 명세 자체가 깨져
    있으면(예: derived 식과 표가 안 맞음, source 누락) 그 위에 쓰는 비교·분석이
    잘못된 기준과 맞대는 셈이다.

    ```bash
    python3 -c "
    from scripts.lab.spec_parser import parse_spec
    from scripts.lab import validate
    spec = parse_spec('<실험NN>/체크리스트/명세.md')
    findings = (validate.validate_spec(spec)
                + validate.check_netlist('<실험NN>/결선도/netlist.md', spec))
    print('\n'.join(str(f) for f in findings) or '문제 없음')
    "
    ```

    **error 가 있으면 작성을 멈추고 보고한 뒤 사용자 판단을 기다린다.** warn 은
    알리고 진행한다.

2. **기록.md 상태 판정 — 확인 칸도 실험 사진(행 사진·스텝표·파형 사진)도 없으면 여기서 멈춘다.** 명세·기록을 같이 읽어
   확인 칸이 실제로 몇 개 채워졌는지 센다.

   ```bash
   python3 -c "
   from pathlib import Path
   from scripts.lab import config, md
   root = config.find_project_root(Path('.'))
   fmt = config.load_report_format(root)
   print('결보 섹션:', [(s.name, s.repeat, s.generate) for s in fmt.result])
   text = Path('<실험NN>/체크리스트/기록.md').read_text(encoding='utf-8')
   front, body = md.split_frontmatter(text)
   print('filled_by:', front['filled_by'])
   checks = [r[-1] for t in md.parse_tables(body) for r in t.rows]
   print('확인 칸 총', len(checks), '개 / 채워진 것', sum(1 for c in checks if c.strip()))
   "
   ```

   판정은 **`filled_by` 필드가 아니라 실제로 채워진 칸 개수**로 한다 —
   메타데이터는 갱신을 잊을 수 있지만 빈 칸은 거짓말을 못 한다.

   - **채워진 칸이 0개인데 행 사진이 있으면** 멈추지 않고 3단계의 사진 전사로
     간다. 아래로 센다(`행 사진` 이 빈 목록이면 사진이 없는 것이다). `규칙 밖`
     은 규칙에 맞지 않는 이미지 파일이다(스텝표·파형 사진 `<항목> <표ID> <설명>.jpg`
     는 빼고 센다).

     ```bash
     python3 -c "
     from pathlib import Path
     from scripts.lab import config
     from scripts.lab.photo_names import FILE, SIDE
     d = Path(config.experiment_dir(<실험번호>)) / '실험사진'
     imgs = sorted(p.name for p in d.iterdir() if p.suffix.lower() in ('.jpg', '.jpeg', '.png')) if d.is_dir() else []
     print('행 사진:', [n for n in imgs if FILE.match(n)] if d.is_dir() else '사진 폴더 없음')
     print('스텝표·파형 사진:', [n for n in imgs if not FILE.match(n) and SIDE.match(n)])
     print('규칙 밖:', [n for n in imgs if not FILE.match(n) and not SIDE.match(n)])
     "
     ```

   - **채워진 칸이 0개이고 행 사진은 없는데 규칙 밖 이름의 이미지 파일이 있으면**
     "실험을 진행하지 않았다" 로 보고하지 않는다 — 사진을 찍었는데 이름만 어긋난
     것이다(실험02 는 `실험02 1-1 …` 처럼 접두어를 붙였다). 그 파일 목록을 사용자에게
     보여 주고, 규칙(진리표 행 사진은 `<항목> <입력비트>.jpg`, 예 `1-2 000.jpg` —
     앞에 실험 번호를 붙이지 않는다)을 인용한 뒤 이름을 바꿀지 묻는다. 이름을
     바꾸면 행 사진이 생긴 것이므로 위 분기로 간다. 이름을 스스로 바꾸지 않는다.

   - **채워진 칸이 0개이고 행 사진은 없는데 스텝표·파형 사진이 있으면**
     "실험을 진행하지 않았다" 로 보고하지 않는다 — 진리표가 없는 주차(실험02 는
     capture 표뿐이었다)는 확인 칸도 행 사진도 생기지 않는다. 위 `스텝표·파형 사진`
     목록을 사용자에게 보여 주고 진행한다.
     - `capture` 표는 사진 자체가 결과이므로 4단계부터 이어 간다(6단계의 kind 표대로).
     - `stepped` 표의 빈 칸은 사진에서 값을 읽어 **칸마다 사용자 확인을 받거나**,
       사용자에게 값을 묻는다. 추측으로 채우지 않는다.

   - **채워진 칸이 0개이고 행 사진도 스텝표·파형 사진도 없으면**(규칙 밖 이름의 이미지 파일도 없으면)
     결과 표를 만들지 말고 다음과 같이 보고하고
     **완전히 멈춘다.** md·html·pdf 어느 것도 만들지 않는다.

     > `<실험NN>/체크리스트/기록.md` 의 확인 칸이 전부 비어 있습니다(채워진
     > 칸 0개, `filled_by: 미기입`). 아직 실험을 진행하지 않으신 것 같습니다
     > — 이 상태로는 결과보고서를 쓸 수 없습니다. 실험을 마치고 `기록.md`
     > 를 채우신 뒤(또는 필기한 PDF 를 알려주시면 제가 vision 으로 옮겨
     > 적겠습니다) 다시 불러주세요.

   - **하나라도 채워졌으면** 3단계(vision 전사가 아직 필요하면) 또는 4단계로
     진행한다. 일부 표만 채워진 상태(실험을 중간까지만 했다)도 정상 입력이다
     — 5단계가 셀 단위로 처리한다.

3. **vision 전사 (필기 PDF 가 있거나, 행 사진이 찍힌 행에 빈 확인 칸이 있을 때만).** **필기 PDF 경로는 스스로
   추측하지 않는다** — 태블릿 필기 산출물의 파일명 관례가 아직 정해져 있지
   않다. 사용자가 경로를 주면 그것을 쓰고, 안 주면 `<실험NN>/체크리스트/`
   안에서 `명세.md`·`기록.md`·`체크리스트.html`·`체크리스트.pdf` 를 제외한
   PDF 를 후보로 찾아 제시한다. 후보가 없고 행 사진(`<항목> <입력비트>.jpg`)도
   없으면 "필기 PDF 를 찾지 못했다" 고 보고하고 경로를 요청한다(2단계의 멈춤과
   별개로, 확인 칸이 이미 일부 채워진 채 이번 세션에서 추가로 옮길 필기가 있는
   경우다). 필기 PDF 가 없을 때, 사진이 찍힌 행에 아직 빈 확인 칸이 있으면 아래 사진 전사로 간다.
   사진이 찍힌 행의 확인 칸이 이미 전부 채워졌으면 사진에서 옮길 것이 없으므로
   전사를 건너뛰고 4단계로 간다 — 행 사진이 있다는 것만으로 사진 전사에 들어가지
   않는다. 아래로 사진마다 그 행의 확인 칸이 비었는지 본다.

   ```bash
   python3 -c "
   from pathlib import Path
   from scripts.lab import config
   from scripts.lab.contact_sheet import load_records
   from scripts.lab.photo_names import FILE
   exp = Path(config.experiment_dir(<실험번호>))
   recs = {r.token: r for r in load_records(exp / '체크리스트/기록.md')}
   for p in sorted((exp / '실험사진').iterdir()):
       m = FILE.match(p.name)
       if not m:
           continue
       rec = recs.get(m['item'])
       row = rec.rows.get(m['bits']) if rec else None
       state = '기록에 없는 행' if row is None else ('빈 칸' if not row[1] else '채워짐: ' + row[1])
       print(p.name, '→', state)
   "
   ```

   PDF 를 읽어 각 표의 확인 칸을 채운다.

   - **체크 표시(`✓`)와 숫자·문자를 혼동하기 쉽다** — ②
     `prep-lab-checklist` 가 `기록.md` 를 만들 때 확인 칸을 넓게 잡아 둔
     것이 이 구분을 돕기 위한 것이다. 그래도 판독이 애매한 칸은 **자동
     확정하지 않는다.**
   - 애매한 칸을 아래 형식으로 모아 제시하고 사용자 확정을 기다린다.

     ```markdown
     아래 3칸은 판독이 불확실합니다. 확인해 주세요.

     | 표 | 행 | 읽은 값 | 대안 |
     |---|---|---|---|
     | T1 | 5 | `✓` | `1` |
     | T3 | 2 | `0` | `✓` |
     ```

   - 표를 통째로 진행하지 않았으면 그 표 아래에 `- 실험을 진행하지 않았음.`
     을 적는다(기록.md 자체의 표기 규약).
   - 확정되면 `기록.md` 를 갱신하고 프론트매터의 `filled_by:` 를 `vision`
     으로 바꾼다.

   **필기 PDF 가 없고 행 사진만 있으면 사진에서 전사한다** (2026-09-19 정식 경로로
   인정 — 실험03 은 확인 칸을 손으로 채우지 않고 행 사진만 찍었다).

   - 입력 조합은 **파일명에서만** 읽는다(`1-2 011.jpg` → 그 표의 입력 열 순서로
     A=0·B=1·Ci=1). 사진 속 스위치 위치로 입력을 읽지 않는다.
   - 사진에서는 LED 상태만 판독한다. 예상값과 같으면 `✓`, 다르면 관찰값을 적는다.
   - 사진 전사는 빈 칸만 대상이다. 이미 채워진 칸은 덮어쓰지 않고, 사진 판독이
     다르면 두 값을 나란히 제시해 사용자가 정한다.
   - 사진이 없는 행은 공란으로 둔다 — 시험하지 않은 행이다. 예상값으로 채우지 않는다.
   - 사진이 한 장도 없는 표는 진행 여부를 사용자에게 묻고, 진행하지 않았으면 그 표
     아래에 `- 실험을 진행하지 않았음.` 을 적는다.
   - 애매한 칸만이 아니라 **모든 칸**을 위 판독 표 형식으로 한 번에 제시하고 사용자
     확정을 받는다 — 어둡게 켜진 LED 를 꺼짐으로 읽기 쉽다.
   - 확정되면 `기록.md` 를 갱신하고 `filled_by:` 를 `vision` 으로 바꾼다. 이 기록으로
     `export-photo-sheet` 를 돌리면 그 스킬의 사진 대조는 같은 출처를 다시 읽는
     재확인이다.

5. **결과 표 구성.** 명세와 기록을 같이 읽어 항목마다 결과 표를 만든다.
   `기록.md` 의 표는 `md.parse_tables` 로, 원래 예상값·kind 는
   `spec_parser.parse_spec` 으로 얻는다(같은 표 ID 로 둘을 대응시킨다).
   `role: reference` 표(예: 실험1 T6~T10)는 애초에 기록.md 에도 없으므로
   다룰 필요가 없다.

   | 확인 칸 | 결과 표 | 본문 서술 |
   |---|---|---|
   | `✓` | 예상값을 그대로 | "예상과 일치" (행을 일일이 나열하지 않는다) |
   | 값 | **그 실제 관찰값**으로 | **행을 지목해 원인을 논한다** |
   | 공란 | `(미확인)` 으로 채운다 | "미확인" 으로 명시 |
   | 표 전체 미진행 | 표 생략 | "실험을 진행하지 않았음" 을 명시 |
   | 표 전체 공란 + 마커 없음 | 표를 싣되 전 행 `(미확인)` | 마커를 빠뜨린 것인지 사용자에게 확인 |

   표 전체 미진행 여부는 `md.parse_tables` 가 돌려주는 `MdTable.line`
   (표 구분선 줄 번호, 1-based)부터 다음 헤딩까지의 **`body`** — 즉
   `split_frontmatter` 가 돌려준 둘째 값 — 에 `실험을 진행하지 않았음`
   문자열이 있는지로 판단한다. `parse_tables` 자체는 표 그리드만 주고 표
   아래 산문은 주지 않으므로 그 구간은 직접 훑어야 하는데, **`text` 를 훑으면
   프론트매터 줄 수만큼 어긋난다** — `기록.md` 에서는 7줄이다.

   **결과 표에서 세 경우를 표기로 구분한다** — 불일치 셀은 관찰값을
   `**굵게**` 쓰고, 공란(미확인) 셀은 `(미확인)` 으로 채운다. `✓` 행(예상과
   일치)은 평범한 셀로 둔다. 셋이 표 안에서 구별돼야 "전부 일치한 표"처럼
   보이지 않는다.

   **원시 HTML 태그를 쓰지 않는다.** 이 md 는 그대로 노션에 올라가 그대로
   제출본이 되는데, 노션은 원시 HTML 을 옮기지 못한다 — ⑦ 의 업로드 전
   검사(`validate.check_notion_markdown`)가 이것을 error 로 잡는다. **예외:
   `<table_of_contents color="gray"/>` 와 `<empty-block/>` 은 원시 HTML 이
   아니라 노션이 입력으로도 받는 자체 블록 태그다(§절대 규칙 11·13)** — 이
   둘은 쓴다. 표 캡션·여백은 §절대 규칙 13·14 를 따른다.

   **일치와 불일치를 본문에서 구분해 서술한다. 전부 일치한 척하지 않는다.**
   불일치 행이 하나도 없으면 그렇게 쓰고, 있으면 6단계(kind 별 서술
   골격)대로 원인을 논한다.

   **출력이 `Q(t-1)` 처럼 상태 유지를 뜻하는 토큰(실험6)이면** `✓` 는 특정
   비트가 아니라 "이전 상태를 그대로 유지했다"는 뜻이다 — 고정값 일치와
   혼동하지 않고 그렇게 풀어 쓴다. 입력에 `x`(don't-care) 가 있는 행은 여러
   조합을 대표한다는 점을 밝힌다.

6. **kind 별 서술 골격.**

   | kind | 골격 |
   |---|---|
   | `truth-table` | 전부 일치면 일치를 한 문장으로 말하고, 표가 못 보여 주는 관찰을 한두 문장 더한다 — 중간단·최종단 LED 가 어느 조합에서 어떤 순서로 켜졌는지, 시험하지 못한 행이 있으면 무엇을 못 봤는지(승인본 실험01: "A=B=1, C=0에서 중간단 LED만 켜지고 최종단은 꺼져 있다가, C를 1로 올리자 최종단까지 켜지는 것으로 두 단이 제대로 이어졌음을 확인했다"). 표 값을 다시 읽어 주는 문장(§절대 규칙 15)과는 다르다 — 표는 값을, 이 문장은 눈으로 본 과정을 말한다. 이 서술은 실험 사진 절이 아니라 여기 둔다. **관찰 서술은 `기록.md` 의 ✓ 행 사이의 전이만 말한다** — 시험하지 않은 행을 거치는 전이("C만 1인 채로 A를 올리자"가 101 을 함축)나 시험하지 않은 행까지 덮는 일반화("어느 하나만 1로 올려도")를 쓰지 않는다. 승인본 실험01 은 "C만 1인 경우와 B만 1인 경우를 각각 넣어" 처럼 시험한 행만 짚는다(2026-09-12 격리 2회차에서 두 번 나온 부작용). 불일치는 **행을 지목**하고 원인 후보(플로팅 입력·배선 오류·IC 불량)를 논한다 |
   | `stepped` | "N번째 클럭/펄스에서 천이했다" — 스텝 진행 자체가 결과다. 명세에 예상 열이 없는 표(실험10 T2 처럼 정답이 안 주어지는 경우)는 확인 칸이 "그 스텝을 정상 수행했는가"에 가깝다 — 비교 대상이 있는 표와 서술을 구분한다 |
   | `capture` | 사진 + 관찰 서술. 명세의 `expected` 산문과 대조한다 |

7. **고찰.** 재료는 `기록.md` 끝 "# 실험 종료 메모" 의 4문항이다: 막혔던
   것 / 예상과 달랐던 것 / 뭘 바꿔서 해결했나 / 새로 안 것.

   `실험보고서 평가기준.txt`(권위 2순위)는 고찰을 "실험으로부터 배운점,
   목적 달성 여부"로 규정한다 — 4문항은 이미 그 틀에 대응한다: 막힘·예상과
   다름·해결 과정이 "배운 점"의 재료이고, 5단계의 일치·불일치 결과가 "목적
   달성 여부"의 재료다. **답변 내용 자체를 지어내지 않는다** — 서술 순서를
   재구성할 뿐이다.

   **순서는 목적 달성 여부 문단으로 열고, 그 뒤에 4문항 순서(막힘 → 예상과
   다름 → 해결 → 새로 안 것)로 잇는다.** 승인본 실험01 이 이 순서다 — 2026-09-12
   격리 1회차의 재생성은 목적 달성 문단을 맨 끝에 두어 갈렸다. 첫 문단은 5단계의
   일치·불일치 결과를 한두 문장으로 요약해 "목적을 달성했다고 본다/못 봤다" 로
   맺는다.
   다만 메모 원문의 표 ID·파일명은 그 표가 무엇인지 가리키는 말로 바꿔 적는다
   (§절대 규칙 9). 그 밖의 내용은 손대지 않는다.

   **메모의 인과 주장은 옮기기 전에 표·결선과 맞춰 본다.** 메모가 "~때문에",
   "~가 원인" 이라고 적은 문장은 사실이 아니라 실험 직후의 추정이고, 결과
   표·`netlist.md` 와 어긋날 수 있다. 어긋나면 그대로 옮기지 않고 어긋나는
   지점을 짚어 사용자에게 묻는다. 확정되면 **`기록.md` 메모를 먼저 고치고**
   보고서는 거기서 파생한다 — 보고서만 고치면 다음 재생성 때 모순이
   되살아난다. 실험01 결보 v2 에서 실제로 났다: 메모의 "칩 사전 시험에서
   11 을 안 넣어서 놓쳤다" 는 문제 조합(A=B=1)이 74HC08 에 넣는 입력이
   01 이고 앞선 항목에서 이미 11 을 시험했다는 표·결선 사실과 부딪쳤는데,
   고찰·결과 분석·추가 공부 세 절이 그 전제를 그대로 물려받았다. 이 대조는
   §절대 규칙 4(지어내지 않는다)와 충돌하지 않는다 — 사실을 바꾸는 것이
   아니라 확인하는 것이다.

   **대조는 결선표의 게이트·핀 단위까지 내려간다.** "같은 칩" 이 아니라
   "같은 칩의 어느 게이트, 어느 핀에 어느 신호" 를 예비보고서 결선표에서
   읽고, 앞 항목에서 그 게이트에 실제로 들어간 입력 조합(`기록.md` 의 ✓
   행)과 맞춘다. 실험01 v3 에서 "이 불량은 고착 모델 밖" 이라는 결론이 근거
   없이 서 있었는데, 결선표를 대조하니 증상에 맞는 고착 고장(핀 1 고착-1)이
   2-1 의 011 에서 드러났어야 한다는 사실이 나와 그것이 근거가 됐다. 배선이
   계획과 같았는지는 사용자에게 한 번 확인한다.

   **4문항이 비어 있고 자유 메모 파일이 있으면 그것이 재료다** (2026-09-19 —
   실험03 은 실험 뒤 메모를 `실험중있었던일.md` 에 자유 형식으로 적었다). 후보는
   `<실험NN>/` 최상위의 `.md` 파일이다. 스스로 하나를 골라 쓰지 않고 후보를 제시해
   사용자가 고르게 한다. 고른 파일의 문장을 4문항에 대응시킨 표(`| 문항 | 메모에서
   옮긴 문장 |`)를 보여 주고, 어느 문항에도 안 맞는 문장은 따로 표시한다. 문장을
   요약하거나 윤색하지 않는다. 확정되면 **`기록.md` 종료 메모를 먼저 채우고** 고찰은
   거기서 파생한다 — 위의 인과 대조 규칙과 같은 이유다(보고서만 고치면 다음 재생성
   때 어긋난다).

   **4문항이 전부 공란이고 자유 메모 파일도 없으면 만들지 말고 사용자에게 묻는다.**
   **중단 범위: 이 섹션만이다.** 보고서 전체를 멈추지 않는다 — 퀴즈 섹션과
   같은 규칙이다(§절대 규칙 6). 나머지 섹션은 계속 쓰고, 고찰 자리는 비운 채
   무엇을 물었는지 한 줄로 남긴다. 기록 자체가 비어 있을 때만(§절대 규칙 1)
   보고서 전체를 만들지 않는다. 예:

   > `기록.md` 종료 메모 4문항이 비어 있습니다. 고찰은 본인 경험이 재료라
   > 제가 대신 지어낼 수 없습니다 — 막혔던 것, 예상과 달랐던 것, 뭘 바꿔서
   > 해결했는지, 새로 안 것을 알려주시면 그대로 옮겨 쓰겠습니다.

   `repeat: per-item` 프리셋에서는 §repeat 처리 절을 따른다.

8. **퀴즈 해설 섹션.** `fmt.result` 에서 "퀴즈문제에 대한 해설" 섹션의
   `generate` 를 먼저 본다.

   - **`generate: false`(교집합 프리셋의 오늘 기본값)면 만들지 않는다.**
     `<실험NN>/퀴즈/` 를 들여다볼 필요도 없다.
   - **`generate: true` 가 되면:** `<실험NN>/퀴즈/` 에서 **그 주 실제
     문제**를 찾는다. 없으면 "이번 주 퀴즈 문제 원본을 찾지 못했다" 고
     보고하고 요청한 뒤, 이 섹션은 헤딩까지 함께 뺀다 — 헤딩만 남기고
     내용을 비우면 12단계의 `check_report_sections` 는 절 이름만 대조하므로
     error 를 내지 않아, 빈 섹션이 그대로 제출된다. 나머지 섹션은 계속
     작성한다 — 퀴즈 하나 때문에 이미 완성된 다른 절까지 버리지 않는다.
     12단계 검증에서 이 섹션 누락이 error 로 잡히고, 그 라운드 문서에 "퀴즈
     원본 대기 중"이라고 적어 둔다.
   - 문제 원본이 있으면 그 원문을 그대로 인용하고,
     `from_the_past/정리/퀴즈/실험N/` 의 같은 유형 기출·정답과 강의노트를
     근거로 해설을 새로 쓴다. **해설 문단에는 이 자료들의 이름을 밝히지
     않는다** — 강의노트에서 확인한 내용은 강의노트로만 인용하고, 과거
     기출·정답 자료는 아예 언급하지 않는다(§절대 규칙 9). 문제 하나당
     `**문제 N.** <원문>` 한 줄과 그 아래 해설 문단으로 쓴다 —
     **HTML 태그로 감싸지 않는다**((1)과 같은 이유: 노션이 원시 HTML 을
     옮기지 못한다). **과거 정답을 그대로 베끼지 않는다** — 퀴즈는
     학기마다·분반마다 다르다(월요반과 금요반 문제지가 다르다). AI 활용은
     보고서·퀴즈·프로젝트 전부 승인됐으므로 정책 제약은 없다.

9. **md 저장.** `<실험NN>/output/<실험NN>_결과보고서.md` 에 쓴다. **이 md 가
   유일한 산출물이다** — HTML 로 옮기지 않는다 (11단계).

   **첫 헤딩(`# …`)은 손으로 짓지 않는다.**
   `config.document_title(<실험번호>, <명세의 title>, '결과보고서')` 이 유일한
   형식이다 (`실험1 Basic Gates 결과보고서`). **제목에 주차를 넣지 않는다** —
   주차는 폴더를 찾을 때만 쓴다 (0단계). 실험 번호는 폴더 이름(`실험01`)이
   아니라 **0 을 뺀 정수**다.

   ```bash
   python3 -c "
   from scripts.lab import config
   from scripts.lab.spec_parser import parse_spec
   s = parse_spec('<실험NN>/체크리스트/명세.md')
   print(config.document_title(s.experiment, s.title, '결과보고서'))
   "
   ```

   **이 규칙은 PDF 를 안 만들게 되면서 오히려 더 중요해졌다.** 노션은 마크다운의
   첫 `#` 헤딩을 그대로 페이지 제목으로 삼는다 — 여기서 틀리면 노션 페이지
   제목과 제출 PDF 제목이 한꺼번에 틀린다.

   이 헤딩 바로 다음이 목차 블록 자리다(§절대 규칙 11). 그 아래 본문 헤딩은
   번호 없이 대절 `#`·소절 `##` 로, 앞에는 여백 블록을 둔다(§절대 규칙
   12·13).

10. **조 편성 확인 → 표지 여부 분기 (판정만 한다).** 표지를 만들지도 합치지도
    않는다 — 11단계에서 다시 밝힌다.

    ```bash
    python3 -c "
    from pathlib import Path
    from scripts.lab import config
    info = config.load_course_info(config.find_project_root(Path('.')))
    print('미확정:', config.missing_identity(info) or '없음')
    "
    ```

    판정은 ⑥ `make-lab-report-cover` 1b 단계와 **같은 함수**를 쓴다 — 두 곳이
    따로 판정하면 한쪽만 고쳐지고 다른 쪽이 `None` 을 표지에 찍는다.

    - **`미확정: 없음` 이면(조 편성 확정):** ⑥ `make-lab-report-cover` 로 표지를
      만들 수 있다고 알린다. **이 스킬은 표지를 만들지도 합치지도 않는다.**
    - **하나라도 `~` 면(조 편성 미확정):** 조 편성이 확정돼야 표지를 만들 수
      있다고 알린다. **본문에는 아무 안내문도 넣지 않는다** — 이 md 는 그대로
      노션에 올라가고 그대로 제출본이 되므로, 하네스 사정을 적은 문장이 제출
      문서 첫 페이지에 찍힌다.

11. **PDF 를 만들지 않는다.** 이 스킬의 산출물은 `.md` 하나다.

    제출본은 사용자가 ⑦ `sync-report-to-notion` 으로 노션에 올린 뒤 노션에서
    PDF 로 내보내고, ⑥ `make-lab-report-cover` 가 만든 표지를 앞에 손으로 붙여
    만든다. **표지는 이 스킬의 관심사가 아니다.**

    예전에는 여기서 `template.html` 을 채워 Chrome 헤드리스로 PDF 를 내고
    `pypdf` 로 표지를 합쳤다. 그 경로에는 "본문 재렌더가 방금 합친 표지를 조용히
    덮어쓴다" 는 함정이 있었는데(③이 실제로 이 구조였다), PDF 를 아예 만들지
    않게 되면서 함정 자체가 사라졌다. `template.html` 은 되돌릴 경우를 위해
    남겨 두지만 이 절차는 쓰지 않는다.

12. **⑤ 로 검증하고 error 0 까지 반복한다.**

    ```bash
    python3 -c "
    from pathlib import Path
    from scripts.lab import config, validate
    from scripts.lab.spec_parser import parse_spec
    root = config.find_project_root(Path('.'))
    fmt = config.load_report_format(root)
    spec = parse_spec('<실험NN>/체크리스트/명세.md')
    rep = '<실험NN>/output/<실험NN>_결과보고서.md'
    for f in (validate.check_report_sections(rep, fmt.result, item_count=len(spec.items))
              + validate.check_report_references(rep, spec, root=root)
              + validate.check_notion_markdown(rep)
              + validate.check_body_style(Path(rep).read_text(encoding='utf-8'))
              + validate.check_result_photo_diagrams(Path(rep).read_text(encoding='utf-8'))
              + validate.check_report_tables(rep, spec, cells=False)):
        print(f)
    "
    ```

    **여섯 검사를 한꺼번에 돌린다.** `check_body_style` 은 warn 이지만 여기서
    고친다 — §절대 규칙 8·18 의 기계 검사판이라 남기면 그대로 노션에 올라간다.
    섹션만 보면 참고문헌 누락(§절대 규칙 10)은 ⑤ 에서야 걸린다 — 실험01
    결보 v2 가 그렇게 노션까지 올라간 뒤에 error 5건으로 돌아왔다.
    `check_notion_markdown` 은 ⑦ 이 업로드 전에 다시 돌리지만, 여기서 먼저
    잡아야 md 를 낸 세션 안에서 고칠 수 있다.
    `check_report_tables(…, cells=False)` 는 결과 표 머리가 명세 기록표 머리와 같은지만
    본다(§절대 규칙 19) — 결과 칸은 관측값이라 셀은 보지 않는다.

    `check_result_photo_diagrams` 는 실험 사진 절 항목 소절마다 예보 결선도가
    시트 앞에 있는지 warn 으로 본다(§사진 배치). 결선도를 구할 수 없던 주차라
    남기는 warn 이면 §실행 절차 14 결과 안내에 그 사정을 적는다.

    `item_count=len(spec.items)` 를 항상 넘긴다 — `repeat: per-item` 섹션이
    항목 수만큼 정확히 반복됐는지는 이 인자 없이는 검사되지 않는다. 출력이
    없으면 모든 섹션이 존재하는 것이다. **출력을 파일로 남기지 않는다** —
    error 0 이면 빈 파일이라 "검사했음"과 "안 했음"이 구별되지 않는다.
    누락이 나오면(퀴즈 원본 대기 등으로 못 채운 섹션 포함) 본문을 고치거나
    사용자 응답을 기다린 뒤 검증을 다시 돌린다 — 두 번째, 세 번째로 돌릴
    때도 같은 명령을 그대로 다시 쓸 뿐, 파일을 남기지 않는다.

13. `과목정보.md` 의 `ai_usage_log` 가 비어 있지 않으면(`None` 이 아니면) 그
    경로에 로그 한 줄을 남긴다. 비어 있으면 아무것도 하지 않는다.
    `config.load_course_info()` 는 YAML `~` 를 파이썬 `None` 으로 돌려주므로
    `!= '~'` 로 비교하면 항상 참이 되어 로그를 남긴다.

14. **결과 안내.** md 경로, 섹션 검증 결과(error 0 여부), 노션에서 손으로 끼울
    그림 수(시트 + 결선도 — `check_notion_markdown` 의 info 가 센다), 결선도를
    폴백으로 채웠거나 못 실은 항목(§사진 배치), 그리고 **다음 할 일**을
    한 줄로: `⑦ sync-report-to-notion` 으로 노션에 올린다.

## repeat: per-item 처리

`fmt.result` 의 어떤 Section 이든 `repeat == "per-item"` 이면, 그 이름의
헤딩이 `spec.items` 개수만큼 **반복해서** 나와야 한다 — 항목별 소제목으로
묶는 게 아니라 헤딩 자체가 반복된다. `check_report_sections(..., item_count=N)`
이 반복 횟수를 정확히 대조한다.

오늘의 교집합 프리셋에는 `repeat: per-item` 이 없다(전부 `None`). 실제로
나타나는 곳은 `항목반복형` 프리셋의 "결선도"·"구성한 회로"·"실험 결과"·"고찰"
4개다(마지막에 반복되지 않는 "전체적인 고찰" 이 한 번 더 온다).

- **"실험 결과"** 가 반복이면: 항목별 결과 표 + kind 별 서술(5·6단계)을 그
  항목 전용 헤딩 아래 싣는다.
- **"결선도"·"구성한 회로"** 가 반복이면: 그 항목의 `netlist.md` 해당 절 +
  그 항목의 완성 회로 사진(§사진 배치)을 싣는다. ③의 결선도 절과 재료는
  같고, "구성한 회로"만 결보 전용으로 **실제 사진**을 쓴다는 점이 다르다
  (③은 아직 찍지 않은 빈 브레드보드 템플릿을 쓴다).
- **"고찰"** 이 반복이면: 종료 메모 4문항은 원래 실험 전체에 대한 것이라
  항목별로 나뉘어 있지 않다. **임의로 쪼개 배정하지 않는다** — 메모가
  특정 항목을 명시하면 그 항목 아래 싣고, 아니면 "이 메모가 어느 항목
  얘기인지" 사용자에게 물어 확인한 뒤 배치한다. 마지막 "전체적인 고찰"에는
  4문항 전체를 종합해 싣는다(이건 나누지 않는다).

## 사진 배치

**"실험 사진" 절은 항목마다 예보 손그림 결선도 한 장 + 합성 시트다.** 시트는
`export-photo-sheet` 가 만든다 — 파일명 규칙, 캡션 도출, 사진 대조 절차는 전부
그 스킬에 있고 여기 되풀이하지 않는다. `<실험NN>/실험사진/시트/` 에 시트가 없으면
그 스킬을 먼저 돌리고, **시트 없이는 실험 사진 절을 쓰지 않는다.** 실험 결과 절에는
사진을 두지 않는다(같은 사진이 두 절에 실리면 노션 손 삽입이 두 배가 된다).

본문에는 `## <항목 제목>` 소절마다 **결선도 → 시트** 순서로 상대경로 그림을 넣는다:

    ![예비보고서에서 그린 3입력 AND 결선도](../결선도/손그림/실험01_1-1_손그림_3입력_AND.png)

    ![3입력 AND 회로의 네 입력 조합](../실험사진/시트/실험01_1-1_사진_3입력_AND.jpg)

캡션에 파일명을 쓰지 않는다(§절대 규칙 9). 대절 머리말 첫 문장은 결선도를 먼저
싣는다는 것을 말한다(예: "항목마다 예비보고서에서 그린 결선도를 먼저 싣고, 그
아래에 시험한 입력 조합의 사진을 한 장에 모았다.").

**결선도는 예보 제출본에 실린 손그림이다** — 2026-09-18 실험01 결보 조교
피드백("실험 사진과 함께 예비보고서에서 그리셨던 회로 결선도를 첨부")에서 왔다.
예보 md 는 `netlist.md` 의 `diagram` 작도 PNG 를 가리키지만, 사용자는 노션에서
그 자리에 손그림을 끼워 제출한다(실험03 예보 제출본 6쪽). 그래서 정본은
`../결선도/손그림/실험NN_<소단원>_손그림_<회로명>.png` 이고, 이름은
`export-hand-diagram` 이 정하므로 짐작하지 말고 `ls` 로 실재를 확인한다. 칩만
갈아 끼운 항목(실험02 1-2)도 손그림이 따로 있으면 따로 싣는다. 그 항목에 손그림이
따로 없으면 앞 항목 손그림을 재사용하지 않고 아래 사슬을 그대로 적용한다.

없을 때의 사슬:
1. 손그림 PNG 가 없고 `output/손그림검토/round<max>/hand.pdf` 나
   `output/<실험NN>_손그림결선도_최종통합본.pdf` 가 있으면 `export-hand-diagram`
   을 먼저 돌린다(기본값, 크롭 없음).
2. 그것도 없으면 `netlist.md` 그 회로 블록의 `diagram` 작도 PNG
   (`../결선도/<파일명>`)를 싣고 캡션을 "예비보고서의 <회로명> 결선도" 로 쓴다.
3. 둘 다 없으면 결선도 없이 시트만 싣는다. 어느 경우든 사정은 본문이 아니라
   §실행 절차 14 결과 안내로만 알린다. 작성은 멈추지 않는다.

§실행 절차 12 의 `check_result_photo_diagrams` 가 소절마다 결선도 유무와 순서를
warn 으로 잡는다.

아래 규칙은 시트에 들어가지 않는 사진(스텝표·파형 사진)과, 시트 밖에서 사진을
다시 가리켜야 할 때에 해당한다.

- **진리표 행 사진**: 파일명 `<항목> <입력비트>.jpg`(예 `1-2 000.jpg`)로
  `<실험NN>/실험사진/` 에 있고 전부 시트에 들어간다 — 따로 싣지 않는다. 불일치
  행도 시트 캡션이 관찰값을 말한다. 불일치 행에 사진이 없으면 "사진 없음" 이라고
  명시한다 — 지어내지 않는다.
- **항목당 완성 회로 사진**: 별도 명명 규칙이 없다. 그 항목의 물리 배선은 행마다
  바뀌지 않으므로 그 항목의 아무 행 사진이나 재사용한다. 어느 사진인지 애매하면
  사용자에게 확인한다.
- **스텝표·파형 사진**: 파일명 `<항목> <표ID> <설명>.jpg`(예 `1-1 T1 xy.jpg`,
  `2-1 T3 s4.jpg`). `capture` 표는 `기록.md` 그 표 블록의 "사진 파일:" 줄에 값이
  있으면 그것을 쓴다. 둘 다 없으면 "사진 없음" 으로 명시한다.
- 상대경로 이미지로 넣는다: `![반전기 입출력 파형(X-Y)](../실험사진/1-1 T1 xy.jpg)`
  — **캡션에는 파일명을 쓰지 않는다**(§절대 규칙 9). 경로에만 남는다.

  **노션에서는 이 이미지가 깨져 보이는 것이 정상이다.** 노션 API 의 마크다운은
  URL 만 받으므로 상대경로는 반드시 깨진다. 캡션이 그 자리에 무슨 사진이
  들어가야 하는지 알려주고, 사용자가 노션에서 직접 끼워 넣는다. ⑦ 의 업로드 전
  검사가 넣어야 할 목록을 세어 알린다.

사진이 한 장도 없으면 본문에는 학생 말투의 한 문장만 남기고(예: "촬영본이 남아
있지 않아 배선 사진은 싣지 못했다."), 하네스 사정은 §실행 절차 14 의 결과 안내로
사용자에게만 알린다.

## 섹션별 재료

**아래 표는 절 이름 목록이 아니라 내용별 재료 안내다.** 왼쪽 열은 오늘
`.claude/보고서양식.md` 의 `교집합` 프리셋 이름을 그대로 썼을 뿐이고, 실행
시 실제로 몇 개의 절을 무슨 이름으로 쓸지는 항상 §실행 절차 4에서 읽은
`fmt.result` 를 따른다 (§절대 규칙 2). 그리고 이 표에 적힌 `기록.md`·명세·
`netlist.md` 같은 내부 자료는 **작성 재료**일 뿐 본문 인용 대상이 아니다 —
본문에서 실제로 이름을 대도 되는 자료는 강의노트뿐이다 (§절대 규칙 7·9·10).
표·헤딩의 겉모습(번호·여백·캡션)은 이 표가 아니라 §절대 규칙 11~16 을 따른다.

## 비-목표

- 기록에 없는 값을 채우지 않는다.
- 예상값을 결과로 옮겨 적어 "성공한 실험"을 만들지 않는다.
- 예비보고서 섹션을 다시 쓰지 않는다 (재료로 인용만 한다 — ③의 영역이다).
- 표지를 이 스킬 안에서 만들지도, 합치지도 않는다 (⑥ 의 영역이고, 병합은
  사용자가 노션 PDF 를 내려받은 뒤 손으로 한다). 조 편성이 미확정이면 그
  사실만 알리고 표지를 억지로 채우지 않는다.
- PDF 를 만들지 않는다. 제출본은 노션 내보내기 + ⑥ 표지의 수동 병합이다 (⑦ 참조).
- 캐시 신선도 로직(mtime 비교·SOURCES 블록)을 만들지 않는다. 소스(`기록.md`)가
  실험 후에는 고정이므로 다시 읽는 것이 싸고 안전하다.
