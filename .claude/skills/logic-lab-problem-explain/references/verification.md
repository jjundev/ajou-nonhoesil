# 실제 증거로 검토하고 발행하기

1. included 전체 ID·번호·순서를 문제지 PDF와 payload 및 설명 목차/본문에서 대조해요. 각 원문 소문항의 설명 위치·단서·개념/기호·적용 조건/선택 이유·첫 줄·검산·원문 path/PDF page·경고 보존·요약 일치·결과를 표로 기록해요. 회로도·오버바·엣지·enable·초기 조건·단위를 실제 원문에서 확인해요. 새 원문 재추출이나 답안 상태 변경으로 범위를 넓히지 않아요.
2. 원문에서 독립적으로 재계산해요. 조합회로는 작은 입력 전수검사, 순서회로는 초기 상태와 엣지 전후 표, 계산은 단위·차원·경계값을 확인해요. 초기 Q를 임의로 0으로 두지 않고 비동기 제어를 먼저 적용해요. 정성 문항은 정의·판단 기준과 조건을 대조해요. 답안 충돌/미확정과 기존 경고를 줄이지 않아요.
3. 개념을 공부한 학생이 본문과 문제만 보고 각 소문항의 답을 재현할 수 있는지 점검해요. recall의 단서·선택 이유와 적용 조건, start의 첫 실행, solve의 완성 답안, verify의 독립 확인을 읽고 구역 간 반복을 덜어요. 설명을 줄인 자리에서는 답을 가르는 조건·근거·경고가 남아 있는지 다시 확인해요. 요약은 본문과 일치해야 해요. 구조 check 성공은 정확성·충분성 또는 독립 계산 증거가 아니에요. 독립 리뷰어 미실시는 not_run, 자신의 내용 검토는 self_review로 기록하고 independent=pass를 쓰지 않아요.
4. 모든 문항을 실제 브라우저에서 375px/1280px × light/dark로 확인해요. 목차·현재 항목·이전/다음·요약·읽음 유지/분리·키보드 포커스·모바일 drawer 닫기·긴 표/수식 내부 스크롤을 확인해요. pageerror·katex-error·깨진 그림·문서 가로 넘침은 0이어야 해요. JS 비활성에서도 문항·목차·완성 풀이가 보여야 해요.
5. 문제 읽기 다음 '이 문제에서 할 일' 간격은 margin-top 24px + padding-top 24px + 구분선 1px예요. 중간 eli5 단락에 첫 단락 간격 제거가 적용되지 않는지 확인해요. equation-card/table-card의 배경·1px 테두리·16px 안쪽 여백, 카드 안 스크롤·터치 시 문제 넘김 방지를 확인해요. 필요한 경우 tests/test_review_pack_explanation_browser.py의 생성본/발행본 회귀 검사를 실행해요.
6. 원문/은행/자산 hash 검사를 유지하고 기존 HTML/MD/PDF·그림·사용자 파일의 전후 해시와 manifest 문항·출처·토픽 보존을 확인해요. 원문 hash나 원문 일치가 실패하면 그 팩은 보류해요. 이 흐름에서 checksum을 덮어써 실패를 숨기지 않아요. 성공한 다른 팩은 독립 발행할 수 있어요.

원문·계산 증거와 브라우저 결과는 .pack/problem-explanations/검증결과.md에 남겨요. author-root 보고서를 explain-stage가 복사한 경우도 실제 최종 stage 검토 결과를 기록해요. explanation_checks는 실제 수행 후에만 갱신하고 기존 checks를 재사용하지 않아요. 수정 후 새 stage와 검토 초기화가 필요해요. 최종 stage의 check를 다시 실행한 뒤 publish하고 최종 링크·보존 해시·백업을 확인해요. 기존 워크북 바이트가 그대로면 PDF를 다시 만들지 않아요. 실패한 검증으로 기존 팩을 교체하지 않아요.

## 본문–요약 감사와 패널 검증

[부모 스킬의 감사표·검증 JSON·브라우저 계약](../../logic-lab-review-pack/references/verification.md#본문요약-감사와-패널-검증)을 따라요. 각 문항에서 풀이 본문의 판단 조건·결론·단서와 요약을 대조하고 일반·강조·주의·보충의 다른 핵심을 별도 행으로 기록해요. 빠진 핵심은 보완 전 unresolved, 다시 읽어 확인한 뒤 pass 또는 unresolved로 남겨요. 본문에 없는 사실을 요약에만 추가하지 않고 항목 수의 고정 상한을 두지 않아요. 기존 동반 MD와 실제 생성 원고도 맞춰요.

1280×900 및 375×812 × light/dark에서 패널을 열어 중앙 문항 제목·고정 패널 제목·현재 요약 하나·이전 요약 숨김을 확인해요. 우측에는 복사된 문항 제목이 없어야 하고 sum-for ID는 .sums 컨테이너 하나에만 있어야 해요. 표지 안내·기존 문제/원문 탭 또는 링크·이전/다음·읽음 저장 키 분리·pageerror와 katex-error 0을 확인해요. missing-sum 검사가 누락을 계속 탐지해야 해요. 원문·문제 payload·풀이 본문·앵커와 저장 키는 보존해요. UI 성공과 의미 검토 상태를 분리하고 실제 수행 뒤에만 상태를 바꿔요.
