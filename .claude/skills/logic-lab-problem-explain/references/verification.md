# 실제 증거로 검토하고 발행하기

1. included 전체 ID·번호·순서를 문제지 PDF와 payload 및 설명 목차/본문에서 대조해요. 각 원문 소문항의 설명 위치·단서·개념/기호·적용 조건/선택 이유·첫 줄·검산·원문 path/PDF page·경고 보존·요약 일치·결과를 표로 기록해요. 회로도·오버바·엣지·enable·초기 조건·단위를 실제 원문에서 확인해요. 새 원문 재추출이나 답안 상태 변경으로 범위를 넓히지 않아요.
2. 원문에서 독립적으로 재계산해요. 조합회로는 작은 입력 전수검사, 순서회로는 초기 상태와 엣지 전후 표, 계산은 단위·차원·경계값을 확인해요. 초기 Q를 임의로 0으로 두지 않고 비동기 제어를 먼저 적용해요. 정성 문항은 정의·판단 기준과 조건을 대조해요. 답안 충돌/미확정과 기존 경고를 줄이지 않아요.
3. recall의 다섯 의미 기준과 서로 다른 소문항 개념, start의 실제 첫 실행을 확인해요. 요약은 본문과 일치해야 해요. 구조 check 성공은 정확성·충분성 또는 독립 계산 증거가 아니에요. 독립 리뷰어 미실시는 not_run, 자신의 내용 검토는 self_review로 기록하고 independent=pass를 쓰지 않아요.
4. 모든 문항을 실제 브라우저에서 375px/1280px × light/dark로 확인해요. 목차·현재 항목·이전/다음·요약·읽음 유지/분리·키보드 포커스·모바일 drawer 닫기·긴 표/수식 내부 스크롤을 확인해요. pageerror·katex-error·깨진 그림·문서 가로 넘침은 0이어야 해요. JS 비활성에서도 문항·목차·완성 풀이가 보여야 해요.
5. 문제 읽기 다음 '이 문제에서 할 일' 간격은 margin-top 24px + padding-top 24px + 구분선 1px예요. 중간 eli5 단락에 첫 단락 간격 제거가 적용되지 않는지 확인해요. equation-card/table-card의 배경·1px 테두리·16px 안쪽 여백, 카드 안 스크롤·터치 시 문제 넘김 방지를 확인해요. 필요한 경우 tests/test_review_pack_explanation_browser.py의 생성본/발행본 회귀 검사를 실행해요.
6. 원문/은행/자산 hash 검사를 유지하고 기존 HTML/MD/PDF·그림·사용자 파일의 전후 해시와 manifest 문항·출처·토픽 보존을 확인해요. 원문 hash나 원문 일치가 실패하면 그 팩은 보류해요. 이 흐름에서 checksum을 덮어써 실패를 숨기지 않아요. 성공한 다른 팩은 독립 발행할 수 있어요.

원문·계산 증거와 브라우저 결과는 자료/problem-explanations/검증결과.md에 남겨요. author-root 보고서를 explain-stage가 복사한 경우도 실제 최종 stage 검토 결과를 기록해요. explanation_checks는 실제 수행 후에만 갱신하고 기존 checks를 재사용하지 않아요. 수정 후 새 stage와 검토 초기화가 필요해요. 최종 stage의 check를 다시 실행한 뒤 publish하고 최종 링크·보존 해시·백업을 확인해요. 기존 워크북 바이트가 그대로면 PDF를 다시 만들지 않아요. 실패한 검증으로 기존 팩을 교체하지 않아요.
