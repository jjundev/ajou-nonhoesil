# check-wiring-photo

실물 보드 사진을 체크리스트 단계의 참조 결선과 대조한다. 판정 규칙은 손그림 검토
(`scripts/lab/hand_compare.py`)를 그대로 쓴다. 이 스킬이 새로 하는 일은 **사진에서 홀 주소를
읽는 앞단**뿐이다. 코드는 `scripts/lab/photo_wiring.py` 다.

## 왜 이렇게 하는가

2026-11-07 실험08 영상 프레임 한 장을 참조 없이 판독해 본 시험에서 LED–저항 연결점 4곳 중
**0곳**을 확정했다. 원인은 세 가지였고 절차가 하나씩 막는다.

| 원인 | 막는 절차 |
|---|---|
| 몸통·다른 선에 가린 다리 | 단계마다, 여러 각도로 찍는다(촬영 안내) |
| 5칸마다만 있는 행 번호로 구멍을 **세다가** 한 행 어긋남 | 세지 않는다. 앵커 몇 개만 짚고 코드가 모든 홀에 주소를 찍는다(2·3단계) |
| 참조를 보면 애매한 자리를 정답 쪽으로 읽음 | 전사가 끝나 파일로 남기 전에는 참조 결선도(PNG·JSON·체크리스트 그림)를 열지 않는다 |

판독이 한 행 어긋난 것인지 결선이 한 행 어긋난 것인지 사진만으로 가를 수 없으면, 그 끝점은
**재촬영**으로 돌린다. 추측해서 통과시키지 않고, 추측해서 오류라고 하지도 않는다.

## 인자

`<실험N> <단계> <사진 경로…>`

- 단계는 `2단계_Y0`·`1준비_2` 같은 결선도 파일명 뒤꼬리다. 없거나 여러 단계와 맞으면 아래 명령으로
  후보를 보여 주고 되묻는다.

  ```bash
  PYTHONUTF8=1 python -m scripts.lab.photo_wiring stages <N>
  ```

- 걷기(선 뽑기) 보드는 단계 목록에 없다. 선을 뽑은 뒤의 상태는 다음 단계 사진으로 본다.
- 사진이 없거나 아래 ①이 빠졌으면 **촬영 안내를 보여 주고 멈춘다.**
- 실험 폴더는 `python -c "from scripts.lab import config; print(config.experiment_dir(N))"` 로 얻는다.
  없으면 거절하고 `init-lab-experiment` 를 안내한다.

## 촬영 안내 (사용자에게 그대로 보여 준다)

> 한 단계를 꽂은 뒤, **전원을 끄고** 아래처럼 찍어 주세요. 동영상 프레임 말고 사진 모드로 찍어 주세요.
>
> ① **전체 정면 1장**: 보드 바로 위에서, 이번 단계에 쓴 블록의 네 모서리가 다 들어오게.
> ② **구역 근접 사진**: 칩 주변, LED 묶음마다 한 장. **인쇄된 행 번호 두 개 이상과 열 글자(a~j)가 같이 보이게.**
> ③ **낮은 각도 사진**: LED·저항이 있으면 좌우에서 비스듬히 한 장씩. 몸통 밑 다리가 보이게.
>
> 선은 손으로 눌러 보드에 붙이고, 손·집게가 구멍을 가리지 않게 해 주세요.

②에 행 번호가 안 보이는 근접 사진은 격자를 세울 수 없으므로 쓰지 않고 다시 찍어 달라고 한다.

## 실행 절차

출력 폴더는 `<실험NN>/output/결선사진검토/<단계 뒤꼬리>/round<N>/` 다. `round<N>` 은 기존 최대 번호 + 1 이다.
사진을 `사진/p1.jpg`, `사진/p2.jpg` … 로 복사하고 이후에는 복사본 경로만 쓴다.

### 1. 단계 이름만 확정한다

`stages` 로 단계 이름을 확정한다. **참조 그림은 열지 않는다.**
칩 이름은 `<실험NN>/체크리스트/명세.md` 의 부품 목록에서 읽어도 된다. 칩 이름은 결선 답이 아니다.

### 2. 사진마다 앵커를 짚는다

사진은 크다. Read 도구는 줄여서 보여 주므로 화면 좌표를 그대로 쓰지 않는다.
원본 픽셀 눈금을 덮은 그림을 만들어 읽는다.

```bash
PYTHONUTF8=1 python -m scripts.lab.photo_wiring ruler <사진> <round>/눈금/p1_전체.png
PYTHONUTF8=1 python -m scripts.lab.photo_wiring ruler <사진> <round>/눈금/p1_위.png --crop x0 y0 x1 y1
```

블록마다 앵커를 **다섯 개 이상** 고른다.

- 인쇄된 행 번호(1·5·10·…)와 열 글자 바로 옆 홀만 고른다. 주소를 세지 않고 읽을 수 있는 홀이다.
  블록 **맨 윗줄은 1행**이라 가장 확실한 앵커다. 숫자는 사진 각도에 따라 자기 행보다 반 칸쯤
  위에 보일 수 있다. 애매하면 그 숫자 대신 다른 숫자 옆 홀을 고르고, 3단계의 격자 그림으로 확인한다.
- 보이는 영역의 네 모서리 근처로 퍼뜨린다. 한 줄에 몰리면 코드가 거절한다.
- 홀 **중심**의 원본 픽셀 좌표를 눈금에서 읽는다. 필요하면 `--crop` 으로 더 좁혀 다시 본다.

`<round>/앵커.json` 에 적는다. 한 사진에 두 블록이 보이면 그 사진은 grids 항목이 둘이다.

```json
{"grids": [
  {"name": "p1_우", "photo": "<round>/사진/p1.jpg", "rows": [1, 35],
   "anchors": [{"px": [1712, 905], "hole": "우 a5"}, {"px": [2240, 918], "hole": "우 j5"},
               {"px": [1688, 2410], "hole": "우 a30"}, {"px": [2231, 2433], "hole": "우 j30"},
               {"px": [1950, 1650], "hole": "우 f20"}]}
]}
```

### 3. 격자를 덮고 맞는지 본다

```bash
PYTHONUTF8=1 python -m scripts.lab.photo_wiring grid <N> <round>/앵커.json <round>/격자
```

- `PhotoGridError` 가 나면 메시지가 짚는 앵커를 다시 짚는다. 상한을 올리지 않는다.
- `<이름>_격자.png` 를 **모든 장, 네 귀퉁이까지** 연다. 점이 구멍 위에 앉아 있어야 한다.
  어느 쪽에서 반 칸 이상 밀리면 그 근처에 앵커를 더해 다시 돌린다.
- 격자가 안 맞는 사진은 전사에 쓰지 않는다. 그 사진만으로 볼 수 있던 끝점은 재촬영으로 간다.

### 4. 전사한다 (참조를 보지 않는다)

`_격자.png` 로 리드가 들어간 점의 라벨을 읽고, 같은 자리의 `_맨.png` 로 리드가 정말 그 구멍에 들어갔는지
확인한다. 같은 끝점이 여러 사진에 보이면 가장 또렷한 것을 쓴다. 사진끼리 다르게 읽히면 `uncertain` 에 올린다.

`<round>/전사.json` 에 적는다. 주소 문법은 손그림 전사와 같다(`review-hand-diagram` 3절).

```json
{
  "photos": ["p1.jpg", "p2.jpg", "p3.jpg"],
  "chips": [{"label": "74HC76", "block": "좌", "pin1_row": 5, "pin1_col": "e"}],
  "wires": [{"color": "빨강", "from": "좌 a9", "to": "좌 VCC레일9행", "seen_in": "p2"}],
  "external": [{"name": "CLK", "at": "좌 b5"}],
  "leds": [{"tag": "P1", "legs": ["우 g3", "우 g4"]},
           {"tag": "P2", "anode": "우 g11", "cathode": "우 g12"}],
  "resistors": [{"tag": "P1", "top": "우 i4", "bottom": "우 i8"}],
  "bridges": [{"kind": "gnd", "from": "좌 GND레일39행", "to": "중앙GND레일39행"}],
  "uncertain": ["우 h22"]
}
```

전사 규칙:

- **끝점만 적는다.** 선이 지나가는 홀은 적지 않는다.
- **리드가 구멍에 들어간 것이 보인 끝점만 주소로 적는다.** 선 방향으로 짐작한 끝점, 다른 선·몸통에 가린
  끝점은 가장 가까운 주소를 `uncertain` 에 올린다. 한 행이 애매해도 `uncertain` 이다.
- **LED 꼬리표는 위에서부터 `P1`·`P2`…** 다. 참조 이름(Y0…)은 코드가 칩 핀으로 찾아 붙인다.
  저항은 이어진 LED 와 같은 꼬리표를 단다.
- **LED 극성:** 긴 다리나 테두리의 평평한 쪽(캐소드)이 보였을 때만 `anode`·`cathode` 로 적는다.
  못 봤으면 `legs` 로 적는다. 코드가 저항 쪽 다리를 캐소드로 놓고 '극성 미확인' 알림을 남긴다.
- **칩:** `pin1_row` 는 노치(반달 홈)나 점이 있는 끝의 행이다. 노치가 위면 `pin1_col` 은 `e`, 아래면 `f` 다.
  칩 글자를 못 읽으면 명세 부품 목록과 꽂힌 위치로 정하고, 그래도 모르면 사용자에게 묻는다.
- **레일:** 파란 줄 쪽이 GND, 빨간 줄 쪽이 VCC 다. 행은 옆 단자대 격자의 가장 가까운 행으로 적는다.
  레일 행은 판정에 거의 쓰이지 않는다(극성만 본다).
- **보드 밖 신호원**(함수발생기 집게 등)에 물린 선은 `external` 에 이름과 보드 쪽 끝을 적는다.
  이름은 체크리스트의 입력 이름(CLK·R0 …)이다.
- **전원장치 잭**에서 온 선은 `"전원잭(빨강)"`·`"전원잭(회색)"` 이다.
- 색은 적어도 되지만 판정에 쓰지 않는다.
- v2 판형(실험05~)의 가운데 레일은 접두어 없이 `중앙GND레일9행` 이다.

### 5. 판정한다

전사 파일을 저장한 **뒤에** 판정을 돌린다. 판정 결과를 보고 전사를 고치지 않는다.
다시 읽어야 할 자리가 생기면 그 끝점을 `uncertain` 에 올려 재촬영으로 돌린다.

```bash
PYTHONUTF8=1 python -m scripts.lab.photo_wiring judge <N> <단계> <round>/전사.json <round>
```

`<round>/판정.md` 와 `<round>/전사_판정용.json`(꼬리표·극성·보드 밖 입력을 메운 것)이 생긴다.
사진 판정은 종이 표기 검사 H11(제목)·H15(신호 이름)를 뺀다. 나머지 H1~H14 는 손그림 검토와 같다.

| 판정 | 뜻 |
|---|---|
| 수정 필요 | 치명·기능 결함이 있다 |
| 재촬영 필요 | 결함은 없지만 확정 못 한 끝점(H13)이 있다 |
| 통과 | 읽은 끝점이 모두 참조 넷과 같다 |

### 6. 알린다

- 판정을 먼저 말한다.
- **수정 필요**면 고칠 자리를 **사진 기준 주소**로 적는다. 참조 좌표로 옮겨 쓰지 않는다. 칩이 밀려 있으면
  참조 좌표는 다른 자리를 가리킨다. 그 자리의 `_격자.png` 를 잘라 `SendUserFile` 로 보낸다.
- **재촬영 필요**면 `uncertain` 자리마다 무엇을 어떤 각도로 다시 찍을지 한 줄씩 적는다.
- '극성 미확인' 알림이 있으면 그 LED 의 평평한 테두리가 저항 쪽인지 눈으로 보라고 적는다.
- 'LED 꼬리표를 순서로 맞췄다' 알림이 있으면 그 대응(P1 → Y0 …)을 그대로 전한다.
  칩 핀으로 확인한 대응이 아니다.

## 한계 (사용자에게 숨기지 않는다)

- 좌·우 단자대 두 블록과 그 레일만 주소가 있다. WISH 보드의 세 번째 블록에 꽂은 부품은 전사할 수 없으니
  `uncertain` 으로 돌린다.
- 홀 하나에 리드가 둘이거나, 리드가 구멍 대신 다른 리드에 얹힌 것은 사진으로 갈리지 않을 수 있다.
  의심되면 `uncertain` 이다.
- 전기적 불량(헐거운 접촉, 끊어진 점퍼)은 사진으로 보이지 않는다. 통과는 "결선 자리가 맞다"는 뜻이지
  "회로가 돈다"는 뜻이 아니다.
- 2026-11-07 기준으로 **좋은 사진에서 실제로 오류를 잡는지는 아직 검증하지 않았다.** 첫 실사용에서
  일부러 한 행 틀리게 꽂은 사진을 함께 받아 잡는지 확인하고, 결과를 이 절에 적는다.

## 비-목표

- 결선도를 그리지 않는다. 참조는 `breadboard-diagram` 빌더가 만든다.
- 사진에서 선을 자동으로 추적하지 않는다. 엉킨 점퍼는 색으로도 갈리지 않는다.
- 기록.md·보고서를 채우지 않는다.
