# write-pre-report

## 절대 규칙

1. **섹션 목록을 이 문서에 적지 않는다.** `.claude/보고서양식.md` 에서 읽는다.
   양식은 연도마다·학생마다 다르고 이번 학기 것이 미확정이다 (R1).
2. **예상값의 출처를 항상 밝힌다 — 단, 각주에는 강의노트만 인용한다.** 명세의
   `source` 필드는 내부적으로 근거를 확인하는 용도로 읽는다. `manual:pN` 이면
   "강의노트 p.N" 으로 자연스럽게 풀어 쓰고, `derived(...)` 면 그 항의 부울식
   유도 과정 자체를 근거로 서술한다. 데이터시트·다른 주차 자료처럼 강의노트
   밖의 `source` 는 각주로 노출하지 않는다 (§절대 규칙 9).
3. **자동 배선도를 그리지 않는다.** netlist 표 + 크롭된 브레드보드 템플릿까지다.
4. **과거 제출본을 베끼지 않는다.** 권위 5순위 코퍼스이고 알려진 오염이 있다.
   참고하려면 다수결로, 연도를 밝히고.
5. **없는 근거를 지어내지 않는다.** 예: `74HC08`·`74HC32` 핀아웃 데이터시트는
   저장소에 없다. 표준 DIP-14 배치임을 밝히고 실물 대조를 권고한다.
6. **본문에서 그 주 실습 자료는 `강의노트`라 부른다.** 예전에는 `교안`이라고
   불렀다 — 이제 보고서 서술에서는 `강의노트`로 쓴다. 명세의 `source_manual`
   필드나 절차 안의 파일 경로 같은 하네스 내부 이름은 이 규칙과 무관하게
   그대로 둔다. **주의**: `<실험NN>/강의노트/실험N.pdf` 가 그 주 실습 자료이고,
   `from_the_past/정리/논회 강의노트/Ch*.pdf` 는 이름이 겹칠 뿐 **별도의 이론
   교재**다 — 본문에서 `강의노트`는 항상 전자만 가리킨다.
7. **생성형 AI 를 써도 되지만 티가 나면 안 된다.** 실제로 나왔던 티: 문서·과정
   자기 언급("이 보고서가 직접 도출했다", "vision 으로 직접 열람해 판독했다"),
   하네스 도구 언급(함수명, `lab-spec/v1` 같은 스키마 이름), 내용 대신 "어떻게
   썼는지"를 설명하는 메타 서술, 균일한 문단 길이와 평범한 문장에 붙는 과도한
   굵게. **판별 기준**: 학생이 손으로 썼다면 이 문장을 쓸 이유가 있는가 —
   프로그램이 만들었기 때문에만 말이 되는 문장이면 지운다.
8. **강의노트 외의 다른 파일은 본문에서 언급하지 않는다.** 채점자는
   `실험01/체크리스트/명세.md`, `netlist.md`, 브레드보드 이미지 경로, 코드
   식별자 같은 하네스 내부 이름을 모른다 — 언급해도 이해하지 못하고 오히려
   생성형 AI 티만 난다. **사실 자체는 남긴다** — 결선 근거는 여전히 서술하되,
   "netlist.md 표에 따르면"이 아니라 학생이 강의노트 회로도를 직접 읽고 파악한
   것처럼 쓴다.
9. **출처 및 참고문헌은 강의노트만 올린다.** 데이터시트·다른 주차 자료·이론
   교재는 참고문헌에 올리지 않는다 — §절대 규칙 2 의 예상값 각주에도 같은
   제한이 적용된다. 지금까지 일부 핀 레벨 사실은 데이터시트에 근거해 왔는데
   그 인용은 이제 빠진다 — 그렇다고 **없는 근거를 지어내지 않는다(§절대 규칙
   5)** 가 풀리는 것은 아니다. 강의노트가 실제로 보여주는 것만 강의노트로
   인용하고, 강의노트에 없는 것은 인용을 지어내거나 조용히 단정하지 말고
   "실물 IC 로 확인이 필요하다"고 그대로 밝힌다.

## 실행 절차

0. **주차로 불렸으면 폴더를 코드로 옮긴다.** 사용자는 "2주차 …" 처럼 주차로
   부르는데 아래 절차의 경로는 `<실험NN>/` 이다. **매핑은 1:1 이 아니다** —
   실험4는 7주차다. 손으로 옮기지 말고 아래를 돌린다.

   ```bash
   python3 -c "
   from scripts.lab import config
   print(config.folder_for_week(<N>))
   "
   ```

   출력이 이후 모든 경로의 `<실험NN>` 이다. 사용자가 `실험N` 으로 불렀으면
   `config.experiment_dir(<N>)` 을 대신 쓴다. `ValueError` 가 나면(중간고사·범위
   밖) 그 메시지를 그대로 사용자에게 전하고 중단한다. 13~15주차는 `실험NN`
   대신 `프로젝트` 를 돌려준다 — 그 뒤로는 모든 경로에서 `<실험NN>/` 자리에
   `프로젝트/` 를 쓴다.

1. **주차·명세·결선도 확인.** `<실험NN>/체크리스트/명세.md` 가 없으면 거절하고
   `init-lab-experiment` 또는 명세 작성(교안 판독)을 안내한다. `<실험NN>/결선도/netlist.md`
   가 없으면 §3 의 `check_netlist` 가 "결선도 netlist 파일이 없다" error 를 내는데,
   그 자리까지 미루지 않고 여기서 먼저 정직하게 보고하고 멈춘다 — **회로 결선도
   절(§섹션별 재료)은 이 파일 없이는 채울 근거가 없다.** 없는 근거를 지어내지
   않는다는 §절대 규칙 5 와 같은 이유다. netlist.md 를 만드는 자동 생성 스킬은
   없으므로, 교안 회로도를 vision 으로 직접 읽어 먼저 만들도록 안내한다.

2. **양식 로드** (§절대 규칙 1). `repeat: per-item` 인 섹션은 항목마다 반복한다.

   ```bash
   python3 -c "
   from pathlib import Path
   from scripts.lab import config
   root = config.find_project_root(Path('.'))
   fmt = config.load_report_format(root)
   print('프리셋:', fmt.preset)
   for s in fmt.pre:
       flag = ' (항목마다 반복)' if s.repeat == 'per-item' else ''
       skip = '' if s.generate else '  [생성 안 함]'
       print(f'  - {s.name}{flag}{skip}')
   "
   ```

3. **명세 로드 및 검증.**

   ```bash
   python3 -c "
   from scripts.lab.spec_parser import parse_spec
   from scripts.lab import validate
   spec = parse_spec('<실험NN>/체크리스트/명세.md')
   findings = (validate.validate_spec(spec)
               + validate.check_netlist('<실험NN>/결선도/netlist.md', spec))
   print('\n'.join(str(f) for f in findings) or '문제 없음')
   "
   ```

   **error 가 있으면 작성을 멈추고 보고한 뒤 사용자 판단을 기다린다.** warn 은
   알리고 진행한다.

4. **섹션별 작성.** 아래 §섹션별 재료 표를 따른다. `role: reference` 표는
   실험 이론 절의 재료이지 실험 과정 절의 기록 대상이 아니다 — ②
   `prep-lab-checklist` 가 체크리스트·`기록.md` 양쪽에서 이미 같은 표를
   제외하는 것과 같은 구분이다. `kind: capture` 표는 셀 표 대신 `expected`
   산문을 싣는다.

5. **보수 표기 (R5).** 저작은 `'`, 부울식만 오버바로 승격한다.

   ```bash
   python3 -c "
   from scripts.lab.notation import to_overbar_html
   print(to_overbar_html(\"(A'·B)'\"))   # 중첩 스코프도 지원한다
   "
   ```

   **표 헤더·신호명·셀 값에는 절대 부르지 않는다** — `normalize_cell` 이 돌려주는
   `CellValue` 를 넘기면 `TypeError` 가 난다. 이건 버그가 아니라 안전장치다.

6. **md 저장.** `<실험NN>/output/<실험NN>_예비보고서.md` 에 쓴다. **이 md 가
   유일한 산출물이다** — HTML 로 옮기지 않는다 (8단계).

   **첫 헤딩(`# …`)은 손으로 짓지 않는다.**
   `config.document_title(<실험번호>, <명세의 title>, '예비보고서')` 이 유일한
   형식이다 (`실험1 Basic Gates 예비보고서`). **제목에 주차를 넣지 않는다** —
   주차는 폴더를 찾을 때만 쓴다 (0단계). 실험 번호는 폴더 이름(`실험01`)이
   아니라 **0 을 뺀 정수**다.

   ```bash
   python3 -c "
   from scripts.lab import config
   from scripts.lab.spec_parser import parse_spec
   s = parse_spec('<실험NN>/체크리스트/명세.md')
   print(config.document_title(s.experiment, s.title, '예비보고서'))
   "
   ```

   **이 규칙은 PDF 를 안 만들게 되면서 오히려 더 중요해졌다.** 노션은 마크다운의
   첫 `#` 헤딩을 그대로 페이지 제목으로 삼는다 — 여기서 틀리면 노션 페이지
   제목과 제출 PDF 제목이 한꺼번에 틀린다.

7. **조 편성 확인 → 표지 여부 분기 (판정만 한다).** 표지를 만들지도 합치지도
   않는다 — 8단계에서 다시 밝힌다.

   ```bash
   python3 -c "
   from pathlib import Path
   from scripts.lab import config
   info = config.load_course_info(config.find_project_root(Path('.')))
   print('미확정:', config.missing_identity(info) or '없음')
   "
   ```

   판정은 ⑥ `make-lab-report-cover` 1b 단계와 **같은 함수**를 쓴다 — 두 곳이
   따로 판정하면 한쪽만 고쳐지고 다른 쪽이 `None` 을 표지에 찍는다.

   - **`미확정: 없음` 이면(조 편성 확정):** ⑥ `make-lab-report-cover` 로 표지를
     만들 수 있다고 알린다. **이 스킬은 표지를 만들지도 합치지도 않는다.**
   - **하나라도 `~` 면(조 편성 미확정):** 조 편성이 확정돼야 표지를 만들 수
     있다고 알린다. **본문에는 아무 안내문도 넣지 않는다** — 이 md 는 그대로
     노션에 올라가고 그대로 제출본이 되므로, 하네스 사정을 적은 문장이 제출
     문서 첫 페이지에 찍힌다.

8. **PDF 를 만들지 않는다.** 이 스킬의 산출물은 `.md` 하나다.

   제출본은 사용자가 ⑦ `sync-report-to-notion` 으로 노션에 올린 뒤 노션에서
   PDF 로 내보내고, ⑥ `make-lab-report-cover` 가 만든 표지를 앞에 손으로 붙여
   만든다. **표지는 이 스킬의 관심사가 아니다.**

   예전에는 여기서 `template.html` 을 채워 Chrome 헤드리스로 PDF 를 내고
   `pypdf` 로 표지를 합쳤다. 그 경로에는 "본문 재렌더가 방금 합친 표지를 조용히
   덮어쓴다" 는 함정이 있었는데, PDF 를 아예 만들지 않게 되면서 함정 자체가
   사라졌다. `template.html` 은 되돌릴 경우를 위해 남겨 두지만 이 절차는
   쓰지 않는다.

9. **⑤ 로 검증하고 error 0 까지 반복한다.**

    ```bash
    python3 -c "
    from pathlib import Path
    from scripts.lab import config, validate
    root = config.find_project_root(Path('.'))
    fmt = config.load_report_format(root)
    for f in validate.check_report_sections('<실험NN>/output/<실험NN>_예비보고서.md', fmt.pre):
        print(f)
    " | tee <실험NN>/output/pre_review_round1.md
    ```

    출력이 없으면 모든 섹션이 존재하는 것이다. 누락이 나오면 본문을 고치고
    `round2`, `round3`... 로 다시 돌린다.

10. `과목정보.md` 의 `ai_usage_log` 가 `~` 가 아니면 그 경로에 로그 한 줄을
    남긴다. `~` 면 아무것도 하지 않는다.

11. **결과 안내.** md 경로, 섹션 검증 결과(error 0 여부), 그리고 **다음 할 일**을
    한 줄로: `⑦ sync-report-to-notion` 으로 노션에 올린다.

## 섹션별 재료

**아래 표는 절 이름 목록이 아니라 내용별 재료 안내다.** 왼쪽 열은 오늘
`.claude/보고서양식.md` 의 `교집합` 프리셋에 있는 이름을 그대로 썼을 뿐이고,
실행 시 실제로 몇 개의 절을 무슨 이름으로 쓸지는 항상 §실행 절차 2 에서 읽은
`fmt.pre` 를 따른다 (§절대 규칙 1). 조교 안내로 절 이름이 달라져도 이 표는
"목적/이론/부품/과정/결선/출처"라는 개념 대응만 유지하면 되고, 실행 로직은
전혀 손댈 필요가 없다. 그리고 이 표에 적힌 명세·`netlist.md`·`ic칩.txt` 같은
내부 자료는 **작성 재료**일 뿐 본문 인용 대상이 아니다 — 본문에서 실제로
이름을 대도 되는 자료는 강의노트뿐이다 (§절대 규칙 6·8·9).

| 섹션 | 재료 |
|---|---|
| 실험 목적 | 강의노트 p2 "목적" 슬라이드 |
| 실험 이론 | 그 주 강의노트(`실험N.pdf`) 이론 슬라이드 + `논회 강의노트/Ch*.pdf`(이름이 겹치는 별도의 이론 교재 — §절대 규칙 6) + `docs/study/` + 명세의 **`role: reference` 표**(실험1 T6~T9 = 2입력 이론표, `encoding: H/L`). **`H/L` 을 `0/1` 로 바꾸지 말 것.** 본문에는 이 자료들의 이름을 밝히지 않고 내용만 녹여 쓴다(§절대 규칙 8) |
| 실험 부품 | 명세 `ics` + `ic칩.txt` + 핀아웃 이미지. **그 주 명세의 `items[].device` 를 먼저 확인한다** — `LED` 면 330Ω 직렬·미사용핀 처리를 포함하고, `oscilloscope`·`DMM`·`7segment` 등이면(예: 3주차 실험2 CMOS 특성처럼 `capture` 중심 실험) LED·저항 서술 대신 그 장비를 재료로 쓴다 |
| 실험 과정 및 예상 결과 | 명세의 표 전부 + 예상값 각주(§절대 규칙 2·9 — 강의노트만 인용하고, 강의노트 밖 출처는 실물 대조가 필요하다고 밝힌다) |
| 회로 결선도 | `<실험NN>/결선도/netlist.md` 표 + 크롭된 브레드보드. **본문에는 `netlist.md` 를 인용하지 않는다** — 결선 근거는 학생이 강의노트 회로도를 직접 읽고 파악한 것처럼 쓴다(§절대 규칙 8) |
| 출처 및 참고문헌 | 강의노트 쪽 번호만. **데이터시트·이론 교재는 올리지 않는다**(§절대 규칙 9) — 실제로 강의노트에서 본 것만 |

`ic칩.txt` 처럼 원천 자료 자체에 오류가 있을 수 있다 — 발견하면 조용히 정정해
쓰지 말고, 무엇을 왜 정정했는지 각주로 남긴다 (§절대 규칙 5 의 연장). **이
각주에도 내부 파일명을 대지 않는다** — "표준 핀 배치와 다른 부분을 정정함"
처럼 사실만 쓴다 (§절대 규칙 8).

## 비-목표

- 결과를 예측해 실험 결과 섹션을 채우지 않는다 (④의 영역이다).
- 고찰을 쓰지 않는다 (예보엔 없고, 결보에서도 본인 경험이 재료다).
- 표지를 이 스킬 안에서 만들지도, 합치지도 않는다 (⑥ `make-lab-report-cover`
  의 영역이고, 병합은 사용자가 노션 PDF 를 내려받은 뒤 손으로 한다).
  조 편성이 미확정이면 그 사실만 알리고 표지를 억지로 채우지 않는다.
- PDF 를 만들지 않는다. 제출본은 노션 내보내기 + ⑥ 표지의 수동 병합이다 (⑦ 참조).
