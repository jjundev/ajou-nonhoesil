# 실험영상 근거 추출

영상의 **발언 근거·화면 관찰·사용자 설명·미확인 사항**을 분리한다. 사진과 편집본은 같은 원본 시간선을 사용한다. 사진만 요청하면 사진만, 편집만 요청하면 편집만 수행한다.

## 입력과 원본 조사

영상을 직접 보고 교안·명세·결선도 및 제공 전사본과 대조한다. 파일명의 ‘실험1’을 교안의 첫 항목으로 간주하지 않는다. 명세와 원본 파일은 수정하지 않는다.

제공 전사본을 우선 사용한다. 없는 원본은 프로젝트 로컬 [logic-lab-stt](../logic-lab-stt/SKILL.md)의 Gemini API 실행기를 `inspect` CLI가 자동 호출한다. 최초 사용 시 해당 스킬을 읽는다. 원본에서 추출한 음성만 전송하며 키는 환경변수 또는 `--env-file`(생략 시 프로젝트 `.env`)로 읽는다. Whisper는 사용하지 않는다. 자동 전사는 직접 청취가 아니며 네이티브 청취 도구가 없으면 들었다고 쓰지 않는다. 실패해도 가능한 프레임 분석은 진행하고 발언 맥락은 미확인으로 남긴다. 사용자 지정 방식이 있으면 따른다.

저장소 루트에서 아래 도구를 실행한다. `TOOL`은 이 SKILL.md 옆 `scripts/video_evidence.py`의 실제 경로다. Python 3·FFmpeg·ffprobe·Pillow가 필요하다. 한글 폰트를 못 찾으면 설치된 폰트를 `LAB_VIDEO_FONT`로 지정한다. 자동 설치하지 않는다.

```bash
python3 "$TOOL" inspect --experiment 6 --label '실험1_JK' \
  --source '/실제/첫 영상.mp4' --source '/실제/두번째 영상.mp4' \
  --mode both
```

수동 전사본은 `--transcript 'p1=/실제/첫 전사본.md'`로 제공하면 해당 원본을 API에 보내지 않는다. `--no-transcribe`로 자동 전사를 생략할 수 있다. 압축만 요청할 때에는 이 옵션을 지정한다. `--mode video`만으로는 압축과 발언 기반 편집 의도를 구분하지 않는다.

전사 실패는 manifest의 `transcription`·`unknowns`에 남고 조사 결과 경로는 유지된다. 상세 오류는 실행 폴더 `transcripts/<원본id>/<지문>/state.json`에서 확인한다. 성공 청크를 재사용한 재개 명령은 다음과 같다.

```bash
python3 "$TOOL" transcribe '/실제/manifest.json' --env-file '/실제/.env'
```

완료된 MD와 출처 JSON만 manifest에 등록한다. 전사 시각은 원본 첫 표시 프레임 기준으로 오디오 시작 차이를 반영한 근사값이다. 자동 전사만으로 `review.audio`를 승인하거나 보이지 않은 입력값·클럭 에지를 확정하지 않는다.

반환된 `manifest.json`이 이번 실행의 공통 근거다. 선택 항목을 채우기 전에 [근거 스키마](references/evidence-schema.md)를 읽는다. 경로는 디렉터리에서 실제 이름을 발견해 사용한다. 조사 도구는 원본 해시와 미디어 정보를 기록하고 기존 산출물이 있으면 공통 버전 접미사를 붙인다.

## 모든 영상 출력의 기본 압축

`ffprobe` 기록에서 표시 해상도·회전·길이·평균/명목 프레임률·비트레이트·음성 유무를 먼저 확인한다. 평균 프레임률과 실제 PTS를 함께 보고, 높은 비트레이트나 명목 120fps만으로 불필요한 데이터라고 단정하지 않는다.

새 실행의 최종 MP4는 기본적으로 `libx264 / CRF 26 / preset slow / yuv420p / AAC 128k / +faststart`를 적용한다. 기본 출력 프레임률은 첫 보존 영상의 실제 평균 fps를 기준으로 최대 30fps이며, 더 낮으면 유지한다. 재생 속도·시간축과 표시 해상도는 유지한다. 크기가 다른 촬영본은 기존처럼 첫 영상 크기에 맞춰 여백 처리한다. 편집과 압축은 원본에서 한 번에 수행하고, 사진은 압축본이 아닌 원본에서 추출한다.

압축만 요청하면 `--mode video --no-transcribe`로 조사하고, `cuts`에 요청한 원본 전체 구간을 순서대로 넣는다. 사진·장면 해석은 요구하지 않는다. 여러 촬영본을 연결할 때에는 실제 촬영 중단을 표시한다. 출력 이름은 기존 `_편집본.mp4` 규칙을 유지하며, 전체 구간 압축 여부는 manifest의 보존 구간에 기록한다.

해상도 유지는 무손실 화질을 뜻하지 않는다. 원본과 출력의 작은 글자·핀 번호·LED 상태를 직접 대조한다. 판독이 어려우면 새 실행에서 `render.crf`를 낮춰 재생성한다. 짧은 점멸·전이의 근거는 원본으로 확인하며, 해당 전이를 출력에도 보존해야 하면 `render.fps`로 필요한 fps를 명시한다. `render.preset`·`render.audio_bitrate`도 요청에 따라 조정할 수 있다. 이전 manifest에 새 설정이 없으면 기존 인코딩 설정을 유지한다.

`faststart`는 재생 시작을 돕지만 무버퍼링·모든 환경 호환을 보장하지 않는다. 용량 절감률도 고정하지 않고 매번 실제 바이트 수로 계산한다. 구간 삭제가 있으면 원본 전체 대비 감소에 편집 효과도 포함된다고 밝힌다. 출력이 커진 경우도 그대로 알린다.

## 직접 판독하고 선택하기

1. 전체 영상의 저밀도 미리보기를 열어 흐름을 확인한다. 필요한 구간만 더 좁게 본다.

   ```bash
   python3 "$TOOL" preview '/실제/manifest.json' --source-id p1 --step 1
   python3 "$TOOL" preview '/실제/manifest.json' --source-id p1 --start 20 --end 22 --step 0.1
   ```

   상태 변화나 절단 경계는 필요하면 원본 프레임 간격까지 확인한다. 미리보기의 시간은 실제 프레임 시각이며 전사의 근사 시각과 구분한다.

2. `scenes`에 관찰·전사 출처·실험 항목·불확실성을 기록하고, `captures`·`pairs`·`cuts`를 채운다. 원본 입력을 예상 출력에서 역산해 확정하지 않는다. LED와 핀의 대응도 확인 근거를 적는다.
3. 안정 상태에는 대표 사진을, 유지·전이에는 의미 있는 전후 사진을 고른다. 손 가림과 초점을 확인한다. 출력이 전후 같으면 새 전이를 관찰했다고 쓰지 않는다. 클럭 에지를 실제로 확인하지 못했으면 에지 방향을 캡션에 확정하지 않는다.
4. 촬영 중단·배선 수정 전후는 `interrupted` 비교로 표시한다. 수정 후 최종 상태만 보이면 그 상태 사진만 제공하고 연속 토글 성공이라고 부르지 않는다.
5. 편집은 필요한 설명과 정상 관찰을 보존하면서 요청한 실패·설정·종료 구간을 제거한다. 중단이 있으면 뒤 구간의 `break_before`에 보통 2초의 사실적인 안내를 넣는다. 경계가 불명확하면 분명한 보존 구간으로 좁히고 제외된 내용을 알린다.

## 생성·검증·전달

```bash
python3 "$TOOL" build '/실제/manifest.json'
python3 "$TOOL" verify '/실제/manifest.json'
```

도구는 PNG 전체 프레임, 설명을 붙인 별도 비교 시트, 요청한 편집본과 사진 ZIP을 만든다. 원본의 표시 방향과 시간축을 유지하고, 명목 120fps만 보고 배속하지 않는다. 편집 음성은 영상과 같은 구간에서 가져온다. 음성이 없는 원본 구간에 연결용 무음이 필요하면 그 사실을 기록한다.

사진·시트 전체와 최종 영상 시작·모든 연결점·끝을 직접 연다. 파일명·캡션 시각은 manifest의 실제 프레임 시각과 대조한다. `review.photos`와 `review.boundaries`는 해당 확인 뒤에만 `verified`로 바꾼다. `review.audio`는 직접 청취했다면 `verified`, 불가능하면 `unavailable`로 적고 청감 미확인을 전달한다. 다시 `verify`를 실행해 `complete: true`를 확인한다. 수치상 동기는 실제 청취를 대신하지 않는다.

검증은 원본 해시, 사진 출처·방향, 영상 전체 디코딩, 출력 길이·프레임률·회전·A/V 종료차, ZIP 무결성을 확인한다. 실패하면 해당 원인을 해결한 뒤 재검증한다. 부분 생성본이나 기존 결과는 덮어쓰지 않고 새 실행으로 남긴다.

사진은 `<실험NN>/실험사진/<촬영명>_영상추출/`, 근거는 `<실험NN>/output/<촬영명>_영상분석/`, 최종 MP4·사진 ZIP은 다운로드 폴더에 둔다. 새 실행의 MP4는 사진 요청 유무와 관계없이 위 `실험사진/<촬영명>_영상추출/`에도 같은 파일명으로 복사한다. 검증은 두 MP4의 SHA-256이 생성 시 기록과 일치하는지도 확인한다. 사진 ZIP에는 MP4를 포함하지 않는다. 경로를 지정받으면 `--experiment-dir`·`--deliver-dir`로 따르되 실험 폴더 보관은 유지한다. 생성 임시물은 실행 폴더 안에서만 정리한다.

마지막에 사진·시트 수, 영상 길이, 압축 전후 용량·절감률, 다운로드·실험 폴더의 파일 링크와 중요한 미확인 사항을 전달한다. 기존 `기록.md`·보고서는 자동으로 채우지 않는다. 이 스킬의 비교 PNG는 기록의 확정값으로 만드는 `export-photo-sheet` 시트와 구분한다. 커밋·푸시는 별도 요청이 있을 때만 한다.
