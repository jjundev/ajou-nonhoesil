# review-hand-diagram

손그림 결선도를 참조와 대조한다. 선 끝점과 신호 이름이 가리키는 대상은
사람(vision)이 전사(轉寫)하고, **결함 검사와 최종 판정은 코드가 전사에 적용한다.**
판정문에 별도의 사람 판정을 덧씌우지 않는다.

## 왜 코드가 판단하는가

2026-09-08 회차에서 사람이 눈으로 대조하다 **LED 사슬 검사를 통째로 건너뛰었다.**
칩별 전원·미사용핀·신호선만 보고 통과시켰는데, 재검토에서 저항이 한 행 위에
꽂혀 LED 가 아예 안 켜지는 것이 나왔다. 절차서를 더 써서 막을 수 있는 종류가
아니다 — 절차는 이미 알고 있었고 그중 하나를 건너뛴 것이다.

그래서 검사를 `scripts/lab/hand_compare.py` 의 `_RULES` 목록에 넣었고,
`tests/test_hand_compare.py` 가 **`check_` 로 시작하는 함수가 전부 목록에
올라 있는지** 검사한다.

## 인자

`<N주차|실험N> <PDF 경로> [round<N>]`

- 번호 토큰이 없으면 한 줄로 되묻고 중단한다.
- `round<N>` 이 없으면 기존 `round*` 폴더 중 최대 번호 + 1 을 쓴다.
- 출력 폴더는 `<실험NN>/output/손그림검토/round<N>/` 이다.

## 실행 절차

### 1. 실험 번호를 폴더 이름으로 옮긴다

사용자는 "실험1", "2주차", "다음 실험" 으로 부르고 경로는 `<실험NN>/` 이다.
손으로 `실험1` 이라고 적지 않는다 — 0 을 안 채우면 `실험10` 이 `실험2` 앞에 선다.

```bash
python3 -c "
from scripts.lab import config
print(config.experiment_dir(<실험번호>))
"
```

주차로 불렸으면 `config.experiments_in_week(<N>)`, 날짜로 불렸으면
`config.next_experiments()` 를 쓴다. 리스트가 둘 이상이면 되묻고 중단한다.

폴더가 없으면 **거절하고** `init-lab-experiment` 를 안내한다. 만들어 주지 않는다.

### 2. 쪽마다 판형을 꺼내고 격자를 덮는다

```bash
python3 -c "
from scripts.lab import hand_grid
import sys
pdf = sys.argv[1]
out = sys.argv[2]
import fitz
n = len(fitz.open(pdf))
for i in range(n):
    b = hand_grid.board_image(pdf, i)
    cal = hand_grid.calibrate(b)
    page = hand_grid.render_page(pdf, i)
    hand_grid.overlay_grid(page, cal, f'{out}/격자/p{i+1}.png')
    print(i+1, b.md5[:8], round(cal.res_x,2), round(cal.res_y,2))
" <PDF> <출력폴더>
```

`GridError` 가 나면 그대로 알리고 중단한다. 판형이 다른 그림 위에 그렸거나
판형이 바뀐 것이다 — 추측으로 넘어가지 않는다.

### 3. 격자 그림을 보고 전사한다

`격자/p<N>.png` 를 읽고 `전사/p<N>.json` 을 쓴다. **이 단계만 사람(vision)이
한다.**

```json
{
  "page": 3,
  "circuit": "e1_nand",
  "title": "2-1 NAND Gate",
  "signed": false,
  "chips": [
    {"label": "74HC08", "block": "좌", "pin1_row": 7, "pin1_col": "e"},
    {"label": "74HC00", "block": "좌", "pin1_row": 17, "pin1_col": "e"}
  ],
  "wires": [
    {"color": "빨강", "from": "좌 g7", "to": "좌 중앙VCC레일7행"},
    {"color": "검정", "from": "좌 GND레일7행", "to": "좌 b7"}
  ],
  "leds": [{"tag": "L1", "anode": "좌 c14", "cathode": "좌 c15"}],
  "resistors": [{"tag": "L1", "top": "좌 d15", "bottom": "좌 d16"}],
  "bridges": [{"kind": "gnd", "from": "좌 GND레일29행", "to": "좌 중앙GND레일29행"}],
  "labels": [{"name": "A", "at": "좌 GND레일7행"}, {"name": "L1", "at": "좌 c14"}],
  "uncertain": []
}
```

전사 규칙:

- **끝점과 점만 홀로 읽는다.** 선이 지나가는 홀은 적지 않는다. 끝점이 아닌
  자리에 점이 찍혀 있으면 그 자리도 꽂힌 것으로 읽는다 — 출력끼리 맞물린
  결함이 그렇게 나타난다.
- 두 행 사이로 보이면 **3배로 확대해** 다시 본다.
  `hand_grid.crop_rows(page, cal, 시작행, 끝행, 경로, scale=3)`.
- 그래도 못 정하면 그 주소를 `uncertain` 에 올린다. 추측으로 채우지 않는다.
- 색은 보이는 대로 적되 **판정에 쓰지 않는다.** 색이 틀려도 끝점이 맞으면
  통과, 색이 맞아도 끝점이 틀리면 오류다.
- **연결 대상을 판독할 수 있는 신호 이름을 `labels` 에 적는다** — 입력 `A`·`B`·`C` 와 출력
  `L1`·`L2`·`X`·`Y`·`Z`, 입력도 LED 도 없는 주차의 계측 지점 이름(실험02
  `VIN`·`VOUT`·`CH1`·`CH2`) 같은 글자다. `at` 은 그 글자가 붙어 있는 점퍼 끝이나 LED
  다리의 홀(계측 이름은 그 스트립의 홀)이다. **보드 밖 여백의 글자라도 화살표·연결선이
  하나의 대상 점퍼 끝·LED 다리·계측 스트립을 분명히 가리키면 적는다.** 화살표 끝이
  홀에 직접 닿을 필요는 없지만, 이름과 대상 신호가 일치해야 한다. 여백에 이름만 있거나
  가리키는 대상이 여럿이면 3배 확대한다. 그래도 분명하지 않으면 그 이름은 빼고
  `증거/` 에 크롭을 남긴다. 여백 글자를 확대할 때는 `crop_rows` 가 글자를 자를 수
  있으므로 원본 페이지에서 글자·화살표·대상 끝점을 모두 포함해 자른다. 이름이
  하나도 없으면 `"labels": []` 로 두고 H15 가 잡는다.
- **칩은 pin 1 표시가 어느 열인지 적는다.** 노치가 위를 보면 `"pin1_col": "e"`,
  아래를 보면 `"f"` 다. 없으면 e 로 읽는다. 채널을 걸치지 않은 칩(pin 1 이
  a~d·g~j 열)은 전사가 못 담으니 그 pin 1 홀을 `uncertain` 에 올린다 — H13
  보류로 사람에게 간다.
- 회로 ID(`circuit`)는 제목과 칩 라벨로 고른다. 완성본을 따라 그렸으면 실험01
  `e1_and` · `e1_or` · `e1_nand` · `e1_nor` · `e1_comb`, 실험02 `e2_inv` ·
  `e2_schmitt`, 실험03 `e3_fa` · `e3_fs` 중 하나다. 단계 그림을 따라 그렸으면
  `_s1`·`_s2` 가 붙은 ID 를 쓴다(전체 목록은 `hand_compare.CIRCUITS`). `e2_tpd`·
  `e3_ha`·`e3_hs` 도 목록에 있지만 조교 공지 `_350547_1` 로 하지 않는 회로라 손그림이
  올 일이 없다 — 렌더러 회귀 사례로만 남았다.
- **같은 글자는 적힌 개수만큼 `labels` 에 따로 적는다.** 실험03 반감산기는 입력
  `B` 와 출력 `B` 가 같은 글자다 — 하나로 합치면 H15 가 출력 `B` 를 빠뜨린
  것으로 잡는다.
  H15 는 개수만 세고 자리는 보지 않으므로, 입력 `B` 를 두 번 적고 출력 `B` 를
  빠뜨린 그림도 조용하다 — 반감산기는 LED 옆 `B` 를 사람이 눈으로 확인한다.

### 4. 대조하고 판정문을 낸다

```bash
python3 -c "
from pathlib import Path
from scripts.lab import hand_compare as hc
from scripts.lab.hand_transcript import parse_transcript
import sys
out = Path(sys.argv[1]); rnd = int(sys.argv[2])
pages = []
for p in sorted((out/'전사').glob('p*.json')):
    hand = parse_transcript(p)
    ref = hc.reference_diagram(hand.circuit)
    pages.append((hand.page, hand.circuit, hc.compare(ref, hand), hand))
(out/'판정.md').write_text(hc.judgment_markdown(pages, rnd), encoding='utf-8')
for page, _c, fs, _h in pages:
    for f in fs:
        print(page, f)
" <출력폴더> <라운드번호>
```

### 5. 치명 결함마다 증거 크롭을 만들어 보낸다

결함의 `where` 에 행이 들어 있으면 그 행 앞뒤 5행을 잘라 `증거/` 에 넣고
`SendUserFile` 로 보낸다. 사용자가 직접 눈으로 확인할 수 있어야 한다.
H15 이름의 화살표 대상이 불분명해 전사에서 뺐다면 그 자리도 확대 크롭으로 남긴다.

### 6. 요약한다

판정문 총평(`제출 가능` / `수정 필요`)을 먼저 말하고, 쪽별로 고칠 선을
**손그림 좌표로** 적는다. 참조 좌표를 그대로 옮기지 않는다 — 칩이 밀려 있으면
참조 좌표가 다른 자리를 가리킨다. 사람 판독으로 코드 판정을 덮어쓰지 말고,
판독 가능한 화살표 이름을 먼저 `labels` 에 전사한 뒤 코드를 다시 실행한다.
모든 쪽이 `제출 가능`으로 판정되면, 보고서 및 노션 첨부용 300 DPI 크롭 PNG 를 생성하기 위해 `/export-hand-diagram <실험번호>` 실행을 사용자에게 안내한다.

**치명·기능이 0건이면 제출 가능이다.** 표기는 막지 않고 별도 줄로 알린다 —
학번 미기재로 제출을 막을지는 채점 관행이지 회로 문제가 아니다.

**H15 는 표기가 아니라 기능이다.** 2026-09 실험01 예보에서 조교가 "결선도에 입력
A·B·C 위치 표기가 없어 확인하기 어렵다" 며 실제로 감점했다(-1). 회로는 돌아도
채점에서 깎이므로 제출을 막는다. 이름을 개수까지 세고 자리는 보지 않는다(실험03
반감산기의 입력 B 와 출력 B 는 둘로 센다) — 행이 밀려도 넷이 같으면 통과시키는
이 검사기의 원칙과 같다. 보드 밖 글자의 화살표가 무엇을 가리키는지는 전사 단계에서
판독한다. 연결 대상이 분명하면 `labels` 에 넣고 코드 판정 하나로 결론낸다.

실험01 `output/손그림검토/round1~8` 의 전사·판정은 2026-09-12 슬롯 고정 이전
배치(칩 10행 등) 기준이다 — 지금 참조 빌더와 대조하면 통째로 어긋나므로
재검토 근거로 쓰지 않는다.

## 판정할 때 지키는 것

- **행이 밀린 것은 오류가 아니다.** 칩과 배선이 함께 옮겨져(또는 뒤집혀)
  있으면 그림은 유효하다. H10 이 표기로만 알린다. 참조 좌표와 다르다는 이유로
  치명을 매기지 않는다. 다만 **따라오지 않은 요소가 옮겨진 칩의 핀 행에 앉으면
  H14 가 원인을 낸다** — 2026-09-09 시험 PDF 에서 74HC00 이 한 행 올라갔는데
  L1 저항만 참조 자리에 남아 아랫다리가 pin 1 행에 앉은 것이 그 사례다. H7 이
  증상을, H14 가 원인을 말한다. 요약할 때 H14 를 첫 줄에 둔다.
- **참조 그림도 의심한다.** 참조가 `overlap_warnings` 에 올린 배선은 다른 선에
  깔려 잘 안 보이는 자리다. H6 메시지에 그 사실이 붙는다 — 놓친 쪽을 탓하기
  전에 원도를 본다. 2026-09-08 5쪽에서 빠진 `A → 74HC32 pin 1` 이 그런 선이었다.
- **한 결함을 두 번 보고하지 않는다.** 브리지 누락은 H8 만 낸다. 미사용핀은
  H4·H5 가 보고 H6 에서는 뺀다.

## 비-목표

- 결선도를 그리지 않는다. 참조는 `breadboard-diagram` 이 만든다.
- 손그림 선을 자동 벡터화하지 않는다. 검정이 신호선·칩 글자·저항을 겸해서
  색으로 갈리지 않는다.
- 다이오드 극성을 판정하지 않는다. 손그림이 점 하나라 판정 불가다.
- 명세·보고서를 검증하지 않는다. `review-lab-report` 가 한다.
