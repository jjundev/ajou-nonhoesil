## 특이사항 — diff 가 아니라 직접 지시로 들어온 라운드

이 라운드는 사용자가 노션에서 고친 뒤 되읽는 정상 경로가 아니라, **검토 중에 규칙 네 개를
말로 준 것**이다. 그래서 diff 분류 표 대신 규칙을 그대로 옮긴다. 네 건 모두 **체계적**이며,
사용자가 "앞으로 생성되는 보고서들도 따르는 것"임을 명시적으로 확인했다.

발단은 사용자가 보고서를 읽다가 **"교안이 뭘 말하는거야?"** 라고 물은 것이다. 본인이 낸
보고서를 읽으면서 용어를 되물었다는 것은 채점자도 같은 의문을 가질 수 있다는 뜻이었다.

## 2번이 지목한 실제 문장들 (v1 에서 잡아낸 AI 티)

- `이 보고서가 vision 으로 직접 열람해 판독했다` — 문서가 자기 제작 과정을 설명한다
- `이 하네스는 핀 번호를 바코드처럼 나열한 자동 배선도를 만들지 않는다` — 도구를 언급한다
- `행 수(30)는 scripts.lab.render.crop_rows(netlist_text) 계산값이다` — 코드 식별자
- `이 보고서에서도 서로 바꿔 쓰지 않는다` — 자기 지칭
- `명세(실험01/체크리스트/명세.md)에 role: reference 로 등록된 참조표` — 스키마 용어

판정 기준으로 삼은 것: **손으로 쓰는 학생이라면 이 문장을 쓸 이유가 있는가.**
프로그램이 만들었기 때문에만 성립하는 문장이면 지운다.

## 4번이 만든 긴장과 해소

v1 의 참고문헌 6개 중 강의노트는 2개뿐이었고 나머지는 데이터시트·명세·결선도였다.
그런데 §절대 규칙 5(없는 근거를 지어내지 않는다)가 여전히 살아 있다.

해소 방식: **핀 배치를 표준 74HC DIP-14 배치로 제시하고, 실물 칩 각인과 대조하라고
적었다.** 데이터시트 파일명을 인용하지도, 근거 없이 단정하지도 않는다. 실험 전 확인
사항 절(§5.5)이 그 대조를 명시적으로 요구한다.
