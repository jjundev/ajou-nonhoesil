# 과거 코퍼스 감사

`from_the_past/정리/예비보고서/`·`결과보고서/` 의 학생 제출본을 교안·데이터시트와
대조해 **어느 제출본의 어느 대목이 틀렸는지**를 주차별로 남기는 곳이다.

## 다른 두 로그와 무엇이 다른가

출처가 셋 다 다르다.

| 폴더 | 무엇의 기록인가 |
|---|---|
| `docs/notion-feedback/` | 사용자가 노션에서 고친 것 |
| `docs/rule-friction/` | 격리 에이전트가 규칙을 실행하다 부딪친 것 |
| `docs/corpus-audit/` | **과거 제출본이 틀린 자리** |

## 왜 남기는가

이 과목의 과거 제출본은 **자료 권위 5순위이고 알려진 오염이 있다**
(`.claude/skills/explain-lab-preview/SKILL.md` 의 grounding 절). 그런데 명세를
새로 짤 때는 그 코퍼스를 읽게 된다 — 다른 주차의 실물 자료가 그것뿐인 경우가
있기 때문이다. 그때 "이 편의 이 대목은 틀렸다" 를 알고 보는 것과 모르고 보는
것은 다르다.

대조는 한 번 하는 데 비싸다. 실험02 는 PDF 38쪽을 읽는 데 13분이 걸렸다.
그 자리에서 적지 않으면 다시 만들어야 한다.

## 이 문서들의 지위 — 정본이 아니다

**여기 적힌 것은 단서지 확정 사실이 아니다.** 감사 자체가 에이전트 한 번의
판독이고, 대상이 5순위 코퍼스다. 각 문서의 머리에 **무엇을 사람이 검증했고
무엇을 안 했는지**를 반드시 적는다. 검증 안 된 항목을 근거로 명세를 고치기
전에 그 항목부터 다시 확인한다.
