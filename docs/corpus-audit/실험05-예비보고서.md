## 2. 우리 보고서의 내용 문제

### F1 (하) — "갈라 주는 것은 `GS` 하나뿐이다" 는 사실과 다르고, 같은 보고서가 두 번 스스로 반박한다

**어디**: `실험05/output/실험05_예비보고서.md:59`
> `GS` (Active Low) 는 … `EO` (Active Low) 는 칩이 켜져 있는데 활성 입력이 하나도 없을 때 0 이
> 된다. **이 두 신호가 필요한 이유는** 코드 출력만으로는 "아무 입력도 없음"과 "0번 입력이 활성"을
> 구별할 수 없기 때문이다. 두 경우 모두 코드 출력이 같은 값으로 나오고, **갈라 주는 것은 `GS`
> 하나뿐이다.**

**무엇이 틀렸나**

`EI` 가 0 인 동안 `GS` 와 `EO` 는 서로의 보수다. 보고서 자신의 T6 표(`:188`~`:197`)를 보면:

| 상태 | `A2 A1 A0` | `GS` | `EO` |
|---|---|---|---|
| 아무 입력도 없음 (1행) | 1 1 1 | 1 | **0** |
| `IN0` 만 활성 (마지막 행) | 1 1 1 | 0 | **1** |

`EO` 도 `0` ↔ `1` 로 갈린다. **두 상태를 가르는 신호는 두 개**다. 이 문장은 앞 절("이 두 신호가
필요한 이유는")과도 어긋난다 — 이유가 하나뿐이면 신호 하나만 있으면 된다.

같은 보고서가 뒤에서 두 번 반대로 말한다:

- `:317` (실험 전 확인 사항): "`EI` 를 GND 에 물린 상태에서는 아무 스위치도 내리지 않아도 `EO`
  LED 하나가 켜져 있으므로, 이 LED 를 회로가 살아 있다는 표시로 삼는다." — 이것이 바로 `EO` 로
  "아무 입력도 없음"을 판별하는 절차다.
- `:308` (8X3 결선 절)도 같은 논지다.

`EO` 가 실제로 존재하는 이유는 **캐스케이딩**이다 — 여러 개의 74HC148 을 이어 붙일 때 상위 칩의
`EO` 가 하위 칩의 `EI` 로 들어가, "내 쪽엔 활성 입력이 없으니 네가 받아라"를 전달한다. 이 사실은
보고서 어디에도 없다.

**근거**: `실험5 예비보고서 201006.pdf` p4 에 실린 벤더 Truth table(§4 참조) 1·2행과 마지막 행,
그리고 `실험5 결과보고서 181019.pdf` case1·case2·case10 실측이 모두 `GS`/`EO` 가 동시에 갈리는
것을 보여 준다.

**왜 중요한가**: 낮다. 표 값이 옳고 절차도 옳으므로 실측을 틀리게 하지 않는다. 다만 결과보고서
고찰에서 "`GS` 와 `EO` 는 왜 둘 다 있나"를 물으면 답을 낼 수 없다.

**고칠 방향(참고)**: "갈라 주는 것은 `GS` 하나뿐이다" → "이 두 경우는 `GS` 와 `EO` 가 서로 반대로
서서 갈린다. `EO` 는 여기에 더해 칩을 여러 개 이어 붙일 때 다음 칩의 `EI` 를 몰아 주는 캐스케이딩
출력이다."

### F2 (하) — 교안 준비물에 없는 `SPDT 스위치 8개` 를 근거 표시 없이 준비물 표에 올렸다

**어디**: `실험05/output/실험05_예비보고서.md:94`
> | SPDT 스위치 | 8개 | 입력 인가용. 8X3 우선순위 인코더가 여덟 개를 쓴다 |

**무엇이 문제인가**

교안 p2 "실험준비" 는 일곱 줄이고 그 전부가 IC·LED·저항이다 — `74HC04` 1, `74HC08` 1, `74HC20` 2,
`74HC42` 1, `74HC148` 1, LED 10, 330Ω 10. **스위치는 한 줄도 없다.** 회로도(p8·p13·p14·p22)가
`SW SPDT` 심볼을 그려 두었을 뿐이다.

저장소의 다른 문서는 이 불확실성을 이미 올려 두었다 — `실험05/결선도/netlist.md` 의 **M3**:
"교안이 입력 소자를 `SW SPDT` 로 그렸으나 실험실 키트에 SPDT 딥스위치가 있는지는 명시하지 않는다."
보고서는 같은 표에서 `74HC148` 의 전원핀에 대해서는 한 문단을 따로 떼어 미확정임을 밝히면서
(`:113`), 스위치는 확정 수량처럼 적었다. **불확실성 표시가 항목마다 다르다.**

수량 8 자체는 옳다(P4 가 8개, P3 이 6개, P2 가 4개, P1 이 2개이므로 최대 8). 브레드보드·점퍼선도
교안에 없지만 그쪽은 실험대 소모품이라 다투기 어렵고, 스위치는 **없으면 회로가 안 돌아가는 부품**
이라는 점이 다르다.

**과거 제출본 대조**: 5편 중 스위치를 준비물에 적은 편은 **없다**(`160408`·`181012`·`201005`·
`201006`·무날짜 모두 교안 p2 목록만 옮겼다). 다수결도 우리 쪽이 아니다.

**왜 중요한가**: 낮다. 보고서 `:318` 이 "SPDT 스위치가 없으면 점퍼선을 +5V 나 GND 에 직결하고,
입력을 띄운 채로 두지 않는다"로 대안을 이미 적어 두어 실험이 막히지는 않는다.

**고칠 방향(참고)**: 비고 칸에 "교안 준비물에는 없다. 회로도가 `SW SPDT` 로 그렸을 뿐이므로 키트
확인 필요" 한 줄을 넣으면 끝난다.

**왜 중요한가**: 낮다. 다만 결과보고서에서 P3 의 출력과 P4 의 출력을 서로 대응시키려 들면 답이

## 3. 과거 제출본이 틀린 자리 — 저장소 오염 기록용

### C1. Excess-3 의 십진 2 행을 `0010` 으로 적었다 — `실험5 예비보고서 181012.pdf` (p5), `실험5 예비보고서 201005.pdf` (p7)

두 편이 **같은 값으로 틀렸다.** 표 이미지로도 확인했다.

| 입력 | 두 편이 적은 출력 | 옳은 값 |
|---|---|---|
| `SW0` | 0011 | 0011 ✓ |
| `SW1` | 0100 | 0100 ✓ |
| **`SW2`** | **0010** | **0101** |
| `SW3` | 0110 | 0110 ✓ |
| `SW4` | 0111 | 0111 ✓ |
| `SW5` | 1000 | 1000 ✓ |

십진 2 의 Excess-3 는 2 + 3 = 5 = `0101` 이다. 자기 표의 다른 행과도 어긋나고, 회로가 만드는 식
(`Bit2 = SW1+SW2+SW3+SW4` 이므로 `SW2` 에서 `Bit2` 는 반드시 1)과도 어긋난다.

**두 편이 일치하지만 다수결로 채택하면 안 되는 사례다.** `181012`(2018)와 `201005`(2020)는 본문
문장과 표 서식이 거의 동일해 같은 계보로 보이므로 독립 관측 두 개가 아니다. 반증도 셋 있다:

- `실험5 결과보고서 201005.pdf` 의 **실측표**가 같은 행을 `0101` 로 적어 **자기 예보를 반증한다.**
- 퀴즈 `기출_풀이.pdf` Q1: `0010`(십진 2) → Excess-3 `0101`.
- `201006` 예보·결보와 무날짜 편 모두 `0101`.

### C2. `74HC148` 예상 진리표를 양논리 표로 갈아 끼웠다 — `실험5 예비보고서 181012.pdf` (p6), `실험5 예비보고서 201005.pdf` (p8)

두 편 다 슬라이드 제목은 "74HC148을 이용한 8 X 3 Priority Encoder" 인데, 실린 표는 일반
octal-to-binary priority encoder 의 **양논리** 표다:

- 입력 활성 = **1** (74HC148 은 0)
- 출력 = 그 번호의 2진수 **그대로** (74HC148 은 보수)
- `GS`·`EO` 열이 **없다** (74HC148 은 이 둘이 출력의 절반이다)

`201005` 는 아예 "Octal – to – Binary Priority Encoder Truth Table" 이라는 캡션이 붙은 외부
이미지를 그대로 붙였다(입력 `D0`~`D7`, 출력 `Y2 Y1 Y0`). 같은 조의 `실험5 결과보고서 201005.pdf`
실측표는 `L`/`H` 로 정반대 값을 적어, 예보와 결보가 서로 모순된다.

이 표를 그대로 믿고 실험실에 들어가면 LED 다섯 개 중 어느 것도 예상과 맞지 않는다.

### C3. 실험 부품 목록에 `74HC86` 이 들어가고 `74HC20`·`74HC148` 이 빠졌다 — `실험5 예비보고서 201005.pdf` (p3)

> 실험 준비물: 5V 전압원, 74HC04, 74HC08, 74HC42, **74HC86**, 저항, LED 등.

`74HC86`(XOR)은 이 주차에 쓰지 않는다(가산기 주차 부품이다). 반대로 실제로 쓰는 `74HC20` 2개와
`74HC148` 1개가 목록에서 빠졌다. 바로 다음 두 쪽의 소자 표에는 `74HC20`·`74HC148` 이 정상으로
들어 있으므로 목록 줄만의 오기로 보이지만, 교안 p2 준비물과 어긋난다.

### C4. 2X4 진리표의 입력 열 이름이 값과 반대 순서다 — `실험5 예비보고서 201006.pdf` (p9), `실험5 결과보고서 201006.pdf`

두 문서가 같은 표를 쓴다. 헤더는 `Bit0 Bit1`(LSB 먼저)인데 값은 `Bit1 Bit0` 순서다.

| 헤더대로 읽으면 | 십진 | 표가 켠 LED | 옳은 LED |
|---|---|---|---|
| `Bit0=0, Bit1=1` | 2 | `D3` | `D2` |
| `Bit0=1, Bit1=0` | 1 | `D2` | `D3` |

같은 문서의 부울식(`D2=A'B`, `D3=AB'`)과도, 결보 결과 분석의 문장("만약 1,0의 Input이 들어오면
D2와 연결된 다이오드에 불이 들어오게 된다")과도 어긋난다. **값은 우리와 같고 헤더만 뒤집혔다.**

### C5. `74HC148` 표의 출력 열 이름이 값과 반대 순서다 — `실험5 예비보고서 201006.pdf` (p11), `실험5 결과보고서 201006.pdf`

헤더는 `A0 A1 A2`(LSB 먼저)인데 값은 MSB 먼저 적혀 있다. `IN6` 활성 행이 `0 0 1` 인데, 헤더대로
읽으면 `A0=0, A1=0, A2=1` 이다. 실제 74HC148 은 `A2=0, A1=0, A0=1` 이다. 같은 문서 p4 에 자기가
붙여 넣은 **벤더 Truth table 과도 어긋난다.**

### C6. BCD to Decimal 표의 스위치 번호가 교안과 반대다 — `실험5 예비보고서 160408.pdf` (p6), `실험5 예비보고서.pdf` (무날짜, p5)

두 편 다 입력 열이 `SW1 SW2 SW3 SW4` 이고 `0 0 0 1` 행에서 `Y1` 이 내려간다 — 즉 **`SW4` 를 LSB**
로 본다. 2020-2 교안 p13 은 `SW1` 옆에 `Bit0` 을, `SW4` 옆에 `Bit3` 을 붙이고 `SW1` 을 pin 15
(`A`, LSB)에 물린다. 값 자체(어느 `Y` 가 어느 입력에서 내려가는가)는 우리와 같고, **열 이름만**
반대다.

**단정하지 않는다.** 두 편 모두 2016년 또는 연도 미상이고, 저장소에는 2020-2 교안만 있어 그
시절 교안의 스위치 번호 규약이 달랐을 가능성을 배제할 수 없다. 다만 2020년 세 편(`201005` 결보의
`SW4 SW3 SW2 SW1`, `201006` 의 `bit3 bit2 bit1 bit0`, `181019` 의 `Bit3 Bit2 Bit1 Bit0`)은 모두
MSB 를 왼쪽에 두고 LSB 쪽이 `SW1`/`bit0` 이라 교안과 정합한다.

### C7. `74HC42` 의 BCD 아닌 입력을 "의미 없는 출력" 이라고 적었다 — `실험5 결과보고서 181019.pdf` (고찰), `실험5 결과보고서 201005.pdf` (고찰)

> 이진수 표현상 10이상의 값을 가지는 1010, 1011, 1100, 1101, 1110, 1111 는 입력에서 회로가 의미
> 없는 출력을 내보낸다.

`74HC42` 는 그 여섯 입력에서 **출력 10개가 전부 HIGH** 라는 정의된 동작을 한다(선택되는 출력이
없음). "의미 없는 출력" 이 아니다. `201005` 결보는 같은 문장을 쓴 뒤 다음 문단에서
"입력이 … 1010~1111인 경우 모든 출력이 H임을 알 수 있다" 라고 스스로 정정한다. `181019` 는
정정하지 않는다.

### C8. Excess-3 인코더의 LED 위아래 순서를 뒤집어 적었다 — `실험5 결과보고서 201005.pdf` (실험 3 분석)

> LED 4개( 위에서부터 **Bit0, Bit1, Bit2, Bit3** 을 나타냄. )

교안 p14 의 출력 라벨은 위에서부터 `Bit3`, `Bit2`, `Bit1`, `Bit0` 이다(U2A→`Bit3`, U2B→`Bit2`,
U3A→`Bit1`, U3B→`Bit0`). 같은 문서의 실측표는 값이 옳으므로 서술만의 오기다.

### C9. `74HC148` 의 우선순위 방향을 반대로 설명했다 — `퀴즈/실험5/실험5 퀴즈 해설.pdf` (p1)

> **IN0가 가장높은 우선순위, IN7이 가장 낮은 우선순위이다.** 따라서 IN0쪽에 가까운 입력 핀에
> **HIGH신호**가 되었을 때 2진화 시켜 출력으로 나타난다.

두 군데가 틀렸다. `74HC148` 은 **`IN7` 이 최우선**이고, 입력은 **active-low** 라 활성 신호는 LOW
다. 바로 다음 문장이 스스로를 반박한다 — "6번 7번이 각각 L, H일 때 출력은 … L L H가 출력된다.
… 같은원리로 7번이 L이면 출력은 … L L L" 은 `IN7 > IN6` 일 때만 성립한다. 같은 문서의 표(3행)도
우리와 값이 같다.

**해설 문서가 표는 맞고 산문만 틀린 형태**라 인용할 때 특히 위험하다.
