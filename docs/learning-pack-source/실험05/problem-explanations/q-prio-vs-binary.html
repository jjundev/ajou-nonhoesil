이 문제에서 할 일

일반 인코더의 한 입력 가정이 깨지는 예를 보인 뒤 우선순위 규칙이 해결하는 일을 비교해요.

이 문제를 봤을 때 떠올릴 개념과 공식

동시 입력 시 일반형은 OR 혼합, 우선순위형은 최상위 하나

문제에 “Priority encoder”를 “Binary encoder와 비교”하라는 말이 보이면 D1·D2가 동시에 켜진 예를 떠올려요. 일반형은 비트 OR가 섞여 011을 내지만 우선순위형은 순위가 높은 하나만 골라, 번호 큰 쪽 우선이면 D2의 010을 내기 때문이에요.

“특징을 Binary encoder와 비교”에서는 one-hot 전제와 다중 활성 처리 규칙을 비교해요. 일반 인코더는 한 활성 선 번호를 코드로 바꿔요.

OR형 일반 인코더에서 D1과 D2가 동시에 1이면 001 OR 010=011이라 어느 요청도 나타내지 못해요. 번호 큰 쪽 우선이면 D2를 골라 010을 내요.

우선순위는 정해진 규칙이 있을 때만 선택을 결정해요. 모든 활성 요청을 한꺼번에 기록하거나 일반 인코더가 자동으로 큰 번호를 고르는 것은 아니에요.

첫 줄을 이렇게 시작해요

D1=D2=1인 상황을 정하고 일반형 출력 A1=D2+…, A0=D1+…부터 계산해요.

필요한 개념: 우선순위 인코더와 74HC148을 배워요 · 인코더는 켜진 줄의 번호를 코드로 바꿔요

왜 이렇게 푸는지 함께 따라가요

일반 OR형은 두 비트를 동시에 1로 만들어 011을 내요. 켜지지 않은 D3 코드가 되어 해석이 틀어져요. 번호 큰 쪽 우선인 priority형은 D2 하나를 골라 010을 내요. 모든 다중 입력이 반드시 엉뚱한 번호를 내는 것은 아니지만 일반형의 출력 의미는 보장되지 않아요.

풀이

Binary(일반) 인코더는 한 줄만 켜진다고 가정해서 출력 비트를 “그 비트가 1인 번호들의 OR”로 만들어요. 8×3에서 D1과 D2가 동시에 1이면 A1=1, A0=1이라서 011이 나오고, 이는 1도 2도 아닌 3의 코드예요.

우선순위 인코더

Priority 인코더는 동시에 켜진 입력 중 우선순위가 가장 높은 입력만 코드로 내요. 번호가 큰 쪽이 우선이면 D1과 D2가 동시에 1일 때 D2의 코드 010이 나와요.

완성 답과 검산

여러 입력이 동시에 1이면 Binary 인코더는 한 입력만 활성이라는 가정이 깨져 코드의 의미가 보장되지 않고, Priority 인코더는 우선순위가 높은 입력의 코드만 내요.

같은 D1,D2 입력으로 일반형 011과 우선순위형 010이 다르게 나오는지 식에 대입해요.

검산: 8×3 일반 인코더 식 A1=D2+D3+D6+D7, A0=D1+D3+D5+D7에 D1=D2=1을 넣으면 A2A1A0=011이에요.

여기서 헷갈리기 쉬워요

흔한 실수: 우선순위 인코더가 모든 입력을 합쳐 계산한다고 쓰면 반대예요. 하나만 골라요.

이제 설명을 닫고 다시 풀어요
  1. D1=D2=1인 상황을 정하고 일반형 출력 A1=D2+…, A0=D1+…부터 계산해요.
  2. 앞의 풀이를 보지 않고 문제에서 요구한 모든 표·식·회로·설명을 완성해요.
  3. 같은 D1,D2 입력으로 일반형 011과 우선순위형 010이 다르게 나오는지 식에 대입해요.
