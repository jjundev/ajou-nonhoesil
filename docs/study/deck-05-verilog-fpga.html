Paradigm Shift Hardware Concurrency vs Software

Verilog HDL vs C언어의 결정적 차이

소프트웨어의 순차 실행(Sequential)과 하드웨어의 공간적 동시 실행(Concurrent)

비교 항목C 언어 (Software)Verilog HDL (Hardware)
실행 방식CPU가 명령어를 위에서 아래로 **순차 실행 (Sequential)**모든 회로 모듈이 전원 인가 시 **동시에 동작 (Concurrent)**
변수의 본질RAM 메모리 주소 공간의 임시 보관함실제 구리 도선(wire) 또는 플립플롭(reg)
시간(Time)코드 실행 시간은 CPU 클록 속도에 종속실제 게이트 전파 지연($t_{pd}$) 및 클록 에지 명시
컴파일 결과기계어 바이너리 명령어 스트림 (.exe / .hex)LUT, 플립플롭, 배선 매핑 비트스트림 (.bit)
💡 하드웨어 엔지니어의 마인드셋
• 코드를 작성할 때마다 "이 코드가 어떤 실물 게이트와 플립플롭으로 합성될 것인가?"를 머릿속으로 그리며 작성해야 합니다.
• always @(posedge clk) 블록 1개는 실제 실리콘 다이 위에 D 플립플롭 하드웨어 뱅크를 생성합니다.
• assign 문 1개는 실제 조합논리 게이트 망을 배선합니다.

[C언어 개발자가 가장 많이 하는 실수]

C언어의 for 루프는 시간을 두고 반복 실행되지만, Verilog의 for 루프는 하드웨어 회로를 그 횟수만큼 병렬 복제(Unrolling)하여 면적을 수십 배로 키워버립니다.

Syntax Core Module Structure & Data Types

Verilog 기본 구조와 wire vs reg

모듈 선언 뼈대, 포트 입출력, 진법 표기법 및 2대 핵심 데이터 타입

module FullAdder ( input wire a, input wire b, input wire cin, output wire sum, output wire cout ); // 데이터흐름 연속 할당 (Continuous Assignment) assign sum = a ^ b ^ cin; assign cout = (a & b) | (cin & (a ^ b)); endmodule
📌 wire vs reg 명확한 구분
• wire (Net 타입):
- 소자 간을 연결하는 물리적 도선. 값을 스스로 기억하지 못함.
- assign 문의 좌변(LHS) 또는 하위 모듈 포트 연결에 사용.
• reg (Variable 타입):
- 값을 대입받아 보관할 수 있는 변수.
- always 또는 initial 블록 내부의 좌변(LHS)에서만 대입 가능.
- *주의:* reg라고 무조건 플립플롭이 되는 것은 아니며, 조합회로 always @(*) 내부에서는 단순 도선(wire)으로 합성됨!

[진법 표기법 규칙]

[비트수]'[진법][값]: 예) 4'b1010 (4비트 2진수 1010), 8'hFF (8비트 16진수 FF = 255), 16'd1000 (16비트 10진수 1000).

비트 수를 생략하고 그냥 10이라고 쓰면 컴파일러가 기본 32비트로 확장하여 불필요한 게이트가 낭비될 수 있으므로 반드시 비트 폭을 명시하십시오.

Abstraction Levels Structural, Dataflow & Behavioral

Verilog 회로 모델링의 3대 추상화 방식

구조적(Gate-Level), 데이터흐름(RTL assign), 동작적(Behavioral always)

1 구조적 (Structural)

기본 게이트 프리미티브를 직접 인스턴스화

and g1 (c1, a, b); xor g2 (s1, a, b); xor g3 (sum, s1, cin);

* 회로도(Schematic)와 1:1 매핑

2 데이터흐름 (Dataflow)

부울 연산자와 assign 연속 할당

assign sum = a ^ b ^ cin; assign cout = (a & b) | (cin & (a ^ b));

* RTL 조합논리 표준

3 동작적 (Behavioral)

알고리즘적 if/else, case 문

always @(*) begin if (sel) y = b; else y = a; end

* 복잡한 MUX, ALU, FSM 구현

[동작적 모델링의 생산성]

가장 복잡한 32비트 ALU나 FSM 제어기도 동작적 모델링(Behavioral)을 사용하면 if/else나 case문 몇 줄로 가독성 높게 설계할 수 있으며, 합성기(Synthesis Tool)가 이를 최적의 게이트로 자동 변환해 줍니다.

Critical Rule Blocking (=) vs Non-Blocking (<=)

블로킹(=) vs 논블로킹(<=) 황금률

순차적 즉시 대입과 클록 에지 동시 대입의 차이 및 하드웨어 오합성 방지

📌 블로킹 할당 (Blocking: =)

문장이 나타난 순서대로 즉시 연산되어 다음 줄에 바로 영향

// 조합논리 회로에만 사용! always @(*) begin t1 = a & b; t2 = c & d; out = t1 | t2; end
규칙: always @(*) ➔ 반드시 '=' 사용
📌 논블로킹 할당 (Non-Blocking: <=)

우변의 값들을 동시에 읽은 뒤, 클록 에지 끝에서 동시에 대입

// 순서논리 (플립플롭)에 필수! always @(posedge clk) begin q1 <= d; // q1과 q2가 동시에 전이! q2 <= q1; // 시프트 레지스터 정상 합성 end
규칙: always @(posedge clk) ➔ 반드시 '<=' 사용

[Verilog 2대 절대 수칙 (The Golden Rules)]

1. 조합논리 회로(Combinational Logic)를 설계할 때는 always @(*)와 블로킹(=)을 쓴다.

2. 순서논리 회로(Sequential Logic)를 설계할 때는 always @(posedge clk)와 논블로킹(<=)을 쓴다.

이 둘을 섞어 쓰면 시뮬레이션 결과와 실제 하드웨어 동작이 불일치하는 치명적 버그가 발생합니다.

Synthesis Safety Inadvertent Latch Prevention

의도치 않은 래치(Inadvertent Latch) 방지 원칙

조합회로에서 조건 분기 누락 시 합성기가 이전 값을 기억하는 투명 래치를 만드는 참사 예방

❌ 래치가 생성되는 나쁜 코드 (Bug!)
always @(*) begin if (sel == 2'b00) out = a; else if (sel == 2'b01) out = b; // else 분기가 없음! // sel=10, 11일 때 이전 out을 "기억"해야 하므로 // 합성기가 원치 않는 투명 래치를 자동 생성함! end
✔ 래치를 완벽 차단하는 2대 해결책
• 해결책 1: 모든 조건 완전 기술
모든 if에는 반드시 else를, 모든 case에는 반드시 default를 작성.
• 해결책 2: 블록 최상단 기본값 선할당 (강력 추천):
always @(*) begin out = 1'b0; // 1. 기본값 먼저 선할당! if (sel == 2'b00) out = a; else if (sel == 2'b01) out = b; end

[FPGA에서 래치가 금기시되는 이유]

FPGA의 기본 단위 블록(Slice/LUT)은 룩업테이블과 에지 트리거 플립플롭으로 구성되어 있습니다.

래치를 생성하면 LUT의 피드백 루프를 억지로 사용해야 하므로 타이밍 검증(STA)이 불가능해지고 심각한 글리치와 발열이 발생합니다.

Hardware Implementation 50MHz to 1Hz Clock Divider

클록 분주기(Clock Divider) 모듈 설계

FPGA 보드의 50MHz/100MHz 초고속 시스템 클록을 인간이 볼 수 있는 1Hz 신호로 분주

module ClockDivider_1Hz ( input wire clk_50mhz, // 50MHz 메인 클록 input wire reset, output reg clk_1hz // 1Hz LED 토글 클록 ); // 50MHz에서 1초 = 50,000,000 주기 (절반 = 25,000,000) parameter COUNT_MAX = 25_000_000; reg [31:0] counter; always @(posedge clk_50mhz or posedge reset) begin if (reset) begin counter <= 32'd0; clk_1hz <= 1'b0; end else if (counter >= COUNT_MAX - 1) begin counter <= 32'd0; clk_1hz <= ~clk_1hz; // 0.5초마다 반전 = 1Hz! end else begin counter <= counter + 1'b1; end end endmodule
📌 분주비 계산 원리
$$\text{COUNT\_MAX} = \frac{f_{\text{in}}}{2 imes f_{\text{target}}} = \frac{50\,\text{MHz}}{2 imes 1\,\text{Hz}} = 25,000,000$$
  • 32비트 카운터는 최대 $2^{32} \approx 42.9$억까지 카운팅 가능하므로 5000만 카운팅을 너끈히 수용.
  • FND 스캐닝용 1kHz 분주: $\text{COUNT\_MAX} = \frac{50\text{MHz}}{2 imes 1000\text{Hz}} = 25,000$.

[FPGA 클록 설계 실무 팁]

실제 대규모 FPGA 설계에서는 분주된 클록을 직접 플립플롭의 clk 입력으로 쓰지 않고, 1클록 폭의 클록 인에이블(Clock Enable: clk_en) 펄스를 만들어 원본 고속 클록 도메인에서 동기식으로 구동하는 것이 지터(Jitter)를 방지하는 표준입니다.

System Architecture 3-Always Block FSM

업계 표준 3단 유한상태머신(FSM) 아키텍처

State Register, Next State Logic, Output Logic의 3단 분리 설계 및 Moore vs Mealy

1단 상태 레지스터

순서논리 (D-FF): 클록 에지마다 현재 상태를 갱신

always @(posedge clk or posedge rst) if (rst) state <= IDLE; else state <= next_state;
2단 차기 상태 로직

조합논리: 현재 상태와 입력으로 다음 상태 결정

always @(*) begin case (state) IDLE: if (start) next_state = RUN; else next_state = IDLE; RUN: ... endcase end
3단 출력 디코딩

출력 생성: 상태에 따른 제어 신호 출력

// Moore: 오직 현재 상태에만 의존 assign ready = (state == IDLE); assign busy = (state == RUN);

* 글리치 없는 안정적 출력

[Moore vs Mealy FSM 선택 가이드]

• Moore FSM: 출력이 오직 현재 상태($Q$)에 의해서만 결정됨 $ o$ 입력 노이즈가 출력으로 즉시 전파되지 않아 매우 안전함 (표준 추천).

• Mealy FSM: 출력이 현재 상태뿐 아니라 현재 입력($X$)에도 즉시 반응 $ o$ 상태 수를 줄일 수 있으나 입력 글리치가 출력에 그대로 노출됨.

FPGA Peripheral Dynamic Multiplexing Display

4자리 7-Segment 다이나믹 시분할 스캐닝

인간의 잔상 효과(Persistence of Vision)를 이용해 32개 핀 대신 12개 핀으로 4자리 FND 구동

1kHz 스캐닝 클록 ──► [ 2비트 링 카운터 (0➔1➔2➔3) ] │ ┌───────────┬─────────┴─────────┬───────────┐ ▼ ▼ ▼ ▼ [ 자릿수 1 ] [ 자릿수 2 ] [ 자릿수 3 ] [ 자릿수 4 ] (AN0=0 활성) (AN1=0 활성) (AN2=0 활성) (AN3=0 활성) │ │ │ │ └───────────┴─────────┬─────────┴───────────┘ ▼ 공통 7-Segment 데이터 버스 (a~g)
📌 다이나믹 스캐닝 설계 원리
• 정적 구동의 한계: 4자리 FND를 개별 구동하면 $8 imes 4 = 32$개 FPGA 핀 낭비.
• 시분할 동적 구동:
- 데이터 선($a \sim g$) 7개는 4자리가 모두 병렬 공유.
- 자릿수 선택 선($AN_0 \sim AN_3$) 4개를 **$1\text{kHz}$ 속도로 번갈아 가며 1자리씩만 순차 점등**.
- 인간의 눈은 $60\text{Hz}$ 이상의 깜빡임을 연속 점등으로 인지하므로 4자리가 모두 완벽히 켜져 있는 것으로 보임!

[스캐닝 주파수 튜닝 노하우]

• 주파수가 너무 낮으면($< 100\text{Hz}$): 숫자가 심하게 깜빡거립니다 (Flickering).

• 주파수가 너무 높으면($> 100\text{kHz}$): 기생 커패시턴스로 인해 이전 자릿수의 잔상이 다음 자릿수로 번지는 고스팅(Ghosting) 현상이 발생하므로 **$1\text{kHz} \sim 2\text{kHz}$**가 최적입니다.

Verification Testbench & RTL Simulation

테스트벤치(Testbench) 작성 & 기능 검증

하드웨어 보드 다운로드 전 가상 클록 및 자극(Stimulus) 주입을 통한 시뮬레이션

`timescale 1ns / 1ps module tb_Counter; reg clk; reg reset; wire [3:0] count; // DUT (Device Under Test) 인스턴스화 Counter uut (.clk(clk), .reset(reset), .count(count)); // 100MHz 클록 생성 (주기 10ns) always #5 clk = ~clk; initial begin clk = 0; reset = 1; #20 reset = 0; // 20ns 후 리셋 해제 #200; // 200ns 동안 계수 관찰 $finish; // 시뮬레이션 종료 end endmodule
📌 테스트벤치 작성 3대 원칙
• 포트 없음: 테스트벤치 모듈은 외부 핀이 없는 최상위 닫힌 모듈 (module tb; ... endmodule).
• DUT 입력은 reg, 출력은 wire로 선언: 자극을 대입해야 하므로 reg.
• 시간 지연(#10) 사용: 실제 칩에서는 합성 불가능하지만 시뮬레이션 테스트벤치에서는 필수적으로 사용.

조건문에서 else나 default가 누락되어 이전 값을 보존하려 할 때 발생하며, 블록 시작 시 기본값을 선할당하여 해결합니다.
Q3 Vivado 5단계 흐름

FPGA 개발 5대 파이프라인:

  1. RTL Synthesis: Verilog 코드를 게이트/LUT로 변환
  2. Implementation: 칩 내부 물리적 배치 & 배선 (Place & Route)
  3. XDC Constraints: 클록 및 보드 스위치/LED 핀 번호 매핑
  4. Bitstream Generation: .bit 파일 생성
  5. Hardware Program: JTAG 케이블로 FPGA 다운로드
