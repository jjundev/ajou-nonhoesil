# lab-netlist/v2 — 결선도 스키마

`scripts/lab/netlist_parser.py` 가 이 계약을 구현한다. 실물이 적합성 픽스처다 —
`보고서/실험01/결선도/netlist.md` 가 다섯 `kind` 를 모두 쓴다.

## 왜 절마다 `kind` 를 요구하나

`kind` 는 **인쇄 라우터**다. 이 필드가 없던 시절 `render._procedure()` 는 netlist
본문의 모양으로 목적지를 짐작했고, 세 가지가 조용히 틀렸다:

1. 핀아웃 출처(참고문헌)가 배선 단계 7~11번으로 인쇄됐다
2. 표 줄(`|`)을 전부 건너뛰어 `참조 핀아웃` 표가 사라졌다 — 74HC02 만 출력이
   pin 1·4·10·13 이라는, netlist 스스로 "가장 흔한 배선 실수"라고 표시한 정보다
3. `미확정 사항` 은 제목과 도입문만 찍히고 표가 빠져 문장이 끊긴 채 끝났다

목적지를 데이터로 적으면 이 셋이 구조적으로 불가능해진다.

적지 않는다** — 두 곳에 두면 한 곳만 고쳐진다.

## 절 (`# <제목>`)

모든 `# ` 절이 **속성 리스트로 시작한다.** 속성은 절 첫머리의 연속된
`- key: value` 줄이고, 첫 비-속성 줄에서 멈춘다 — 본문의
`- 미사용 입력핀: pin 9 → GND` 같은 한글 불릿을 속성으로 오인하지 않기 위해서다.

| `kind` | 인쇄 목적지 |
|---|---|
| `must-read` | 공통면 맨 위, 전원 박스 바로 아래 경고 상자. **인쇄되는 유일한 규칙 절**(2026-09-28). 최상위 불릿 ≤5(`MUST_READ_MAX`)와 표만 — 산문 줄은 `NetlistError`. 실험당 최대 하나, 없어도 된다 |
| `common` | **인쇄하지 않는다**(2026-09-28 — 실험실에서 읽히지 않았다). 공통 규칙의 저작·검토 자리다. 실험실에서 손으로 할 일은 `must-read` 로 올린다 |
| `lookup` | 공통면 — 표를 그대로 인쇄한다. **명세 표의 `role: reference` 와 무관하다** — 그쪽은 "인쇄하지 않는다"는 뜻이라 이름이 겹치지 않게 갈랐다 |
| `open-issues` | **인쇄하지 않는다**(2026-09-28). 미확정 표(`M1`~)의 저작·검토 자리다 |
| `sources` | **인쇄하지 않는다.** ③ 예비보고서의 참고문헌 재료다 |
| `circuit` | 회로 페이지 하나 (강제 개쪽) |
| `layout` | 공통면 — **칩 자리표**. `\| 슬롯 \| 자리 \| 회로별 칩 \|` 표 하나. 실험의 모든 회로가 칩 자리를 공유한다는 선언이고, 주차 `배치.py` 의 슬롯 상수(`E1_SLOTS` 등)와 `tests/test_breadboard_wiring.py` 가 맞댄다. 실험당 최대 하나 |

`kind: circuit` 만 추가 필드를 갖는다.

| 필드 | 필수 | 값 |
|---|---|---|
| `id` | ● | `C<n>`. 문서 안에서 유일. 인쇄 순서이자 오류 메시지의 지시 대상 |
| `item` | ● | 명세 `items[].id` 중 하나. 고아면 `check_netlist_circuits` 가 error |
| `tables` | ● | 이 회로가 검증하는 표 ID 리스트 (`[T1]`) |
| `diagram` | ○ | 결선도 폴더 기준 PNG 파일명 — 완성본. 이름은 `실험NN_<소단원>_결선도_<회로명>.png` (`breadboard-diagram` SKILL §4a 파일명 규칙; 소단원은 `item` 의 `P` 뒤 토큰). 없거나 파일이 없으면 warn + 빈 브레드보드 |
| `continues` | ○ | **직전** 회로의 ID (`C1`). 그 회로를 **뜯지 않고 이어 붙인다**. 직전이 아닌 회로를 가리키면 error 다 — 배너가 "점퍼선을 걷지 않는다"고 말하는 순간 그 사이 회로들의 점퍼를 어떻게 하라는 지시가 사라진다. 칩 교체 배너가 "점퍼선을 모두 걷는다" 대신 "그대로 두고 이어 붙인다" 로 바뀌고, **이 회로가 선언한 칩은 전부 "추가로 꽂는다" 로 나온다** — 앞 회로를 그대로 두므로 이름이 겹쳐도 재배선이 아니라 두 번째 패키지다. 실험10 `E10.P2` 가 실물이다 — 다 만든 DAC 에 `741` 비교기를 하나 더 붙이고, C1 의 `U4` 와 C2 의 `U5` 가 둘 다 `741 OP amp` 다 |
| `rebuild` | ○ | `true` \| `all` \| `false`(기본). **앞 회로의 신호선을 전부 뽑고 새로 짓는** 회로 경계다. 배너가 "앞 회로의 신호선을 전부 뽑는다 — 전원선·레일 브리지·LED 사슬은 그대로 둔다" 와 칩 교체를 말한다 — 단계 표가 있는 회로의 기본 배너(`앞 회로 배선은 그대로 둔다`)와 반대다. `all` 은 기반까지 걷는다 — 배너가 "선과 LED 사슬까지 전부 뽑는다 — 레일 브리지만 그대로 둔다" 다(앞 회로와 LED 방향이 반대라 사슬을 남길 수 없는 경계, 실험05 C2 2026-10-05). 아래 규칙은 `true`·`all` 이 같다. 전부 뽑으면 놓칠 선이 없으므로 걷기 행·홀 주소 목록을 두지 않는다. 첫 회로·`continues`·첫 행이 걷기인 단계 표와 함께면 error. `true`·`all`·`false` 밖의 값은 파서가 거절한다. 브레드보드 사슬에서는 그 회로 첫 보드를 `render_breadboard.fresh_board(builder)` 로 감싸 기준선을 끊는다. 실험04 C2 가 실물이다(2026-09-27) |
| `refs` | ○ | 표 ID 리스트 (`[T8]`). `role: reference` 표를 이 회로 페이지에 **읽기 전용**으로 싣는다. 기록 칸·미니표·사진 지시가 붙지 않는다. 실험02 `T7`(tpd 측정)이 `T8`(데이터시트 기준값)과 대조하는 것이 실물이다 |

### 회로 안의 `## 단계` 표 (선택)

칩이 둘 이상인 회로, 또는 앞 회로가 있어 전환이 필요한 회로는 본문 어디든
`## 단계` 헤딩 아래 표 하나를 둔다.

**단계 하나는 관측 노드 하나를 세운다.** 그 단계 끝의 `확인` 은 같은 회로
`## 노드` 표의 노드 하나를 가리키고, 그 단계에서 **새로 꽂는 신호선은 셋
이하**다(`render_breadboard.STAGE_WIRE_BUDGET`). 둘 중 먼저 걸리는 쪽이 단계를
가른다 — 노드마다 단계를 두라는 말이 아니라(중간 노드는 한 단계 안에서 여럿
세워도 된다) 단계마다 볼 것이 하나여야 한다는 말이다.

**주차 예외.** 칩 구조상 셋으로 관측 노드 하나를 세울 수 없는 주차는 주차 `배치.py` 에
`STAGE_WIRE_BUDGET = <n>` 과 `STAGE_WIRE_BUDGET_REASON = '<이유>'` 를 둔다
(`render_breadboard.stage_budget`). 값은 **게이트 입력 수 + 1**(입력 전부 + 관측선 하나)이고
이유가 없으면 거절한다. 실험04 가 첫 실물이다 — 4입력 NAND 라 5 다(2026-09-27 결정).

- **신호선**은 `sig`(입력·출력)·`mid`(칩 사이) 배선이다. 전원·GND·레일 브리지·
  잭·LED 사슬 부품·칩 꽂기는 **기반**이라 세지 않는다 — 회로가 바뀌어도 그대로
  있는 것들이고 첫 단계에 한꺼번에 꽂는다. 이 셈은 주차 `배치.py` 의 보드 사슬에서
  렌더러가 낸다(`bb.new_signal`). 단계 표에 적는 숫자가 아니다 — 적으면 표류한다
- **관측 노드의 상류에 뜬 입력이 없어야 한다.** 상류가 아직 없으면 임시 입력
  점퍼로 0 을 물린다. **그 점퍼도 나중에 뽑으므로 뽑는 자리에 걷기 행 한 줄과
  걷기 보드 한 장을 둔다** — 임시 급전선과 같은 규칙이다
- **관측은 그 시점에 비어 있는 LED 의 급전선을 그 노드로 잠시 옮겨 한다.** 여분
  LED 를 더하지 않는다(교안 부품 수·손그림 제출본). 완성본에서 그 LED 가 맡는
  출력이 아직 안 세워진 단계에는 LED 가 비어 있다 — 그 사이 그것이 프로브다.
  멀티미터·로직프로브가 있으면 그것으로 대신해도 되고, 그때는 선을 옮기지 않는다.
  임시 급전선을 **뽑는 자리마다 걷기 행 한 줄과 걷기 보드 한 장**을 둔다 — 회로
  경계든 회로 안이든 같다. footer 의 "앞 단계에서 걷는다" 표로만 두지 않는다:
  2026-09-18 실험03 에서 글로만 있던 두 가닥을 실험실에서 놓쳤고, 그것이 걷기
  보드를 만든 근거다
- `단계` 셀은 **양의 정수** 또는 정확한 `<k>걷기`다. `2 걷기`·`걷기2`·`0`·
  `0걷기`는 error다. 앞자리 0은 숫자 비교에서 같은 번호로 본다.
- 걷기 행 둘은 연달아 올 수 없다. 걷기는 바로 다음 일반 단계 하나의 머리다.
- 걷기 행의 `이 단계에서`에는 `좌 b9→좌 a25` 꼴 **주소쌍**을 걷기 번호 순서대로
  적는다. `확인`에는 각 주소쌍의 **양 끝 홀**을 같은 순서로 모두 적는다.
- 걷기 행은 관측 노드 포인터와 새 신호선 예산에서만 면제된다. 확인 칸·단계 문법·
  주소 완전성 검사는 그대로 받는다.

실험01·02 승인본만 단계 세분화 이전 레거시다. 두 실험은 단계가 있는데 `## 노드`
표가 없어도 warn을 유지한다. 실험03 이후에는 같은 상태가 error다. 면제 열쇠는
노드 표의 우연한 부재가 아니라 frontmatter의 `experiment`다. **노드 표가 있는
회로의 단계는 노드 포인터 검사를 받는다.** 설계:
`docs/plans/2026-09-20-단계세분화-설계.md`.

| 열 | 값 |
|---|---|
| `단계` | 꽂기 행은 1부터의 정수. **걷기 행은 `<k>걷기`** — k 는 바로 다음 행의 단계 번호다 (`2걷기` 는 2단계 머리의 걷기) |
| `그림` | 결선도 폴더 기준 PNG. **회색 기준선이 든 절차 그림**이다 — `diagram`(완성본)과 같은 파일이면 `check_netlist_circuits` 가 error |
| `이 단계에서` | 꽂는 것·걷는 것 한 줄 |
| `확인` | **`` 노드 `<이름>` `` 로 시작한다.** `<이름>` 은 이 회로 `## 노드` 표의 이름 그대로이고, 뒤에 관측 방법과 행 범위를 산문으로 잇는다. 핀은 적지 않는다 — 체크리스트가 노드 표에서 조회해 찍는다. 비면 error 다 — 단계의 존재 이유다. 걷기 행만 노드 포인터에서 면제(손과 빈 홀로 적는다 — 확인 칸 자체는 비울 수 없다) |

헤딩 아래 **첫 비어 있지 않은 줄이 표의 머리 줄**이어야 한다 — 설명 산문은
헤딩 **위**에 둔다. 헤딩과 표 사이에 산문을 끼우면 파서가 "`## 단계` 아래에
표가 없다" 로 거절한다.

파서는 이 헤딩과 표를 본문에서 떼어 `NetlistSection.stages` 로 낸다. 남겨 두면
"칩이 아닌 헤딩 아래의 표" 규칙으로 참조표로 두 번 인쇄된다.

실험01 실험실 기록(2026-09-11)이 근거다 — 복합회로를 전부 꽂고 불이 안
들어오자 어디가 틀렸는지 알 수 없었고, 74HC08 결함은 11 조합을 건너뛰어
마지막 회로에서야 드러났다.

칩 목록은 필드로 두지 않는다. 배선 본문의 `U<n> = <칩>` 선언에서 뽑는다
(`NetlistSection.ics`) — 필드를 늘리면 본문과 표류한다.

### 회로 안의 `## 노드` 표 (선택)

게이트가 둘 이상인 회로는 본문 어디든 `## 노드` 헤딩 아래 표 하나를 둔다 —
열은 `| 노드 | 식 | 핀 |` 다. **게이트 출력 핀 하나 = 노드 하나**이고, 최종
출력(LED 가 달린 핀)도 노드다. 체크리스트는 이 표와 기록 진리표의 입력 행으로
단계마다 그 단계 노드의 기대값을 계산해 **단계 블록 안에 단계 진리표**로 찍는다
(마지막 관측 단계는 그 노드가 기록표 출력이면 바로 뒤 기록표가 대신한다). 단계마다
노드 하나를 확인하고 넘어가므로, 틀리면 용의자가 "선 전부"가 아니라 그 단계에서 꽂은
두세 가닥이다. 어느 단계도 가리키지 않는 노드는 기록표 뒤 "단계에서 안 본 노드" 표에
핀과 기대값이 남는다.

저작 규칙은 "게이트 둘 이상"이지만 자동 채근은 그보다 좁다 — `_check_nodes` 의
"노드 표가 없다" warn 은 `## 단계` 표가 있는 회로에서만 뜬다. 단계 없는 회로에
노드 표를 빠뜨려도 검사기는 말이 없으니 저작자가 챙긴다.

헤딩 아래 **첫 비어 있지 않은 줄이 표의 머리 줄**이어야 한다 — 설명 산문은
헤딩 **위**에 둔다. 헤딩과 표 사이에 산문을 끼우면 파서가 "`## 노드` 아래에
표가 없다" 로 거절한다.

| 열 | 값 |
|---|---|
| `노드` | 표시 이름. 자유 문자열(`A⊕B`, `(A⊕B)'`). 회로 안에서 유일. 명세 `derived` 의 출력 이름은 **그대로** 써야 한다(`S`, `Co`) |
| `식` | `boolexpr` 문법(`·` `+` `⊕` `'` 괄호)으로 **그 회로 기록 진리표의 입력 변수만** 쓴다. 다른 노드 이름을 참조할 수 없다 |
| `핀` | `U<n> pin <m>`. `U<n>` 은 이 회로 배선 본문의 `U<n> = <칩>` 선언에 있어야 한다 |

기준 진리표는 회로 `tables` 의 첫 기록 진리표(`role != reference`, `kind:
truth-table`)다. 둘 이상이면 입력 열이 같아야 한다. 셀은 그 표의 `encoding`
그대로 찍힌다. 단계 진리표는 노드 식에 나오는 입력만 열로 두고, 그 입력에
don't-care 가 남은 행은 노드 값이 정해질 때만 `X` 째 싣는다(`nodes.stage_table`).

파서는 이 헤딩과 표를 본문에서 떼어 `NetlistSection.nodes` 로 낸다(`## 단계` 와
같은 이유 — 남기면 참조표로 두 번 인쇄된다). 계산은 `scripts/lab/nodes.py`.

## 배선을 적는 두 형식

배선은 **칩 상자**로 인쇄된다. 상자를 여는 방법이 둘이고, **회로마다** 고른다
— 주차 단위가 아니다. 교안 원문이 그 회로의 배선을 어떤 모양으로 적었는지를
따른다. 한 결선도 안에 두 형식이 섞여도 된다.

| | 불릿형 | 헤딩형 |
|---|---|---|
| 선언 | `- U<n> = <칩>` | `## U<n> = <칩>` |
| 배선 | 아래에 들여쓴 `- ` 불릿 | 아래의 마크다운 표 (행마다 체크박스) |
| 상자 범위 | 들여쓴 `- ` 배선 불릿과 그것을 잇는 들여쓴 줄만 | 다음 헤딩(어느 레벨이든) 또는 다음 칩 선언까지 |
| 미사용핀 | `미사용` 으로 **시작하는** 불릿 | 어느 셀에든 `미사용` 이 든 행 |
| 그 밖 | (없음) | 열 0 불릿·산문 → 상자 안 주석, 체크박스 없음 |
| 쓰는 회로 | 실험01 전부 · 실험03 전부 · 실험05 전부 · 실험06 전부 · 실험02 의 `E2.P1`~`E2.P3-2` | 실험02 의 `E2.P4` · 실험10 전부 |

실험02 가 실물 근거다 — 다섯 회로 중 `E2.P4` 하나만 헤딩형이고 나머지 넷은
불릿형이다. 교안 p13 의 지연 체인만 핀 표가 `단 | 게이트 | 입력핀 | 출력핀 |
출력이 가는 곳` 다섯 열이라 표로 적을 값이 있었기 때문이다.

**불릿형 상자는 첫 배선 불릿 앞에 아무것도 끼워 넣을 수 없다.** 상자를 닫는
조건이 "열 0 줄"이 아니라 "배선 불릿도 그것을 잇는 줄도 아닌 줄"이다 —
들여쓰기와 무관하다. 칩 선언과 첫 `- pin ...` 사이에 설명을 한 줄 끼우면
(들여쓰든 아니든) 그 자리에서 상자가 닫히고 **그 칩의 배선이 통째로 상자 밖
산문으로 나간다.** 칩에 대한 설명은 칩 선언 **앞**에 열 0 으로 쓰거나,
헤딩형으로 바꿔 쓴다.

미사용 판정이 형식마다 다른 이유: 실험10 `U2` 표는 `| 미사용 입력핀 11, 13 |
GND | 플로팅 금지 |` 로 1열에 있고, 실험02 `E2.P4` 의 `U2` 표는 `| 3 (2A) |
GND | 미사용 입력 |` 로 3열에 있다. 열 위치를 못 박을 수 없다.

**칩이 아닌 헤딩(`## 소자 배치`·`## 가중 저항망`) 아래의 표는 참조표다** —
원문 위치에 그대로 인쇄되고 체크박스를 받지 않는다. `must-read` 절의 표도 같다
(`common` 절은 인쇄되지 않으므로 거기 둔 표는 실리지 않는다).

**참조표를 인쇄본에서 빼고 싶으면 `kind: sources` 절로 옮긴다.** 그것만
인쇄하지 않는다.

## 검사 강도

**정본은 코드다.** 구조 결함은 `netlist_parser.parse_netlist` 가
`NetlistError` 로 던지고(모르는 `kind`, 회로인데 `id`·`item`·`tables` 가 없음,
회로 ID 중복, 회로가 하나도 없음, `## 단계`·`## 노드` 표의 행 셀 수가 열 수와
다름), 의미 결함은 `validate.check_netlist_circuits` 가 findings 로
보고한다(없는 `item`, 없는 표, `role: reference` 표를 `tables` 로 가리킴,
`refs` 가 기록 대상 표나 없는 표를 가리킴, `continues` 가 없는 회로·자기
자신·**직전이 아닌 회로**를 가리킴, 단계 그림이 완성본과 같은 파일·단계 확인
칸 비어 있음·**단계가 가리키는 노드가 노드 표에 없음**·**걷기 행이 `## 단계`
표의 마지막**·**걷기 행의 k 가 다음 행 단계 번호와 다름**·layout 절 둘
이상·**노드 표**의 식 평가 불가·핀 형식 위반·선언
안 된 칩·이름 중복·명세 출력 노드 누락·출력 노드 값이 명세 식과 불일치·기록
진리표 없는 회로의 노드 표 = error / `diagram` 부재·파일 부재·고아 기록표·칩
선언 부재·배선 없는 칩·**칩 상자 밖의 배선처럼 보이는 줄**·단계 그림 파일
부재·**실험01·02의 단계는 있는데 노드 표 없음** = warn / **실험03+의 단계는
있는데 노드 표 없음** = error / **노드 표가 있는 회로의 1 이상 단계가 노드를
안 가리킴** = warn).

`role: reference` 표를 가리키는 것을 error 로 잡는 이유: 렌더러도 그런 표는
걸러내지만, 그 필터는 netlist 가 실제로 참조표를 가리켜야만 발화하므로 회귀를
못 잡는다. 저작 단계에서 막는다 — 교안 이론표는 실험실에서 채우는 물건이
아니다.

기존 `validate.check_netlist(path, spec)` 은 **이 계약과 무관하다.** 그것은
`VCC`·`GND`·`미사용` 토큰과 항목별 IC 를 grep 하는 별도 검사이고, 다섯 스킬이
부른다. 회로 메타를 요구하는 것은 인쇄본을 내는 ① 뿐이라 요구를 그 자리에만 둔다.
