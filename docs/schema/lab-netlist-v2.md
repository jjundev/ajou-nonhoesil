# lab-netlist/v2 — 결선도 스키마

`scripts/lab/netlist_parser.py` 가 이 계약을 구현한다. 실물이 적합성 픽스처다 —
`보고서/실험01/결선도/netlist.md` 가 다섯 `kind` 를 모두 쓴다.

## 왜 절마다 `kind` 를 요구하나

`kind` 는 **인쇄 라우터**다. 이 필드가 없던 시절 `render._procedure()` 는 netlist
본문의 모양으로 목적지를 짐작했고, 세 가지가 조용히 틀렸다:

1. 핀아웃 출처(참고문헌)가 배선 단계 7~11번으로 인쇄됐다
2. 표 줄(`|`)을 전부 건너뛰어 `참조 핀아웃` 표가 사라졌다 — 74HC02 만 출력이
   pin 1·4·10·13 이라는, netlist 스스로 "가장 흔한 배선 실수"라고 표시한 정보다
3. `미확정 사항` 은 제목과 도입문만 찍히고 표가 빠져 문장이 끊긴 채 끝났다

목적지를 데이터로 적으면 이 셋이 구조적으로 불가능해진다.

### v1 에서 무엇이 바뀌었나

`week` 필드가 사라졌다. 주차는 한 날에 실험이 둘인 경우(9/18 실험2·3)를
표현할 수 없었고, 실험이 없는 주(추석·중간고사)를 예외 표로 따로 관리하게
만들었다. 일정은 이제 `scripts/lab/config.py` 의 `EXPERIMENT_DATES` 한 곳에만
있고, 산출물은 `experiment` 번호로 그것을 조회한다. **날짜를 프론트매터에도
적지 않는다** — 두 곳에 두면 한 곳만 고쳐진다.

## 절 (`# <제목>`)

모든 `# ` 절이 **속성 리스트로 시작한다.** 속성은 절 첫머리의 연속된
`- key: value` 줄이고, 첫 비-속성 줄에서 멈춘다 — 본문의
`- 미사용 입력핀: pin 9 → GND` 같은 한글 불릿을 속성으로 오인하지 않기 위해서다.

| `kind` | 인쇄 목적지 |
|---|---|
| `common` | 공통면 — 공통 규칙 |
| `lookup` | 공통면 — 표를 그대로 인쇄한다. **명세 표의 `role: reference` 와 무관하다** — 그쪽은 "인쇄하지 않는다"는 뜻이라 이름이 겹치지 않게 갈랐다 |
| `open-issues` | 공통면 — 표의 행마다 체크박스를 붙인다 |
| `sources` | **인쇄하지 않는다.** ③ 예비보고서의 참고문헌 재료다 |
| `circuit` | 회로 페이지 하나 (강제 개쪽) |
| `layout` | 공통면 — **칩 자리표**. `\| 슬롯 \| 자리 \| 회로별 칩 \|` 표 하나. 실험의 모든 회로가 칩 자리를 공유한다는 선언이고, 빌더 상수 `E1_SLOTS` 와 `tests/test_breadboard_wiring.py` 가 맞댄다. 실험당 최대 하나 |

`kind: circuit` 만 추가 필드를 갖는다.

| 필드 | 필수 | 값 |
|---|---|---|
| `id` | ● | `C<n>`. 문서 안에서 유일. 인쇄 순서이자 오류 메시지의 지시 대상 |
| `item` | ● | 명세 `items[].id` 중 하나. 고아면 `check_netlist_circuits` 가 error |
| `tables` | ● | 이 회로가 검증하는 표 ID 리스트 (`[T1]`) |
| `diagram` | ○ | 결선도 폴더 기준 PNG 파일명. 없거나 파일이 없으면 warn + 빈 브레드보드 |
| `continues` | ○ | **직전** 회로의 ID (`C1`). 그 회로를 **뜯지 않고 이어 붙인다**. 직전이 아닌 회로를 가리키면 error 다 — 배너가 "점퍼선을 걷지 않는다"고 말하는 순간 그 사이 회로들의 점퍼를 어떻게 하라는 지시가 사라진다. 칩 교체 배너가 "점퍼선을 모두 걷는다" 대신 "그대로 두고 이어 붙인다" 로 바뀌고, **이 회로가 선언한 칩은 전부 "추가로 꽂는다" 로 나온다** — 앞 회로를 그대로 두므로 이름이 겹쳐도 재배선이 아니라 두 번째 패키지다. 실험10 `E10.P2` 가 실물이다 — 다 만든 DAC 에 `741` 비교기를 하나 더 붙이고, C1 의 `U4` 와 C2 의 `U5` 가 둘 다 `741 OP amp` 다 |
| `refs` | ○ | 표 ID 리스트 (`[T8]`). `role: reference` 표를 이 회로 페이지에 **읽기 전용**으로 싣는다. 기록 칸·미니표·사진 지시가 붙지 않는다. 실험02 `T7`(tpd 측정)이 `T8`(데이터시트 기준값)과 대조하는 것이 실물이다 |

### 회로 안의 `## 단계` 표 (선택)

칩이 둘 이상인 회로, 또는 앞 회로가 있어 전환이 필요한 회로는 본문 어디든
`## 단계` 헤딩 아래 표 하나를 둔다. **칩 하나를 더할 때마다 단계 하나**이고,
단계 끝은 반드시 그 회로의 LED 로 관측된다. 상류가 아직 없으면 입력 점퍼로
임시 대체하고 다음 단계 `이 단계에서` 첫 줄에 "걷는다" 로 적는다.

| 열 | 값 |
|---|---|
| `단계` | 1부터 |
| `그림` | 결선도 폴더 기준 PNG. **회색 기준선이 든 절차 그림**이다 — `diagram`(완성본)과 같은 파일이면 `check_netlist_circuits` 가 error |
| `이 단계에서` | 꽂는 것·걷는 것 한 줄 |
| `확인` | 이 단계 끝에서 보는 관측값과 입력 조합. 비면 error — 단계의 존재 이유다 |

파서는 이 헤딩과 표를 본문에서 떼어 `NetlistSection.stages` 로 낸다. 남겨 두면
"칩이 아닌 헤딩 아래의 표" 규칙으로 참조표로 두 번 인쇄된다.

실험01 실험실 기록(2026-09-11)이 근거다 — 복합회로를 전부 꽂고 불이 안
들어오자 어디가 틀렸는지 알 수 없었고, 74HC08 결함은 11 조합을 건너뛰어
마지막 회로에서야 드러났다.

칩 목록은 필드로 두지 않는다. 배선 본문의 `U<n> = <칩>` 선언에서 뽑는다
(`NetlistSection.ics`) — 필드를 늘리면 본문과 표류한다.

## 배선을 적는 두 형식

배선은 **칩 상자**로 인쇄된다. 상자를 여는 방법이 둘이고, **회로마다** 고른다
— 주차 단위가 아니다. 교안 원문이 그 회로의 배선을 어떤 모양으로 적었는지를
따른다. 한 결선도 안에 두 형식이 섞여도 된다.

| | 불릿형 | 헤딩형 |
|---|---|---|
| 선언 | `- U<n> = <칩>` | `## U<n> = <칩>` |
| 배선 | 아래에 들여쓴 `- ` 불릿 | 아래의 마크다운 표 (행마다 체크박스) |
| 상자 범위 | 들여쓴 `- ` 배선 불릿과 그것을 잇는 들여쓴 줄만 | 다음 헤딩(어느 레벨이든) 또는 다음 칩 선언까지 |
| 미사용핀 | `미사용` 으로 **시작하는** 불릿 | 어느 셀에든 `미사용` 이 든 행 |
| 그 밖 | (없음) | 열 0 불릿·산문 → 상자 안 주석, 체크박스 없음 |
| 쓰는 회로 | 실험01 전부 · 실험03 전부 · 실험05 전부 · 실험06 전부 · 실험02 의 `E2.P1`~`E2.P3-2` | 실험02 의 `E2.P4` · 실험10 전부 |

실험02 가 실물 근거다 — 다섯 회로 중 `E2.P4` 하나만 헤딩형이고 나머지 넷은
불릿형이다. 교안 p13 의 지연 체인만 핀 표가 `단 | 게이트 | 입력핀 | 출력핀 |
출력이 가는 곳` 다섯 열이라 표로 적을 값이 있었기 때문이다.

**불릿형 상자는 첫 배선 불릿 앞에 아무것도 끼워 넣을 수 없다.** 상자를 닫는
조건이 "열 0 줄"이 아니라 "배선 불릿도 그것을 잇는 줄도 아닌 줄"이다 —
들여쓰기와 무관하다. 칩 선언과 첫 `- pin ...` 사이에 설명을 한 줄 끼우면
(들여쓰든 아니든) 그 자리에서 상자가 닫히고 **그 칩의 배선이 통째로 상자 밖
산문으로 나간다.** 칩에 대한 설명은 칩 선언 **앞**에 열 0 으로 쓰거나,
헤딩형으로 바꿔 쓴다.

미사용 판정이 형식마다 다른 이유: 실험10 `U2` 표는 `| 미사용 입력핀 11, 13 |
GND | 플로팅 금지 |` 로 1열에 있고, 실험02 `E2.P4` 의 `U2` 표는 `| 3 (2A) |
GND | 미사용 입력 |` 로 3열에 있다. 열 위치를 못 박을 수 없다.

**칩이 아닌 헤딩(`## 소자 배치`·`## 가중 저항망`) 아래의 표는 참조표다** —
원문 위치에 그대로 인쇄되고 체크박스를 받지 않는다. `common` 절의 표도 같다.
표를 `kind: lookup` 절로 뺄 필요가 없다.

**참조표를 인쇄본에서 빼고 싶으면 `kind: sources` 절로 옮긴다.** 그것만
인쇄하지 않는다.

## 검사 강도

**정본은 코드다.** 구조 결함은 `netlist_parser.parse_netlist` 가
`NetlistError` 로 던지고(모르는 `kind`, 회로인데 `id`·`item`·`tables` 가 없음,
회로 ID 중복, 회로가 하나도 없음), 의미 결함은
`validate.check_netlist_circuits` 가 findings 로 보고한다(없는 `item`, 없는 표,
`role: reference` 표를 `tables` 로 가리킴, `refs` 가 기록 대상 표나 없는 표를
가리킴, `continues` 가 없는 회로·자기 자신·**직전이 아닌 회로**를 가리킴,
단계 그림이 완성본과 같은 파일·단계 확인 칸 비어 있음·layout 절 둘 이상
= error / `diagram` 부재·파일 부재·고아 기록표·칩 선언 부재·배선 없는 칩·
**칩 상자 밖의 배선처럼 보이는 줄**·단계 그림 파일 부재 = warn).

`role: reference` 표를 가리키는 것을 error 로 잡는 이유: 렌더러도 그런 표는
걸러내지만, 그 필터는 netlist 가 실제로 참조표를 가리켜야만 발화하므로 회귀를
못 잡는다. 저작 단계에서 막는다 — 교안 이론표는 실험실에서 채우는 물건이
아니다.

기존 `validate.check_netlist(path, spec)` 은 **이 계약과 무관하다.** 그것은
`VCC`·`GND`·`미사용` 토큰과 항목별 IC 를 grep 하는 별도 검사이고, 다섯 스킬이
부른다. 회로 메타를 요구하는 것은 인쇄본을 내는 ① 뿐이라 요구를 그 자리에만 둔다.
