# 명세 생성 스킬 (`draft-lab-spec`) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `subagent-driven-development` (recommended) or `executing-plans` to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking.

**Goal:** 교안 PDF 에서 `<실험NN>/체크리스트/명세.md` 와
`<실험NN>/결선도/netlist.md` 를 저작하는 스킬 하나를 만들고, 그 산출물이
조용히 틀릴 수 있는 세 경로(텍스트 추출 지뢰 · 중복 열 이름 · 방향을 붙인
진단 문장)를 코드로 막는다.

**Architecture:** 스킬은 하나이고 내부가 두 단계(명세 → 결선도)다. 명세의
`ics`·`power` 자체가 회로도 vision 판독에서 나오므로 나누면 같은 쪽을 두 번
읽고 두 판독이 어긋난다. 판독 규칙은 스킬 문서에 베끼지 않고
`docs/schema/lab-spec-v1.md` 를 읽게 한다 — 계약서가 한 곳이어야 개정이 한
번에 먹는다. 사람 확인은 무인 생성 **뒤에** 한 번, 실제로 부딪친 것에서
파생된 세 목록으로 받는다.

**Tech Stack:** Python 3.14 표준 라이브러리 + `pypdf`, `unittest`,
poppler(`pdftotext`·`pdftoppm`), Claude Code 프로젝트 스킬
(`.claude/skills/`), 마크다운 + 자체 프론트매터 서브셋

### Task 3: `check_diagnostic_claims` — 방향을 붙인 문장을 센다

명세·결선도에서 가장 위험한 문장은 관측 결과에 **방향을 붙이는** 것이다 —
"~하면 ~를 의심한다", "~보다 크게 나오면 ~다". 교안에 원본이 없어 아무도
대조하지 않은 채 보고서로 넘어간다. 실험02 명세가 이 형태로 **두 번**
거꾸로였고 둘 다 제출본까지 갔다.

**판정하지 않는다 — 센다.** 방향이 맞는지는 절차의 산술을 굴려 봐야 알고
그건 코드가 못 한다. 이 검사가 하는 일은 "굴려 봐야 할 문장이 여기 N개
있다" 를 보이게 만드는 것뿐이라 `level` 이 `info` 다.

실측: 살아 있는 문서 10개에 총 33건, 최대 9건(실험10 결선도). 읽을 수 있는
크기다. **결선도 쪽이 명세보다 많다**(실험10: 9 대 1) — 명세만 검사하면
절반을 놓치므로 `check_netlist` 에도 건다.

**Files:**

### Task 4: 살아 있는 명세 코퍼스 스윕

지금 이름으로 찍어 보는 테스트는 실험01·06·10 뿐이다 — **실험02·05 는 여태

**Interfaces:**
- Consumes: `parse_spec`, `validate.validate_spec`,
  `validate.check_folder_convention`, `validate.check_netlist`
- Produces: `ROW_COUNT_WARN_ALLOWLIST: dict[tuple[str, str], str]` —
  `(폴더이름, 표ID) → 사유`. 새 명세가 warn 을 내면 사람이 여기 한 줄을
  쓰면서 "이 표는 정말 축약표인가" 를 판단하게 된다. 그 마찰이 목적이다.

- [ ] **Step 1: 스윕 테스트를 쓴다** (이 태스크는 테스트가 곧 산출물이다)

```python

이름으로 찍어 보는 테스트(`test_lab_spec_parser.py` 는 실험01·06·10)는
**새로 만든 명세를 보지 않는다.** 실험02·05 는 여태 어떤 테스트도 안 봤다.
glob 으로 훑으면 다음에 만드는 명세가 자동으로 그물에 든다 —
`draft-lab-spec` 이 조용히 깨진 명세를 남길 수 있는 경로를 막는다.

여기 있는 테스트는 **구조만** 본다. 실험02 는 이 검사들을 전부 통과한 채로
물리 오류 두 개를 갖고 있었다. 통과는 "파서가 읽을 수 있다"는 뜻이지
"내용이 맞다"는 뜻이 아니다.
"""

import unittest
from pathlib import Path

from scripts.lab import validate
from scripts.lab.spec_parser import parse_spec

ROOT = Path(__file__).resolve().parents[1]

# `2^n` 행 수 warn 을 정상으로 허용하는 자리. **사유를 반드시 적는다.**
# 사유 없이 늘리면 이 목록이 경고를 삼키는 쓰레기통이 된다.
ROW_COUNT_WARN_ALLOWLIST = {
    ("실험05", "T4"):
        "one-hot 입력 — 입력 하나당 한 행이면 족하다 (교안 p7 원문)",
    ("실험05", "T5"):
        "one-hot 입력. `D0` 가 어느 출력식에도 안 나와 입력 수가 7 로 세진다",
}


def live_specs():
    return sorted(ROOT.glob("실험*/체크리스트/명세.md"))


class LiveSpecCorpus(unittest.TestCase):
    def test_코퍼스가_비어_있지_않다(self):
        # glob 이 0건이면 아래 테스트가 전부 조용히 통과한다.
        self.assertGreaterEqual(len(live_specs()), 5, "명세를 하나도 못 찾았다")

    def test_전부_파싱된다(self):
        for path in live_specs():
            with self.subTest(path.parent.parent.name):
                parse_spec(path)

    def test_명세에_error_가_없다(self):
        for path in live_specs():
            with self.subTest(path.parent.parent.name):
                spec = parse_spec(path)
                errors = [f for f in
                          validate.check_folder_convention(path, spec)
                          + validate.validate_spec(spec)
                          if f.level == "error"]
                self.assertEqual(errors, [],
                                 "\n".join(str(f) for f in errors))

    def test_결선도가_짝으로_있고_error_가_없다(self):
        for path in live_specs():
            with self.subTest(path.parent.parent.name):
                spec = parse_spec(path)
                netlist = path.parent.parent / "결선도" / "netlist.md"
                errors = [f for f in validate.check_netlist(netlist, spec)
                          if f.level == "error"]
                self.assertEqual(errors, [],
                                 "\n".join(str(f) for f in errors))

    def test_warn_은_사유와_함께_허용목록에만_있다(self):
        for path in live_specs():
            folder = path.parent.parent.name
            spec = parse_spec(path)
            for f in validate.validate_spec(spec):
                if f.level != "warn":
                    continue
                table_id = f.where.rsplit(":", 1)[-1]
                with self.subTest(f"{folder}/{table_id}"):
                    self.assertIn(
                        (folder, table_id), ROW_COUNT_WARN_ALLOWLIST,
                        f"허용목록에 사유와 함께 올리거나 표를 고친다: {f}")

    def test_허용목록에_죽은_줄이_없다(self):
        # 표를 고쳐 warn 이 사라져도 목록 줄은 남는다 — 그러면 다음 사람이
        # 그 표를 "허용된 예외" 로 읽는다.
        live = set()
        for path in live_specs():
            folder = path.parent.parent.name
            spec = parse_spec(path)
            live |= {(folder, f.where.rsplit(":", 1)[-1])
                     for f in validate.validate_spec(spec)
                     if f.level == "warn"}
        self.assertEqual(set(ROW_COUNT_WARN_ALLOWLIST) - live, set(),
                         "warn 이 사라진 줄이 허용목록에 남아 있다")
```

# draft-lab-spec

저장소에서 **명세를 만드는 유일한 스킬**이다. 나머지 여덟은 전부 소비만
한다. 산출물의 계약서는 `docs/schema/lab-spec-v1.md` 이고, 이 문서는 그
계약서를 **어떤 순서로 채우는가**만 정한다.

## 인자

`<N주차|실험N> [명세만|결선도만]`

- 번호 토큰이 없으면 한 줄로 되묻고 중단한다.
- `명세만` 이면 결선도를 만들지 않는다. `결선도만` 이면 기존 명세를 읽어
  근거로 쓴다 — 없으면 거절한다.

## 절대 규칙

1. **교안이 유일한 근거다.** 과거 학생 제출본은 권위 5순위이고 알려진
   오염이 있다. 다른 실물 자료가 그것뿐이면 `docs/corpus-audit/` 의 대조
   기록을 먼저 읽고, 다수결로만·연도를 밝혀 쓴다. 단일 제출본을 근거로
   삼지 않는다.
2. **판독 규칙을 이 문서에 베끼지 않는다.** `docs/schema/lab-spec-v1.md`
   의 "교안 판독 규칙"·"교안에서 오지 않은 문장"·"셀 값"·"표기" 네 절을
   저작 전에 읽는다. 계약서가 한 곳이어야 개정이 한 번에 먹는다.
3. **표가 있는 쪽은 텍스트와 vision 을 둘 다 읽어 대조한다.** "수상하면
   vision" 은 안 된다 — 실험6 교안 p9·p11 의 `C` 열은 `pdftotext` 와
   `pypdf` 가 **둘 다** 리터럴 `1` 을 내놓고 그것이 그럴듯하다. 수상할
   계기가 없으므로 선택적 vision 은 이 지뢰를 못 밟는다. 어긋나면
   **vision 이 이긴다.**
4. **셀은 교안 원문 그대로 적는다.** 교안이 소문자 `x` 를 쓰면 `x` 로
   적는다. **`H/L` 과 `0/1` 을 서로 바꾸지 않는다.** 정규화는 파서가
   한다 — 그래야 정규화 규칙이 픽스처로 검증된다.
5. **열 이름은 한 표 안에서 유일해야 한다.** 교안이 입력과 출력에 같은
   글자를 쓰는 실물이 있다(실험3 반감산기 `A B D B` — 출력 borrow 가
   입력 `B` 와 같다). 출력 쪽 이름을 구분해 적고, 그 자리에 교안 표기가
   무엇이었는지 밝힌다. 파서가 중복을 거절한다.
6. **`ics` 는 패키지 수다.** 회로도에 같은 칩이 두 번 나와도 쿼드
   패키지에서 게이트 둘을 뽑는 것이면 하나다. `×2` 같은 수량 접미사를
   쓰지 않는다. 준비물에 있어도 그 항목이 안 쓰면 넣지 않는다.
7. **준비물 쪽 이름이 주차마다 다르다.** `준비물`·`실험준비`·
   `실험에 필요한 장비`·`실험기기` 를 **다 본다.** 한 이름으로만 찾아
   "없다"고 결론지으면 미확정이 불필요하게 부풀고 명세가 약해진다.
8. **IC 계열은 교안 본문 표기를 싣는다.** 교안 사진·실물 각인이 다르면
   (실험3 본문 `7408` / 사진 `74HC08N`) 본문 표기를 `ics` 에 넣고, 차이를
   결선도 미확정 표에 올려 수령 시 확인하게 한다. 지어내 고르지 않는다.
9. **교안에 없는 수치를 적지 않는다.** 지어낸 예상값은 측정값을 그쪽으로
   끌어당긴다. 비워 두고 무엇을 재야 하는지만 적는다.
10. **파생 문장은 그 자리에서 밝힌다.** 교안 원문이 아닌 절차·해석에는
    "교안 원문이 아니다" 를 같은 자리에 쓴다. 문서 끝에 몰아 적으면 읽는
    사람이 그 문장에 닿을 때 표시가 없다.
11. **방향을 붙인 문장은 절차의 산술로 굴려 본다.** "~하면 ~를 의심한다",
    "~보다 크게 나오면" 은 교안에 원본이 없다. 그 상태의 각 스텝에 실제
    값을 대입해 부호와 크기를 확인한다. 못 굴리면 **방향을 지우고 무엇을
    보고 판정할지만** 적는다. 실험02 명세가 이 형태로 두 번 거꾸로였다.
12. **미확정을 추측으로 채우지 않는다.** 결선도의 `# 미확정 사항` 표가
    단일 대장이다. 명세는 `source` 와 산문에 미확정임을 적고 번호 없이
    그 표를 가리킨다 — 명세를 먼저 쓰므로 번호를 앞당겨 매길 수 없다.
13. **기존 산출물을 제자리에서 덮어쓰지 않는다.** 이미 있으면 스크래치패드
    에 내고 `diff` 를 보여준 뒤 멈춘다. 이 규칙 하나가 승인본 보호와 격리
    재생성을 동시에 처리한다.

## 실행 절차

0. **번호를 코드로 옮긴다.** 주차와 실험 번호는 **1:1 이 아니다** —
   실험4가 7주차다. 손으로 옮기지 말고 아래를 돌린다.

   ```bash
   python3 -c "
   from scripts.lab import config
   print(config.folder_for_week(<N>))
   "
   ```

   사용자가 `실험N` 으로 불렀으면 `config.experiment_dir(<N>)` 을 쓴다.
   `ValueError`(8주차 중간고사·범위 밖)면 그 메시지를 그대로 전하고
   중단한다. 출력이 `프로젝트` 면 **거절한다** — FPGA 는 산출물이 HDL·
   시뮬레이션 파형이라 이 스키마 밖이다.

1. **폴더와 교안을 확인한다.** `<실험NN>/체크리스트/` 와
   `<실험NN>/결선도/` **둘만** 요구한다. 없으면 거절하고
   `init-lab-experiment` 를 안내한다 — 폴더를 만들어 주지 않는다.
   (하위폴더 7개를 요구하지 않는다. 실험06·10 은 둘뿐인데 정상이다.)

   ```bash
   python3 -c "
   from scripts.lab import config
   for p in config.manual_candidates(<실험번호>):
       print(p)
   "
   ```

   앞에서부터 실재하는 첫 후보를 연다. 실제로 연 경로가 명세의
   `source_manual` 이 된다. 둘 다 없으면 거절한다.

2. **판독 규칙을 읽는다.** §절대 규칙 2 가 지정한 네 절을 지금 읽는다.
   외워서 쓰지 않는다.

3. **전 쪽을 두 번 읽는다.** 쪽마다:

   ```bash
   pdftotext -layout -f <p> -l <p> "<교안>" -
   pdftoppm -r 300 -f <p> -l <p> -png "<교안>" <스크래치>/p
   ```

   표·회로도·기호가 있는 쪽은 렌더한 PNG 를 `Read` 로 본다. 두 판독을
   나란히 스크래치패드에 적고 **어긋난 자리를 전부 표로 남긴다** — 9단계
   확인 목록의 재료다. 회로도 세부가 안 잡히면 같은 쪽을 900dpi 로 다시
   렌더해 관심 영역을 크롭한다.

   판독 노트는 **스크래치패드에만** 둔다. 저장소에 남기지 않는다 —
   소비자가 없는 파일은 다음 주차에 아무도 안 채운다. 영구 보관 자리는
   명세 머리말의 토큰 규약 표와 결선도의 `## 핀아웃 출처` 다.

4. **명세를 저작한다** (`결선도만` 이면 건너뛰고 기존 명세를 파싱한다).

   프론트매터는 `schema`·`week`·`experiment`·`title`·`source_manual`·
   `power`(레일 이름 → 전압의 **열린 맵**)·`items[]` 다.

   - 표 ID 는 `T1` 부터 본문 등장 순서로 붙인다.
   - `kind` 는 **표 단위 속성**이다. 한 실험 안에 `capture` 와 `stepped`
     가 섞일 수 있다(실험10 이 실물).
   - `role: reference` 판정 기준: **"이 표를 채우려면 브레드보드에 무엇을
     꽂아야 하는가" 에 답이 없으면** `reference` 다.
   - 자명하지 않은 셀 토큰이 하나라도 있으면 머리말에
     `| 토큰 | 뜻 | 근거 |` 표를 둔다. **근거 열에 판독 방식을 적는다**
     (예: "p9·p11 을 300dpi 렌더 후 vision 판독").

5. **명세를 검증한다.** error 가 0 이 될 때까지 반복한다.

   ```bash
   python3 -c "
   from pathlib import Path
   from scripts.lab.spec_parser import parse_spec, SpecError
   from scripts.lab import validate
   p = Path('<실험NN>/체크리스트/명세.md')
   try:
       spec = parse_spec(p)
   except SpecError as e:
       print('SPEC-ERROR:', e); raise SystemExit(1)
   for f in validate.check_folder_convention(p, spec): print(f)
   for f in validate.validate_spec(spec): print(f)
   "
   ```

   **error 를 표 수정으로 없애지 않는다.** 원인이 열 이름일 수 있다
   (§절대 규칙 5). 부울식 역검산이 "표에는 X 이다" 라고 할 때, 표가
   틀렸는지 `source` 의 식이 틀렸는지를 교안으로 먼저 가른다.

6. **결선도를 저작한다** (`명세만` 이면 건너뛴다). 골격은 §결선도 골격.

   **회로도가 없는 주차가 있다.** 실험3 교안은 11쪽 전부가 이론·진리표·
   브레드보드 사진이고 회로도가 한 쪽도 없다. 그런 주차는 위상을 게이트
   논리에서 파생하고, 파생이라는 사실과 핀아웃의 근거 없음을 **전부 미확정
   표에 올린다.** 미확정이 크게 불어나는 것이 정상 동작이지 실패가 아니다.

7. **결선도를 검증한다.** error 가 0 이 될 때까지 반복한다.

   ```bash
   python3 -c "
   from pathlib import Path
   from scripts.lab.spec_parser import parse_spec
   from scripts.lab import validate
   spec = parse_spec('<실험NN>/체크리스트/명세.md')
   for f in validate.check_netlist(
           Path('<실험NN>/결선도/netlist.md'), spec):
       print(f)
   "
   ```

8. **진단 문장을 감사한다.** 5단계·7단계가 낸 `info` finding 을 하나씩
   짚어 §절대 규칙 11 을 적용한다. 굴려 본 산술을 그 자리에 남기거나,
   방향을 지운다.

9. **보고한다.** 세 목록을 낸다 — 텍스트와 vision 이 어긋난 자리와 어느
   쪽을 택했는지, 남긴 진단 문장과 방향을 정한 근거, 미확정 항목 전부.
   그리고 한 줄을 반드시 붙인다:

   > 구조 검증이 통과했다는 것은 파서가 읽을 수 있다는 뜻이고, 내용이
   > 맞다는 뜻이 아니다.

   실험02 는 이 검사들을 전부 통과한 채 물리 오류 둘을 갖고 있었다.
   다음 단계로 `prep-lab-checklist` 를 안내한다.

## 결선도 골격

다섯 실물에서 뽑은 공통 구조다. 순서를 지킨다.

| 절 | 내용 |
|---|---|
| `# 공통 규칙` | 전원 레일이 어느 핀으로 가는가 · 계열과 다른 전원핀을 가진 칩 · **미사용 입력핀 처리**. 이 과목의 대표 실패 원인이 플로팅 입력이다 |
| `## 핀아웃 출처` | 실물 데이터시트인지, 교안 안의 핀아웃 쪽인지, 표준 배치 가정인지. **가정이면 미확정 표에 올린다.** 실험01·06 결선도에 이 절이 없다 — 메울 구멍이지 예외가 아니다 |
| `## 참조 핀아웃` | 위 출처를 옮긴 핀 표 |
| `# E<n>.P<n> · <제목>` | 항목마다 하나. 명세 `items[].id`·`title` 과 글자 그대로 맞춘다. 소자 배치 표 + 칩별 핀 표 + `## 계측` |
| `# 미확정 사항` | `M1`~ 번호를 매긴 표. `| 항목 | 내용 | 확인 방법 |`. 명세 쪽 미확정도 여기로 모은다 |

## 비-목표

- **폴더를 만들지 않는다.** `init-lab-experiment` 의 일이다.
- **보고서를 쓰지 않는다.** `write-pre-report` 의 일이다.
- **기존 명세·결선도를 고치지 않는다** (§절대 규칙 13).
- **스키마를 바꾸지 않는다.** `lab-spec/v1` 이 표현하지 못하는 것을
  만나면 미확정으로 남기고 사용자에게 보고한다. 스키마 개정은 별개
  판단이다.
- **FPGA(13~15주차)를 다루지 않는다.** 산출물이 HDL·시뮬레이션 파형·핀
  할당이라 이 스키마로 확장하지 않기로 되어 있다.
- **검사 규칙을 이 문서에 새로 적지 않는다.** 규칙은 `validate.py` 에
  있고 테스트가 붙어 있다. 새 규칙이 필요하면 테스트부터 쓴다.
