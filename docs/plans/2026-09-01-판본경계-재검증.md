# 판본 경계 재검증 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> `subagent-driven-development` (recommended) or `executing-plans` to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking.

**Goal:** `draft-lab-spec` 스킬의 격리 검증을 **현재 판본으로** 닫는다 —
낡은 판본 결과로 남은 V1·V4·V5a·V5b·V6 을 다시 돌리고, 오늘 새로 쓴
§인자 문장을 재는 시나리오 V7 을 만들어 함께 돌린다.

**Architecture:** 이 계획은 **코드를 안 고친다.** 문서 하나(런북에 V7
추가)를 쓰고 나머지는 전부 **격리 재생성 회차**다 — 맥락 없는 fresh
에이전트를 worktree 안에 띄우고 결과를 판정한다. 판정 도구는 이미
있으므로(`compare_specs`·`uncovered_tables`·`check_netlist`) 새로 만들
것이 없다. 실패가 나오면 그때 스킬을 고치고 그 시나리오만 다시 돈다.

**Tech Stack:** git worktree, Claude Code 서브에이전트,
Python 3.14 표준 라이브러리, `unittest`, 마크다운

> **이 계획은 대부분 컨트롤러가 직접 수행한다.** Task 1 만 서브에이전트로
> 돌린다. Task 2~7 은 안에서 **또 다른** fresh 에이전트를 띄워야 하는데,
> 구현 에이전트가 띄우면 자기 맥락이 새어 통제군이 깨진다. 그리고 산출물이
> 코드 diff 가 아니라 **판정**이다.

## Global Constraints

- **fresh 에이전트에게 이 세션의 맥락을 넘기지 않는다.** 특히 **합격
  조건을 알려주지 않는다.** 넘기면 통제군이 아니다. 프롬프트는 런북
  §공통 템플릿을 **그대로** 쓰고 인자와 경로만 갈아 끼운다.
- **답안지 넷을 반드시 뺀다** — `docs/verify/`·`docs/plans/`·
  `scripts/lab/specdiff.py`·`tests/test_lab_specdiff.py`.
  런북 §공통의 `rm -rf` 가 정본이다.
- **`pytest` 없다.** `unittest` 만.
  `zsh -c 'PYTHONPATH=. python3 -m unittest discover -s tests -t .'`
- **`requests` 없다.** 표준 라이브러리만.
- 비대화형 셸이 `~/.zshrc` 를 안 읽는다. 파이썬은 `zsh -c '...'` 로 감싼다.
- **격리 worktree 안에서 `unittest discover` 를 돌리지 않는다.** 실험06·10
  명세를 경로로 참조하는 테스트가 넷이다.
- **브랜치는 `feat/draft-lab-spec-clean`.** 바꾸지 않는다.
- 시작 기준선 **453 tests OK.** 옆 세션이 계속 늘리므로 **절대 숫자가
  아니라 증가분과 `OK`** 를 본다. 이 계획은 테스트를 안 늘린다.
- 스킬 문서(`.claude/skills/` 아래)는 **한국어**, **76열** 이내(한글 2열).
  표 행과 프론트매터 `description:` 만 예외. **`docs/` 는 안 걸린다.**
- 커밋 접두는 `feat:`·`fix:`·`docs:`·`test:`. **`chore:` 금지.**
- **원격에 푸시하지 않는다.** `git add` 로 파일을 하나씩 지정한다.
- **규칙·단계·시나리오 번호를 밀지 않는다.** 기존 항목의 **본문만** 고친다.
- **기존 명세·결선도를 고치지 않는다** — 실험01·02·05·06·10 은 승인본,
  실험03 은 대조군. 전부 worktree 안에서 돈다.
- 옆 세션이 같은 저장소에서 작업 중이다. `실험05/`·`docs/corpus-audit/`·
  `.claude/skills/write-pre-report/SKILL.md` 를 건드리지 않는다.
- **worktree 를 남기지 않는다.** 회차가 끝나면
  `git worktree remove --force` 로 지우고 `git worktree list` 로 확인한다.

오늘 최종 리뷰(I4)가 §인자에 세 줄을 더했다 —


→ **사용자는 결선도를 못 받고 명세 diff 를 받는다.** 그 함정이 실제로
닫혔는지 재는 시나리오를 런북에 만든다.

**그리고 같은 파일의 판정 불가능한 조건 둘을 고친다.** V5·V6 의 합격
조건이 `git status --porcelain` **공란**인데, 런북이 답안지 넷을 지우라고
시키므로 그 출력은 **영영 공란이 안 된다** — 실측 **27줄**(`docs/plans/`
