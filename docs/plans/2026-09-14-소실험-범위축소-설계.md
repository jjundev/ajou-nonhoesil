# 소실험 범위 축소 (설계)

2026-09-14 `/grill-yourself` 로 만든 설계다. 근거는 같은 날 조교 공지 `_350547_1`
("[필독] 논리회로실험 보고서 관련 공지", `강의노트/공지사항/2026-09-14_[필독]_논리회로실험_보고서_관련_공지.md`)
이다. 구현 계획은 `docs/plans/2026-09-14-소실험-범위축소-구현계획.md`.

이 문서에서 **교안 = 강의노트**(`강의노트/*.pdf`)다.

## 배경

공지 원문: "다음 주차 즉, 실험 2번과 3번부터 실험을 선택해서 진행하는 것으로 결정하였습니다 …
예비 및 결과 보고서에는 표기된 실험만 작성하시면 됩니다." 사용자가 **실험실에서 하는 실험
자체도 줄어든다**고 확인했다(보고서만 줄이는 것이 아니다).

| 실험 | 하는 소실험 |
|---|---|
| 2 | 1-1, 1-2 |
| 3 | 1-2, 2-2 |
| 4 | 1-1, 2-1 |
| 5 | 1-2, 2-2 |
| 6 | 1, 2-1, 3-2 |
| 7 | 1 |
| 8 | 1, 3 |
| 9 | 1, 2 |
| 10 | 1 |

실험1 은 이미 끝나 기존 공지대로 전체다. 실험2·3 은 둘 다 9/18(3주차)이다. 공지의 번호는
실험2·3 강의노트의 항목 번호와 글자 그대로 같다(`pdftotext` 로 확인).

영향을 받는 산출물은 실험02·03 뿐이다(실험04~10 은 아직 명세가 없다).

- 실험02: 교안 실험 2(CMOS AC 특성, t_pd)가 빠진다.
- 실험03: 반가산기(1-1)·반감산기(2-1)가 빠진다.

## Intent

명세 → 결선도 → 체크리스트 → 예비·결과보고서 전 구간이 공지의 소실험 범위만 다루고,
명세가 범위를 벗어나거나 범위 번호가 교안 항목과 어긋나면 기계가 잡도록 하네스를 고친다.
완료는 범위 표가 `config.py` 한 곳에 있고, 실험02·03 명세·결선도·결선도 PNG·예비보고서가
범위대로 줄어 있으며, 범위 검사와 전체 스위트가 통과하는 상태다.

Classification: **bounded** — 새 표와 새 검사는 기존 `config.EXPERIMENT_DATES`·
`validate.check_folder_convention` 의 틀에 얹힌다.

## 결정

사용자가 고른 것 둘과 코드로 닫은 것들이다.

| # | 갈래 | 결정 | 근거 |
|---|---|---|---|
| 1 | 명세에 범위 밖 항목을 남기나 | **뺀다.** 명세에는 실험실에서 하는 항목만 싣는다(사용자 선택) | `spec.items` 를 도는 소비자(`record.py`·`render.py`·`check_report_tables`·세 스킬의 `item_count`·프리뷰)가 코드 변경 없이 따라온다. 덧씌우기는 그 전부에 필터가 필요하다 |
| 2 | 범위 표 위치 | `config.EXPERIMENT_SCOPE`, `EXPERIMENT_DATES` 옆. 표에 없는 실험 = 전체 | `EXPERIMENT_DATES` 주석이 적어 둔 교훈 — 스킬 문서에 베낀 주차표가 한꺼번에 거짓이 됐다 |
| 3 | 토큰 매칭 | 항목 id 의 `P` 뒤(`E3.P1-2` → `1-2`)가 토큰과 같거나 `토큰-` 로 시작하면 범위 안. `1` 은 `1-1`·`1-2` 를 덮고 `10` 은 덮지 않는다 | 공지가 `실험 1`(가지 없음)과 `실험 1-2`(가지)를 섞어 쓴다 |
| 4 | 검사 | `validate.check_item_scope(spec)` — 범위 밖 항목 error, 어느 항목에도 안 맞는 토큰 error. **`validate_spec` 밖**에 두고 `check_folder_convention` 처럼 따로 부른다 | 강의 방침에 매인 검사다. 픽스처 `spec_manual_outputs.md`(실험 3, 반가산기·반감산기 포함)가 명세 문법의 표본으로 쓰이므로 `validate_spec` 에 넣으면 그것까지 막는다 |
| 5 | 번호 | 항목·표·회로·미확정(M) 번호를 다시 매기지 않는다 — 실험03 은 `E3.P1-2`·`E3.P2-2`, `T3`·`T4`·`T7`·`T8`, `C2`·`C4` | 스키마 문서가 표 ID 는 "유일하기만 하면" 된다고 한다. 실험01 의 재번호 금지 선례. 렌더러 주석이 `netlist M8` 처럼 번호로 가리킨다 |
| 6 | 실험03 결선도 | 걸러내기로는 안 된다 — 단계가 앞 회로 상태의 차분이다(C2 1단계가 C1 상태를, C3 1단계가 C2 여덟 가닥 걷기를, C4 가 C3 상태를 전제). C2 는 **맨바닥 2단계**(① XOR 두 개 + LED1, ② AND 두 개 + OR + LED2), C4 는 **C2 완성 상태에서 1단계**(두 가닥을 걷고 74HC04 와 네 가닥을 꽂는다) | 칩 자리 고정·단계 차분이 이 하네스의 관례다. 단계가 있는 회로의 배너는 "앞 회로 배선은 그대로 둔다"로 인쇄된다(`render._chip_swap`) |
| 7 | 단계 확인 칸 | 범위 안 표만 가리킨다 | 중간 단계에 반가산기 진리표를 넣으면 뺀 실험이 돌아온다 |
| 8 | 렌더러 | 완성본 빌더 `build_e2_tpd`·`build_e3_ha`·`build_e3_hs` 는 남긴다. 사슬(`E2_BOARDS`·`E3_BOARDS`)과 단계 래퍼·CLI·`hand_compare.CIRCUITS` 의 단계 ID 에서만 뺀다. `_e3_draw` 는 `hs`·`fs` 에 1단계를 주면 거절한다 | 넷·가독성·손그림 테스트가 `e2_tpd`(같은 칩 두 패키지)와 `e3_hs`(입력·출력이 같은 글자 `B`)를 회귀 사례로 쓴다 |
| 9 | 범위 밖 PNG | 결선도 폴더에서 지운다(git 이력에 남는다) | `check_filename` 은 소단원이 명세 항목에 있어야 통과한다 |
| 10 | 예비보고서 | **기존 원고를 손으로 줄인다**(재생성 아님, 사용자 선택). 노션 최신본(실험02 v4·실험03 v2)을 먼저 되읽는다 | 리뷰 3~4 라운드와 노션 수정을 거친 원고다. 마감 9/18 |
| 11 | 예비보고서 이론 | 범위 안 회로가 범위 밖 회로를 구성 요소로 쓰면(전가산기 = 반가산기 둘 + OR) 이론 절에 **식까지만** 둔다. 진리표·과정·결선 소절은 두지 않는다. 뺐다는 사실을 본문에 밝히지 않는다 | `write-pre-report` §절대 규칙 16 의 "왜 안 쓰는지조차 설명하지 않는다" |
| 12 | 준비물 수량 | 강의노트 수량 그대로 둔다(실험02 `74HC04(2개)`) — 비고에 사실만 | `write-pre-report` §절대 규칙 16 둘째 문단 |
| 13 | 체크리스트 | 두 실험 모두 아직 없다. 하네스를 고친 뒤 `prep-lab-checklist` 로 새로 만든다 | 되돌릴 작업이 없다. 스위트의 남은 실패 2건(인쇄본 코퍼스)이 이것으로 풀린다 |

## 완료 시 동작

- `config.item_in_scope(3, "E3.P1-1")` 은 거짓, `config.item_in_scope(1, <무엇이든>)` 은 참.
- 명세에 범위 밖 항목이 있으면 `check_item_scope` 가 "항목 E3.P1-1 는 실험3 범위(1-2, 2-2)
  밖이다 — 조교 공지 `_350547_1` …" error 를 낸다. 범위 번호에 맞는 항목이 없으면
  "범위 번호 `2-2` 에 맞는 항목이 없다" error. `draft-lab-spec` 5단계, `review-lab-report`,
  코퍼스 테스트에서 돈다.
- 실험02 결선도는 3장(절차 2 + 완성본 1), 실험03 은 5장(절차 3 + 완성본 2)이다.
- 전감산기 단계 그림은 걷을 선 두 가닥(`A → 74HC08 pin 1`, `A⊕B → 74HC08 pin 4`)과 새 번호
  일곱 개(74HC04, 네 가닥, 전원 두 가닥)를 낸다. `Ci` 점퍼는 회색으로 남아 `Bi` 가 된다 —
  기준선은 끝점으로 비교하므로 이름만 바뀐 선은 그대로다(2026-09-14 스크래치 시제품으로 확인).
- 스위트 실패 0.

## 이번 라운드에서 빼는 것

- 결과보고서 — 실험 전이다. `write-result-report` 는 명세를 따르므로 따로 고칠 규칙이 없다.
- 실험01 — 공지가 전체 작성이라 했다. 격리 재생성 통제군도 실험01 이라 흔들리지 않는다.
- 실험04~10 명세 — 아직 없다. 저작할 때 `draft-lab-spec` §절대 규칙 14 와 `check_item_scope`
  가 받친다.
- 렌더러 `_E3_LED_NOTE` 의 `C·Co·B·Bo` 문구 — 보드 아래 주석이라 손그림에 옮겨지지 않고,
  회귀 그림(`e3_ha`·`e3_hs`)에는 여전히 맞다.

## 위험

- 교안 판본이 바뀌어 항목 번호가 공지와 어긋날 수 있다(실험4~10 은 배포본이 아직 없다) —
  `check_item_scope` 의 둘째 방향이 잡는다. 잡히면 사용자에게 묻는다.
- 조교가 범위를 다시 바꿀 수 있다 — `EXPERIMENT_SCOPE` 한 줄과 해당 명세만 고친다.
