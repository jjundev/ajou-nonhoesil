# v2 칩 행·LED 행 자동 배치 (배치기) — 설계

2026-10-05. `/grill-yourself` 결과. 결정 N1·N3·N4 는 추천안, N2 는 사용자가 3행으로 바꿨다.
선행: `2026-10-04-v2-배선기-밀도-설계.md`(경로만 고르는 배선기 — 그 설계 #12 는 "배치는 안 바꿈").

## 의도

v2 주차의 **칩 슬롯 행과 LED 사슬 윗행을 사람이 손으로 정하지 않고, 엔진이 신호선 총길이가 최소가
되도록 고르게** 한다. 지금은 시험판의 `K1..K4 = 5, 17, 29, 41`, `LED_TOP`, `MUX_LED_TOP`, 브리지
53·54행이 전부 손으로 정한 값이다. 지난 작업(배선기)은 이 자리를 고정한 채 경로만 골랐다.

입력은 이미 정해진 것이다: 회로마다 배선표(게이트 배정은 R7·R8 결과), 칩→슬롯, LED 태그 목록.
출력은 슬롯 행, 슬롯 위아래 순서, 회로별 LED 윗행, 브리지 행이다. 대상은 실험05 이후 v2 주차를
저작하는 사람(= Claude)이다.

완료 = v2 주차는 배치 탐색 기록이 없으면 테스트가 막는다. 실험04 v2 시험판에 적용하면 superset
(모든 단계의 선) 신호선 총길이가 손 배치(MUX 658.7 + DMUX 303.9 = 962.6칸, λ=0.5, 2026-10-05 실측)보다
짧고 밀도 합(45.2 + 6.3 = 51.5칸)은 늘지 않으며, R1~R14·진리표·단계 LED 시험이 그대로 통과한다.

분류: **architectural** — 새 하위 체계(배치 탐색)와 주차 파일의 새 인터페이스(레이아웃을 인자로
받는 빌더)가 생긴다.

## 완료 시 동작

- `python -m scripts.lab.place_search <배치.py>` 가 근사 비용으로 슬롯 후보 전부의 순위를 매기고(1분
  안), 지금 `LAYOUT`(기준)과 앞 8개를 `route_plan` 으로 실측하고(한 판에 약 1분), 막히지 않고 밀도가
  기준 이하인 것 중 가장 짧은 것부터 단계 사슬 전부를 `verify()` 로 그려 처음 통과한 것을 고른다.
  같은 폴더에 `배치탐색.md`(배선표 지문, 고른 layout JSON, 후보 표)를 쓴다.
- 저작자는 고른 값을 `배치.py` 의 `LAYOUT` 과 netlist `kind: layout` 표에 옮겨 적는다.
- 배선표를 바꾸고 다시 안 돌리면 테스트가 지문이 다르다며 막고 다시 돌릴 명령을 댄다. `LAYOUT` 이
  보고서와 달라도 막는다.
- 후보가 전부 막히면(3라운드 24개) "고를 배치가 없다" 와 마지막 사유로 멈춘다. 기준 `LAYOUT` 이
  막히면 그 사유로 멈춘다. 기준도 늘 후보라 나빠지는 배치는 고르지 않는다.
- 14핀이 아닌 칩(16핀·7-segment)이 있으면 `ValueError` — 배선기와 같은 한계다.
- SKILL §4 강제 규칙: "v2 칩 행·LED 행은 `place_search` 로만 정한다"(`route_plan` 강제와 같은 지위).

## 이번에 안 하는 것

- 게이트 배정·핀 선택 — R7·R8 과 저작 규칙이 정한다. 흔들면 교안 핀 번호·netlist 가 바뀐다.
- 승인본 v1 실험01~04 — 소급하지 않는다.
- 16핀 칩·7-segment — 배선기가 먼저 그 끝점을 다뤄야 한다.
- 오른쪽 블록 f~j 활용, 가운데 띠 세로선 금지, 찢고 다시 깔기 — 배치 효과를 잰 뒤 따로.
- λ(밀도 가중) 재선정 — 배선기는 `DENSITY_WEIGHT = 0.5` 그대로.

## 구현 명세

### 엔진 `render_breadboard.py` — 새 절 "배치기 (v2)" (배선기 절 뒤, `# 주차 결선 파일` 앞)

- `PlaceCircuit(name, chips, models, leds, wires, fixed, inputs=())` — chips 는 칩→슬롯, models 는
  칩→모델(14핀 `DIP14` 만), leds 는 위→아래 태그 순서(R10), wires 는 `route_plan` 꼴이되 LED 끝은 태그
  `('LED', 'L1')`, `fixed(bb, stage, superset, layout)`, inputs 는 입력 점퍼가 꽂히는 (칩, 핀).
- layout = `{'slots': {슬롯: pin1 행}, 'leds': {회로: {태그: 윗행}}, 'bridge': [GND 행, VCC 행]}` —
  JSON 과 그대로 맞대려고 리스트·문자열 키만 쓴다.
- 근사 비용 `place_wire_cost` — 끝 홀 후보 사이 최소 맨해튼 + 40·꺾임 + 400·몸통(배선기 `_coster` 와
  같은 상수). 꺾임은 행이 다르거나 가운데를 건너면(LED, R12 반 행) 2. 몸통은 쪽이 다른 같은 칩 안
  선이나 a쪽 → LED 면 1.
- `slot_candidates(slots, gmin=3)` — 순열 × 맨 위 행 3~8 × 칩 사이 빈 행 3~6. 칩 행 k·k+6 이
  `RAIL_GAP_ROWS` 면 버린다(전원선 사선). 브리지 자리가 없으면 버린다.
- `bridge_rows(slots)` — 맨 아래 칩에서 2행 이상 아래인 첫 연속 비간극 두 행.
- `led_rows(circuit, slots, bridge)` — DP. 태그 순서 고정, 사슬 간격 ≥ 4행, 윗행+3(GND 점퍼 행)이
  레일 빈 행·가운데 레일 사용 행(칩 pin 14 행·브리지·f쪽 입력 행)이 아니다. 그 LED 로 가는 모든 단계
  선의 근사 비용 합 최소, 동률이면 위쪽. MUX L1(단계 관측 + 최종 Y)도 따로 다루지 않는다.
- `place_r10_ok` — 단계마다 LED 로 건너는 선의 칩 쪽 행 순서가 LED 순서와 같은지 미리 본다.
- `place_plan(module)` — 근사 순위 → 기준 + 앞 8개 실측(`place_metrics` = superset 판 `wire_metrics`)
  → 막힘·밀도 초과(기준보다 큼) 탈락 → 길이 순으로 `place_verify`(모듈 `LAYOUT` 을 잠시 바꿔 `BOARDS`
  사슬·`FINALS` 를 다 그림) → 첫 통과. 없으면 다음 8개, 3라운드까지.
- `place_paths(circuit, layout, λ)` — 회로·자리·λ 별 `route_plan` 캐시. 주차 빌더가 쓴다.
- `place_report` / `read_place_report` / `place_module_hash`.

### 도구 `scripts/lab/place_search.py` — 주차 파일을 읽어 `place_plan` → `배치탐색.md`.

### 주차 계약 (SKILL §4)

v2 `배치.py` 는 `PLACE`(PlaceCircuit 목록)·`SLOTS`·`LAYOUT` 을 내보내고 빌더는 전역 행 상수 대신
`LAYOUT` 을 읽는다. 선택으로 `GMIN`.

### 시험

단위(근사·후보·DP·R10·선택 로직·보고서 왕복·캐시) + 시험판 인터페이스 이전(스냅숏 동일) + 강제
시험(v2 주차 = 보고서·지문·LAYOUT 일치) + 시험판 측정(손 배치보다 짧고 밀도 안 늘어남).
