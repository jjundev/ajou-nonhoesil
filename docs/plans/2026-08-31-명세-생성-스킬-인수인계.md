# 인수인계 — 명세 생성 스킬 설계

> 계획서가 아니라 **계획을 쓰기 전의 인수인계**다. 별도 세션이 이 문서로
> 시작해 설계 → 계획 → 실행으로 간다.

작성: 2026-08-31 · 이전 세션은 실험02 예비보고서 루프를 닫는 작업이었다

## 이 세션이 할 일

`<실험NN>/체크리스트/명세.md` 와 `<실험NN>/결선도/netlist.md` 를 **교안 PDF 에서
만드는 스킬**을 설계한다. 지금은 이 둘만 손으로 만든다.

```
교안 PDF  →  ??? (없음)  →  명세.md + netlist.md  →  ③ 예비보고서  →  ⑦ 노션
```

## 왜 지금인가

스킬 8개가 **전부 명세를 소비만 한다.** 생산자가 없다. 손으로 다섯 번 만들었고
(실험01·02·05·06·10), 여섯 번째부터는 규칙이 있는 편이 낫다.

## 설계하면서 부딪칠 것

1. **회로도는 반드시 vision 으로 읽는다.** `extract_text()` 는 오버바·라이징
   엣지·아래첨자를 파괴하고 회로도는 아예 래스터다. `pdftoppm -r 250~300` 으로
   렌더해 크롭·확대한다. 실험02 체인의 `6→13` 점프는 900dpi 로만 나왔다.
2. **텍스트 추출과 vision 이 어긋나면 vision 이 이긴다.** 지뢰가 문서에 있다 —
   실험6 교안의 라이징 엣지 글리프가 텍스트로는 리터럴 `1` 로 나와서, 믿고
   검증하면 표를 **자신 있게 틀리게** 고친다.
3. **진단 문장이 가장 위험하다.** "~하면 ~를 의심한다" 처럼 관측에 방향을 붙이는
   문장은 교안에 원본이 없다 — 명세 쓴 사람의 추론이다. 실험02 에서 이 형태로
   **두 번** 방향이 거꾸로였고 둘 다 보고서로 그대로 넘어갔다. 상세는
   `docs/schema/lab-spec-v1.md` 의 해당 절.
4. **미확정을 추측으로 채우지 않는다.** `source` 에 미확정이라 적고 미확정 표에
   올린다. 실험02 netlist 는 M1~M9 아홉 개를 그렇게 남겼다.
5. **검증이 통과해도 내용은 틀릴 수 있다.** `validate_spec` 은 구조를 본다.
   실험02 는 검증 전부 통과한 채로 물리 오류 두 개를 갖고 있었다.

## 하지 말 것

- **기존 명세 다섯 개를 고치지 않는다.** 실험01·02 는 노션에 올라간 승인본과
  묶여 있다. 스키마를 바꾸고 싶으면 그것부터 별개 판단이다.
- **과거 학생 제출본을 근거로 삼지 않는다.** 권위 5순위 코퍼스이고 오염이 있다.
  실험2 대조 결과가 `docs/corpus-audit/실험02-예비보고서.md` 에 있다 —
  그 문서도 정본이 아니니 머리의 검증 상태를 먼저 읽는다.
- **규칙·단계 번호를 밀지 않는다.** 새 항목은 마지막 번호 뒤에 붙인다.
- 원격에 푸시하지 않는다. 로컬이 `origin/main` 보다 93 커밋 앞서 있다.

- Python 3.14.6. **`pytest` 없다** — `unittest` 만.
  `zsh -c 'PYTHONPATH=. python3 -m unittest discover -s tests -t .'`
- **`requests` 없다** — `urllib.request`.
- 비대화형 셸이 `~/.zshrc` 를 안 읽는다. 토큰 필요하면 `zsh -c '...'`.
- 스킬 문서는 **한국어**, **76열** 이내(한글 2열). 표 행만 예외.
  `docs/` 파일은 이 규칙에 안 걸린다.
- 커밋 접두는 `feat:`·`fix:`·`docs:`·`test:`. **`chore:` 금지.**
- 현재 **391 tests OK**. 깨뜨리지 않는다.

## 설계에서 먼저 답해야 할 것

- 스킬 하나인가 둘인가 — 명세와 결선도는 난이도가 다르다(결선도가 vision 부담을
  전부 진다)
- 사람이 확인하는 지점을 어디에 두는가 — 회로도 판독을 무인으로 통과시킬 것인가
- 산출물 검증을 어떻게 강제하는가 — `parse_spec` + 세 검사를 스킬 절차에 넣는지
- 기존 다섯 개를 회귀 픽스처로 쓸 것인가 (새 스킬로 재생성해 대조)
