# 브레드보드 v2 구조 설계

2026-10-02 · 확정(#9 가운데 GND·VCC, #10 왼쪽 바깥 → 가운데 브리지, #11 우측 LED+저항만, #12 우측 바깥 레일 안 씀 — 추천값 그대로)

## 의도

실험실 실물 보드에 맞춘 **브레드보드 판형 v2 의 논리 구조**를 정한다. v1 양식
(`.claude/assets/Breadboard.jpg`)과 다른 점은 하나다 — 가운데 전원 레일이 **4열(2쌍)이 아니라
2열(1쌍)**이다. 같은 설계에 배치 규약을 함께 싣는다: **칩은 전부 왼쪽 블록, LED 만 오른쪽
블록.** 칩 사이 연결이 가운데를 좌우로 왕복하면 선이 꼬이고 배선이 어렵다 — 칩끼리는 왼쪽
블록 안에서 수직으로만 잇는다.

픽셀·색·여백 같은 시각 요소는 정하지 않는다(별도 디자인 세션). 디자인 세션과 스킬 업데이트
세션이 해석 없이 구현할 수 있으면 완료다.

분류: architectural — 판형이 하나뿐이라(`render_breadboard.py:32-39`) "판형 버전" 개념이 새로 생긴다.

## 완료 시 동작

- `배치.py` 에 `BOARD = 'v2'` 를 적은 실험은 v2 양식 위에 렌더된다. 없으면 v1 — 실험01~04 는
  지금 결과 그대로(바이트 동일).
- v2 에서 가운데 GND·VCC 는 각각 **한 넷**이다. 왼쪽 칩 pin 14 와 오른쪽 LED 캐소드가 가운데
  레일에 꽂히면 브리지 없이 같은 레일로 판정된다.
- v2 에서 칩을 오른쪽 블록에 놓으면 렌더 시 검사 오류로 멈춘다. 가운데를 건너는 선이
  "칩 출력 → LED" 가 아니어도 오류다.
- 손그림 검토는 v2 양식에서 26열을 찾는다. 사이드카 JSON 에 판형 버전이 남는다.
- `BOARD = 'v2'` 인데 v2 양식 파일이 없으면 v1 로 조용히 넘어가지 않고 오류로 멈춘다.

## 이번에 안 하는 것

- 시각 디자인(픽셀·색·로고·잭 그림) — 별도 디자인 세션.
- 스킬·코드 수정 — 별도 세션. 이 문서가 그 입력이다.
- 실험01~04 의 v2 이전 — 승인·손그림 검토·도장 해시가 끝났다. 옮기면 얻는 것 없이 다 무효가 된다.
- 오른쪽 블록의 LED 수용량 — 실험04 기준 LED 가 적어 아직 제약이 아니다.

## 구현 명세

### 1. 물리 구조 (왼쪽 → 오른쪽, 26열)

| 순서 | 구역 | 열 키 | 열 수 |
|---|---|---|---|
| 1 | 왼쪽 바깥 레일 | `gnd`, `vcc` | 2 |
| 2 | 왼쪽 블록 | `a`–`e` · (칩 골) · `f`–`j` | 10 |
| 3 | **가운데 레일 (공유)** | `mid_gnd`, `mid_vcc` — 왼쪽이 GND(파랑), 오른쪽이 VCC(빨강) | **2** |
| 4 | 오른쪽 블록 | `a`–`e` · (칩 골) · `f`–`j` | 10 |
| 5 | 오른쪽 바깥 레일 | `gnd`, `vcc` | 2 |

- 63행. 레일 빈 행은 v1 과 같은 `{1, 2, 8, 14, 20, 26, 32, 38, 44, 50, 56, 62, 63}`
  (`render_breadboard.py:254-260`).
- 레일 한 열은 63행 전체가 한 넷이다. 단자대는 한 행의 `a`–`e`, `f`–`j` 가 각각 한 스트립이다(v1 과 같음).
- v1 대비 바뀐 것은 3번뿐이다. v1 은 여기에 레일 쌍이 둘(왼쪽 블록용 `mid_gnd 468`·`mid_vcc 484`,
  오른쪽 블록용 `mid_gnd 542`·`mid_vcc 558`) 있었다.

### 2. 열 표 (`_init_cols`)

- 판형 버전별로 표를 따로 둔다. v1 표는 손대지 않는다.
- v2 에서 `cols['left']['mid_gnd']` 와 `cols['right']['mid_gnd']` 는 **같은 x** 다(VCC 도 같다).
  한 열을 두 이름으로 부른다.
- 넷의 단위가 `('rail', x)` 라서(`render_breadboard.py:1568`) 이것만으로 한 넷이 된다. 아래는
  고칠 필요가 없다:
  - `connect_power` — 왼쪽 칩 pin 14 → `mid_vcc`, pin 7 → 바깥 `gnd` (`:1238-1239`)
  - `nearest_gnd_rail` · `nearest_vcc_rail` (`:1253`, `:1257`)
  - 입력 점퍼의 레일 선택 (`:2015-2018`)

### 3. 주소 이름 (`_build_addr_map` · `_build_sym_map`, `:712-735`)

- 같은 x 가 두 번 나오므로 중복을 뺀다.
- 가운데 레일은 좌·우 접두어 없이 `중앙GND레일` · `중앙VCC레일` 로 부른다.
- 기호상 소속 블록은 `left` 로 고정한다.
- 입력 배지 자리(`:2034`, 좌 중앙 VCC 와 우 중앙 GND 사이 여백)는 v2 에 그 여백이 없다.
  배지 자리는 디자인 세션이 정한 여백에 맞춰 스킬 업데이트 세션이 다시 정한다.

### 4. 전원 경로 (v2 표준)

- 전원 잭(+5V·0V)은 **왼쪽 바깥 레일**에 꽂는다(`connect_jacks`, `:777`, 지금과 같음).
- 왼쪽 바깥 레일 → 가운데 레일로 GND 하나, VCC 하나를 브리지한다. 그러면 왼쪽 블록 칩의
  pin 7(바깥 GND)과 pin 14(가운데 VCC), 오른쪽 LED 캐소드(가운데 GND)가 모두 전원을 받는다.
- **오른쪽 바깥 레일은 기본 배선에서 쓰지 않는다.** 양식 그림에는 남긴다. 필요한 주차만 브리지한다.
- v2 에서 `mid` 끼리 브리지(같은 x 를 잇는 셈)는 오류로 막는다. v1 의 `실험01 배치.py:213`,
  `실험04 배치.py:139` 같은 습관이 넘어오는 것을 막는다.

### 5. 배치 규약 (새 검사, v2 에서만)

- 칩은 `block='left'` 에만 둔다.
- 오른쪽 블록에는 **LED 체인(LED + 저항)만** 둔다.
- 블록을 건너는 선은 한쪽 끝이 왼쪽 칩 출력 스트립, 다른 쪽 끝이 오른쪽 LED 체인 스트립이어야
  한다. 그 밖은 오류다. (전원 브리지는 레일끼리라 이 검사 대상이 아니다.)
- 건너는 선들은 위에서 아래로 LED 순서와 같은 행 순서로 놓는다 — 건너는 선끼리 꼬이지 않게 한다.
- 칩 수용량: 14핀 칩 7행, 16핀 칩 8행. 63행이면 칩 사이 한 행씩 띄워 대략 7개다. 실험04 는
  최대 4개(`실험04 배치.py:52`)라 넉넉하다. 넘치는 주차가 생기면 규약에 예외 조항을 두지 않고
  기존 면제 열쇠(`docs/plans/2026-09-21-면제열쇠-설계.md`)로 푼다.

### 6. 판형 버전 계약

- `배치.py` 모듈 상수 `BOARD` 가 `'v1'` 또는 `'v2'`. 없으면 `'v1'`.
- 버전마다 짝으로 묶이는 것:

| 항목 | v1 | v2 |
|---|---|---|
| 양식 경로 | `.claude/assets/Breadboard.jpg` | 디자인 세션이 정함 |
| `TEMPLATE_SIZE` | `(998, 1345)` | 디자인 세션이 정함 |
| 열 표 | 지금 `_init_cols` | 2번 |
| 손그림 검토 `EXPECTED_COLS` | 28 (`hand_grid.py:34`) | 26 |
| 레일 빈 행 · 행 수 | `RAIL_GAP_ROWS` · 63 | 같음 |

- 사이드카 JSON 에 `board` 필드를 추가한다(`SIDECAR_SCHEMA`, `render_breadboard.py:2078`).
- 손그림 검토 쪽 `_reference_cols` 는 x 를 모을 때 중복을 빼야 26 이 나온다(`hand_grid.py:291-302`).
  `_SHORT` 약칭(`hand_grid.py:342`)의 `g-`·`v+` 는 v2 에서 좌우 구분 없이 하나다.

### 7. 디자인 세션에 넘기는 계약

- 산출물은 1번 표의 26열 순서, 63행, 레일 빈 행, 가운데 레일 극성(GND 왼쪽·VCC 오른쪽)을 지킨
  이미지다. 픽셀 값은 디자인 세션이 정한다.
- 완성 이미지를 실측해 v2 열 표를 뜬다. 렌더러 주석이 가리키는 `tools/measure_template.py` 는
  **저장소에 없다**(2026-10-02 확인). 스킬 업데이트 세션이 실측 도구를 만들거나,
  `hand_grid.detect_grid` 로 열·행 중심을 뽑아 쓴다.

### 8. 병합 정책

양식 이미지와 코드 변경은 한 브랜치에 모아 테스트가 통과하면 한 번에 병합한다. 이미지만 먼저
들어가면 손그림 검토의 28열 가정(`hand_grid.py:34`)이 깨진다. v2 는 양식 파일이 있어야만 켜진다.

### 9. 테스트

- 실측한 v2 열 표가 1번 표의 순서와 26열을 지킨다.
- 가운데 레일에 꽂은 왼쪽 칩 VCC 와 오른쪽 LED 가 브리지 없이 한 넷이다.
- v2 에서 `mid` 끼리 브리지하면 오류다.
- v2 에서 칩을 오른쪽 블록에 두면 오류다. 블록을 건너는 선이 출력 → LED 가 아니면 오류다.
- `BOARD = 'v2'` 인데 양식 파일이 없으면 오류다.
- v1 기준선(`tests/test_breadboard_baseline.py`)은 그대로 통과한다.
