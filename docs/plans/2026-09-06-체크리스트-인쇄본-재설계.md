# 체크리스트 인쇄본 재설계 — 회로 단위 분해

`prep-lab-checklist` 가 내는 `체크리스트.pdf` 를 실험실에서 실제로 쓸 수 있는
형태로 다시 짠다. 결정은 2026-09-06 grilling 으로 확정했다.

## 왜 고치나 — 현재 인쇄본의 실측

`보고서/실험01/체크리스트/체크리스트.pdf` 는 8쪽이고 이렇게 생겼다.

- 1~4쪽: 배선 지시가 **번호 1~95 연속 한 덩어리**. 회로 5개가 이어 붙어 있다
- 5~7쪽: 표 5개를 몰아서
- 8쪽: 빈 브레드보드 1장

AND 회로를 배선하려면 2쪽, 결과를 적으려면 5쪽이다. **실험 내내 쪽을 왕복한다.**

구체적 결함 여섯 가지:

1. `_procedure()` 가 netlist 의 **모든** 불릿을 평평하게 번호 매겨서, 번호 7~11번
   "단계"가 실은 **핀아웃 출처(참고문헌)** 다. 실험실에서 근거의 등급을 읽을 일은 없다
2. 표 줄(`|`)을 통째로 건너뛰어 **`참조 핀아웃` 표가 인쇄본에서 사라진다.**
   74HC02 만 핀 1·4·10·13 이 출력이라는, netlist 스스로 "가장 흔한 배선 실수"라고
   표시한 정보다. 가장 필요한 표가 없다
3. `미확정 사항` 은 제목과 도입문만 찍히고 표 본문이 없어 **문장이 끊긴 채 끝난다**
4. 칩 계층이 사라진다. `- U3 = 74HC08` 과 그 아래 들여쓴 `- pin 14 → VCC` 가
   형제 번호가 되어 칩의 경계가 없다. 번호가 문서 전체 1~95 라 "62번 배선 중"이
   아무 의미도 없다
5. 회로마다 `결선도 | 구성한 회로 (사진 부착)` 2열 상자를 찍는데 **실험실에서
   사진을 붙일 수 없다.** 보고서 배치는 `write-result-report` 가 한다 —
   결과보고서 레이아웃이 실험실 인쇄본에 샌 것이다
6. `확인` 칸 규약(`✓` 일치 / 값 = 불일치 시 관찰값 / 공란 = 미확인)과 사진 파일명
   규칙(`T<n> row<m>.jpg`)이 **`기록.md`·`SKILL.md` 에만 있고 PDF 에는 없다.**
   태블릿에 PDF 만 띄운 사람은 규약을 알 방법이 없다

| T | `기록.md`(`record.py`)는 **손대지 않는다** | 전사의 조인 키는 순서가 아니라 표 ID(`T<n>`)다 |

### 지면 계산 (M 의 근거)

결선도 PNG 는 `998×755` 안팎. 인쇄 폭 190mm 에 맞추면 높이 **약 144mm** — A4
사용가능 높이 273mm 의 53%. 폭을 절반(95mm)으로 줄이면 12px 핀 라벨이 약 **3.2pt**
가 되어 읽을 수 없으므로 **결선도는 전체 폭을 요구한다.**

한 쪽에 다 넣으면 결선도 144 + 배선 55 + 진리표 80 + 제목 20 ≈ **299mm > 273mm**
라 안 들어간다. 그래서 앞쪽(결선도+배선) / 뒤쪽(유의사항+표) 으로 자연 분할된다.

**실측(2026-09-06):** 실험01 은 15쪽이다. 공통면이 1쪽이 아니라 3쪽인데, 미확정
M1~M10 표가 크기 때문이다. 백지는 0장이다.

## 선행 결함 — `breadboard-diagram` 의 거짓 별칭

`render_breadboard.py:730` 의 dispatch 가 이렇다.

    "e1_or":  build_e1_and,     # OR 인데 AND 빌더
    "e1_nor": build_e1_nand,    # NOR 인데 NAND 빌더

`breadboard-diagram/SKILL.md` 는 `e1_nor` 를 "74HC32 + 74HC02, 출력 핀 1번 특이배치
반영"이라고 광고하지만 **파일 전체에 `74HC02` 문자열이 없다.** `--circuit e1_nor` 는
74HC00 을 그린 NAND 결선도를 `..._NOR.png` 이름으로 낸다. netlist 가 "가장 흔한
배선 실수"라고 경고하는 바로 그 지점에서 틀린 그림이 조용히 나온다. 실험01 에
PNG 가 3장뿐인 것도 OR·NOR 이 앞 그림과 똑같이 나오기 때문이다.

**조치: 별칭 두 개를 dispatch 와 `choices` 에서 제거하고 SKILL.md 의 지원 목록에서
지운다.** 그림이 틀린 것보다 없는 것이 낫다 — 결정 2와 같은 원칙이다. 74HC32 전용
빌더와 74HC02 빌더 작성은 별건으로 남긴다.

## `lab-netlist/v1` 계약 (신설)

모든 `# ` 절이 속성 리스트로 시작한다. **`kind` 가 인쇄 라우터다** — 휴리스틱으로
목적지를 짐작하던 것을 데이터로 만든다. 결함 1·2·3 이 구조적으로 사라진다.

| `kind` | 인쇄 목적지 |
|---|---|
| `common` | 공통면 — 공통 규칙 |
| `reference` | 공통면 — 참조 핀아웃 표 (**표를 인쇄한다**) |
| `open-issues` | 공통면 — 실험실 확인 체크박스 |
| `sources` | **인쇄 제외** (예비보고서 참고문헌 재료) |
| `circuit` | 회로 페이지 하나 |

`kind: circuit` 만 추가 필드를 갖는다.

| 필드 | 필수 | 값 |
|---|---|---|
| `id` | ● | `C<n>` — netlist 안에서 유일. 페이지 순서이자 오류 메시지의 지시 대상 |
| `item` | ● | 명세 `items[].id` 중 하나 (`E1.P1-1`). 고아면 error |
| `tables` | ● | 이 회로가 검증하는 표 ID (`[T1]`). 명세에 없으면 error |
| `diagram` | ○ | `결선도/` 기준 PNG 파일명. 없거나 파일이 없으면 **warn** + 빈 브레드보드 fallback |

칩 목록은 새 필드로 두지 않고 기존 `U<n> = <칩>` 선언에서 뽑는다 (`render.py` 의
`_IC_DECL` 재사용). 필드를 늘리면 표류한다.

## 렌더 구조

**공통면 (1쪽)**
- 제목 + 전원 박스
- **오늘의 흐름 표** — 회로별 `번호 · 이름 · 쓰는 IC · 검증 표 · 쪽번호`
- 공통 규칙 (`kind: common`)
- **참조 핀아웃 표** (`kind: reference` — 지금 사라지는 것)
- **실험실 확인 체크박스** (`kind: open-issues` 표의 행마다 `□ 항목 / 확인 방법`)
- 확인 칸 범례

**회로 페이지 (회로마다 강제 개쪽)**
- 머리글 `회로 3/5 · 3-input NAND (74HC08 + 74HC00) · 검증: T3`
- **칩 교체 배너** — 앞 회로와 IC 집합을 비교해 뺄 칩·꽂을 칩 (M10 근거)
- 결선도 전체 폭 (없으면 빈 브레드보드 크롭)
- 칩별 배선 상자 — 번호 1부터, 줄마다 체크박스
- **미사용핀 강조 박스** (입력 → GND / 출력 → 개방)
- 이 회로의 유의사항 산문 (복합회로의 `X ≡ Z` 자체 검산 등)
- 측정표 + 사진 지시 한 줄 + **불일치 행 미니표** (`행 · 예상 · 실제 · 사진파일 · 짐작된 원인`)

**마지막 쪽** — 종료 전 확인 목록 (사진 · 미확정 질의 · 부품 반납 · 빈 표)
