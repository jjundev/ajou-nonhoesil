# ③·④ 공통 서식 규칙 공용화 — 설계

## 의도

③ `write-pre-report` 와 ④ `write-result-report` 에 같은 서식 규칙 열 쌍이 두 벌로
복사돼 있다(강의노트 호칭·AI 티·다른 파일 언급·목차·헤딩·여백·표 캡션·관찰 문장·
표 예고·붙여쓰기). 2026-09-29 측정에서 그중 넷이 유사도 0.55~0.79 로 벌어져 있었다 —
한쪽만 고치고 다른 쪽을 안 고친 흔적이다. 이 열 쌍의 본문을 `.claude/보고서서식.md`
한 곳으로 옮기고, ③·④ 의 해당 번호 자리에는 번호·굵은 첫 문장·포인터(와 그 보고서에만
해당하는 부가 규칙)만 남긴다.

완료 기준: 두 스킬이 같은 규칙 본문을 읽고, 규칙을 고칠 자리가 한 곳이며, 기존 테스트와
규칙 번호 인용 442곳이 깨지지 않고, ③·④ 격리 재생성이 서식 영역에서 나빠지지 않는다.

분류: bounded — `.claude/보고서양식.md` 를 공용으로 읽는 흐름(③ §절대 규칙 1, ④ §절대
규칙 2)이 이미 있고, 같은 방식으로 파일 하나를 더한다.

**로드량은 거의 줄지 않는다.** ③·④ 가 공용 파일을 반드시 같이 읽기 때문이다. 이번
작업이 얻는 것은 출처가 하나라는 점이다. 문서가 방대한 문제는 이 설계 밖(아래)이다.

## 끝난 뒤의 동작

- `/write-pre-report`·`/write-result-report` 의 호출과 산출물은 그대로다. 두 스킬이
  양식 로드 단계에서 `.claude/보고서서식.md` 를 전부 읽는다.
- 서식 규칙은 `.claude/보고서서식.md` 한 곳만 고친다.
- `보고서서식 §<이름>` 포인터가 없는 절을 가리키거나, 공용 절을 ③·④ 중 한쪽만
  가리키면 `pytest` 가 잡는다.
- `③ §절대 규칙 13`·`④ §절대 규칙 8` 같은 기존 인용은 그대로 유효하다.

## 이번에 안 하는 것

- 0단계 "실험 번호를 폴더 이름으로 옮긴다"(10개 스킬 × 43줄) 공용화 — 별개 작업.
- 절대 규칙을 두 층으로 나누고 사고 기록을 `references/` 로 옮기기 — 로드량을 실제로
  줄이는 작업이지만 규칙이 안 읽힐 위험이 있어 따로 검증해야 한다.
- ④ vision 전사·퀴즈, breadboard §6·§7 의 references 분리.
- 참고문헌(③9/④10)·명세 열 이름(③22/④19)·미사용 소자(③16/④17) — 이름은 같지만
  보고서마다 내용이 다르다. 제자리에 둔다.
- ③ 에만 있는 서식 규칙(③18 문단 한 줄, ③19 11열) — 올리면 ④ 에 새 규칙이 생긴다
  (결정 #11).
- `scripts/lab/validate.py` 메시지 속 `④ §절대 규칙 8/18`, `docs/plans/` 의 과거 인용 —
  번호를 유지하므로 유효하다.
