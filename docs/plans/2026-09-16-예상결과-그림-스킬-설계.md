# 예상 결과 그림 스킬 `draw-expected-figure` 설계

- 날짜: 2026-09-16
- 기준 커밋: `3e9d701` (실험02 체크리스트 PDF 재생성 직후)
- 계기: 실험02 예비보고서의 예상 결과에 모식도를 손으로 만들어 넣었고, 같은 작업을
  실험03 에 해 보니 진리표가 이미 예상 결과라 그림이 중복이었다. "글로 설명하기 어려운
  예상 결과만 그림으로 만드는 스킬" 을 만든다. 필요 없으면 즉시 종료하고, 필요하면
  grill 을 거쳐 생성한다.

> 이 문서는 격리 검증의 **답안지**다. 격리 트리에 넣지 않는다(§검증).

## 문제

1. 그림이 필요한지를 모델이 "글로 설명하기 어려운가" 로 판단하면 주마다 결론이 흔들린다.
2. 손으로 만든 두 회차에서 grill 이 잡은 결함(측정 화면 흉내, 5V 보간값, 본문에 없는
   주장, 하단 각주)은 매주 똑같이 적용되는 원칙인데 문서가 없다.
3. PNG 추출이 대화 속 셸 한 줄이다. 한글이 깨지지 않으려면 doctype·charset 을 붙인 사본을
   만들어야 한다는 사실이 어디에도 남지 않았다.
4. 실험02 에서는 그림을 노션에 직접 끼웠다. md 에 자리가 없으니 `check_notion_markdown` 의
   "넣어야 할 그림 N장" 안내도, pull 8b `check_pulled_images` 의 빈 그림 검사도 이 그림을
   모른다.

## 사실 (코드로 확인한 것 — 결정의 전제)

1. **명세 표의 `kind` 가 판정을 이미 담고 있다.** `truth-table`·`stepped` 는 셀 표가 곧
   예상 결과이고, `capture` 는 셀 표 없이 `expected` 산문만 갖는다
   (`docs/schema/lab-spec-v2.md` 표 속성 절). 손으로 한 두 회차가 정확히 이 경계로 갈렸다
   — 실험02 T1·T2 는 `capture`(그림 필요), 실험03 T3·T4·T7·T8 은 `truth-table`(중복).
   실험01 은 표 열 개가 전부 `truth-table` 이다.
2. **범위는 명세가 이미 줄였다.** `parse_spec` 이 돌려주는 항목이 곧 이번 학기 범위다
   (`config.EXPERIMENT_SCOPE`, 2026-09-14 범위 축소).
3. **예비보고서 항목 소절 제목은 명세 항목 `title` 과 글자가 같다**
   (`## 실험 1-1) Inverter의 입출력 특성 확인`). 소절 사이는 `<empty-block/>` 이다.
4. **결선도 그림은 번호 없이 alt 만 쓰고 상대경로로 건다**
   (`![실험 1-1) … 브레드보드 작도](../결선도/실험02_1-1_결선도_인버터_입출력특성.png)`).
   결선도 PNG 이름은 `실험NN_<소실험>_결선도_<이름>.png` 이고, 단계 그림은
   `_<n>단계_` 가 끼어 있다.
5. **노션은 덮어쓰지 않는다**(`sync-report-to-notion` 절대 규칙 1). 올린 기록은
   `<실험NN>/output/notion.json` 에 있고 `notion.load_records` 가 읽는다.
6. **격리 트리는 `git archive HEAD` 로 만든다**(`scripts/lab/isolate.py`). 커밋하지 않은
   파일은 트리에 없다. 세션 메모리는 서브에이전트에 주입된다
   (메모리 "격리 재생성이 스킬 결함을 찾는 유일한 방법").
7. **Chrome 경로 해석은 이미 있다** — `html2pdf.resolve_chrome` 과 `.claude/과목정보.md`
   의 `chrome` 목록. macOS 에서 Chrome 은 stderr 로 무해한 경고를 뱉으므로 산출 파일
   존재로만 성공을 판정한다(`html2pdf` docstring).
8. **로컬 file:// 에서 doctype·charset 없이 열면 한글이 깨진다.** 아티팩트 게시본은 게시
   때 skeleton 이 붙어 괜찮지만 헤드리스 캡처는 사본에 직접 붙여야 한다(실험02 회차에서 확인).
9. **`output/*.html` 은 리뷰 4b 가 `check_rendered_html`·`check_embedded_images` 로 본다.**
   실험02·03 의 손 작업 HTML 은 둘 다 통과했다.
10. **명세에 `figure` 필드가 생기고 있다(설계 중 작업 트리, 커밋 전).** `SpecTable.figure`
    는 명세 파일 위치 기준 상대경로이고, `render._capture_html` 이 체크리스트 인쇄본의
    `expected` 산문과 스케치 상자 사이에 그림을 싣는다. 파일이 없으면 `<img>` 대신 안내
    한 줄을 낸다. 스키마 설명은 "예비보고서용 그림을 만든 뒤 사람이 적는다" 였다.

## 스킬 흐름 (`.claude/skills/draw-expected-figure/SKILL.md`)

0. 실험 번호 → `config.experiment_dir`. 명세를 `parse_spec` 으로 읽는다.
1. **판정.** `figure_export.capture_tables(spec)` 가 비면 `T3: truth-table, T7: truth-table
   → 표가 곧 예상 결과라 그림을 만들지 않는다` 식으로 알리고 **끝낸다.**
2. **재료 읽기.** 명세 `expected`, 예비보고서 md 의 그 항목 소절, 강의노트에서 그 항목과
   이론 쪽의 그림(래스터라 렌더 후 vision). 과거 제출본은 읽지 않는다.
3. **요소 ↔ 근거 표.** 패널·축·곡선·문턱선·화살표·라벨·범위 표시마다 한 행. 근거는
   md 문장, 명세 `expected`, 강의노트 그림 쪽 중 하나 이상. 빈 행은 지운다.
4. **HTML 작성.** `template.html` 을 `<실험NN>/output/<실험NN>_예상결과.html` 로 복사하고
   그림 함수만 쓴다. 눈금 라벨에는 `class="tick"` 을 단다.
5. **숫자 검사.** `figure_export.check_figure_numbers` — error 가 있으면 3단계로 돌아간다.
6. **PNG 추출.** `figure_export.export_pngs` — 이름은 `figure_png_name`.
7. **한 번 본다.** PNG 를 한 장씩 열어 겹침·잘림만 고친다. 두 번째 보기는 없다.
8. **게시.** artifact-design 스킬을 읽고 아티팩트로 게시한다. URL 은 HTML 맨 위 주석에
   적어 다음 회차가 같은 주소를 갱신하게 한다.
9. **명세 `figure`.** `figure.set_spec_figure` 로 표마다 적고 다시 파싱해 확인한다(D9).
10. **자리 넣기 또는 안내.** `figure.is_uploaded` 가 거짓이면
    `insert_placeholder` 로 md 에 넣고 `check_notion_markdown`·`check_body_style`·
    `check_report_wrapping` 을 돌린다. 참이면 md 를 건드리지 않고 "어느 소절 어느 문단
    뒤, 캡션 글자" 를 알린다.
11. **보고.** 3단계 표, PNG 경로·크기, 아티팩트 URL, 9·10단계 결과, 다음 할 일(체크리스트
    다시 뽑기, 노션 올리기 또는 직접 끼우기).

## 절대 규칙 (스킬 문서에 들어갈 것)

1. **`capture` 표가 없으면 그리지 않는다.** 표가 곧 예상 결과인 주에 그림은 같은 행을
   두 번 보여 줄 뿐이다.
2. **측정 화면처럼 그리지 않는다.** 흰 바탕 모식도. 결과보고서에서 실측 사진과 나란히
   놓일 때 둘이 섞이면 안 된다.
3. **그림 속 숫자는 예비보고서 md 에 같은 글자로 있는 값만 쓴다.** 보간·환산 금지.
4. **본문에 없는 주장을 그림에만 넣지 않는다.** 맞는 말이어도 넣지 않는다. 넣고 싶으면
   먼저 본문에 있어야 한다.
5. **패널 구성은 강의노트의 해당 그림을 따른다.** 강의노트에 그림이 없으면 명세
   `expected` 가 말하는 축 하나로만 그린다.
6. **흑백 인쇄에서도 구분되게 한다.** 색만으로 구분하는 요소를 두지 않는다.
7. **이미지 안에 각주·그림 제목을 넣지 않는다.** 캡션은 이미지 밖 글자다(사용자가 하단
   각주 삭제를 요청했다, 2026-09-16).
8. **그림 영역은 테마와 무관하게 흰 종이로 고정한다.** 노션 흰 페이지에 들어간다.
9. **올린 노션 페이지에 해당하는 md 는 고치지 않는다.**

## 코드

Chrome 을 부르지 않는 순수 함수와 부르는 함수를 두 모듈로 가른다.

### `scripts/lab/figure.py` — 판정·이름·자리

| 함수 | 하는 일 |
|---|---|
| `capture_tables(spec) -> list[tuple[SpecItem, SpecTable]]` | 범위 안 `capture` 표 |
| `gate_message(spec) -> str` | 1단계 종료 한 줄 (표 id·kind) |
| `figure_png_name(exp_dir, item) -> str` | D10 |
| `set_spec_figure(spec_text, table_id, rel_path) -> str` | D9. 그 표 블록의 `- figure:` 를 바꾸거나 `- kind: capture` 다음 줄에 넣는다 |
| `is_uploaded(output_dir, source_name) -> bool` | `notion.load_records` 에 그 md 를 source 로 한 예비보고서 기록이 있는가 |
| `insert_placeholder(md_text, item_title, png_name, caption) -> str` | `# 실험 과정 및 예상 결과` 안 `## <item_title>` 소절의 마지막 내용 줄 뒤(`<empty-block/>` 앞)에 빈 줄·그림 줄·빈 줄·캡션을 넣는다. alt 는 `<item_title> 예상 결과`. 같은 alt 가 있으면 그대로 돌려준다 |

### `scripts/lab/figure_export.py` — 캡처·숫자 검사

| 함수 | 하는 일 |
|---|---|
| `wrap_for_capture(html_text) -> str` | doctype·`lang="ko"`·charset 을 붙인 사본 본문 |
| `dump_dom(html_path, chrome) -> str` | 사본을 `--dump-dom` 으로 연 결과 |
| `parse_heights(dom_text) -> list[int]` | `data-fig-heights` |
| `export_pngs(html_path, out_dir, names, heights, chrome, scale=3) -> list[Path]` | `?fig=N` 캡처. 파일이 생겼는지로만 판정 |
| `check_figure_numbers(dom_text, md_text) -> list[Finding]` | SVG `<text>` 중 `class="tick"` 이 아닌 것의 소수값이 md 에 같은 글자로 없으면 error |

`python3 -m scripts.lab.figure_export <실험번호> [--check-only]` 는 판정·숫자 검사·추출을
한 번에 돈다.

테스트는 `tests/test_lab_figure.py`·`tests/test_lab_figure_export.py`. Chrome 을 실제로
부르는 것은 `subprocess.run` 을 가로채 명령 구성만 보고, Chrome 이 있을 때만 도는 실측
하나를 둔다. 픽스처는 `tests/fixtures/spec_capture.md`(실험10)·`spec_derived.md` 와 새
최소 md·HTML 조각이다 — **실험02 값을 쓰지 않는다**(D6). 누출 방지 테스트만 예외다.

### `.claude/skills/draw-expected-figure/template.html`

실험02·03 손 작업 HTML 에서 그림 함수를 뺀 틀: 페이지 토큰(밝음·어둠), 흰 종이 `.paper`,
`?fig=N` 추출 모드, `data-fig-heights` 기록, SVG 보조 함수(`text`·`line`·`path`·
`arrowHead`·`lin`), 요소 ↔ 근거 표를 싣는 `.notes` 절. 그림 모양을 담지 않는다.

## 연결

- `write-pre-report` §실행 절차 끝에 한 줄: 명세에 `capture` 표가 있으면
  `draw-expected-figure` 를 돌릴 수 있다. 생성 규칙이 아니라 안내라 예비보고서 재생성
  사유가 아니다.
- `tests/test_skill_docs.py` 의 `DOCS` 에 `("절대 규칙", "실행 절차")` 로 편입한다.
  `REPORT_SECTION_DOCS` 에는 넣지 않는다(보고서 섹션을 만들지 않는다).
- `sync-report-to-notion` 은 고치지 않는다. D3 으로 그림 자리가 md 에 생기면 기존 push
  안내·pull 8b 가 그대로 이 그림을 센다.

## 손 작업 산출물 정리

- 실험02: 파일 이름을 규칙에 맞춘다 — `실험02_1-1_예상결과_인버터_입출력특성.png`,
  `실험02_1-2_예상결과_슈미트트리거_입출력특성.png`. HTML 은 템플릿 틀로 옮기고 숫자
  검사가 잡는 `1.40` 을 본문 글자 `1.4` 로 고친다. 명세 `figure` 두 줄을 새 이름으로
  바꾸고 체크리스트를 다시 뽑는다. 노션 v5 에 이미 올렸으므로 md 는 건드리지 않는다(D3).
  승인본으로 커밋한다.
- 실험03: 그림을 쓰지 않는다. HTML·PNG 는 사용자가 남길지 정한다(미정).
