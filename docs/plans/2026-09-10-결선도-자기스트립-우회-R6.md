# 결선도 자기 스트립 우회 검사(R6) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AND·OR 결선도의 중간단 갈래가 `좌 c12 → 좌 a12 → 좌 a24` 로 꺾여 그려지던 것을 `좌 a12 → 좌 a24` 직선으로 펴고, "자기 스트립 안을 달리는 구간"을 `verify()` 가 **R6** 로 막아 같은 부류가 다시 검사를 통과하지 못하게 한다.

**Architecture:** 새 기계는 없다. 렌더러에는 이미 스트립 모델(`_strip`), 홀 판정(`hole_at`), 기호 좌표(`sym`)가 있다. `verify()` 의 R5 블록 바로 뒤에 열한 줄을 더해, 배선 폴리라인의 **이웃한 꺾임점 둘이 같은 스트립**이면 그 구간을 결함으로 낸다 — 같은 스트립이면 전기적으로 한 점이므로 그 구간은 없어도 되는 우회다. R5ⓐ 가 배선의 **양 끝점**만 보는 것과 달리 R6 는 **구간마다** 본다. 그 틈으로 이 결함이 지나갔다.

**Tech Stack:** Python 3.14 (`.venv`), Pillow, pytest (`.venv/bin/python -m pytest`). 렌더러는 `.claude/skills/breadboard-diagram/scripts/render_breadboard.py` 한 파일이고 패키지가 아니다 — 테스트는 `importlib` 로 경로 로드한다 (`tests/test_breadboard_nets.py` 의 `_load()` 와 같은 방식).

**Spec:** 별도 명세 문서가 없다. 결함의 근거와 이력은 이 문서 `## 배경` 에 싣는다. 정답의 권위는 `보고서/실험01/결선도/netlist.md` 의 C1·C2 다 — **넷리스트는 옳고 그림의 경로만 군더더기였다.** 넷이 바뀌지 않는다는 것은 태스크 1 의 Step 5 가 증명한다.

## 배경 — 왜 이 결함이 검사를 통과했나

2026-09-10 사용자가 OR 결선도의 ⑪ 번 선을 짚었다. "왜 굳이 꺾어서 연결하는가, 같은 열로 내리면 되지 않는가."

**전기적으로는 꺾을 이유가 없다.** 12행의 `a~e` 는 한 스트립이라 `c12` 와 `a12` 는 같은 점이다. `c12 → a12` 가로 구간은 전기적으로 없는 것과 같다. 갈래는 `a12` 에서 시작해 `a24` 로 내려가면 그만이다.

**이력을 보면 이 모양은 설계가 아니라 잔재다.** 커밋 다섯 개가 두 빌더(`build_e1_and`·`build_e1_or`)의 같은 자리를 이틀에 걸쳐 옮겼다.

| 커밋 | 날짜 | 갈래 경로 | 왜 그렇게 됐나 |
|---|---|---|---|
| `3ec077c` | 09-07 | `a12 → a19` | 최초 판. **지금 되돌리려는 그 직선이다.** |
| `8718349` | 09-07 | `c12 → a12 → a19` | 갈래를 점퍼 끝홀 `c12` 에서 출발시켜 "여기서 갈라진다"를 눈에 보이게 했다. 꺾임이 여기서 태어났다. 당시 `addr()` 에는 '분기점(T 접속)' 갈래가 있어 한 홀에 선 둘이 만나는 그림이 허용됐다. 커밋 메시지는 이 변경을 언급하지 않는다. |
| `fd96a63` | 09-08 | `d12 → a12 → a19` | R2(한 홀에 리드 하나)가 `c12` 충돌을 잡았다. 수정은 시작 홀을 `d12` 로 한 칸 옮긴 것. **이 순간 갈래는 점퍼와 닿지 않게 됐고, `c12` 에서 출발시킨 이유가 사라졌다.** 경로 모양은 그대로 남았다. |
| `d722f03` | 09-08 | `d12 → a12 → a24` | L1 저항이 L2 선 밑에 깔려 19행을 24행으로 내렸다. 가로 구간과 무관. |
| `063d580` | 09-08 | `c12 → a12 → a24` | R3(끝점 위 통과)가 `d12` 에서 왼쪽으로 가는 가로 구간이 점퍼 끝 `c12` 위를 지나는 것을 잡았다. 수정은 점퍼와 갈래를 맞바꾼 것 — 다시 한 칸. |

**두 번 연속(R2·R3) 위반의 원인이 가로 구간 자체였는데, 두 번 다 구간을 없애는 대신 시작 홀만 한 칸씩 옮겼다.** `a12` 에서 출발했다면 R2 위반도 R3 위반도 애초에 생기지 않았다.

**왜 아무 검사도 못 잡았나.** R1~R4 는 전부 충돌 기하다 — 끝점이 홀인가, 한 홀에 리드 하나인가, 끝점 위를 지나는가, 축이 포개지는가. 같은 스트립 안을 지나는 여분 구간은 전기적으로도 기하적으로도 무해해서 걸릴 자리가 없다. R5ⓐ 는 "같은 스트립 안에서 끝나는 점퍼"를 보지만 **양 끝점만** 본다 — 자기 스트립 안을 지나다 밖으로 나가는 배선은 끝점이 다른 스트립이라 통과한다.

**주석이 제약만 적고 목적을 안 적었다.** 지금 `render_breadboard.py:1401` 의 주석은 "왜 `c` 이고 `d` 가 아닌가"만 설명한다. "왜 가로 구간이 있는가"는 어디에도 없다. 다음 사람은 꺾임을 기능으로 읽는다.

> 2026-09-09 의 교훈이 형태를 바꿔 반복됐다. 그때는 "R3 를 통과시키려는 재배치가 넷을 끊었고 검사는 오히려 통과로 바뀌었다"였다. 이번에는 재배치가 넷을 끊지는 않았지만 **이유를 잃은 모양을 남겼고, 검사는 그것을 볼 눈이 없었다.** 검사를 조일수록 배선을 옮길 일이 늘고, 옮길 때마다 최소 패치는 원인이 아니라 증상을 건드린다.

- **배선 경로 규칙을 산문으로 더 쓰는 것.** SKILL.md 는 이미 규칙 다섯과 사연이 촘촘하다. 이 결함이 살아남은 이유는 문서가 부족해서가 아니라 **검사에 눈이 없어서**다 (2026-09-07 의 "문서를 읽어선 안 나온다"와 같은 결론). R6 한 줄과 교훈 한 문단에서 멈춘다.
- **다른 11장의 경로를 눈으로 다시 훑는 것.** R6 가 13장 전부를 이미 기계로 훑었고 걸린 것은 두 장뿐이다. 사람 눈으로 다시 보는 것은 이 계획의 범위가 아니다.
- **여백(홀 아닌 자리)을 지나는 우회.** R6 는 양 끝이 실제 홀인 구간만 본다. 꺾임점이 홀과 홀 사이 골에 앉은 우회는 여전히 조용하다. 실제로 그런 빌더는 지금 없고(격리 사본에서 확인), 가드를 풀면 전원잭 배선이 통째로 오탐이 된다. 넓히려면 잭·여백을 따로 구분하는 설계가 먼저다 — 사용자 판단이 필요하다.
- **`보고서/실험02` 배포본 재생성.** 이 작업 트리에서 폴더가 통째로 지워져 있다. 태스크 1·2 는 실험02 빌더를 건드리지 않으므로 되살릴 이유가 없다. 계획이 임의로 되살리지 않는다.
