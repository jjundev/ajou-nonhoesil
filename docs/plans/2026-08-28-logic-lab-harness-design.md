# 논리회로실험 보고서 하네스 설계 및 2주차 수직 슬라이스 구현 계획서

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **개정 v2 (2026-08-28).** 초판은 `가이드라인_및_기준/가이드라인/*.pdf` 를 조교 배포 문서로 오인해 작성됐다. 병렬 검증(과거 제출본 89편 직접 판독) 결과 그 4개 파일은 **한 학생의 개인 템플릿**임이 확인되어, 양식·스키마·표기·사진 정책을 전면 개정했다. 무엇이 왜 바뀌었는지는 §개정 근거 참조. **초판 내용을 근거로 인용하지 말 것.**

**Goal:** 2026-2학기 논리회로실험(ECE253, 허용석 교수님) 수강을 위한 Claude Code 하네스 7종을 설계·구축한다. 1차 목표는 **스키마를 실험1·실험10 명세로 먼저 검증한 뒤, 2주차(실험1 Basic Gates)를 개념설명 → 예비보고서 → 체크리스트 → 결과보고서까지 관통**시키는 것이다.

**Architecture:** 단일 소스(주차별 `명세.md`)에서 파생되는 파이프라인. 명세가 체크리스트 인쇄본·기록 템플릿·netlist·예비보고서 재료를 모두 공급하고, 실험 후 기록이 결과보고서로 흘러간다. **보고서 양식은 스킬에 하드코딩하지 않고 `.claude/보고서양식.md` 로 파라미터화**한다 — 양식이 연도·학생마다 다르고 이번 학기 것이 미확정이기 때문이다. 지난 학기 `ajou-basic-circuit-lab` 하네스의 검증된 부분(리뷰 라운드, 표지, PDF 파이프라인)을 이식하되, 측정값 파이프라인은 폐기한다.

**Tech Stack:** Markdown + YAML 프론트매터 (명세·기록·양식), HTML + CSS (인쇄 레이아웃), Chrome/Chromium headless (PDF 변환, macOS), Python 3 (pypdf — 교안 파싱), Claude Code 프로젝트 스킬 (`.claude/skills/`)

## Global Constraints

- **AI 활용 정책:** **보고서·퀴즈·프로젝트 모두 AI 활용을 승인받았다**(2026-08-28 사용자 확인). 강의계획서 §13의 기본값은 "퀴즈, 보고서 및 프로젝트를 제외한 학습 활동에 허용"이지만, 체크된 유형이 "제한적 허용(AI-Assisted Assessment) — 교수자 승인 하에 사용 가능"이므로 승인으로 해소된다. 평가 항목 100% 전체가 승인 범위 안에 있다. 단 §13이 명시한 **활용 내역 표기(프롬프트·실행일자·도구명·생성물)가 승인 후에도 요구되는지는 미확인**이므로, **파이프라인에 로깅 자리를 미리 비워둔다** — 나중에 붙이는 것보다 싸다.
- **이번 학기 양식은 미확정이며, 확정 가능한 과거 양식도 없다.** 89편 판독 결과 양식은 연도마다·학생마다 다르고, 같은 학기 안에서도 두 학생이 완전히 다른 구조를 썼다. **양식을 스킬에 박지 말 것.** 조교 안내가 오기 전까지는 교집합 프리셋으로 운용한다.
- **from_the_past는 정답지가 아니라 코퍼스다.** §자료 권위 서열을 반드시 지킨다. 과거 보고서는 "이렇게 쓰더라"의 근거로만, 그것도 **다수결로만** 쓴다.
- **camui20 은 다른 과목의 워크북이다.** 구조·서술을 참조하지 말 것 (§자료 권위 7순위).
- **원본 자료는 읽기 전용.** `from_the_past/`, `강의계획서/`, `docs/` 아래를 스킬이 수정하지 않는다.
- **주차 폴더가 모든 스킬의 전제다.** 폴더가 없으면 생성하지 말고 거절하고 초기화를 안내한다.
- **macOS 환경.** 지난 학기 하네스의 Windows 종속(`.bat`, PowerShell `Get-Date`, Edge headless, `C:\Users\Hyunjun\...` 하드코딩)을 모두 걷어낸다.
- **2026-2 교안 미확보.** 모든 실험 분석은 2020-2판 교안에 근거한다. 이 과목은 개정될수록 아날로그 요소가 줄어드는 추세(2016-2판 실험1은 오실로스코프 → 2020-2판은 LED)이므로 **실제 교안이 배포되면 명세를 재검증한다.**
- **PDF 텍스트 추출은 수식을 파괴한다.** 오버바는 벡터 선 또는 MathType/HyhwpEQ PUA 폰트라 추출되지 않고, HWP 인라인 수식의 아래첨자는 통째로 사라진다(`C_i` 소실 확인). **표기·수식에 관한 판단은 반드시 vision 으로 확인할 것.** 초판이 이 함정에 빠졌다.

### 조합에서 파생되는 제약

- **2+3+9** → 체크칸은 **세로 정렬**, 펜 끝으로 찍기 충분한 크기, vision이 체크와 숫자를 구분할 여백 확보. 세로줄 관통으로 "전항 일치" 표기 가능.
- **5+R8** → 사진 파일명 `T2 row5.jpg`. ④가 T번호로 표에 자동 배치.
- **R4+R8** → kind가 사진 정책까지 결정하므로 별도 규칙이 필요 없다.
- **R3+R4** → `value_type` 필드가 불필요해진다. `waveform`은 `capture` kind로, `numeric`은 폐기로, `bit`/`digit`은 토큰 집합 차이로 흡수된다.
- **R7** → netlist가 필요 행 수를 결정하므로 크롭이 자동 계산된다. 소스가 하나다.

### 세 번째 양식이 존재하고, 실증이 가장 강하다

`가이드라인_및_기준/예비보고서 양식.pdf` 는 진짜 배포 양식이다 — 1쪽 IEEE 윤리, 2~6쪽이 섹션 제목만 있는 빈 페이지. 목차는 `1.실험목적 / 2.실험이론 / 3.실험부품 / 4.실험과정 및 예상결과 / 5.출처 및 참고문헌`. **2017·2018·2019 제출본이 실제로 따르는 것이 이것이다.** 초판의 "두 출처" 프레이밍이 이걸 통째로 빠뜨렸다.

### 실제 지배적 구조는 번호가 없다

결보 29편 중 **14편**이 번호 없는 항목반복형이다:

```
실험 N) 제목
  결선도 / 구성한 회로
  예상 결과 / 실험 결과
  고찰                     ← 항목마다 반복
실험 N+1) …
전체적인 고찰               ← 마지막에 종합
```

**고찰이 항목마다 반복된다.** 두 목차 다 단일 고찰을 전제하는데 실제는 아니다. R2의 `repeat: per-item` 이 이걸 담는다.

### 그 밖

- **2020 코호트는 브레드보드를 거의 안 썼다** — PSpice 시뮬레이션(15편 중 10편, 코로나 원격). 가장 최근이자 가장 베끼기 쉬운 템플릿이 실은 예외 상황의 산물이다.
- **표지는 2016-2부터 IEEE 윤리 페이지**, 그 전엔 ABEEK 교육목표 페이지. 영문판·국문판 두 변형이 돈다.
- **참고문헌은 결보 31편 중 11편(35%)**만. 2018년 결보는 0편.
- **`추가 공부` 섹션은 2016년 2편뿐.** 평가기준.txt 의 "+2점"과 짝이 맞고, 그 공지가 2016년 봄 문서임을 시사한다.
- **결선도에 핀 번호가 없다.** 실제 주석은 신호명·전원명·저항값(`330Ω`)·외부장비 박스·하위항목 라벨. 위치가 핀을 암시할 뿐. → netlist 의 가치가 오히려 커진다.
- **디지털 잉크가 사진 워크플로보다 압도적으로 낫다.** 인쇄→펜→촬영본 중 그림자·저대비로 배선 판독 불가한 보고서가 여럿.
- **크롭이 실제 관행이다.** 2020 예보2는 쓰는 행만(1~10, 1~20, 1~30) 남겨 작도 면적을 60~80% 줄였다.

```markdown
  - id: E1.P1-1

# E1.P1-1 · 3-input AND / OR gate 구성

## netlist
- U1 = 74HC08
  - pin 14 → VCC(+5V)
  - pin 7  → GND
  - pin 1  ← 입력 A
  - pin 2  ← 입력 B
  - pin 3  → U1.pin4
  - pin 5  ← 입력 C
  - pin 6  → LED1 (330Ω 직렬)
- 미사용 입력핀: U1.pin9,10,12,13 → GND (플로팅 금지)

## T1 · 3-input AND 진리표
- kind: truth-table
- encoding: 0/1
- source: derived (Y = A·B·C)

| A | B | C | Y |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| ... |
```

**필드 정의**

| 필드 | 위치 | 값 |
|---|---|---|
| `kind` | 표 | `truth-table` \| `stepped` \| `capture` |
| `encoding` | 표 | `0/1` \| `H/L` — **표의 속성이다. 서로 변환하지 말 것** |
| `device` | 항목 | `LED` \| `7segment` \| `oscilloscope` (복수 가능) |
| `source` | 표 | `manual:p11` \| `derived (근거)` \| `past-report:2020` — **필수** |
| `power` | 문서 | 결선도 템플릿 단자 라벨 (연도마다 달랐으므로 명시) |

**셀 값 (R3)** — 닫힌 enum이 아니라 열린 토큰. 실증된 토큰:

```
0 1                       비트 (encoding: 0/1)
L H                       비트 (encoding: H/L)
X                         don't care  ← x, -, 빈칸을 X로 정규화
0->1  1->0                엣지
Q(t-1)  Q(t-1)'           이전 상태
0 : Reset  1 : Set        비트 + 라벨 복합
Q=D  Q0  Z                메모리 상태 / Hi-Z
D0 D1 D2 D3               신호 이름 (MUX 출력이 선택된 입력의 이름)
```

**정규화 규칙 (이것만):** `x`→`X`, `-`→`X`, don't-care 열의 빈칸→`X`, 앞뒤 공백 제거. **`H/L`↔`0/1` 변환 금지.**

**표기 (R5·R6)**
- 보수: 저작 `'`, **괄호로 스코프 명시** — `(A·B)'` 는 `A·B` 위, `A'` 는 `A` 위. PDF 렌더 시 **부울식만** 오버바 승격. 표 헤더·신호명은 `'` 유지
- active-low: **맨 이름 + 첫 등장 시 `(Active Low)`**. 실험9만 `GWN`/`GRN`
- XOR `⊕`, don't care `X`

### Task 6: ④ `write-result-report`

**Files:** `.claude/skills/write-result-report/{SKILL.md,template.html}`

- [ ] **Step 1: vision 전사.** 필기 PDF → `기록.md` 확인 칸. **불확실한 칸은 목록으로 제시하고 사용자 확정.** 자동 확정 금지.
- [ ] **Step 2: 양식 파일 구동** (Task 4 Step 1과 동일). `repeat: per-item` 이면 고찰이 항목마다 반복된다.
- [ ] **Step 3: 결과 표 구성.** `✓` 행은 예상값으로, 불일치 행은 실제 관찰값으로 채우고 **본문에서 구분해 서술.** 사진을 T번호로 매칭.
- [ ] **Step 4: kind별 서술 골격.** `truth-table` → "모든 입력 조합에서 일치/불일치 행 지목", `stepped` → "N번째 클럭에서 천이", `capture` → 사진 + 관찰 서술.
- [ ] **Step 5: 고찰.** 종료 메모 4문항을 재료로. **비어 있으면 생성하지 말고 사용자에게 묻는다** — 배운 점은 본인 경험이다.
- [ ] **Step 6: 퀴즈 섹션.** 양식이 요구하면 생성한다(정책 승인됨). 입력은 `<N>주차/퀴즈/` 의 그 주 문제. 근거는 `from_the_past/정리/퀴즈/실험N/` 기출·정답과 교안. **문제 원본이 없으면 생성하지 말고 요청한다** — 기억으로 지어낸 문제에 답을 다는 건 무의미하다.
- [ ] **Step 7: ⑤로 검증 + 라운드 반복.**

### Task 7: 스키마 확산 검증

Task 0에서 2개, 여기서 나머지 어려운 것들.

- [ ] **Step 1: 실험6** — 심볼릭 토큰(`Q(t-1)`, `Q(t-1)'`, `0 : Reset`), 엣지 값(`0->1`). Task 0 Step 6에서 했으면 건너뜀.
- [ ] **Step 2: 실험8** — 한 항목에서 LED와 7-segment 혼재, `truth-table`과 `stepped` 혼재.
- [ ] **Step 3: 실험7** — 제어 펄스 조작(`CLR: 1→0→1`, `PE: 0→1→0`)을 스텝으로 표현. 못 하면 `stepped` 에 `control_pulse` 추가.
- [ ] **Step 4: 실험9** — 한 행에 세 알파벳(`L/H` 주소·enable, `Q=D`/`Q0` 워드, `0/1` 출력). 열린 토큰 모델의 최대 시험대.
- [ ] **Step 5: 스키마 개정 판단.** 깨지면 `lab-spec/v2` 로 올리고 **기존 명세를 즉시 일괄 재생성**한다. 소스(교안·과거자료)가 고정이므로 재생성이 안전하다. **캐시 신선도 로직(mtime 비교, SOURCES 블록)은 만들지 않는다** — 지난 학기 v3/v4/v5 드리프트의 원인이었고 여기서는 값어치가 없다.

## 정책 해제로 열린 범위 (현 계획 밖 — 착수 여부 미정)

퀴즈·프로젝트 승인으로 평가 항목 **100% 전체**가 하네스 사정권에 들어왔다. 현 계획(스킬 7종)은 **과제 50%만** 다룬다. 나머지 40%에 대응하는 후보 둘을 여기 기록해 둔다. **아직 Task 로 만들지 않았다** — 사용자 결정 대기.

### ⑧ 퀴즈 대비 (평가 10%)

- **자산이 이미 두텁다:** `from_the_past/정리/퀴즈/실험1~10/` 에 기출 84편(2015-2 ~ 2017-1) + 예상문제 은행 + 정답/해설 + **채점본 스캔**(점수와 빨간 첨삭이 보이는).
- **퀴즈의 실제 성격** (검증 확인): 3~5문항 / **10점 만점** / 1장 / 실험 중 시행 / **객관식 없음**. 유형은 진리표 채우기, 부울식 쓰기, 종이 회로 설계(2입력 게이트로 3입력 NAND 구성, D F/F로 4비트 SIPO), 파형 그리기, 2~4줄 단답.
- **주의:** 퀴즈는 **학기마다·분반마다 다르다**(월요반 vs 금요반 문제지가 다름). 기출을 "그대로 나올 것"으로 다루면 안 되고 **유형 대비**로만 써야 한다.
- ④와의 관계: 결보의 퀴즈 해설 섹션과 재료가 겹치나 목적이 다르다 — ⑧은 사전 대비, ④는 사후 서술.

### ⑨ 텀프로젝트 지원 (평가 30%)

- **자산:** `텀프로젝트_설계/` 에 Verilog 계산기 만점 설계보고서(43p) 풀세트, VHDL 계산기·도어락 레퍼런스, ModelSim 자동 검증 TB, `HDL_소스_및_예제/` 에 스톱워치 골드스탠다드·통합 디지털시계·보드별 핀맵, `가이드라인_및_기준/FPGA pin map (1).pdf`.
- **과제 내용** (2020-2 공식 자료): DE0-Nano(Altera Cyclone IV) + Quartus Lite + **7-segment 모듈과 Keypad 모듈로 사칙연산 계산기**. 계획서 본문은 VHDL만 언급하나 실제 배포 자료는 Verilog.
- **⚠️ 현 스키마가 FPGA 를 전혀 다루지 않는다.** 13~15주차와 프로젝트의 산출물은 진리표도 시퀀스도 사진도 아니다 — **HDL 소스, 시뮬레이션 파형, 합성 결과, 핀 할당, 보드 동작**이다. `lab-spec/v1` 을 억지로 확장하지 말고 **별개 파이프라인**으로 설계해야 한다.
- 시점: 13주차(FPGA 도입)까지 시간이 있다. Task 0~7 을 끝낸 뒤 착수해도 늦지 않다.
