# 하네스 이름 보존 완전 수정 (설계)

2026-09-14 `/grill-yourself` 로 만든 설계다. 근거는 같은 날의 하네스 전체 점검(세 갈래:
이름 키 충돌, 강의노트 이름 보존 파이프라인, 테스트·문서 정합)이다. 구현 계획은
`docs/plans/2026-09-14-하네스-이름보존-구현계획.md`.

이 문서에서 **교안 = 강의노트**(`강의노트/*.pdf`)다. 저장소 문서가 두 말을 섞어 쓴다.

## 배경

2026-09 실험01 예비보고서가 조교에게 두 항목으로 -2점을 받았다 — 예상 결과 표가 회로도
출력 `L1`·`L2` 를 `Y` 로 바꿨고, 결선도에 입력 위치 표기가 없었다. 그 뒤 사용자의 규칙:
표와 그림의 신호 이름은 강의노트 표기를 글자 그대로 쓴다(모호해도).

2026-09-14 실험03 예비보고서 검토에서 명세가 반감산기 내림 수 `B` 를 `Bo` 로 바꾼 것을
찾았고 되돌렸다(커밋 `3372a67`·`b1c41a2`). 그때 드러난 구조적 사실:

- 모든 이름 검사가 **명세만** 기준으로 본다. 명세가 강의노트와 어긋나면 하류 검사가 전부
  통과한다(스크래치에서 명세·예보를 둘 다 `Bo` 로 바꿔 넣었더니 warn 0건).
- 손그림 검토(`hand_compare`)는 e1 회로 13개만 안다. e2·e3 손그림은 검토할 수 없다.
- H15 와 결선도 배지 테스트가 이름을 **집합**으로 본다. 반감산기의 둘째 `B` 가 빠져도 통과한다.
- 결과보고서에는 표 머리 검사가 없고, write-result-report 의 예시가 `| A | B | C | Y |` 다.
- 스위트가 늘 빨갛다(낡은 테스트 4건 + 체크리스트 부재 2건).

## Intent

강의노트의 신호 이름이 명세 → 결선도 → 체크리스트 → 예비·결과보고서 → 손그림 검토 전
구간에서 교안 그대로 유지되고, 벗어나면 기계가 잡도록 하네스를 고친다. 대상은 사용자와
그 흐름을 도는 스킬들이다. 완료는 명세 열 이름을 **강의노트 PDF 자체와** 대조하는 검사가
생기고 실험01~03 명세가 거기서 0건, 손그림 검토가 실험01~03 회로를 전부 받고 같은 글자
둘을 개수로 세며, 결과보고서·스텝표도 표 머리 검사를 받고, 낡은 테스트·문서 불일치가
정리돼 스위트 실패가 체크리스트 부재 2건뿐인 상태다.

트랙이 넷이지만 모두 기존 흐름을 고치는 일이고 "이름 보존" 한 의도를 공유한다.

Classification: **bounded** — 새 검사도 기존 `validate.py` 검사 체계와 명세 필드에 얹힌다.

## 완료 시 동작

- 명세 진리표 머리가 강의노트 쪽에 없으면 error. 예: 실험03 T5 를 `Bo` 로 적으면 "교안
  p6 에 `Bo` 가 없다". draft-lab-spec 저작, review-lab-report 3단계, 코퍼스 테스트에서
  돈다. 강의노트 쪽에 텍스트 층이 없으면(래스터) info 로 "vision 으로 본다" 를 알린다.
- 결과보고서 표 머리도 명세 기록표 머리와 대조한다(셀은 관측값이라 안 본다). 예비·결과
  보고서 모두 스텝 기록표 머리까지 본다 — 2026-09 실험02 예보가 `CH1 에지 (U1 pin 4)`
  를 `CH1 에지` 로 줄였을 때 조용했던 자리다(그 판은 다른 세션이 이미 고쳤다).
- 손그림 검토가 e2 6개·e3 12개 회로 ID 를 받는다. 반감산기에서 출력 `B` 를 빠뜨리면
  "신호 이름 `B` 가 참조보다 1개 적다(참조 2 · 그림 1)" 가 기능 등급으로 나온다.
- 결선도 가독성 테스트가 배지를 개수로 센다. 둘째 `B` 배지가 빠지면 실패한다.
- 같은 글자 열은 메시지에서 `B(4열)` 처럼 자리로 부른다(역검산·표 대조·열 역할·재생성 셀 차이).
- 스위트는 체크리스트 부재 2건만 빨갛다(산출물 작업일에 해소).

### 트랙 1 · 강의노트 이름 대조 (새 검사)

- 명세 항목 필드 `pages: [N, …]` — 그 항목의 회로도·절차가 있는 강의노트 쪽. 파서는 선택으로
  읽어 `SpecItem.pages`(없으면 None). 실험01 11~15, 실험02 10~12, 실험03 4~7.
- `validate.extract_manual_pages(manual_path) -> list[str]` — 쪽별(1쪽이 `[0]`), pypdf 우선,
  빈 쪽만 `pdftotext -f N -l N`. 못 열면 `[]`.
- `validate.check_manual_names(spec, pages) -> list[Finding]` — 토큰은 `[A-Za-z][A-Za-z0-9_]*`.
  1. 참조표(`role: reference`, `truth-table`, `source: manual:pN`): 머리 토큰열이 인용 쪽
     중 하나의 토큰열 안에 **연속으로** 있어야 한다. 없으면 error.
  2. 기록 진리표: 열 이름마다, 그 표를 쓰는 항목의 `pages` 텍스트 합집합에 토큰으로 있어야 한다. 없으면 error.
  3. 기록 진리표가 있는 항목에 `pages` 가 없으면 error.
  4. 쪽 번호가 강의노트 쪽 수를 넘으면 error.
  5. 쪽에 라틴 토큰이 하나도 없으면 info(래스터).
  6. `pages == []` 면 info 한 줄.
- 부르는 곳: draft-lab-spec 5단계(`check_manual_quotes` 옆), review-lab-report 3단계,
  `test_lab_spec_corpus`. `validate_spec` 에는 넣지 않는다.

### 트랙 2 · 보고서 표 머리

- `check_report_tables(report_path, spec, *, cells=True)` — 대상은 `role: record` 인
  `truth-table` 과 `stepped`. `stepped` 는 늘 머리만 보고 행 수도 안 본다. `cells=False`
  에서는 명세 순서대로 머리가 맞는(진리표는 행 수 동일) 미점유 표 하나와 1:1 로 짝짓는다.
- review-lab-report 4단계는 결보에도 `cells=False` 로 부른다. write-result-report 12단계에 추가.
- write-result-report 절대 규칙 14 의 예시를 `| A | B | C | L1 | L2 |` 로 바꾸고, 절대 규칙
  19 를 새로 둔다 — 결과 표 머리와 산문 속 회로 신호 이름은 명세 열 이름 그대로.
