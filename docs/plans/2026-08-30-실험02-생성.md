## Task 1: 되읽은 본문의 빈 그림 링크를 잡는다

**Files:**
- Modify: `scripts/lab/validate.py` — `_IMAGE_ANY` 와 `check_pulled_images()` 신설
- Modify: `tests/test_lab_validate.py` — 새 클래스 `TestCheckPulledImages`
- Modify: `.claude/skills/sync-report-to-notion/SKILL.md` — pull 9단계 앞에 검사 단계

**Interfaces:**
- Consumes: 기존 `Finding(level, where, message)` 데이터클래스 (`scripts/lab/validate.py:24`)
- Produces: `check_pulled_images(pulled_text) -> list` — 되읽은 마크다운 문자열 하나만 받아 `Finding` 리스트를 돌려준다. Step 5 가 ⑦ 의 **pull** 절차 `8b` 단계에 배선한다.

**이 태스크의 효과는 이 계획 안에서 발화하지 않는다.** 검사가 되읽기 전용이라 Task 3(업로드)은 이것을 부르지 않는다 — 올린 직후에 그림이 비어 있는 것은 정상이기 때문이다. 처음 실제로 도는 것은 사용자가 노션에서 그림을 끼운 뒤, 다음 계획의 되읽기 단계에서다. 그래도 지금 넣는 이유는 그 되읽기가 실험02 의 첫 되읽기이고, 검사가 없으면 실험01 때와 똑같이 조용히 지나가기 때문이다.

**배경.** 실험01 v7 에서 브레드보드 그림이 노션에 빈 링크로 올라갔고, **아무 검사도 그것을 잡지 못했다.** 사용자가 눈으로 찾았다.

왜 안 잡혔는지가 중요하다. 두 함수가 각자 자기 일만 하고 그 사이에 틈이 있었다:

- `check_notion_markdown`(`validate.py:314`)은 **올리기 전에** md 를 본다. 상대경로 이미지를 찾아 `ℹ 노션에서 직접 넣어야 할 그림 N장` 을 낸다. 이건 "몇 장 넣어야 하는지" 를 알릴 뿐, **실제로 넣었는지는 모른다.**
- `check_notion_roundtrip`(`validate.py:403`)은 올린 것과 되읽은 것의 **모양**만 본다 — 헤딩·표 개수·표 행 수·인용 블록 수. 그림은 세지 않는다. 그래서 조용했다.

**검사를 되읽기 쪽에만 건다.** 올린 직후에는 그림이 비어 있는 것이 **정상**이다(사용자가 노션에서 끼우기로 한 설계다). push 에 걸면 매번 거짓 경보가 되고, 거짓 경보를 내는 검사는 없느니만 못하다.

**실측 픽스처가 이미 저장소에 있다.** 실험01 v7 의 두 파일이 정확히 "넣기 전/후" 한 쌍이다 — 둘 다 git 추적 중이라 테스트가 읽어도 된다:

- [ ] **Step 3: `check_pulled_images` 를 만든다**

`scripts/lab/validate.py` 에서 `_IMAGE = re.compile(...)` 줄(302행 부근)을 찾는다:

```python
_IMAGE = re.compile(r"!\[[^\]]*\]\(([^)]+)\)")
```

그 **다음 줄에** 아래를 더한다. **기존 `_IMAGE` 를 고치지 않는다** — `[^)]+` 는 대상이 있는 그림만 잡도록 일부러 그렇게 쓰였고, `check_notion_markdown` 이 그 의미에 기대고 있다.

```python
# 대상이 비어도 잡고 alt 도 함께 뽑는다. `_IMAGE` 는 `[^)]+` 라 빈 링크를
# 아예 못 잡는다 — 그 함수가 세는 것이 "넣어야 할 그림" 이기 때문이다.
_IMAGE_ANY = re.compile(r"!\[([^\]]*)\]\(([^)]*)\)")
```

이어서 `def check_notion_markdown` 정의 **바로 앞**에 아래 함수를 넣는다 (빈 줄 두 개로 띄운다):

```python
def check_pulled_images(pulled_text) -> list:
    """되읽은 본문에서 **아직 안 끼운 그림**을 잡는다.

    올릴 때 상대경로 이미지는 노션에서 반드시 깨진다 — 그래서
    `check_notion_markdown` 이 올리기 **전에** "몇 장 넣어야 한다" 를 info 로
    알린다. 그런데 사용자가 실제로 넣었는지는 여태 아무도 확인하지 않았다.
    실험01 v7 에서 브레드보드 그림이 빈 링크로 올라갔고 왕복 검사는 조용했다 —
    `check_notion_roundtrip` 은 헤딩·표·인용 **개수**만 보므로 그림은 안 센다.

    **되읽기 쪽에만 건다.** 올린 직후에는 그림이 비어 있는 것이 정상이므로
    (사용자가 노션에서 끼우기로 한 설계다) push 에 걸면 매번 거짓 경보가 된다.
    """
    out = []
    for alt, target in _IMAGE_ANY.findall(pulled_text):
        if target.strip():
            continue
        out.append(Finding("error", "노션 그림",
            f"그림 '{alt}' 이 빈 링크다 — 노션에서 아직 끼우지 않았다. "
            "이대로 PDF 를 내보내면 그 자리가 빈 채로 제출된다"))
    return out
```
