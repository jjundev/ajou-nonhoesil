# 면제 열쇠와 걷기 주소 계약

2026-09-21 · `grill-yourself` 산출. 구현계획:
`docs/plans/2026-09-21-면제열쇠-구현계획.md`.

## 왜 — 같은 레거시 결정을 열쇠 둘로 집행한다

단계 세분화 규약은 실험01·02 승인본만 소급 적용에서 뺀다. 브레드보드 회귀는
`tests/test_breadboard_boards.py::StageBudget.LEGACY_BOARDS = (1, 2)` 로 그 경계를
직접 적지만, netlist 검증기는 실험 번호가 아니라 `## 노드` 표의 존재 여부로 같은
결정을 집행한다. 그래서 실험04 저작자가 노드 표를 빠뜨리면 새 규약이 그 회로에
조용히 적용되지 않고 `단계는 있는데 노드 표가 없다` warn 하나만 남는다. 실험01·02
실물에서 이미 다섯 번 나는 경고라 새 결함이 묻히기 쉽다.

같은 라운드에서 걷기 보드 주소도 세 사본으로 갈라졌다. 실제 그림은 렌더러의
`removals()` 가 주소를 내고, 회귀 테스트는 그 주소를 하드코딩하며, netlist 걷기 행은
`이 단계에서`와 `확인`에 다시 주소를 적는다. 현재 테스트 문서가 “netlist도 같이
고쳐라”라고 부탁할 뿐 둘을 기계로 묶지 않는다. C4 `1걷기`의 확인 칸은 실제로 세 선의
도착 홀만 적어 나머지 출발 홀 셋이 빠져 있다.

마지막으로 걷기 판정 정규식은 정확한 `<k>걷기`만 읽는다. `2 걷기`·`걷기2`는 일반
단계로 강등되고, 노드 표 없는 레거시 경로에서는 그 오타를 따로 거절하지 않는다.

## Intent

실험01·02 승인본은 그대로 두되 **실험 3부터** 단계가 있는 회로에 `## 노드` 표를
필수로 한다. 단계 셀은 파서 한 곳에서 양의 정수 또는 `<k>걷기`로 분류하고, 다른
문자열은 노드 표 유무와 상관없이 error로 막는다. 걷기 행의 `이 단계에서`에 적힌
홀 주소쌍을 정본으로 승격해 같은 행의 `확인` 양 끝 홀과 실제 렌더러 `removals()`를
기계로 대조한다.

끝난 상태: 실험04 이후 저작자가 노드 표를 빼거나 걷기 표기를 틀리거나, 배선 좌표만
옮기고 netlist를 안 고치면 인쇄 전에 error가 난다. 실험01·02는 기존 warn과 PNG를
그대로 유지하고, 실험03 C4 확인 문구는 세 선의 양 끝 여섯 홀을 모두 말한다.

분류: **architectural** — 기존 검증 흐름을 고치지만, netlist 산문의 주소를
렌더러 회귀가 소비하는 새 인터페이스로 승격한다.

## 끝났을 때 보이는 것

- 실험01·02의 단계 회로는 노드 표가 없어도 기존 warn 하나만 난다.
- 실험03 이후 단계 회로는 노드 표가 없으면 error라 체크리스트 인쇄가 멈춘다.
- 단계 값은 양의 정수 또는 정확한 `<k>걷기`만 허용한다. `2 걷기`·`걷기2`·`0`·
  `0걷기`는 error다.
- `03걷기` 다음에 `03`이 오면 둘을 정수 3으로 비교해 거짓 불일치 error를 내지 않는다.
- 걷기 행 두 개가 연달아 오거나, 걷기 행이 마지막이거나, 다음 꽂기 단계 번호가
  다르면 error다.
- 걷기 행의 `이 단계에서`에는 `좌 b9→좌 a25` 꼴 주소쌍이 하나 이상 있고,
  `확인`에는 그 주소쌍의 양 끝 홀이 같은 순서로 모두 나온다.
- 실험03 걷기 그림은 diagram 파일명으로 netlist 행과 연결된다. `BOARDS` 인덱스가
  움직이거나 같은 주소인 두 보드가 자리를 바꿔도 잘못 대응하지 않는다.
- C4 `1걷기` 확인 칸은 `좌 d7·우 a10·좌 a9·우 c13·우 c23·우 c29` 여섯 홀을
  모두 말하고, 실험03 HTML·PDF가 그 문구로 다시 생성된다.

## 이번에 하지 않는 것

- 전원 배너의 “사용하는 게이트의 입력은 반드시 물린다” 절대문 — 모든 주차
  인쇄물을 바꾸는 별도 정책 결정이다.
- `only()`·`probe2`, 단계→노드 사상 복사 제거 — 배치 코드 리팩터링이고 이 계약과
  독립적이다.
- 공통면 디버깅 절차 상자와 선 색 규칙 — 별도 사용자 경험 설계다.
- C4의 2026-09-18 사건 중복 서술 제거 — 주소 완전성에 필요하지 않은 문장 편집이다.
- 브레드보드 엔진 동작과 PNG 외형 변경 — `removal_board()` docstring 외 실행 코드는
  건드리지 않는다.

## 접근안

| | 접근 | 장점 | 단점 | 채택 |
|---|---|---|---|---|

| C | `배치.py` 또는 `removal_board()`에 기대 주소 메타데이터 추가 | 실제 렌더러 가까이에서 검사한다 | netlist와 별도의 세 번째 정본이 생겨 현재 문제를 반복한다 | — |

**B를 고른다.** `WiringE3`가 이미 netlist를 정본이라고 선언하고 있고, 실물 걷기
문구가 필요한 주소쌍을 모두 담고 있다. 새 열과 새 배치 상수를 만드는 대신 이 표기를
기계가 읽을 수 있게 한다.

## 데이터 계약

### 단계 셀

파서가 `NetlistSection.stages` 각 행에 다음 키를 낸다.

| 키 | 형식 | 뜻 |
|---|---|---|
| `n` | `str` | 원문 단계 셀. 오류 메시지와 인쇄용으로 보존 |
| `stage_no` | `int \| None` | 일반 단계의 정수. 걷기·오타면 `None` |
| `walk` | `bool` | 정확한 `^\d+걷기$` 여부 |
| `walk_of` | `int \| None` | 걷기가 머리에 붙는 다음 단계 번호 |
| `walk_addresses` | `list[str]` | `이 단계에서`에서 정규화한 `홀 → 홀` 주소쌍 |
| `check_holes` | `list[str]` | `확인`에서 등장 순서대로 읽은 홀 |

홀 문법은 `(좌|우) + a~j + 양의 행 번호`다. 공백은 입력에서 허용하지만 `좌 b9`,
`좌 b9 → 좌 a25` 꼴로 정규화한다. 주소쌍은 경로 전체가 아니라 배선의 두 끝점이다.

파서는 표현만 분류한다. 잘못된 단계 번호, 주소 부재, 주소 불일치는
`validate.check_netlist_circuits()`가 `Finding`으로 보고한다. 구조 결함만
`NetlistError`로 중단한다는 기존 책임을 유지한다.

### 걷기 행

걷기 행은 다음 조건을 모두 만족해야 한다.

1. `walk_of >= 1`이다.
2. 바로 다음 행이 일반 단계이고 `next.stage_no == walk_of`다.
3. 표의 마지막이 아니다.
4. `walk_addresses`가 하나 이상이다.
5. 주소쌍을 차례로 펼친 양 끝 홀 목록이 `check_holes`와 정확히 같다.

주소 순서를 비교한다. 이 순서는 그림의 걷기 번호 ①·②·③과 같은 순서라 단순 집합으로
바꾸면 안 된다. 걷기 행은 관측 노드 포인터와 새 신호선 예산에서만 면제되고, 확인 칸
자체·단계 문법·주소 완전성에서는 면제되지 않는다.

### 노드 표 검사 강도

- `netlist.experiment <= 2`: 단계가 있는데 노드 표가 없으면 기존 warn.
- `netlist.experiment >= 3`: 단계가 있는데 노드 표가 없으면 error.
- 단계가 없는 회로에는 실험 번호와 관계없이 노드 표를 새로 강제하지 않는다.

면제 열쇠는 `## 노드` 표의 우연한 부재가 아니라 frontmatter의 `experiment`다.
이는 브레드보드 회귀의 `LEGACY_BOARDS = (1, 2)`와 같은 결정을 같은 값으로 집행한다.
