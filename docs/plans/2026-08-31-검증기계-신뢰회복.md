### Task 1: `compare_specs` 의 오정렬을 코퍼스 절반에서 없앤다 (C1·C2)

이 브랜치가 만든 판정 도구가 **코퍼스의 절반에서 못 쓴다.** `_pair_tables`
가 `source` 로 짝지을 때 `derived (...)` 를 키에서 빼는데, 살아 있는 명세 중
실험03 은 4/4, 실험05 는 5/6, 실험01 은 5/9 가 derived 다. 실험03 은 계획이
대조군으로 예약한 바로 그 명세다.

실측: 실험01 에 표 하나를 정당하게 끼우면 **19건**이 뜨고 그중 셀 차이 8건이
전부 오정렬 소음이다(셀은 하나도 안 건드렸다). `derived` 를 키로 허용하면
**4건**으로 준다.

`derived` 를 뺀 근거가 원래 없었다. 부울식은 쪽 번호만큼 안정된 좌표이고,
식이 잘못 옮겨졌으면 그냥 ID 짝짓기로 떨어질 뿐 지금보다 나빠지지 않는다.

`test_표가_끼어들어_ID_가_밀려도_셀_대조가_어긋나지_않는다` 근처에 붙인다.
(그 이름의 테스트가 없으면 클래스 마지막 메서드 뒤에 붙인다.)

```python
    WEEK2 = ROOT / "실험01/체크리스트/명세.md"

    def _shifted(self, source, first, last):
        """`source` 명세의 표 ID 를 한 칸씩 밀고 새 `T2` 를 끼운 사본.

        재생성물이 교안 표를 하나 더 정당하게 싣는 실제 상황이다 — 실험06
        재생성 두 건이 각각 교안 p5 이론표를 `T2` 로 끼워 넣었고, 그때
        이후 ID 가 전부 밀려 서로 다른 표가 짝지어졌다.
        """
        def bump(m):
            n = int(m.group(1))
            return f"T{n + 1}" if first <= n <= last else m.group(0)

        # `tables:` 줄과 `## T<n> ·` 헤딩의 ID 만 민다. 항목이 표를 여럿
        # 가리키는 줄(`tables: [T1, T2, T6, T7]`)도 밀어야 하므로 대괄호
        # 통짜 치환이 아니라 토큰 단위로 바꾼다 — 통짜로 하면 원소가 하나인
        # 목록만 밀려서 항목이 없는 표를 가리키거나 ID 가 중복된다.
        out = []
        for line in source.read_text(encoding="utf-8").split("\n"):
            if line.lstrip().startswith("tables:") or line.startswith("## T"):
                line = re.sub(r"T(\d+)", bump, line)
            out.append(line)
        # 밀고 나면 `T2` 를 가리키는 항목이 없다 — 첫 항목에 붙인다.
        # 고아 표는 파서가 error 로 막는다.
        text = "\n".join(out).replace("tables: [", "tables: [T2, ", 1)
        text += ("\n## T2 · 끼운 참조표\n\n- kind: truth-table\n"
                 "- encoding: 0/1\n- source: manual:p99\n- role: reference\n\n"
                 "| A | Y |\n|---|---|\n| 0 | 0 |\n")
        target = Path(self.tmp.name) / "명세.md"
        target.write_text(text, encoding="utf-8")
        return target

    def test_derived_source_만_있는_명세도_밀림에서_오정렬되지_않는다(self):
        # 이 코퍼스의 절반이 `derived (...)` 다 — 실험03 은 4/4, 실험05 는
        # 5/6, 실험01 은 5/9. `derived` 를 짝짓기 키에서 빼면 그 명세들에서
        # 오정렬이 그대로 남는다. 실측: 고치기 전 19건(셀 차이 8건), 진짜
        # 내용 오류는 0건이었다.
        target = self._shifted(self.WEEK2, 2, 9)
        diffs = compare_specs(self.WEEK2, target)
        cells = [d for d in diffs if "행" in d]
        self.assertEqual(cells, [], f"셀을 하나도 안 건드렸는데 차이가 났다: {cells}")

    def test_짝을_못_지은_표는_한쪽에만_있다고_말하지_않는다(self):
        # source 짝짓기가 원본 Tx 를 재생성 Ty(x≠y) 와 묶으면, 원본 Ty 와
        # 재생성 Tx 가 둘 다 짝을 잃는다. 그것을 "한쪽에만 있다" 로 찍으면
        # 양쪽에 있는 ID 를 없다고 말하는 셈이라 읽는 사람이 오독한다.
        target = self._shifted(self.WEEK2, 2, 9)
        diffs = compare_specs(self.WEEK2, target)
        both = {"T" + str(n) for n in range(1, 10)}
        for d in diffs:
            if "원본에만 있다" in d or "재생성에만 있다" in d:
                tid = d.split()[1].rstrip(":")
                self.assertNotIn(
                    tid, both,
                    f"양쪽 문서에 다 있는 ID 를 한쪽에만 있다고 했다: {d}")
```

```python
def _pair_tables(a_tables, b_tables):
    """원본과 재생성의 표를 짝짓는다. 표는 최대 한 짝에만 쓰인다.

    ID 는 표가 추가·삭제되면 그 뒤 전부 밀린다(`_table_id_mismatch_notice`
    참고) — 이 코퍼스에서 실제로 일어났다. `source`(`manual:p9` 든
    `derived (Y = A·B·C)` 든)는 그 표가 무엇에서 왔는지를 가리키는
    좌표라 밀리지 않으므로, 두 문서 모두에서 **유일하게** 등장하는
    source 를 우선 매칭 키로 쓴다.

    **`derived (...)` 도 키로 쓴다.** 처음엔 뺐는데, 이 코퍼스의 절반이
    derived 라 그러면 오정렬이 그대로 남는다 — 실험03 은 표 4개가 전부,
    실험05 는 6개 중 5개, 실험01 은 9개 중 5개다. 실측으로 실험01 에서
    19건(셀 차이 8건)이 4건으로 줄었다. 식이 잘못 옮겨졌으면 그냥 ID
    짝짓기로 떨어질 뿐이라 빼서 얻는 것이 없었다.

    source 가 없거나 한쪽 문서 안에서 중복이면 믿을 수 없으므로 쓰지
    않는다 — 그런 표는 ID 로 짝짓고, ID 매칭은 여전히 밀림에 취약하다.

    반환: `(짝 목록[(원본표, 재생성표), ...], 원본에만 있는 표 목록,
    재생성에만 있는 표 목록)`.
    """
    def source_counts(tables):
        return Counter(t.source for t in tables if t.source)

    a_src_counts = source_counts(a_tables)
    b_src_counts = source_counts(b_tables)

    pairs = []
    matched_a, matched_b = set(), set()

    # 1차: source 가 양쪽에서 유일하게 일치하는 표부터 짝짓는다.
    for t in a_tables:
        src = t.source
        if src and a_src_counts[src] == 1 and b_src_counts.get(src) == 1:
            match = next(u for u in b_tables if u.source == src)
            pairs.append((t, match))
            matched_a.add(t.id)
            matched_b.add(match.id)
```

- [ ] **Step 4: 짝을 못 지은 표를 구별해 보고한다 (C2)**

`_table_diffs` 를 통째로 바꾼다. 시그니처에 양쪽 ID 집합이 필요하다:

```python
def _table_diffs(pairs, only_a, only_b) -> list:
    """짝지은 표는 필드·셀을 대조하고, 짝을 못 지은 표는 그렇게만 보고한다.

    **"한쪽에만 있다" 와 "짝을 못 지었다" 를 구별한다.** source 짝짓기가
    원본 `Tx` 를 재생성 `Ty`(x≠y) 와 묶으면 원본 `Ty` 와 재생성 `Tx` 가
    둘 다 짝을 잃는데, 그것을 "한쪽에만 있다" 로 찍으면 **양쪽 문서에 다
    있는 ID 를 없다고 말하는 셈**이라 읽는 사람이 오독한다.
    """
    a_ids = {t.id for t in only_a} | {p[0].id for p in pairs}
    b_ids = {t.id for t in only_b} | {p[1].id for p in pairs}
    out = []
    for t in sorted(only_a, key=lambda t: t.id):
        where = "짝을 못 지었다 (재생성에도 같은 ID 가 있다)" \
            if t.id in b_ids else "원본에만 있다"
        out.append(f"표 {t.id}: {where}")
    for t in sorted(only_b, key=lambda t: t.id):
        where = "짝을 못 지었다 (원본에도 같은 ID 가 있다)" \
            if t.id in a_ids else "재생성에만 있다"
        out.append(f"표 {t.id}: {where}")
    for t_a, t_b in sorted(pairs, key=lambda p: p[0].id):
        label = t_a.id if t_a.id == t_b.id else f"{t_a.id}→{t_b.id}"
        for field in _TABLE_FIELDS:
            x, y = getattr(t_a, field), getattr(t_b, field)
            if x != y:
                out.append(f"표 {label} {field}: 원본 {x!r} / 재생성 {y!r}")
        out += _cells(label, t_a, t_b)
    return out
```
