# 결선도 걷기 보드 설계

작성 2026-09-19. `/grill-yourself` 로 핸드오프 A("결선도: 걷는 선을 그림에 그린다")를
설계했고, 사용자가 `#1=중간그림` 으로 표현 방식을 확정했다. 핸드오프 B~E(회로도 크롭·
사진 파일명·물리 주의사항·종료 메모)는 독립 작업이라 이 문서에 없다.

## 의도

회로가 바뀌는 단계 그림에서, 앞 단계에 있었는데 이번에 없는 배선을 **걷기 전용 보드 한 장**
에 빨간 점선 + 번호로 그려, footer 의 "앞 단계에서 걷는다" 표와 netlist 단계 표가 그 번호를
인용하게 한다. 대상은 `breadboard-diagram` 엔진(`render_breadboard.py`)·SKILL.md §4a·실험03
`배치.py`·`netlist.md`·커밋된 PNG 다.

분류: bounded — 기준선 비교(`removed()`)·footer 표·도장이 이미 있고, 그 데이터를 그림 본체에
닿게 하는 확장이다.

## 근거 (실험03 실험실 기록, 2026-09-18)

1-2 전가산기 → 2-2 전감산기로 넘어갈 때 걷어야 할 선 두 가닥(A → 74HC08 pin 1, 74HC86 pin 3
→ 74HC08 pin 4)을 뽑지 않은 채 인버터 쪽 선을 더 꽂았다. `netlist.md` 단계 표와 예비보고서
공통 결선 규칙에는 글로 적혀 있었고, 렌더러도 footer "앞 단계에서 걷는다" 표에 주소로 내보냈다.
그런데도 놓쳤다. 글·footer 표로는 부족하고 그림 위에서 눈에 띄어야 한다.

## 완성 시 동작

- 회로가 바뀌는 경계마다 사슬(`BOARDS`)에 **걷기 보드 한 장**이 끼워진다. 실험03 은
  전가산기 완성 → `실험03_2-2_결선도_전감산기_0단계_걷기.png` → 전감산기 1단계.
- 걷기 보드는 앞 회로가 **전부 회색**이고, 뽑을 배선만 **빨간 점선 + 빨간 채움 원 번호**
  (걷기 ①②)다. 새 선·결선 순서표가 없다. footer 에 "앞 단계에서 걷는다" 표가 같은 번호와
  함께 나온다.
- 다음 보드(전감산기 1단계)는 기준선이 걷기 보드라 "걷는다" 표가 **사라지고** 새 선
  일곱 줄만 남는다.
- netlist C4 단계 표에 `0` 행이 생기고 체크리스트는 "단계 0" 블록으로 그대로 싣는다. 확인
  칸은 LED 가 아니라 "뽑은 두 가닥의 양 끝 홀이 비어 있다" 다.
- 회로 **안** 단계의 임시 점퍼 걷기(실험01 복합 1→2단계 `c7→c9`)는 지금처럼 footer 표만이다.
- 걷을 배선이 없는 보드는 픽셀·도장 모두 지금과 같다.

## 구현 명세 (요약 — 상세는 구현계획)

### 엔진 `.claude/skills/breadboard-diagram/scripts/render_breadboard.py`

- `REMOVE = (160, 30, 30, 255)` — footer 가 이미 쓰는 빨강. `WIRE` 팔레트에 넣지 않는다.
- `snapshot()['paths']`: `{(kind, frm, to): [(x, y), …]}`. 지금은 끝점만 남고 꼭짓점이 버려져
  걷을 선을 그릴 수 없다.
- `removals()`: 기준선에 있었는데 이번 보드에 없는 **배선**을 `{'n', 'key', 'addr', 'desc',
  'points'}` 로, 기준선 그리기 순서대로 1부터 번호 매겨 낸다. `removed()` 는 문자열 API 를
  그대로 두되 배선 줄을 `removals()` 에서 만든다.
- **ghost 모드**: 기준선 dict 의 `ghost` 키 `{'wires': {key: n}, 'title', 'subtitle'}`.
  `step_wire()` 가 그 key 를 만나면 별도 `ghost_layer` 에 빨간 점선, overlay 에 빨간 채움·흰
  숫자 원을 찍고 `_leads`·`_segments`·레일 접촉에는 아무것도 남기지 않는다. ghost 모드는
  `partial` 이다. `set_header()` 는 ghost 의 제목을 쓴다. `export()` 는 `im → ghost_layer →
  overlay` 순으로 합성하고, ghost 대상 key 를 빌더가 한 번도 안 그렸으면 `AssertionError`.
  `content()` 에 ghost 모드일 때만 `'ghost'` 키가 든다.
- `removal_board(prev, nxt, title, subtitle)`: `(빌더, stage)` 둘로 표준 시그니처 클로저를
  만든다. 다음 보드를 임시 렌더해 `removals()` 로 ghost key 를 얻고, 앞 보드를 그 ghost 로
  다시 렌더한다. 클로저의 `__module__` 이 엔진이라 `tests/_boards.py::all_builders` 에
  안 잡힌다(걷기 보드는 `steps` 가 비어 가독성 검사 `steps > 0` 에 걸린다).

### 실험03

- `배치.py` `BOARDS` 네 장. index 2 가 `removal_board((build_e3_fa, None), (build_e3_fs, None), …)`.
  `build_*` 래퍼는 만들지 않는다.
- `netlist.md` C4 단계 표에 `0` 행. 1 행의 굵은 걷기 문장은 "걷기 ①·② 가 끝난 상태에서" 로.
- `render_breadboard.py --experiment 3` 으로 재생성(사슬 4 + 완성본 2).

### 문서

- SKILL.md §4a 에 "걷기 보드" 규약. "단계 끝은 LED 로 관측" 의 유일한 예외가 0단계다.
  파일명 규칙에 `<k>=0` 은 걷기 전용.
- `scripts/lab/render.py:576`·`prep-lab-checklist/SKILL.md:183` 문구에 걷기 그림을 넣는다.
