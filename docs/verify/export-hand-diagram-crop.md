# export-hand-diagram crop 검증

## 범위와 방법

2026-10-01 합의한 크롭 규칙을 스킬과 Python 추출기에 반영했다. 전원·보드 전체·외부 직접 결선 표기를 시각 판독해 hand-crop/v1 JSON으로 기록하고 코드는 보드 너비 2% 여백과 픽셀 경계만 결정한다. 기본 전체 페이지 출력은 유지한다.

fresh 실행자는 대화 이력과 수동 JPEG, 설계 문서, 이전 검증 출력을 보지 않았다. 평가는 출력 확정 후 수동 JPEG와 원본 PDF를 제공한 별도 에이전트가 수행했다. 파일시스템 권한 격리가 아닌 문맥·열람 지시 격리이며 각 실행 기록에 읽은 파일과 해시가 있다.

## baseline

기존 스킬 fresh 실행(`/root/crop_baseline`)은 원본 두 페이지 모두 하단 홀/외곽선이 잘리는 것을 확인했다. 제목 조각은 새 규칙에서 허용되므로 그 자체를 실패로 보지 않는다.

## 코드 검증

- 새 geometry/plan 및 exporter 테스트: RED 확인 후 GREEN.
- 코드 리뷰(`/root/crop_review`)에서 부분 재실행 파일명 충돌과 여러 실험 공통 출력 폴더의 보고서 손실 발견. 두 문제 모두 실패 테스트를 추가하고 수정했다.
- 관련 143개 테스트 통과: `python3 -m unittest discover -s tests -p 'test_*hand*.py' -v`.
- 전체 검사: 1607개 실행, 1개 실패, 5개 skipped. 실패는 `test_lab_config.TestManualCandidates.test_파일_이름은_0_을_채우지_않는다`. 기대 경로 `보고서/실험04/강의노트/실험4.pdf`, 실제 `강의노트/실험4. Multiplexer & Demultiplexer.pdf`. 수정 전 primary checkout의 103개 config 테스트에서도 동일 실패를 재현했다. 해당 무관 코드는 변경하지 않았다.
- 전체 검사 이후 리뷰 수정은 관련 143개 검사로 다시 검증했다.

## 시각 검증 기록

- round01 실제 PDF fresh 실행(`/root/crop_fresh`): 2쪽 저장, pending 없음. 출력 해시 확정 후 독립 수동 비교 수행.
- ambiguity 첫 실행(`/root/crop_ambiguous`): **FAIL**. 양쪽에 넣은 합성 물음표를 1쪽만 ambiguous로 기록하고 2쪽은 누락했다. 재확인으로 원본 변경이 아닌 판독 누락임을 확인했다. 실패 출력 보존.
- 이 실패에 따라 스킬에 각 페이지 네 외부 영역 확대, 외부 필기별 분류 표, 빈 영역 명시, 원본 위 최종 크롭 경계 검토를 추가했다.
- 보강 후 별도 fresh 실행자(`/root/crop_fresh2`, `/root/crop_ambiguous2`)로 재실행한다. 최종 판정은 하단 실행 결과 절에 기록한다.

## 산출물

기본 경로: `output/validation/hand-diagram-crop/`.

- `round00/baseline/`: 수정 전 출력/원본 대조/실행 기록(primary checkout).
- `round01/fresh/`: 처음 갱신 스킬 실행, 계획/보고서/해시.
- `round01/comparison/`: 수동 예시와 첫 출력 비교.
- `round02/fresh/`: 페이지별 검토 절차 보강 후 출력.
- `ambiguity/fresh/`: 실패한 합성 물음표 실행. 정본으로 사용하지 않는다.
- `ambiguity/round02/`: 보강 후 합성 입력 재검증.
- `*-suite*.log`, `red-*.log`, `green*.log`: 실행 증거.

## 한계

실제 사용자 PDF 2쪽과 합성 주석 사례의 검증이다. 다른 판형/필기 모두에 대한 완전한 의미 판독을 보증하지 않는다. 원본과 출력의 내용 보존을 기준으로 판단하며 JPEG 해상도와 수작업 여백 때문에 픽셀 일치는 요구하지 않는다. 회로의 전기적 정확성은 검토 범위가 아니다.

## 최종 실행 결과

- 보강 후 `/root/crop_fresh2`: 원본 2쪽 모두 saved, pending 없음. 원본·8개 방향별 확대·최종 PNG·원본 위 경계 미리보기를 직접 확인했다. MUX 1753×2520, DMUX 1703×2441 px, 300 DPI.
- `/root/crop_ambiguous2`: 합성 물음표를 두 쪽 모두 ambiguous로 분류, 종료 2, 최종 PNG 0개, 후보 6개. 합성 테스트의 기대 행동이므로 실제 사용자 응답 없이 검증 종료했다.
- 원래 프로젝트에 전달한 뒤 관련 테스트 143개 재실행 PASS, `git diff --check` 통과. commit/push는 하지 않았다.
- 최종 독립 시각 비교는 `round02/comparison/result.md`와 나란히 비교 이미지에 기록한다.
- `/root/crop_compare` 최종 round02 독립 비교: **두 페이지 통과**. 필수 요소 보존 및 구분선·하단 캡션 제외 확인. manifest 17개 해시는 비교 전후 동일하다.
- 여백은 지정한 보존 경계 기준 정확히 2%; 육안으로 보이는 잉크 끝 기준 약 2.21–3.14%다. 시각 판독 경계를 보수적으로 잡은 차이이며, 원본 보존과 약 2% 여백이라는 합의에 부합한다.
- 수동 대비 경계 차이(보드 너비 대비, L/T/R/B): p1 −0.27/−1.50/+0.29/−2.24%, p2 −0.76/−2.65/−0.45/+0.01%. 내용 누락이 아니라 여백 차이다. 정렬 좌표와 측정 오차는 개별 result.md에 기록했다.

## 2026-10-01 main 반영 검증

사용자 요청에 따라 기존 config 테스트도 보완했다. 실제 저장소의 배포본 유무에 의존하는 고정 인덱스 검증을 없애고, 임시 폴더에서 배포본 없음/있음 두 경우의 파일명과 우선순위를 검증한다. 교안 검색 코드의 동작은 변경하지 않았다.

최종 전체 검사: `python3 -m unittest discover -s tests -v` — **1609개 실행, OK, 5개 skipped** (137.276초). 이전에 기록한 실패 1건도 해소됐다. 코드·스킬·테스트·설계/검증 문서만 main 반영 대상으로 삼고, 로컬 생성 이미지와 다른 실험 산출물은 제외했다.
