# 논회실 문제설명 전용 스킬과 핵심 개념 보충 설계

## 확정된 의도와 범위

2026-10-12 사용자가 확정했다: 논회실 전용 스킬로 분리한다. 전체 학습팩에는 문제설명을 계속 포함한다. 기존 실험01~06도 모두 보충한다. 구현 방법은 아직 선택하지 않았으며 이번 요청은 설계 확정과 구현 계획 작성이다.

`logic-lab-problem-explain`은 기존 학습팩의 모든 included 문항에 대해 문제의 단서, 떠올릴 개념·공식, 실제 첫 줄, 풀이 이유, 완성 답과 검산을 펼친 HTML과 MD를 만든다. 별도 호출에서는 문제설명만 생성·보충하며 전체 학습팩에서는 기존 네 HTML과 네 MD에 계속 포함한다. 분류는 architectural: 스킬 책임과 설명 계약을 분리하지만 기존 생성기는 재사용한다.

## 변경하지 않는 조건

- 논회실 프로젝트 전용이며 다른 과목용 범용 엔진을 만들지 않는다.
- 기존 Python 표준 라이브러리 생성기를 재사용하며 런타임 의존성을 추가하지 않는다.
- Windows PowerShell에서 저장소 루트를 작업 디렉터리로 사용한다.
- 실행 Python은 3.11 이상이며 기존 hashlib.file_digest 사용 조건을 유지한다.
- 새 해설은 짧고 다정한 '~해요'체로 쓰되 정의·성립 조건·인과를 생략하지 않는다.
- 기존 문항 ID·번호·순서·출처·분류·소문항·답안 상태를 유지한다.
- 기존 실험설명·기출문제·기출풀이 HTML/MD/PDF와 기존 그림·자산·원문·사용자 파일을 보존한다.
- 설명 HTML과 MD는 실험 폴더 루트에, 설명 조각과 검증 기록은 자료/problem-explanations/에 둔다.
- 원문·내용·브라우저 검토는 실제 수행 후에만 기록하고 독립 검토 미실시는 그대로 표시한다.
- 실패한 검증으로 기존 팩을 교체하지 않으며 기존 백업·사용자 파일 충돌 검사·복구 경로를 유지한다.

## 구성과 소유권

새 `.claude/skills/logic-lab-problem-explain/`은 SKILL.md와 references/authoring.md, format.md, verification.md를 소유한다. 기존 `.claude/skills/logic-lab-review-pack/`의 문제설명 전용 저작·검증 지침을 이곳으로 옮긴다. 전체 학습팩 스킬에는 새 전용 스킬을 읽고 같은 작업 흐름에서 설명을 작성한다는 연결 지침과 출력 계약만 남긴다. 연결은 같은 에이전트의 스킬 절차이며 별도 채팅이나 하위 에이전트를 자동 생성하는 의미가 아니다.

Python 코드는 scripts/lab/review_pack/에 유지한다. 템플릿·Pretendard·KaTeX는 기존 팩/학습팩 스킬의 로컬 자산을 재사용하며 복제하지 않는다. 스킬이 원고를 저작하고 CLI가 조립·검증·발행한다. CLI 실행만으로 설명 내용이 자동 작성되지는 않는다.

전용 스킬은 실험 번호·범위·기존 팩 경로를 받는다. 인자 없는 호출은 복습노트/실험NN 중 기존 워크북 v2 manifest가 있는 가장 높은 실험 번호를 선택한다. 백업 폴더는 선택하지 않는다. 후보가 없으면 원 워크북 생성이 선행되어야 함을 안내한다. 여러 대상은 각각 독립 성공/실패로 처리한다. held/duplicate/other_experiment 문항은 설명 대상으로 올리지 않는다. 기존 질문만으로 파일을 수정하지 않는다.

## 설명 계약과 호환성

schema_version=1, review_presentation_version=2는 유지한다. problem_explanation_version=1은 기존 여섯 구역을 그대로 읽고 검사한다. problem_explanation_version=2는 새 일곱 구역을 요구한다. 새로운 전체 팩과 전용 스킬의 신규·갱신 출력은 v2다. 미활성 팩과 legacy 팩의 읽기 동작은 유지한다. 이 작업에서는 기존 실험01~06의 86문항을 명시적으로 v2로 보충한다.

v2 직계 구역은 각각 하나씩 `understand → recall → start → solve → verify → pitfall → retry` 순서다. 기존 problem-explanations/<id>.html 경로와 실험NN_문제설명.html/.md 파일명, 읽음 범위 logic-lab-NN-problem-explanation을 유지한다.

recall은 `layer formal`이며 제목은 '이 문제를 봤을 때 떠올릴 개념과 공식'이다. 문제의 어떤 표현·조건이 단서인지, 개념의 뜻, 필요한 공식·기호, 성립 조건, 적용하는 이유를 연결한다. 정성 문항에는 정의·판단 기준을 쓰고 공식은 강제하지 않는다. 공통 개념은 한 번 설명하며 서로 다른 개념이 필요한 소문항은 구분한다. 개념 개수는 고정하지 않는다. start에는 해당 문제에서 실제로 쓰는 첫 식·첫 행을 남겨 recall과 긴 설명을 중복하지 않는다.

직계 div.sum[hidden]에는 기존 시작·판단·검산과 함께 본문에 있는 핵심 개념·공식을 짧게 넣는다. 새로운 요약 문단은 `data-summary="recall"`로 표시한다. 별도 디자인을 추가하지 않고 기존 요약 패널을 재사용한다. 본문 답은 펼쳐 유지한다.

v2 구조 검사는 누락·중복·알 수 없는 구역·순서 오류·중첩 구역을 거부한다. recall과 해당 요약의 본문 검사에서는 h1~h6, layer-title, hidden, aria-hidden=true 요소의 텍스트를 제외한다. 중첩된 제목만 있거나 제목 밖에 공백만 있으면 실패한다. 개념의 정확성·충분성은 구조 검사로 통과 처리하지 않고 별도 내용 검토에서 판단한다.

## 데이터 흐름과 오류 처리

전체 팩: 자료 읽기 → 학습팩 원고/워크북 저작 → 전용 스킬의 설명 저작 → v2 활성화 → 기존 build → check → 검토 → publish. 네 HTML·네 MD가 계속 생성되어야 한다.

설명만 갱신: 기존 manifest와 question payload 읽기 → 새 RUN에 설명 원고 작성 → explain-stage(v2) → check → 실제 검토 → publish. stage 준비에서는 복제한 manifest에 목표 버전과 explanation_fragment를 지정한 뒤 원고를 검사한다. 원본 폴더는 변경하지 않는다. 설명 검토 상태는 not_run으로 초기화하며 이전 설명 승인으로 새 내용을 승인하지 않는다. 기존 다른 문서의 checks는 실제 원본 바이트가 같다는 근거를 유지하며 설명 승인과 혼합하지 않는다.

파일 누락, workbook v2 부재, 문항 불일치, 위험 경로, symlink, 사용자 파일 충돌, 검토 미완료, 원문 해시 변경을 명시적으로 실패시킨다. disputed/unresolved의 기존 경고와 상태는 유지한다. 기존 원문 hash를 단순히 새 값으로 바꾸어 발행을 통과시키지 않는다.

## 기존 자료 보충

현재 included 수는 실험01=12, 실험02=14, 실험03=15, 실험04=12, 실험05=19, 실험06=14이며 합계 86이다. 문항별 근거는 해당 팩 manifest의 sources/topics/problems 참조와 원 PDF/그림을 실제로 확인한다. ML 개념이나 머신러닝 교재 내용을 논회실 해설에 이식하지 않는다.

실험01~05는 docs/learning-pack-source/실험NN/problem-explanations/<id>.html을 갱신한다. 실험06은 docs/learning-pack-source/실험06/explanations.py가 원고 생성원이다. 이 Python 원고와 build_run.py의 생성 버전도 갱신하고, explain-stage 입력용 problem-explanations/<id>.html을 출력한다. 전체 build_run.py를 실행하여 다른 문서를 다시 생성하는 방식으로 보충하지 않는다. 기존 manifest 원고가 있는 실험04·05의 설명 표시 버전도 v2로 맞춘다.

내용 검토 기록은 각 문항의 단서/개념/기호/조건/선택 이유/소문항 범위/기존 경고 보존/요약 일치/근거 페이지를 명시한다. 모든 86문항을 내용 검토하며 375px/1280px × light/dark에서 실제 문항과 요약 패널, 수식·표·링크·그림·넘침을 확인한다. JS 비활성에서도 전체 설명이 읽힌다.

## 검증과 완료 조건

v1 호환성, v2 구역 오류, HTML/MD/요약 보존, 네 HTML·네 MD 통합, 잘못된 원고의 원본 불변, 설명 갱신의 다른 파일 hash 불변, 미검토 발행 거부를 테스트한다. 출처·경고·공식 성립 조건의 과학적 정확성은 실제 원문/계산과 대조한다. 표·수식 카드와 탐색의 기존 브라우저 검사도 유지한다.

완료는 전용 스킬과 연결 지침, v1/v2 생성·검사·발행 코드, 86문항 원고 및 발행 HTML/MD, 실험별 검증 기록, 백업·보존 증거, 관련 테스트 통과가 모두 있을 때다. 사용자의 이번 요청은 계획 작성이므로 구현 완료로 보고하지 않는다.
