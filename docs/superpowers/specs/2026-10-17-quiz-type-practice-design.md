# 논리회로실험 퀴즈 유형 연습 설계

## 확정된 의도와 범위

2026-10-17 사용자는 실험01~05 퀴즈에서 T/F, 빈칸, 브레드보드 작도, 짧은 서술형이 출제됐다고 알려 주었다. 이는 사용자에게 들은 **유형 관찰**이며, 실제 시험지나 문항별 정답을 확보한 것은 아니다. 다음 퀴즈에도 나올 것으로 예상해 복습팩 생성 스킬이 교안을 근거로 새 문제를 직접 작성하게 한다.

사용자가 확정한 선택:

- 실험당 10문항: T/F 4·빈칸 3·작도 1·서술형 2.
- 앞으로 생성하거나 전체 갱신하는 팩부터 적용.

기존 생성 흐름의 확장(bounded)이다. 에이전트가 내용을 저작하고 Python은 계약 검사·조립·발행을 수행한다. 자동 출제 API, 새 문제은행, 자동 채점 시스템을 추가하지 않는다.

## 학생이 보는 결과

기존 기출과 예상문제 뒤에 새 10문항을 추가한다. 각 문항에 `연습문제`와 `퀴즈 유형 연습 — 자체 출제 · <유형>`을 표시한다. 같은 개념이 기출에 있어도 유형 연습 목적으로 다시 출제할 수 있다. 단순한 단어 교체 대신 성립 조건·입출력·극성·인과·연결 관계를 묻는다.

기존 파일명과 문항별 링크는 유지한다. 새 정책 팩의 표시 제목은 `실험 N · 기출문제와 퀴즈 유형 연습` / `실험 N · 기출풀이와 퀴즈 유형 연습`이다. 문제·해설 HTML 및 MD, 문제설명 HTML 및 MD에 같은 ID·순서로 포함하고, 문제·해설 PDF도 다시 만든다.

| 유형 | 수 | 문제 기준 | 해설 기준 |
|---|---:|---|---|
| T/F | 4 | 판단할 주장 하나, 성립 조건 명시, T/F 각각 2개를 저작 기본값으로 사용 | T/F, 판정 근거, F이면 바른 문장·T이면 성립 조건 확인 |
| 빈칸 | 3 | 개념·소자 상태·입출력 관계, 필요한 경우 선택지 제공 | 빈칸별 답과 이유, 동의어·동치 표현의 인정 범위 |
| 브레드보드 작도 | 1 | 회로도, 칩 핀 번호·이름·역할, 전원·입출력·부품 조건, 빈 보드 제공 | 완성 결선도, 핀 연결표, 전원·미사용 핀·신호 넷 확인 |
| 짧은 서술형 | 2 | 기능·동작 원리 등을 몇 문장으로 설명하게 함 | 모범 답, 채점 핵심 요소, 허용 표현 |

10문항은 학습용 배분이며 실제 시험 출제 비율이 아니다. T/F의 2:2는 저작 기본값으로, 시험의 실제 분포라는 설명이나 출제 보장은 하지 않는다.

## 출처와 정답

새 문항은 `kind=practice`, 별도 ID, `question_type=true_false|fill_blank|breadboard|short_answer`로 기록한다. 모든 새 수록 문항은 해당 실험의 토픽과 확인한 교안·이론·데이터시트 위치에 연결한다. 사용자 경험담을 개별 문항 정답의 출처로 삼지 않는다. 사용자가 쓴 `sw 인버터` 같은 표현의 구체적 뜻은 교안에서 확인하며 임의로 해석해 출제하지 않는다.

은행 수입 문항의 ID·종류·출처·원문 증거는 유지한다. 자체 출제 문항은 원래 은행과 authoring-index의 고정 문항에 추가하지 않는다. 기존의 출처 없는 일반 연습문제 허용 규칙은 구형·비정책 문항에 그대로 적용한다.

동일 조건으로 재생성하면 새 문항의 ID를 재사용한다. 조건이 바뀌면 새 ID를 부여하고 대체된 문항은 사유를 남겨 비수록으로 보존한다. 기존 문항을 재분류하거나 삭제해서 수량을 맞추지 않는다.

정답을 먼저 독립적으로 풀고 진리표·회로 동작·핀 명세와 대조한다. 확인 전 `verified`로 표시하지 않는다. 근거 부족·모호한 정답·작도 자료 부족은 `held`와 사유로 기록한다. 새 10문항의 필수 조건을 충족하지 못한 팩은 완료·발행하지 않고 부족 유형을 보고한다. 기존 팩은 보존한다. 실제 독립 리뷰가 없으면 `independent=self_review` 또는 `not_run`이며 `pass`로 꾸미지 않는다.

## 브레드보드 문제

회로도와 핀 명세는 왼쪽 문제 패널, 빈 보드는 중앙 풀이 공간에 둔다. IC 배치와 방향도 학생이 정하는 것이 기본이다. 힌트에는 완성 배선이나 정답 핀 연결을 주지 않는다. 해설에는 빈 보드를 중복 표시하지 않고 완성 결선도와 연결 기준을 제공한다.

풀이 보드의 기본 인쇄 크기는 100×133.33mm, 최소 너비는 90mm이며 종횡비를 유지한다. 원본 보드 전체를 읽을 수 없으면 해당 회로가 들어가는 구역을 명시적으로 사용한다. 꽂을 수 없는 홀이나 레일의 연결을 임의로 바꾸지 않는다. 핀 번호·홀·배선의 가독성은 PDF 확대 확인으로 별도 검토한다.

그림은 기존 registry의 SVG+PNG, hash, 역할, 출처, 검토 상태 계약을 따른다. 보드 geometry와 기존 엔진의 넷 검증을 재사용하고, 래스터를 SVG에 삽입해 검사 규칙을 우회하지 않는다. 완성 결선도는 `solution/present`, 회로도와 빈 보드는 `problem/none`이다. 모범 그림과 IC 위치·홀 좌표가 달라도 전기적 넷과 부품 조건이 같으면 인정한다. 학생 답안 자동 채점 기능은 만들지 않는다.

## 호환과 적용 경계

- `schema_version=1`, `review_presentation_version=2`, `problem_explanation_version=2` 유지.
- 새 전체 저작에만 선택적 `quiz_practice_version=1`을 기록한다. 기존 파일의 읽기·검사·부분 수정만으로 자동 삽입하지 않는다.
- 정책 필드 없는 기존 팩은 새 수량·분류·제목·작도 배치 검사를 요구하지 않는다.
- 원본 워크북 템플릿과 provenance hash를 유지하고, 새 렌더 패치는 정책 버전이 있는 payload에만 적용한다.
- `rerender`, PDF만 내보내기, 목차·문제설명만 갱신은 출제를 수행하지 않는다.
- 이 기능의 구현·검증 중에는 실제 `복습노트/실험01`~`실험06`을 변경하지 않는다. 시연과 발행 테스트는 임시 루트에서 수행한다.
- 새 패키지·서비스·네트워크 호출을 요구하지 않는다. PowerShell과 현재 Python/pytest·Chrome·PDF 도구를 사용한다.

## 완료 기준

정책·오류·기존 호환 테스트, 문제·해설·문제설명·MD의 ID 일치, 문제지 정답 비노출, 작도 보드 중앙 배치와 PDF 가독성을 확인한다. 1280×900 / 375×812 화면, offline 로딩, `data-ready=true`, `data-overflow=''`, 깨진 그림·수식·콘솔 오류 0을 확인한다. 브라우저/PDF 검증이 실행되지 않았거나 skip되면 통과로 보고하지 않는다.

전체 흐름은 `자료 확인 → 기출 수입 → 10문항 출제·검산 → 문제·해설·문제설명 저작 → build/check → publish → PDF 생성`이다. 원문·사용자 파일·기존 팩의 hash 및 백업 보호를 유지한다.
