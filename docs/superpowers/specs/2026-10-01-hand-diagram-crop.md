# 손그림 결선도 크롭 설계

## 확정한 사용자 요구

- 기본 추출은 전체 페이지를 유지하고, `--crop`에만 새 규칙을 적용한다.
- 전원 단자 3개·극성·연결선, 보드 전체 외곽·모든 홀·행 번호를 보존한다.
- 외부 신호 이름·핀 번호·연결 화살표까지 포함하도록 페이지별로 범위를 조정한다.
- 판형 구분선·하단 캡션·불필요한 주변 공간은 제외한다.
- 제목·설명 때문에 범위를 넓히지는 않되, 안에 걸친 조각은 허용한다.
- 상하좌우에 각각 보드 너비의 약 2% 여백을 붙인다.
- 외부 필기의 분류가 애매하면 후보 영역을 보여주고 사용자 확인을 기다린다. 다른 명확한 페이지는 계속 처리한다.
- 스킬과 코드를 수정한 뒤 fresh 에이전트로 crop을 실행하고 사용자 수동 crop과 비교한다.

## 구현 설계

손글씨의 의미를 픽셀 색상·연결성만으로 분류하지 않는다. 스킬을 실행하는 에이전트가 PDF 전체 페이지를 시각적으로 읽고, PDF 페이지 좌표(pt)로 보드 본체와 보존할 요소의 사각형을 기록한다. 코드는 사각형의 합집합, 여백 계산, 검증, PNG 추출을 담당한다. 외부 API·OCR·새 패키지 의존성은 추가하지 않는다.

`board_box`는 전원 단자를 제외한 브레드보드 본체의 외곽이다. 2%의 기준 너비는 `board_box.x1 - board_box.x0`이며, 행 번호나 외부 필기로 넓어진 전체 영역 너비가 아니다. `keep`에는 행 번호, 단자, 극성, 전선, 외부 신호 표기의 경계를 기록한다. 보드 안의 모든 선을 개별 기록할 필요는 없다. 페이지 좌표는 회전이 적용된 `page.rect`/전체 렌더 이미지와 동일한 좌표계를 사용한다. 렌더 이미지를 (W,H) 픽셀로 읽었다면 x_pt=x_px*page.rect.width/W, y_pt=y_px*page.rect.height/H로 환산한다.

범위 판단을 `crop-plan.json`으로 보존한다. PDF SHA-256, schema version, 페이지 번호(1-based), 페이지 크기, 보드 좌표, keep 항목(label/box), 제외 판단(excluded의 label/reason), ambiguous 항목(label/box/reason)을 포함한다. 임의로 제외할 수 없는 ambiguous 항목이 있으면 최종 PNG 대신 보존 여부가 다른 후보 2개와 원본 위 경계 미리보기를 만든다. 해당 페이지는 pending으로 기록한다. 사용자 응답 후 plan을 수정하고 그 페이지를 재실행한다. 에이전트의 명확한 판단은 자동 확정 가능하며 모든 페이지에 일괄 승인을 요구하지 않는다.

`--crop`을 사용하는 코드는 `--crop-plan PATH`가 필요하다. 스킬은 이를 에이전트가 생성하는 단계까지 책임지고 수행한다. plan 없는 직접 CLI 호출은 고정 좌표로 대체하지 않고 필요한 사용법과 함께 실패한다. `--no-crop`/기존 `--full-page`는 기존 우선순위를 유지하며 plan 없이 전체 페이지를 출력한다. 크롭 결과는 `crop-report.json`에 상태, 실제 좌표, DPI, 출력 이름, 페이지 끝으로 여백이 제한됐는지 기록한다. 페이지 밖 keep/board 좌표나 잘못된 plan은 오류이며, 여백만 페이지 안으로 제한할 수 있다. 성공한 페이지는 계속 저장하고 CLI는 pending이 하나라도 있으면 종료 코드 2를 반환한다(오류 1, 전체 성공 0).

기존 `export_hand_diagrams(...) -> List[Path]` 반환형은 유지한다. pending 후보는 최종 파일 목록에 넣지 않는다. 보고서가 pending 페이지 목록을 전달하며 CLI는 이를 읽어 상태를 알린다. `crop_plan` 선택 인자를 마지막에 추가한다.

fresh 실행자는 `fork_turns="none"`으로 생성한다. 원본 PDF, 갱신 스킬, 필요한 코드와 netlist만 제공하고 대화·계획/설계 문서·수동 이미지·이전 crop 좌표·평가 보고서를 읽지 않도록 지시한다. 공유 파일시스템이므로 이는 접근 권한 차단이 아닌 작업 문맥 격리다. 열람한 파일 목록도 기록한다. 출력 해시를 고정한 다음 평가자가 수동 이미지를 읽는다. 평가에서 발견한 문제를 고친 경우 별도 fresh 에이전트와 새 round로 재검증하며 이전 실패를 지우지 않는다.
