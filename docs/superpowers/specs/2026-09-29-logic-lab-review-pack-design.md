# 논리회로실험 학습팩 설계

상태: 대화 설계를 구현 계획의 근거로 보존. 구현은 아직 시작하지 않았다.
사용자는 writing-plans를 요청했다. grill-yourself의 한 번의 결정 라운드 규칙에 따라 #10 완전판+요약, #11 고유 기출 전체+필요한 예상문제를 기본값으로 확정한다.

## 목적과 범위

논리회로를 오래전에 배웠고 보고서를 주로 AI로 작성하는 학생을 위한 실험별 학습팩이다. 보고서에 적힌 개념을 이미 안다고 가정하지 않는다. 입력에 따른 출력을 예측하고 이유를 설명하며 기출을 스스로 풀 수 있도록 필요한 기초부터 연결한다. 산출물 생성이나 자동 검사 통과를 사용자의 학습 완료로 표현하지 않는다.

기존 explain-lab-preview를 logic-lab-review-pack으로 대체한다. 실험 1~10을 지원한다. FPGA 프로젝트, 보고서 작성·수정, 측정 기록·결선도 변경, 범용 회로 시뮬레이터, PDF 자동 생성은 이번 범위에서 제외한다. 기존 명령은 호환 안내를 통해 새 스킬로 연결한다. 기존 프리뷰 산출물은 보존한다.

## 공통 제약

- 설명 수준은 기초부터 충분히 설명하는 완전판이며, 맨 앞에 짧은 복습 요약을 둔다.
- 판독 가능한 고유 기출 전체를 수록하고, 예상문제는 기출이 다루지 못한 개념만 보충한다.
- 실험 설명과 기출 풀이를 각각 HTML·MD로 생성한다.
- 현재 교안과 과거 판본을 구분하고, 실험 수행 범위와 시험 범위를 별도로 관리한다.
- 원문·보고서·측정 기록·결선도는 읽기만 하며, 기존 프리뷰 산출물은 보존한다.
- HTML은 로컬 자원만으로 동작하며, 위젯에는 MD용 정적 표·그림·설명을 제공한다.
- HTML과 MD는 같은 저작 내용에서 생성하며, MD의 풀이·수식·그림·출처를 누락하지 않는다.
- 독립 검토를 수행하지 않았으면 블라인드 검증 완료라고 표시하지 않는다.
- Windows와 macOS 경로를 지원하고, 실험 번호는 실험01~실험10 형식으로 출력한다.
- 실패한 초안으로 기존 검증된 팩을 교체하지 않는다.

## 사용자 동작

`실험4 설명이랑 기출 풀이 만들어줘`, `/logic-lab-review-pack 4`, `다음 실험 준비해줘`를 지원한다. 번호·번호 범위·주차·다음 실험은 스킬이 해석하고 기존 config의 번호 검증·일정을 사용한다. 같은 날 두 실험이면 두 팩을 생성한다. 대상이 전혀 지정되지 않으면 다음 실험을 기본으로 사용한다. 학기 종료나 프로젝트 주차는 지원 범위를 알리고 임의의 실험을 고르지 않는다.

생성 도중에는 메뉴 선택을 요구하지 않는다. 생성 후 사용자가 특정 부분을 물으면 해당 팩을 바탕으로 설명한다. 질문만으로 파일을 갱신하지 않으며, 수정 요청은 같은 팩에 반영한다. 보고서 폴더가 없어도 교안·기출로 학습팩을 생성할 수 있다.

## 교수법

짧은 요약 → 큰 그림 → 필요한 기초 → 실제 신호를 따라가는 동작 원리 → 완성 예제 → 실험 항목별 조작·관찰·이유 → 이해 확인 → 최종 정리 순서다. 필요한 기초는 해당 문서에서 설명하고 다른 실험 팩을 읽어야만 이해되는 의존성을 만들지 않는다. 완성 예제, 일부 단계 채우기, 기출 독립 풀이 순으로 도움을 줄인다. 비유는 실제 회로와 대응시키고 한계를 명시한다.

진리표·논리식·타이밍도는 완성 예와 도출 과정을 제공한다. 비트, active-low, 클록 엣지, 초기 상태, don't-care, 미정값을 혼동하지 않는다. 모든 실험에 특정 위젯이나 같은 수의 비유를 강제하지 않는다. HTML은 목차, 개념↔문항 링크, 독립적인 힌트·풀이 펼치기와 인쇄 스타일을 제공한다. 서술형 자동 채점은 하지 않는다.

## 자료와 문항

현재 수행 항목은 현재 공지·교안 및 config.EXPERIMENT_SCOPE로 확인한다. 교안은 config.manual_candidates를 사용한다. IC 핀·정격은 정확한 부품·패키지 자료로 확인한다. 기출 조건은 그 기출 원문을 따른다. 사용자 보고서는 설명할 주장을 찾는 재료이며 정답 근거로 취급하지 않는다. 실제 측정값은 출처가 있는 기록만 인용하고 예상값과 구분한다.

퀴즈 폴더의 모든 문항을 실제 기출/출처 미확인/기존 예상/새 연습으로 분류한다. 파일명만으로 실제 기출을 확정하지 않는다. 동일 문제는 출처를 모으고 조건·회로가 다르면 별개로 유지한다. 포함·중복·보류·다른 실험 분류와 이유를 저장한다. 수행 범위 밖이라는 이유로 시험 제외 판정을 내리지 않는다.

문항은 원문·출처 → 필요한 개념 → 힌트 → 단계별 풀이 → 최종 답 → 검산 → 흔한 실수로 작성한다. 정답지와 독립 풀이가 다르면 양쪽을 재확인하고 불명확한 것은 미확정으로 남긴다. 동치식·다른 유효 설계를 인정한다. 회로도·오버바·엣지는 PDF를 이미지로 확인한다.

## 출력과 데이터

`복습노트/실험NN/` 아래 `실험NN_실험설명.html`, `.md`, `실험NN_기출풀이.html`, `.md`, `출처와_문항목록.md`, `manifest.json`, `figures/`, `assets/`, `검증결과.md`를 저장한다. manifest는 자료 ID·상대 경로·해시·판본, 개념 ID·선수 개념·출처, 문항 ID·분류·개념 연결·원문 위치·제공 답안·도출 답안·검증 상태를 보관한다. 문항 ID는 재정렬·재생성에도 유지한다. PDF 페이지와 인쇄 쪽수는 구분한다.

HTML 본문 조각과 manifest에서 두 HTML을 조립하고 MD를 변환한다. 생명과학 프로젝트를 런타임 의존성으로 삼지 않는다. 보조 코드는 기존 Python 패키지 구조를 따라 scripts/lab/review_pack에 두고, 스킬은 이를 호출한다. 이는 대화 설계의 scripts/ 책임을 기존 저장소의 import·test 구조에 맞춘 배치 결정이다.

## 실패와 검증

교안이 없으면 일반 이론임을 밝히고 실제 IC·조건을 확정하지 않는다. 과거 교안이면 현재 학기 미확인을 표시한다. 기출이 없으면 자료 없음을 명시하고 연습문제와 구분한다. 판독 불가 문항은 보류하고 나머지를 생성한다.

원문 기호·수치 대조, 조합회로 전수 검산, 순서회로 초기 상태·엣지별 추적, 계산 단위·경계값 검토, 노트의 풀이 충분성, HTML·MD 대응, 브라우저 렌더링을 검증한다. 독립 검토가 가능한 승인된 실행 방식이면 정답을 뺀 문제와 설명만 전달해 검토하며, 아니면 자기검토로 기록한다. 반복 수정은 최대 두 회 후 미해결 내용을 보고한다. 구조 검사 실패는 초안으로만 남기고 기존 팩을 유지한다.

## 대체와 수용 기준

새 스킬은 `.claude/skills/logic-lab-review-pack/`에 정본을 둔다. 사용자가 지정한 `.claude/` 경로를 사용하며 `.gitignore`는 변경하지 않는다. 기존 explain-lab-preview는 호환 안내로 교체하고 직접 템플릿 참조와 다른 스킬의 오래된 설명을 갱신한다. 구 템플릿은 전환 시 보존하되 새 스킬에서 사용하지 않는다.

실험4를 첫 실제 학습팩으로 검증한다. 별도 작은 사례로 CMOS 수치 계산과 순서회로 타이밍을 검토한다. 모든 포함 문항에 원문 위치·개념 링크·풀이가 있고, 보류 문항에는 이유가 있으며, HTML·MD가 대응하고, 오프라인 브라우저에서 실제로 읽혀야 한다. 코드 검사는 학습 내용의 정확성 검토를 대체하지 않는다.
