# 문제설명 HTML 설계

## 의도와 확정한 선택

실험설명을 한 번 읽었지만 문제풀이 경험이 없는 학생이 문제의 뜻을 이해하고, 첫 줄을 시작하고, 풀이를 완성하도록 돕는다. 기존 학습팩 생성 흐름의 확장이다.
사용자가 grill-yourself 설계 후 writing-plans를 요청했다. 응답에서 변경하지 않은 #7·#8은 해당 스킬 규칙에 따라 기본값으로 확정한다: 실험01~05 전체와 향후 생성 규칙 적용, 풀이·정답 전체 펼침. 구현 실행 방식은 아직 선택하지 않았다.

## 범위와 완료 조건

- 실험01~05의 현재 문제지 전체: 각각 12·14·15·12·19문항, 총 72문항. 구현 시작 때 manifest와 문제지 PDF를 다시 대조한다.
- 문제지에 수록된 모든 문항·소문항을 설명한다. 번호·순서·문항 ID·조건을 유지한다.
- 출력: `복습노트/실험NN/실험NN_문제설명.html`과 `.md`.
- 기존 실험설명 템플릿 재사용. 글꼴·색·본문·목차·우측 요약·모바일·다크모드·이전/다음 동작을 동일하게 한다.
- 목차에는 현재 문서의 문항만 둔다. 자료 이동 영역·진행 합계를 추가하지 않는다.
- 풀이·정답을 본문에 모두 펼친다. 학습 잠금·자동 채점을 넣지 않는다.
- 새 문제, 문제 재정렬, 문제설명 PDF·영상은 이번 범위에서 제외한다.

## 문항별 내용

1. 문제 읽기: 원문·주어진 표/그림, 조건, 구할 것, 기호의 뜻. 앞 세 항목은 기존 문제 데이터에서 가져온다.
2. 쉽게 이해하기: 실제로 해야 하는 일을 짧고 구체적인 ~해요체로 설명한다.
3. 시작하기: 필요한 개념을 복기하고 첫 줄에 무엇을 쓸지 보여준다. 해당 실험설명 토픽 링크를 제공한다.
4. 함께 풀기: 모든 소문항의 계산·표·회로 작성 단계와 그 판단의 이유를 보여준다.
5. 완성 답과 검산: 완성 표·식·회로와 구체적인 검산을 제공한다.
6. 혼동 방지: 그 문항에서 하기 쉬운 실수와 이유를 설명한다.
7. 다시 풀기: 설명을 닫고 문제지에서 혼자 재현할 순서 1~3개를 제시한다.

기존 짧은 풀이를 그대로 복사하는 것으로 완료하지 않는다. 첫 적용 예를 생략하지 않는다. 예: 3×8 디코더에서 001→십진수 1→D1만 1→D7…D0 표의 오른쪽에서 두 번째 칸이라는 연결을 보여준다. 같은 유형도 각 문항의 조건을 자체 포함하며 다른 문항으로 이동해야만 풀 수 있게 만들지 않는다.

## 표시와 자료 계약

- 문항은 `article.topic`/`h3`로 감싸고 `eli5 → formal → warn → supp(필요시)`를 사용한다. 우측 요약은 직계 `div.sum[hidden]`에 시작 방법·핵심 판단·검산을 담는다.
- 읽음 저장 키는 실험설명과 분리한다. 기존 템플릿의 `data-range`만 문서별 값으로 지정한다.
- 설명 저작물은 `problem-explanations/<id>.html`, 발행 시 `자료/problem-explanations/<id>.html`에 보존한다.
- 새 설명 그림은 직접 제작한 SVG이며 viewBox/title과 읽을 수 있는 라벨을 갖는다. 표는 텍스트 표로 제공한다. 주어진 그림/표는 기존 문제 데이터에서 그대로 가져온다.
- HTML에는 설명에 필요한 개념 링크와 불확실성만 표시한다. 상세 원문 경로·판본·쪽수는 MD와 검증 기록에 남긴다.
- `disputed/unresolved`를 설명 작성만으로 `verified`로 바꾸지 않는다. 충돌·조건 부족은 HTML에도 설명한다. 모호한 문제는 가능한 해석과 필요한 조건을 제시하며 단일 정답을 꾸며내지 않는다.

## 구현 경계

manifest·출력명·조립·MD 변환·검사·발행을 확장하고 향후 학습팩 스킬에도 반영한다. 새 표시는 선택적 버전으로 도입하여 기존 팩을 계속 읽는다. 이번 기능은 review_presentation_version=2 워크북에서만 활성화한다. legacy는 현행 동작을 유지한다.

신규 build는 조립된 문제지 payload를 기준으로 설명을 생성한다. 기존 팩은 generated_files에 등록된 소유 파일을 새 stage에 복사하여 문제지 payload와 문항 manifest를 대조한 뒤 설명을 추가한다. 비소유 사용자 파일은 기존 폴더에 남겨 publish가 보존하며 stage의 소유 목록에 편입하지 않는다. 사라진 저작 RUN을 전제로 삼거나 기존 설명·워크북을 다시 생성하지 않는다.

기존 HTML·MD·PDF·원문·문제은행·사용자 파일은 보존한다. 기존 파일의 바이트 보존을 검사하며 manifest와 새 설명 산출물만 추가/갱신한다. 발행은 기존 publish의 source hash·사용자 충돌·백업·교체 실패 복구를 따른다. 기존 검사 기록을 새 설명의 검증으로 재사용하지 않는다.

## 검증

- 생성 시 설명 누락·중복·문항 순서 불일치·위험 경로·깨진 자원/앵커를 오류로 처리한다.
- 내용 검토는 72개 문항과 모든 소문항에 대해 문제지 PDF·문항 payload·원문·교안과 대조한다. 표·식·회로를 다시 계산하고 첫 줄부터 설명이 충분한지 확인한다.
- 새 설명 검토는 별도 기록한다. 원문·내용·브라우저 검증 완료 전에는 발행하지 않는다. 실제 독립 검토 없이는 independent=pass를 기록하지 않는다.
- 375px/1280px × light/dark에서 모든 문항의 그림·표·수식·목차·이전/다음·우측 요약·읽음 저장을 확인한다. 페이지 오류·깨진 그림·수식 오류·본문 가로 넘침은 0이어야 한다.
- JS 비활성에서도 문항·목차·완성 풀이가 읽혀야 한다. 기존 읽음 상태와 섞이지 않아야 한다.
- 기존 문제지·풀이·실험설명 검사가 계속 통과해야 한다.
